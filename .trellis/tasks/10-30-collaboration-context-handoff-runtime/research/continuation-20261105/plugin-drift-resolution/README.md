# Prospective runtime recorder

Prepared only. The original E0a helper, its failure and the raw E0a pass remain
unchanged. The [forensic report](forensic.md) cannot establish the missing
prelaunch plugin leaf inventory; this successor improves future observations.
Root owns the criteria disposition and must independently approve each later
scenario and model window. No Go, database or Provider execution occurred here.

[runtime_entry.py](runtime_entry.py) derives from the reviewed E0a helper and
continues to call the unchanged `run_rk1.py`. Add `--scenario RK1-H1
--start-trial 1` to each of its `describe`, `build`, `check`, `run` modes alongside
the private `--config` and `--permit`. The scenario and remaining trial labels,
per-trial launches and paid-start count come from the registered runtime
addendum and are explicit fields in every root-reviewed binding. The original
launcher still enforces next-unattempted trial, prior stop state and total25 cap.

Each invocation has its own ignored private directory beneath
`.omx/private/runtime-successor-20261105/<scenario>-from-<start>/`. Exclusive
attempt markers and prior original invocation records prevent automatic retries.
Upfront CLI build and check-only still require separate root-bound permits and
results, clean committed source, fresh root-allocated DB, unchanged operator
HOME/configuration, pinned Go and an explicit unexpired window. The helper does
not create databases, change operator settings or authorize the next scenario.

The pre-execution operator equality check remains mandatory for every phase.
It also saves a private per-file plugin manifest using the exact original
path/kind/content hash format, including directory/file symlink targets without
following them. Its aggregate must equal the operator observation. Missing,
unreadable or unstable inventory fails closed. Manifests contain relative paths,
link targets and hashes, so they remain private and are not committed.

Five known JSON metadata files from the forensic delta also receive private
before/after byte copies: the marketplace registry, directory cache, built-in
agents-md and diff stores, and the oh-my-claudecode usage cache. Each copy must
match its manifest leaf hash; a changed file refuses the snapshot. Missing
selected files are recorded as absent. This is selected metadata retention,
not a complete plugin-content backup. All other paths still have full hash/link
manifests; an unexplained changed path requires review and is never exempted.

After invocation, binding and trial collection run as separate evidence steps.
Operator changes no longer prevent recording the actual public result, observed
model/version, physical starts, original private accounting or CLI captures.
The result records changed operator fields and exact added/removed/changed plugin
paths, with old/new values or hashes. No path category is ignored. A post-scan
failure is recorded as an evidence error and requires root review; it cannot
silently become a clean operator observation.

Immutable product/framework/tool/CLI identities remain strict. The passive
observer is unchanged and reads each stable binary generation once. Reconciliation
includes all actual launch-record CLI copies, including fake seed processes,
while paid accounting includes only measured physical starts. For H1 the
registered scenario expects three measured starts; fake seed copies do not use
that allowance. For H6 each remaining trial is a pair of measured starts. All
requested public trial labels must be present and complete; canary, incomplete,
missing or actual launcher failure remains a stop condition. A complete wrong
answer remains its recorded model failure and is never relabeled.

`ready_for_independent_review` concerns completeness of the recorder's facts;
it does not approve the next scenario. Every result explicitly writes
`next_scenario_authorized=false`, with operator drift separately requiring root
review. Root must inspect drift and the actual trial verdict before another
registration/window is granted.

[Eleven credential-free controls](controls.txt) cover admission drift refusal,
postrun drift with an incomplete trial, actual recorder wiring preserving a canary and paid count after a post-binding error, exact file/link inventory against the
original algorithm, absent/unreadable inventory including subdirectory walk errors, H1 seed/paid separation, H6
pairs/partial accounting, blocking canary/incorrect labels, selected metadata
byte equality and refusal after a hash mismatch, and invalid scenario
selection. They read only synthetic temp files plus the original Python helper
source, and invoke no Go, database or Provider. [verification.json](verification.json)
binds the tested successor and unchanged launcher hashes. The matching private
helper copy is prepared; no active scenario permit was created.

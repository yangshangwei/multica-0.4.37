    fix(collaboration): unblock actions after slow issue reads
    
    Human actions could return while the account-scope invalidation was still refreshing the issue that supplies the next write revision. Collaboration issue reads also had no deadline, so polling and focus refreshes could leave the workbench pending indefinitely.
    
    The shared recovery deadline now bounds issue reads, and action completion waits for the current issue read after one account-scope invalidation while fencing access changes.
    
    Constraint: Reuse the existing 10-second withRequestDeadline mechanism and preserve realtime cancellation/restart behavior
    Rejected: Add a second issue invalidation in executeCollaborationAction | it cancels and restarts the same read unnecessarily
    Confidence: high
    Scope-risk: narrow
    Reversibility: clean
    Directive: Keep account-scope invalidation separate from waiting for the issue query; participant removal relies on the shared action path
    Tested: Core focused tests (54), full Core suite (314 files/4209 tests), Core typecheck, targeted Core lint, collaboration views tests (9), diff check
    Not-tested: Full workspace typecheck is blocked by pre-existing missing Web .next generated download page types
    Co-authored-by: OmX <omx@oh-my-codex.dev>

# CCG2 deployment-gate seam (read-only)

The new correction composite does not close deployed `MULTICA_KNOWLEDGE_CONTEXT_ENABLED` ON/OFF. Existing `newHostCompositeFixture` sets both TaskService and CollaborationService bools true after router construction. Existing `TestKnowledgeContextRequiresExplicitStartupOptIn` checks exact router environment parsing and propagation, but does not run a separately configured API process through real knowledge admission/input.

The existing external-process seam is `seedHostRuntime` in `e2e/fixtures/collaboration-host-runtime.ts`: it validates the live password/managed deployment ID; enrolls a test-owned runtime; starts the explicitly configured copied test daemon; creates two human users/workspaces and an ordinary local Claude agent; offers/adopts the resource via real HTTP. `openHostAcceptanceGate` opens/restores only that task database's admission bits. The root may reuse this fixture in distinct ON/OFF task deployments, with the root-built test daemon/provider/CLI and production renderer.

Current `HostVisit` and provider callback intentionally export accepted inputs/context and hashes, not the actual complete knowledge-bearing stdin or its digest. The provider also does not assert knowledge markers. Consequently a passing ordinary Host UI journey alone cannot prove that the ON deployment injected the approved candidate, or that OFF suppressed it. The smallest further test seam should observe the exact negotiated claim descriptor/prepare/authorize response plus a test-owned provider callback reporting the full stdin digest and expected synthetic marker presence/absence. Keep private body out of generic logs; freeze expected marker/hash in test-only material. Verify ON's actual authorization prompt hash equals the child-observed stdin text hash and OFF has no positive knowledge descriptor/no injected marker while normal eligible base input still runs.

Human knowledge seeding can use the existing `/api/collaboration/issues/:id/knowledge-candidates`, exact `/approve` route and real candidate sources. Target scope must be the consuming agent's execution workspace/project, not merely the source workspace. Existing `seedHostRuntime` puts source and execution in separate workspaces, so the root must deliberately choose a valid target and human approver with authority, not bypass membership or directly update a candidate row.

This recommendation requires separately owned E2E/provider callback edits and review; this child owns only the new tagged correction test and made no such change or deployment/test execution. Programmatic true/false tests remain supplemental evidence, not a deployment claim. The production default remains false.

# 角色、状态与阶段门槛

这是目标合同与当前映射草案，不是已实现的权限表。最终职业配置方案尚待阶段审批包收敛。

## 角色

| 业务角色 | 允许的业务动作 | 不可代替的决定 | 当前系统映射/缺口 |
| --- | --- | --- | --- |
| 产品经理 | 描述影响、确认标准、验收结果 | 研发评审、QA签字、发布批准 | 可作为协作发起人；目前最终验收绑定发起人身份 |
| 项目经理 | 分诊、优先级、排期、责任、依赖、风险、推动流转 | 研发和QA签字 | 可作为处理人/参与者；全程业务责任人与流转处理人需明确区分 |
| 研发工程师 | 技术方案、代码、PR、解释与评审结论 | QA、发布、产品验收 | 可作为处理人/参与者；职业签字范围尚未独立配置 |
| 测试工程师 | 测试矩阵、执行、通过/退回/阻塞与最终测试结论 | 发布批准、产品验收 | 可作为处理人/参与者；当前交付验收不是独立QA签字 |
| 需求分析智能体 | 分析、证据、风险、候选拆解 | 接受自身建议、自动关闭 | 复用真实资源和运行身份；“修改后接受并建子任务”合同需补齐 |
| 编码智能体 | 明确授权内修改、测试、回写PR和摘要 | 人工代码评审、发布批准 | 复用运行和结果；不能伪造人类身份 |
| 测试智能体 | 自动回归、日志和测试报告 | QA最终签字 | 人工签字后的新输出只能作为补充或新候选 |
| 发布监控智能体 | 检查构建/配置/迁移/指标、回滚建议 | 批准发布、批准回滚、关闭任务 | 执行必须绑定人工批准及实际构建；当前无完整部署闭环 |

职业角色不能由显示名、评论自述、提示词或客户端 `X-Agent-ID` 声明取得。撤权后已排队动作重新核权；机器持有的凭据不能冒充人类点击。测试脚本使用人类测试账号验证授权路径，只能标注“模拟人工审批”。

## 主任务与业务阶段

现有状态分类：`backlog / todo / in_progress / in_review / done / blocked / cancelled`。协作 `in_review` 是正式交付结果等待发起人验收，不能直接改成代码评审。

| 原方案阶段 | 主协作任务候选映射 | 阶段证据与条件 |
| --- | --- | --- |
| 新建 | backlog 或 todo，按当前创建合同 | 影响、复现、标准、创建人和时间 |
| 已分诊、待研发 | todo，按授权处理人流转 | 唯一责任人、项目、截止时间、P1与标准齐备 |
| 研发中、修改中 | in_progress | 明确接手；修改中引用失败结果/缺陷 |
| 代码评审 | 主任务保留 in_progress；关联研发阶段/子任务 | 对应仓库、分支/PR、提交版本、实现说明；TC07还要求CI缺失时拒绝 |
| 待测试、测试中 | 主任务保留 in_progress；关联QA阶段/子任务 | 人工代码评审与基础CI通过；测试报告绑定同一版本 |
| 待发布、已发布 | 主任务保留 in_progress；关联发布阶段/记录 | QA签字、实际构建、人工发布批准、部署结果分开记录 |
| 已验证 | 已有正式交付结果才可进入 in_review | 线上/预发布验证证据；发起人审阅提交的精确版本 |
| 已完成 | done，通过正式接受/完成合同 | 研发、QA、发布、验证证据齐备，当前有效最终验收人批准 |
| 已阻塞 | blocked及保留的恢复上下文 | 原因、责任人、解除条件、预计解除时间；解除者/时间和恢复阶段留存 |

表中“关联阶段/子任务”是实现候选，不是用评论约定取代系统门禁。阶段包必须在服务端写入口执行规则，并覆盖 UI、CLI、批量、Agent、重试和旧客户端路径；只隐藏按钮不能通过验收。

## 版本与撤回

- 建议、评审、测试、发布和验收决定绑定各自来源版本。上游版本改变时保留旧决定，但旧批准不能用于新的代码/构建/范围。
- 测试失败自动关联对应运行、失败用例与不可变日志，QA决定后进入修改阶段；成功重试保留旧失败。重复同请求恢复原结果，不能改键后把未知结果当作未执行。
- 发布、部署结果与验证是不同事实；批准不能显示成已部署，Agent建议回滚不能显示成已回滚。
- “责任人”与现有“处理人”不可静默混用：用户要求项目经理负责，当前处理人可随研发/QA转交而变化。首包基线只记录当前事实，阶段包确定是否需要独立稳定责任人字段。

## 阶段包需要收敛的产品决定

1. 每任务指定审批人，或项目配置可审批成员集合；是否允许一人兼任及自评审。
2. 最终验收继续使用发起人，还是增加产品/项目经理授权；撤权/离职如何继任。
3. 固定业务责任人与可流转处理人的关系；唯一责任人的服务端约束。
4. 业务阶段的持久表达与通用程度；哪些项目启用，未启用项目如何保持现有行为。
5. TC07较流转表更严格的CI检查时机，以及新提交到来时哪些批准失效。

这些问题属于后续大包设计输入；未确认前不能把首包文档或测试夹具当成正式产品权限模型。

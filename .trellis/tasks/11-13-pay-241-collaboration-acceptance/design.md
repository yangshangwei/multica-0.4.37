# 技术设计草案

状态：用户已确认首包S1；其最终设计由 [S1子任务](../11-13-collaboration-agent-identity-baseline/design.md) 承接。本文保留整体路线，不授权后续业务阶段模型。

## 1. 复用边界

主协作任务保持现有发起人、处理人、参与者、正式交付与验收生命周期。普通子任务关联研发、测试和集成证据；业务阶段与主任务状态分开，避免把 `in_review` 的正式验收语义改掉。最终是否以子任务或独立阶段记录承载强制审批，在阶段包内决定。

数据链为：主任务 → 获批拆解/关联子任务 → 运行与不可变结果 → PR/提交/构建/测试/部署证据 → 当前有权的人作出版本绑定决定 → 事务校验后流转。任何一个读取到的绿色提示或Agent摘要都不能直接成为授权。

现有 React Query 保持服务器数据权威；WebSocket使相关查询失效并触发授权读取。Zustand只保留客户端状态。UI放在共享 `packages/views`，API及schema在 `packages/core`，平台代码仅负责Web/Desktop接线。

## 2. 已确认首包 S1：身份展示与可复现基线

### 具体智能体作者

现有公开评论 `author` 是人类摘要，智能体评论可为null。S1收敛为新增 `author_agent { agent_id, name }`，保留旧 `author` 合同；从可信评论ID批量查当前名称，无迁移。具体协议、缺失/畸形回退和文件范围以子任务最终设计为准。

- 服务端从可信评论/运行/资源关系构建身份；不相信正文、显示名、请求头或调用方自报身份。
- 在当前任务权限内只投影必要显示字段；不借作者展示透露原工作空间成员列表、资源配置或当前不可读来源。
- 前端明确区分人员和智能体；字段缺失/旧服务端时保留通用智能体显示，不能伪造成某个具体人或猜测作者。
- 资源撤回/停用不抹掉可信历史身份；Agent实体缺失时保留ID及空名称，界面显示通用智能体。读者失去任务权限时拒绝读取，不新增名称快照。
- 测试涵盖具体Agent、人员、无摘要、畸形/未知字段、撤权及旧响应；UI只做展示与接线，不重复整个解析矩阵。

### 当前版本验收基线

扩展 canonical `e2e/collaboration-multi-account-closure.spec.ts` 及相应行为层测试。首包保留产品/研发/QA三个独立context、三个Agent资源与五次受控run；第四类发布监控Agent随后续包验收，不扩张原canonical流程。固定源码、构建和报告身份，不逐日期复制脚本。

每项输出 `requirement_id / case_id / run_id / source_version / environment / actor_kind / evidence_refs / result / limitations`。保留旧证据分类另列；未满足全用例的断言不得给整条用例PASS。所有测试账号审批明确标记模拟。

S1允许发现并登记阶段权限缺口，不因此扩张为通用工作流引擎。S1通过只证明首包能力；原24用例整体仍未验收。

## 4. 一致性、安全与兼容

- 复用事务版本/原始请求身份和人工认证主体；当前权限失效时拒绝，历史批准不能恢复已撤销执行权。
- 完成门禁仅在现有项目enforce合同下适用；不自动开启所有项目或把off误称受保护。新阶段策略需显式启用与兼容设计。
- 同一回调/同一执行结果的幂等键分别属于支付域/运行域，不能用平台评论去重证明支付不重复扣款。
- 新接口/字段同步API schema、畸形响应测试和旧Desktop兼容；新SQL遵守无外键及单语句并发索引迁移。
- 审计导出聚合多个权威来源，通过稳定身份关联，不把排序或文本拼接当作不可丢失证明。

## 5. 性能定义候选

100独立授权用户各有真实订阅会话。记录写事务确认、事件身份、每观察者读取/展示该版本的时间；同机单调时钟或已校准时钟，记录超时与未收敛样本，不能只对成功样本取p95。预热、事件数、持续时间和资源规格在S5运行前登记。

Agent回写指标从受控结果提交开始，终点为权威API返回关联结果可见；用户界面收敛另报。模型生成耗时和排队耗时单列，避免把慢推理掩盖或错误归因于回写。该起止定义仍需性能包最终确认。

## 6. 回滚与交付

S1原则上加法投影+共享展示，无数据迁移时可独立回滚；若研究发现必须迁移，返回设计明确方案后再写。新自动化在任务自有环境运行，只清理自建数据，保留失败证据。后续阶段策略与发布集成需独立回滚设计；不以删除审计/重置历史任务回滚。

本轮没有产品变更、测试运行或环境启用。外部依赖不阻止完成平台设计，但未接入的验收必须维持NOT_RUN/BLOCKED。

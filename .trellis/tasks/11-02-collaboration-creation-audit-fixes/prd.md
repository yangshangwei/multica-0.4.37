# 新建协作任务弹窗审计修复

## 目标与授权

修复 2026-11-02 impeccable 审计列出的八项问题，让用户可靠地创建协作任务、辨认接收人，并在键盘与窄屏触摸场景下完成或退出表单。保留现有产品风格、草稿保存、账号/API scope 防护、IME 与原始请求恢复机制。

用户已明确授权本会话创建 Trellis 任务、完成计划与规定评审后进入实现和检查；本任务仍须先完成需求收敛、设计和执行计划的评审，评审通过后按此授权执行。

## 已确认事实

- 原审计报告和结构化证据仍在，复制到本任务 research/ 作为持久证据。
- Git 基线为 codex/cross-workspace-collaboration，已有 47 项未提交改动，必须逐项保留。
- 此轮仅修改共享 Web/Desktop 表单与相关共享 UI，不修改移动端或服务器业务规则。
- 前次证据来自原始组件、模拟 API、内存草稿和隔离 Chromium；不代表真实创建或 Electron 原生验收。

## 范围（按优先级）

### P1

1. 阻止创建待确认时切换来源造成成功反馈丢失；不得削弱现有 scope 与卸载防护。
2. 补全接收人搜索 textbox 与 listbox 的关系、选项身份、选中状态与键盘活动项暴露，保留 IME、Escape 层级和分页。
3. 明暗主题焦点指示与相邻背景至少达到 3:1，含文本框半透明 ring 的实际合成对比；共享样式必须检查其他调用方。

### P2

4. 显示拒绝的具体原因和可执行后续操作，未知错误有安全兜底；保留草稿和附件。
5. 同名接收人显示当前 API 已允许返回的身份信息，选中后的确认也可区分账号。
6. 粗指针下接收人、关闭、父任务搜索及阶段输入的触控命中区域至少 44px。
7. 长表单只滚动主体，窄屏初始视野及滚动到底时均可访问提交和关闭/取消，且操作区不遮挡焦点。
8. 父任务搜索输入即时显示，停顿 250ms 后查询；保留权限刷新、scope 隔离和取消行为。

## 验收标准

- 每项修复均有当前源码确认、必要行为回归或浏览器测量证据；既有三个文件的 15 项测试保持通过。
- 延迟创建、拒绝、结果未知、原请求恢复、上传与草稿保存的行为均保持可用，账号/API scope 改变不会处理过期回执。
- 接收人键盘与 ARIA、明暗主题、桌面及 390×740 / 320×568 窄屏、粗指针触摸均验证；陈述 DOM/AX 与合成触摸的实际范围。
- 运行相关 lint、typecheck 与有意义的测试；共享变更需扩展到相关调用方。
- 不增加依赖，保持改动小且可回退，不覆盖其他会话文件。
- 最终报告给出八项状态、修改文件、验证命令和结果、实际浏览器范围及剩余风险。

## 环境约束

环境启动先读脚本和核对进程归属；使用隔离预览，不运行 make up / gc / down / destroy，不清理或重启现有服务。

## 不在范围内

- 真实任务提交、真实账号读屏朗读、物理触屏/iOS Safari 和 Electron 原生验收；不将模拟证据称为这些验收。
- 服务器/API 数据契约扩展、数据库变更、产品重设计、全局 UI 重构、其他 Trellis 任务推进。

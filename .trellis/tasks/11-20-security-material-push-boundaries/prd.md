# 安全修复材料的推送与披露边界

规划跟踪项；来源 `11-18-security-remediation-v2-template/design.md` 14.2 F10，2026-11-20 按用户批准的建议独立跟踪。当前 v2 保持现状，不增加推送行为。

## Goal

让负责人明确复现测试、补丁和相关元数据可以存放/推送到哪里，并如实区分任务可见性、代码仓库权限和小队自身措辞约束。

## Requirements

- 核对现有 Git/PR/分支推送路径与部署权限，定义 G1 的目标仓库、分支/可见性决定及禁止目的地。
- need-to-know 覆盖范围与边界明确：任务平台没有任务级可见性；测试文件名、用例名、注释、代码 diff 也可能泄露漏洞。
- 没有合法安全目的地时只在受控本地保存并停止推送，不自动扩大 Access 或公开材料。
- 已发布/未发布的允许操作、负责人变更和目标失效时的恢复均可验证。任何指令变化按新模板版本，不能静默回改 v2。

## Acceptance Criteria

- [ ] 有基于实际平台与 Git 操作的设计/执行计划及独立评审。
- [ ] 合成私有/不允许目标矩阵；未授权推送无外部写入；允许路径保留来源与审批记录。
- [ ] 文档说明部署权限仍是最终访问控制；契约和真实模型证据分开。

本轮仅建立跟踪；产品实现与真实调用不在本轮范围。

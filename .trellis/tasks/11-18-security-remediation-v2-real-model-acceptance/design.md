## 4 隔离拓扑

每个角色一个独立 Linux 容器和 HOME、Codex home、Git 工作副本、可写输出目录，不共享会话库。安全/代码/迁移审查员只挂载只读代码快照；实现者只能写当前补丁工作副本；漏洞验证者只能写自己的测试分支；QA 只接收不可变补丁和测试快照。leader 不挂载可写源码，只能通过平台协调。模型看不到本任务设计、评分规则、预期补丁或隐藏答案。

角色容器不挂载其他角色目录、主机 HOME、主检出、Docker socket。进程使用非 root、drop all capabilities、no-new-privileges、只读 rootfs、限量 tmpfs 和进程/内存限制。复现与回归命令由固定包装入口在 `--network=none` 的独立测试容器执行，镜像预装所需 Python/Git，禁止临时下载依赖；包装器不把 Docker socket 交给模型。

独立复核确认这还不足以准入：原生 Codex 若在可以访问模型/API 网关的容器内直接执行任意 shell，模型可以绕过离线包装器。因此真实入口必须先落实强制工具执行 broker，或等价的 provider 控制面/工具执行 OS 分离，证明普通 shell 无法直接在有网络的进程空间运行夹具。仅靠指令要求“用包装器”不满足约束。后续无模型原生探针已证明一条可行机制：不可写 managed requirements 强制 shell 无网，stdio MCP 通道仍可访问控制面的合成 API，并拒绝 scope 外调用（见 `research/native-boundary-findings-20261120.md`）。实际任务的 Multica broker、最终角色容器和生产领取/证据路径尚未接好，仍阻断真实准入；不得手工替模型执行测试。

模型控制平面的容器只连任务私有 internal network；独立网关同时连接该网络与供应商出站网络。网关只允许注册的模型 API 路径、HTTP 方法和精确供应商主机，TLS 验证开启，不跟随重定向，不开放 CONNECT 或任意反向代理。Multica API 路径转发原始任务 Authorization，不能换成人类/管理员凭据。供应商真凭据留在网关私有配置；角色只用任务短期合成代理凭据。每个角色独立网段或明确网络策略阻止互联，不能把“无公网默认路由”误当成角色间不可访问。

必须验证：自己目录读写成功；其他角色已知 canary、主机 HOME 和 socket 读写失败；审批角色写源码失败；测试子进程 DNS、外网和网关连接失败；模型容器直连外网和未授权端点失败；受许模型/API 路径成功；网关关闭后后续出站失败。探针使用合成 canary，不读取真实 secret。要留容器 inspect 的脱敏 mount/network/capability 摘要及镜像 ID。

本目录 `scripts/prepare.py --container-probe` 只验证一次性的离线容器、只读夹具和独立角色挂载，不创建真实网关或守护进程。它的通过也不能替代上面的实际拓扑预检。共享 Docker 超时后只清理有 task label 或精确 mount 证明属于本任务的容器，不重启共享引擎。

## 7 调用账本与时间

最大调用次数定义为每次实际 Codex 进程启动尝试；在进程启动前，以互斥锁、原子写入和 fsync 持久化预留。启动失败、探针、重启、恢复会话都占一次；无法确定是否启动也不退回额度。独立记录预留数、实际成功启动数、完成数、失败数、模型请求数、输入/输出 token 和缺失用量。一个 app-server 内多次模型请求不冒充一次 API 调用；若用户预算以 API 请求计，也需网关独立硬计数。

时间窗口从首次预留开始，持续计入人工闸门等待，另有每次执行上限。超时或耗尽预算：阻止新任务启动、停止本任务正在运行的进程、关闭模型网关访问，保留平台未完状态。不能暂停计时借闸门等待无限延长窗口。来源配置可能带自动重试，必须在网关与物理启动包装两层验证限额；仅靠 README 提醒不算预算守卫。

已实现的 `runtime_guard.py` 和 `gateway.py` 提供可复用的本地机制：私有 hash-bound 注册、互斥/fsync 预留、同一时刻只允许一个有终态的前序之后启动、失败消耗且停止、进程组超时结束、精确模型/路径和原始平台身份、请求计数与 deadline watchdog。9 个合成测试验证这些机制；当前代码无条件拒绝 real 模式，避免尚未验证的 integration/isolation hash 被当作准入证明。关闭 HTTP 连接只能约束本地继续发送和读取，不能证明供应商远端生成/计费已停止；实际供应商 usage 缺失时仍为 unknown。

任何环境/传输不完整、隔离失败、证据写入失败或越界写入都停止余下系列；完整但不符合预期的样本记 disproved，不自动重试刷好结果。是否继续其他独立案例必须在启动前注册中明确，默认遇到首个不完整即停；失败本身留原记录。预算内计划外的 reviewer 重派也计调用，不能因为正文允许一次而获得额外额度。

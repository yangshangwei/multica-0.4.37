# 协作智能体身份展示与闭环回归基线

状态：in_progress；2026-11-13 用户批准执行，S1 已激活。2026-11-13用户选择“先补具体 Agent 身份展示和现有闭环回归基线”，随后要求继续推进；首包范围已确认。

## 目标

协作者能直接辨认评论由哪个智能体产生，并能沿用现有运行记录核对身份。通过当前版本的受控回归证明，这项展示改动没有破坏原有人机协作、人工验收、权限、幂等、冲突和恢复行为。

本任务是PAY-241父任务的S1子任务，只对本首包独立验收；父任务的24条用例和后续S2–S5仍由父任务维护。

## 已确认背景

- 当前评论已保存真实 `author_type / author_id`；运行时写入的Agent ID来自验证后的run，而非正文自述。
- 公共评论的 `author` 只投影人员，Agent评论为null，界面因此只能显示通用“Agent/智能体”。这是展示能力缺口，不能通过混用人类作者结构解决。
- 列表、按字节限制的列表与单评论详情共用同一个服务端投影函数；可在此添加最小身份摘要，不需要数据库迁移。
- 已有canonical三账号/三Agent受控闭环，五次运行按1/2/2分布，包含首轮退回、修订后精确人工验收。旧PAY-1是另一组有限历史证据，不覆盖本次版本。
- 具体来源和边界见 `research/s1-source-map.md`；测试归属和断言见 `baseline-cases.csv`。

## 首包需求与验收条件

| ID | 要求 | 可观察验收 |
| --- | --- | --- |
| S1-01 | 展示可信具体Agent身份 | Agent评论显示对应名称及“智能体”标识；同名人与Agent仍可分辨；API身份与该评论实际运行的Agent ID一致 |
| S1-02 | 保留人员作者和现有权限 | 人员名称/头像/外部标识不变；Agent摘要不赋予编辑、执行或验收权限；Agent结果不能自动完成主任务 |
| S1-03 | 列表、详情和回复提示一致 | 普通分页、字节预算分页、单条补读及回复提示使用相同身份；长名正常换行，无额外资源详情请求 |
| S1-04 | 安全兼容缺失身份 | 旧服务端无新字段、Agent名称为空/实体删除、新字段畸形时仍可读评论且显示通用智能体，不伪造人名或猜测ID |
| S1-05 | 保留历史归因和当前访问控制 | 资源撤回/停用不重写既有评论身份；仍有任务访问权者可见最小历史作者摘要；失去任务访问权者不得获取评论及新增字段 |
| S1-06 | 无越界投影 | 只返回Agent ID及当前显示名；不携带所有者账号、工作空间、运行时配置、凭据或未经授权资源内容；不新增读取Agent详情的权限 |
| S1-07 | 当前版本三会话闭环 | 产品/研发/QA三个独立会话、三个资源所有者及三Agent复用原canonical流程；五个真实受控进程、两轮交付及发起人精确验收均有对应证据 |
| S1-08 | 既有边界回归 | 原请求重放不重复派发；普通评论不派发；冲突不覆盖；无权账号及附件读取拒绝；离线恢复、撤权和原请求恢复通过各自canonical测试 |
| S1-09 | Web/Desktop共享行为 | 共用同一投影及展示逻辑；production Web闭环验证，Electron renderer完成具体作者与回复提示的定向验证；安装版完整Main不在本包 |
| S1-10 | 报告可复核且不夸大 | 记录源码/构建/环境、实际命中的测试与失败/跳过、评论→Agent→run关联、运行终结及清理结果；全部首包验收满足后才能关闭本子任务 |

旧字段兼容不意味着弱化原评论ID、版本或权限字段校验。显示名是当前可查询的名称，不宣称写入时冻结名称；稳定归因由Agent ID与已有运行证据承担。

## 范围与约束

- 只扩展公开协作评论的最小作者摘要、共享评论列表及回复提示、对应协议/视图测试和既有闭环基线。
- 人类评论编辑历史保持现有事件合同；Agent创建与执行仍由已有运行记录核验，不新增历史事件类型或伪造历史记录。
- 沿用现有状态与发起人验收规则。职业角色、建议审批、PR/CI/QA/发布门禁、支付沙箱、真实Provider、100人性能属于父任务后续包。
- 首包使用已有三Agent流程，不把未纳入的第四类发布监控Agent或四职业签字列为本包通过。
- 无新依赖、无迁移、无默认执行开关改变。环境与测试数据独立；不重跑或改变旧PAY-1、PAY-2–6记录。
- 测试使用受控Provider和测试账号；“人工”只说明系统认证主体及授权路径，不代表真实业务人员已经签字。

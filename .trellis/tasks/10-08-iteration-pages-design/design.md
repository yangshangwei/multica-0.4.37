# 迭代业务页方案

状态：实施收尾中；用户已于 2026-10-09 授权按父任务 [closeout-plan.md](../10-08-iteration-workspace-settings/closeout-plan.md) 完成修复、验证、提交和归档。此前的规划状态由该授权取代。

原型用于评审布局和主要动作，可能缩减筛选选项、历史字段和生命周期细节；它不取代本文对完整现有能力的保留要求。当前演示统计口径为 original=12、current=14、cancelled=1、effective=13、completed=8、remaining=5、original_completed=7，全部是任务数；图只含 effective/completed/original。

## 1. 方向与取舍

采用“时间线总览 → 单周期详情”，复用现有周期与任务操作。

| 选择 | 理由 |
| --- | --- |
| 计划／历史为紧凑时间线，当前展开 | 保留参考图的纵向节奏，同时让成员直接看到正在进行的工作。多个大型统计卡会稀释当前重点。 |
| 计划空详情左对齐，先添加后新建 | 常见动作是把已有待办安排进周期；创建任务仍使用现有编辑器。空状态不放虚构进展、插画或设置表单。 |
| 三个详情标签：任务、进展、范围变化 | 将安排任务、看趋势、追踪变更分开，同时保留已有信息，不把全部统计与编辑表单堆在首屏。 |
| 复用完整元数据目录，只取当前／打开周期的详情 | 列表 DTO 没有统计；不为了计划行数字发出 N 个详情请求，不新增批量 API。 |
| 图表命名为“进展” | 现有三条线是有效范围、已完成、原始承诺；视觉参考不构成新增燃尽算法、预测或执行中序列的依据。 |

## 2. 页面与交互

### 总览 `/{workspaceSlug}/iterations`

- 标题“迭代”，右侧“新建迭代”，次级设置入口由父任务集成。名称／日期／状态筛选收纳在“筛选”入口内，展开后使用现有筛选能力；清除入口在有筛选时出现。
- 主体分“当前与计划”和“历史迭代”标签，分别使用细时间轴与有语义的列表，内容左对齐。参考尺寸：时间轴占 24px，行正文左间距 24–32px；紧凑行垂直留白约 24px，周期之间约 32–40px。最终用现有 spacing 与字号 token，不为像素建立新设计系统。
- 计划组按 `start_date DESC, id DESC` 排列；较晚的在上，较早的靠近当前。最近计划标注“即将开始”，其身份继续采用现有 `planned` 中 `start_date ASC, id ASC` 首条规则；只是提示，不是新增状态、定时任务或已开始判断。过期的计划仍是计划。
- 当前组只认服务器 `status=active`。展开区域左侧为进展图，右侧为有效范围、已完成、原始承诺和有效完成率；剩余任务在详情整体统计中展示。右栏比图窄，窄窗口改为图下横排。
- 历史组 `start_date DESC, id DESC`，清楚区分完成与取消；行不显示来源不明的完成率。未知状态／模式保留可读入口和原值提示，不成为可写计划。
- 周期名称是导航链接；整行视觉命中范围可放大，但不能把图例、数据表按钮或其他控件嵌进链接。当前展开是展示布局，不是展开后偷偷触发生命周期。
- 当前不符合筛选时不绕过筛选强行显示；其身份来自完整目录，不根据筛选结果重选。无全局 active 与筛选排除 active 使用不同文案。
- “新建迭代”打开现有 `IterationForm` 的表单内容；明确提交后等待服务端成功再进入详情。默认日期继续使用已有 14 个日历日的表单默认值，它不构成自动排期或设置项。

### 间隔的严格含义

“N 天未安排”仅表示两段已知日期之间没有安排周期的完整日历天。例：10 月 1–7 日与 10 月 10–16 日之间是 8、9 日两天。

1. 仅在完整、成功取得、未应用名称／日期／状态筛选的目录上推断；未完整加载、不确定的背景刷新或部分页面不产生新间隔。
2. 先按日历日期排序并检查完整目录中的覆盖关系，再把确认的间隔映射到相邻展示行。不能直接对两个可见行相减；展示分组造成的非相邻日历关系不连线。
3. 两端必须是同一保存时区、已知手动模式且非取消的周期。取消周期和未知模式／状态若落在该范围，抑制这条间隔，避免暗示其仍在占用日期或对未知规则作判断。
4. 重叠区间按覆盖合并；嵌套、同日起止和紧邻周期不产生负间隔或重复间隔。跨时区边界不提供天数推断。
5. 用校验后的 `YYYY-MM-DD` 做 UTC 日历日序号计算：`later.start - earlier.end - 1`。不按本地午夜毫秒差计算，不以 23／25 小时的 DST 日换算天数。
6. 不在最早／最晚记录之外补“空档”，也不生成默认冷却期。视图文字只用“未安排 / Unallocated days”。

### 详情 `/{workspaceSlug}/iterations/{id}`

标题区含返回、名称、状态、日期、保存时区、协调人、复制链接；有说明才渲染说明。空协调人与成员资料加载失败分开表达。已开始时可查看实际开始时间；逾期只作提示，不自动结束。

| 状态 | 首屏与动作 |
| --- | --- |
| planned，已确认没有任务 | 标题下约 56–72px 留白后出现简短“还没有安排任务”；主按钮添加已有任务，次按钮新建任务。默认任务标签，不展示零曲线。 |
| planned，有任务 | 默认任务标签；保留添加／新建，开始为明确按钮，编辑／取消／删除在次级菜单。开始仍需现有预览确认。 |
| active | 默认任务标签；标题下可显示少量整体统计，完整图在进展标签；结束为明确按钮，编辑、取消与可用的显式交接在次级菜单。总览负责默认展开曲线，详情保持任务工作面。 |
| completed／cancelled | 显示冻结状态与结束时间；任务标签读取冻结事实，进展读取快照，范围变化展示冻结事件与结束／去向。允许时提供更正名称／说明，日期、协调人、范围与快照不可修改。 |
| 未知状态／模式 | 展示可解释的元数据和可用历史，禁用写操作，明确不支持该模式；不把它映射为 planned。 |

标签使用项目现有 Tabs 组件：任务／进展／范围变化（Issues / Progress / Scope changes）。标签是页面内状态，沿用现有详情 URL；不新增路由。任务筛选状态留在稳定挂载的任务组件，操作表单／待恢复区域留在标签面板外；懒查询不能靠卸载编辑器实现。实体边界按 `wsId:id` 重置，不能按 revision 重置。

“添加已有任务”进入 `IterationAssignment` 既有选择与完整预览流程，目标锁定当前周期。新增任务继续使用现有手动创建弹窗 `CreateIssueModal` / `ManualCreatePanel`，加入小型、工作空间校验的周期初值入口：显示当前周期，读取有效 planned/active 选择及 revision，再按现有 `POST /issues` 事务提交 `current_iteration_id` 与 `expected_iteration_revision`。归属与创建一次成功，不先创建再异步移动。周期已关闭、权限变化或修订冲突时保留输入并要求明确选择／刷新，不能静默清空归属后创建。此上下文入口复用已有手动弹窗，不扩展 AI 代建能力或改全局创建方式。

## 3. 读模型与图表合同

`IterationListSchema` 仅有 `IterationSchema[]` 和 `next_cursor`；服务器 `ListWorkspaceIterations` 以日期与 ID 升序分页，游标绑定集合版本。仅倒排首屏会遗漏后页当前周期，也无法得到全局倒序。

因此复用 `useIterationCatalogue` 已有的完整元数据读取路径，按 100 条顺序取完游标；必要时把 query options 下沉到 `packages/core/iterations/index.ts` 并保持原缓存键供引用组件共用。检验重复游标、重复 ID、工作空间身份；集合变化导致 `cursor_stale` 时丢弃本轮不完整集合，从头重试，不拼接不同版本。第一次只在完整结果到达后展示时间线；背景失败保留上次成功目录并标记，关闭间隔推断。核心查询传 AbortSignal 并复用 `protectIterationRead`。

名称／日期／状态筛选以及倒序显示分页在已确认的目录上完成，保留现有筛选语义；历史按约 50 条逐步显示，可收起额外计划，不按可见行判断当前或间隔。删除原总览为相同元数据另发的列表请求；这只减少重复读取，不改变其他选择器、项目参与或历史引用用途。大量目录未来可改服务器倒序分页，但本次不增加 API；不可用未经完整证明的截断集合替代。

总览找到 active 后调用一次 `iterationDetailOptions(wsId, id)`；切换详情复用相同 Query 键，组件重用不代表禁止必要刷新。计划／历史紧凑行零统计请求。无 active 时不调用详情；目录无已确认完整结果时不提示“没有当前”。

进展组件从 `snapshot?.statistics ?? statistics` 读取，历史必须优先快照：

| UI | 来源与规则 |
| --- | --- |
| 有效范围、完成、剩余 | `effective`、`completed`、`remaining`，直接展示服务器任务数，不从已过滤任务列表重算。 |
| 完成率 | `effective_ratio` / `original_ratio`；null 显示不适用。 |
| 曲线 | `chart[].date/effective/completed/original`；original 虚线，图例文字与线型同时区分。 |
| 时间范围 | 日期按周期保存时区理解；只绘制响应点到 `calculated_at` 对应的数据截止日期，不在计划结束日填充未来值。 |
| 完整统计 | 保留 current、original、cancelled、added_unique、removed_events、reentry_events、cancel_events、reopen_events、started、净变化及比例等现有指标，放在进展标签的统计详情中。started 是累计统计，不创建对应历史曲线。 |
| 可访问表格 | 图旁“查看数据表”可展开同一数据源，保留 caption、列／行表头；键盘可到达，无需依赖悬浮提示或颜色。 |

计划详情的无数据进展使用解释性空状态。统计响应无效时沿用 schema 边界错误；不以默认 0 修饰失败。已冻结历史的现时名称引用可单独标注，但任务当时名称、类别、标签和负责人不得用当前资料替换。

## 5. 权限、失败与恢复

- 周期维护是当前人类工作空间成员能力，不能错收紧成管理员专用；启用／关闭工作空间和规划时区是父设置合同中的 owner/admin 能力。服务端仍是权限最终依据。
- `IterationRecovery` 独立于状态、enabled、能力与标签挂载。布局重排不能丢失已提交命令，也不能以“已结束”推断是哪次命令成功。
- 创建、移动和生命周期均等待真实成功再更新成功反馈／导航。移动、开始、结束、取消、删除、显式交接沿用完整预览、原 preview hash 及持久 request ID；超限不分批偷偷执行。
- `iteration_revision_conflict` 保留输入与旧基线，显示比较再显式保存；`cursor_stale` 重新读取集合。响应丢失通过原操作查询／完全相同 POST 恢复，不生成新意图。
- 网络、5xx、408、429 背景失败保留最后成功数据显示刷新提示；首次失败显示重试。读到撤权或确切删除时隐藏对应受保护页面；认证 401／403、`workspace_access_denied` 不作为旧服务兜底。
- 元数据、统计、任务查询分开显示失败。任务请求失败不等于零任务；缺失协调人资料不等于未设置；旧快照缺少可选标签／优先级不等于无标签／无优先级。

## 6. 设置集成、适配与回退

父任务拥有启停／共享规划时区、部署 gate 退出、设置导航及实时集成。本子任务可在当前受支持且已启用的能力合同下单独实施和验证；不复制父任务后端变更。最终从旧业务页移除配置折叠区、接入真实 `settings?tab=iterations` 的共享文件编辑由集成协调，设置目标落地前不交付死链接。本子任务完成标准保留这一明确的父级集成项，不能把它误写成独立设计批准的前置条件。

现有 `manual/supported/enabled/atomic_handoff` 解析兼容保持；新界面不要求新的响应字段。旧服务不支持时显示既有不支持状态。关闭后历史照常可读；未知模式只读。历史名称／说明更正继续受现有 enabled 与权限合同限制。

使用语义颜色与项目字号。900px 窗口下筛选换行、图表与统计纵排；局部数据表允许横向滚动，页面本身不溢出。行链接、菜单、标签页与弹窗均用现有可访问组件；状态反馈使用 status／alert，焦点返回触发器。深浅色与中英文使用同一布局。

无数据库变更或迁移。回退时恢复旧页面组成与相关局部组件，保留原 API、缓存身份及持久恢复格式；不要清空用户草稿或待确认命令。若设置子任务已上线，回退业务页时保留已上线设置入口并避免恢复第二套设置控件。

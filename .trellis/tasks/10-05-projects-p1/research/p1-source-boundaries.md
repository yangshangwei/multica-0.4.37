## 13. 状态、权限与执行边界

### 13.1 项目状态语义

| 状态 | 表达的项目事实 | 禁止隐含的副作用 |
| --- | --- | --- |
| `planned` | 目标或计划准备中 | 不把任务全部改为 backlog/todo |
| `in_progress` | 项目正在推进 | 不因切换状态启动智能体或 AI小队 |
| `paused` | 项目层面暂缓推进 | 不自动停止正在执行的任务、不冻结逾期统计 |
| `completed` | 成员已将项目标为完成 | 不自动将剩余任务 done、不代表目标验收通过 |
| `cancelled` | 项目不再继续 | 不自动取消任务、不清空迭代归属 |

五状态之间沿用现有合法修改能力，不新增强制审批或单向状态机。重新打开项目保留进展和验收历史，当前验收适用性仍按描述版本判断。

暂停项目时说明已有执行仍会继续，提供查看执行入口；成员若需停止执行，应在现有执行界面使用其有权限的停止操作。

### 13.2 权限矩阵

| 操作 | member | owner／admin | 智能体 |
| --- | --- | --- | --- |
| 查看项目、健康与进展 | 按工作空间现有访问权限 | 同左 | 按已有服务端授权范围 |
| 创建／编辑项目与日期 | 允许 | 允许 | 仅已有工具已授予的能力；lead 不增加能力 |
| 发布／更正手动进展、记录验收 | 允许 | 允许 | P1/P2 不作为最终发布者 |
| 请求 AI 草稿 | 另需有权调用选定执行者 | 同左 | 不能仅因 lead 身份自行触发 |
| 删除项目 | 不允许 | 允许 | 不因 lead 或项目上下文获得删除权限 |
| 配置全空间时区、自动跟进策略 | 不允许 | 允许 | 不允许自行扩大策略 |

所有读写、计数、搜索、下载和未来导出都在服务端校验工作空间权限。不能因知道项目 ID、持有旧链接或查看过草稿读取其他工作空间的数据。

## 14. 字段与校验

以下长度是本次新增内容的建议验收边界；既有字段继续沿用服务端有效限制，实施前确认现有上限，不静默收紧旧内容。

| 字段 | 阶段与规则 | 校验反馈 |
| --- | --- | --- |
| 项目名称、图标、优先级、状态 | 既有字段；不新增必填项或枚举 | 无效状态沿用明确错误，不自动改成 planned |
| 项目描述 | P1 模板复用既有内容与编辑能力 | 超出现有限制时保留输入并说明限制 |
| 项目开始／截止日期 | P1 沿用；新增编辑路径校验开始日不晚于截止日 | 历史异常值显示待修正，不静默互换 |
| 项目负责人／默认小队／资源 | 沿用有效引用和现有访问规则 | 失效引用显示原因，不自动改配 |
| 进展类型、正文 | P1 类型必选；正文去空白后 1—10,000 字符 | 空正文不能发布；中文与英文按同一字符计数规则 |
| 进展人工判断 | P1 可选"按计划／需关注／有风险" | 仅作为作者判断，不覆盖系统计算 |
| 证据引用 | P1 单条建议最多 50 个；站内目标须存在且可访问 | 失效引用逐项提示；普通外链不宣称已验证 |
| 验收结论／依据 | P1 验收类型必填；通过／部分通过需证据或可复核说明 | 缺失时保留输入并定位字段 |
| 更正说明 | P1 更正时必填，去空白后 1—1,000 字符 | 不能用空白覆盖旧记录 |

正文与外部引用按现有富文本和链接安全规则展示；链接中的指令、任务正文和资源内容都不能改变生成草稿的权限与行为边界。

## 15. 跨模块契约

- 分拣：候选项目可保存为准入信息，但未接受前不进入项目普通任务视图、甘特图、健康、AI 材料或里程碑。可另示待分拣数量入口，标明不计入正式范围。
- 接受：成功接受并选择项目后，任务才进入实时项目集合；只接受不触发项目默认小队或负责人执行。接受与字段校验不能部分成功。
- 迭代：一个项目可以跨多次迭代，一个迭代可包含多个项目；新增、更换或结转迭代不改变项目归属或任务执行状态。
- 历史：迭代结束快照包含当时项目标识或摘要；项目改名、删除或任务换项目不重写该快照，打开实时对象时说明变化。
- 任务移动：任务从项目 A 转入 B 后，两个项目实时统计分别减少／增加；原进展快照仍保留当时事实。
- 默认小队：设置项目和设置任务负责人仍是两件事；已有任务不因项目默认小队变更而改配。
- 项目上下文：描述模板保存后进入原有项目上下文路径；项目进展不会被无上限地追加到每次任务执行中。
- 自动化：已有自动化入口继续使用；新跟进策略不能绕过待分拣执行门槛，也不能仅因健康变红就启动执行。
- 收件箱：只承载通知和跳转；通知处理结果不改变项目业务状态。

## 16. 异常、并发与删除一致性

| 情况 | 必须呈现的结果 |
| --- | --- |
| 两位成员同时改描述 | 后保存者看到版本冲突和最新内容，保留自己的输入，不能静默覆盖 |
| 发布请求超时后重试 | 同一发布意图只产生一条记录及一组通知；可查询已成功结果 |
| 正在编辑时项目被删除 | 停止提交，显示项目已删除；允许复制自己的正文但不能恢复删除对象 |
| 查看期间失去工作空间权限 | 清除受保护页面内容与候选项，后续请求拒绝，不能继续读缓存证据 |
| 统计部分查询失败 | 标明暂不可计算及失败部分，保留明确标时的旧值，不伪造最新健康 |
| 成员离开或智能体失效 | 保留历史署名，当前责任显示待重新指定；不自动交给其他成员 |
| AI 执行失败／中断 | 无已发布进展，不改项目数据；保留可检查的失败原因与重试入口 |
| 发布时证据变化 | 显示差异和采集时间，重新核对可见性；不引用已经无权读取的内容 |
| 跨端修改状态或日期 | 以服务端确认结果更新；冲突提示后允许基于最新版本重试 |
| 删除项目同时有任务加入 | 删除与关联校验保证只留下"加入失败"或"加入后解除"的一致结果，不能产生悬空项目引用 |
| 删除项目过程中失败 | 整体失败并保留可用项目，或完成全部清理；不能只删除资源而留下半个项目 |
| 有相关自动化的项目被删除 | 清理或禁用依赖该项目的规则并显示失效原因；不删除历史执行，不停止正在运行的执行 |

项目删除确认需列出关联任务数、迭代归属保留说明、将删除的项目专属内容，以及相关自动化的处理。现有执行使用其已取得的上下文继续遵守执行规则，项目删除不授予新增资源访问。

## 17. Given／When／Then 验收场景

以下场景是对应阶段的交付验收条件；P2、P3 场景不阻塞 P1 发布。跨模块完整场景同时见总览 `WM-AC-*`。

| 编号 | 阶段／需求 | Given（前提） | When（操作） | Then（结果） |
| --- | --- | --- | --- | --- |
| PRJ-AC-01 | P1／PRJ-001 | 已有五状态项目及原任务视图 | 打开增强后的项目 | 原项目身份、属性、五状态和看板／列表／表格／泳道／甘特图仍可使用 |
| PRJ-AC-02 | P1／PRJ-002 | 描述为空 | 插入模板并保存 | 内容仅写入既有描述，概览和执行上下文读取相同版本 |
| PRJ-AC-03 | P1／PRJ-002 | 描述已有目标和正文 | 再次应用模板 | 先预览并选择章节，原内容不被覆盖、不自动重复整套标题 |
| PRJ-AC-04 | P1／PRJ-003 | 项目进度为 100%，无验收记录 | 查看概览 | 仍显示尚无验收记录，不自动显示通过或变 completed |
| PRJ-AC-05 | P1／PRJ-003 | 已有针对版本一的通过记录 | 修改项目描述为版本二 | 原记录可追溯，当前验收提示针对旧版本需复核 |
| PRJ-AC-06 | P1／PRJ-003 | 验收结论选择通过且没有依据 | 发布记录 | 阻止该验收记录发布并保留输入，不影响原项目状态 |
| PRJ-AC-07 | P1／PRJ-004 | 项目有 6 条 done、2 条 cancelled、2 条 todo | 打开概览 | 总数 10，进度 80%，完成 6、取消 2、未结束 2，实际完成占比若展示为 60% |
| PRJ-AC-08 | P1／PRJ-004 | 项目没有正式任务 | 打开概览 | 显示暂无任务，比例不适用，不显示 100% |
| PRJ-AC-09 | P1／PRJ-004 | 项目只有两条 cancelled | 打开概览 | 范围闭合 100%、完成 0、取消 2，验收没有自动通过 |
| PRJ-AC-10 | P1／PRJ-005 | 项目候选包含待分拣、拒绝和重复任务 | 查看任务、健康和进度 | 三类均不计入常规集合；分拣历史仍能按权限访问 |
| PRJ-AC-11 | P1／PRJ-005 | 待分拣任务拟归属项目且有默认小队 | 普通接受并保存项目 | 计入项目一次，未自动创建执行 |
| PRJ-AC-12 | P1／PRJ-006 | 未结束任务分别截止昨天、今天及未设置日期 | 以今天为基准计算 | 只有昨天到期的任务计入逾期 |
| PRJ-AC-13 | P1／PRJ-006 | 一条任务同时 blocked、逾期且未分配 | 查看健康 | 三个卡片各计一，风险任务去重总数为一 |
| PRJ-AC-14 | P1／PRJ-006 | 任务分配给仍有效但离线的智能体 | 查看健康 | 不计未分配，显示执行环境不可用信号 |
| PRJ-AC-15 | P1／PRJ-006 | 自定义任务状态属于 in_review 类别 | 计算待验收 | 按类别计入，不依赖显示名称 |
| PRJ-AC-16 | P1／PRJ-007 | 概览有三条逾期，用户视图仅显示自己 | 点击逾期 | 展示项目逾期筛选与三条当前有效任务，个人旧筛选不静默漏项 |
| PRJ-AC-17 | P1／PRJ-007 | 同一快照内部分任务状态不可解析 | 查看健康 | 显示统计不完整，不给出全量健康结论 |
| PRJ-AC-18 | P1／PRJ-008 | 成员写好手动进展 | 发布并刷新 | 一条带作者、时间与证据的进展可见，快照保留采集时刻 |
| PRJ-AC-19 | P1／PRJ-009 | 发布已成功但响应丢失 | 重试同一请求 | 返回同一记录，不重复通知 |

| PRJ-AC-21 | P1／PRJ-010 | 项目仍有未结束任务且无验收结论 | 显式改为 completed | 提示并允许继续，记录原因或未填写，不更改任务状态 |
| PRJ-AC-22 | P1／PRJ-011 | 项目有正在运行的执行和迭代任务 | 将项目改为 paused、cancelled 或重开 | 执行、任务状态、项目任务的迭代归属不被连带修改 |
| PRJ-AC-23 | P1／PRJ-012 | owner 删除项目，任务属于当前与历史迭代 | 完成删除 | 任务保留且项目关联清除，当前迭代与历史快照保留 |
| PRJ-AC-24 | P1／PRJ-012 | member 有项目编辑权限 | 请求删除项目 | 服务端拒绝删除，不以 lead 身份提权 |
| PRJ-AC-25 | P1／PRJ-013 | 成员编辑描述时另一人已保存新版本 | 提交旧版本 | 获知冲突，自己的输入可恢复，不覆盖新版本 |
| PRJ-AC-26 | P1／PRJ-014 | 用户无另一个工作空间的访问权 | 用项目 ID 请求详情、计数或下载 | 不返回其他空间内容、统计、证据或附件 |
| PRJ-AC-27 | P1／PRJ-008 | 进展正文提及智能体 | 发布进展 | 只作为引用，不启动智能体；成员提及通知按当前权限发送 |

## 18. 指标、质量与观察窗口

产品成效建议按上线后四周观察；先采集基线，再确认阈值。不能用项目数量增长或取消数量增加来证明交付效率提高。

| 指标 | 定义 | 建议目标或用途 |
| --- | --- | --- |
| 目标信息可找到率 | 可用性测试中能定位目标与验收标准的成功次数／有效测试次数 | P1 建议达到 90%，测试包含历史描述 |
| 风险定位耗时 | 从进入概览到打开指定风险任务集合的耗时 | P1 建议中位数不超过 30 秒 |
| 进展覆盖率 | 过去七日有已发布进展的进行中项目数／进行中项目数 | 趋势指标；零分母显示不适用 |
| 验收留痕率 | 观察期内变 completed 且有适用验收记录的项目数／同期变 completed 项目数 | 趋势指标，不用来禁止既有状态转换 |
| 统计一致性 | 同版本概览与下钻集合计数一致的检查次数／有效检查次数 | 正确性验收要求 100%，覆盖自定义状态与分拣 |

建议性能场景：单工作空间 500 个项目、单项目 10,000 条正式任务；常用概览和组合时间线首屏在约定测试环境 P95 不超过 2 秒，任务更新后跨端统计 5 秒内收敛。工程评审需确认基线与分页方案后锁定目标，不把建议数值当成已测结果。

性能降级时保留时间戳、明确分页和材料截断；不得用只取第一页的计数冒充全量。键盘可完成模板选择、风险下钻和进展发布，状态不能只依赖颜色表达。

## 19. 上线与回退要求

P1 先验证现有项目无损读取，再开放模板、概览与进展入口。未开启分拣台的既有项目统计结果应保持原口径；开启后的正式范围变化需有说明。

旧客户端仍可管理原有项目；不会因不知道新进展字段而丢失内容或绕过服务端准入。移动端未提供新编辑入口时可展示明确的能力限制，不能显示已发布成功但没有记录。

回退新界面后保留已发布进展与验收记录；是否支持只读查看、如何恢复入口由工程方案确认。不能以回退为由删除任务、改写项目状态或重算迭代历史。

上线前至少覆盖权限矩阵、统计样例、状态副作用、并发发布、删除关联、旧客户端兼容；P2 分别补充时间线、AI 证据和里程碑验收。

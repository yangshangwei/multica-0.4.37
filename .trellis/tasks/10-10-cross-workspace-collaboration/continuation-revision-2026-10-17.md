## 已核实的差异

执行审计见[代码差异报告](research/revision-execution-audit-2026-10-17.md)。已有人员流转、字段编辑、账号撤权和幂等基础可以复用；以下原执行假设不符合新需求：

1. session 同时持有唯一 grant、序号与运行位置，command 没有固定 typed target，不能表示同单多目标。
2. Stop、离开/移除、账号失效和整单结束只处理一个未结 run；小队中的单个 run 收尾不能结算整个执行组。
3. 普通任务的底层 admission/SQL claim 检查尚未排除协作单，不能只依靠 HTTP 入口拒绝。
4. core DTO 只有单 session 控制状态；新协议必须显式表达版本、目标与组，未知协议不能被当作空闲。
5. 普通 @处理按实际 agent 合并 agent/squad，且编辑器可混入当前空间目录，不能直接用于本单已授权 typed target。

## 本轮代码边界与实施顺序

先完成对已有基础的成套调整，防止只改 schema 而遗漏旧 writer：

- 服务端基础：新增后续迁移、typed target、逐目标序号、根执行组与 run 派生关系；固定新指令目标；旧无法确定目标的记录保持明确未解析状态和暂停，保留 UUID、nonce 与未结证明。
- 控制和失效：同一实现责任人调整 queue、workflow、lifecycle 和 account reconciliation，统一按目标或整单处理；目标停止保留无关目标，整单暂停覆盖新增目标，根组等待所有派生收尾。
- 旧执行入口：独立责任人补普通 enqueue/claim/finalize 的协作排除，并验证普通子任务仅引用协作父任务时仍按原规则执行。
- 客户端契约：接入显式版本化执行投影，复用已有账号/server epoch、私有日志裁剪和精确十进制版本。接口形状以最终后端 DTO 为准，测试畸形与未知协议。

修改范围为 `server/migrations/`、协作 SQL/领域/服务/handler、普通执行准入边界及相关测试，以及 `packages/core/collaboration/` 和 API 测试。先读对应规范、保留已有回归，再修改；不改旧迁移、不引入依赖，也不把普通 agent/squad 合并行为改成协作行为。

真实运行监督、许可/proof、资源授权界面、评论与通知提交、完整 Web/Desktop 工作台等继续按 P1–P8 推进。当前切片不以 mock run、超时或进程消失作为真实结束证明；创建和共享执行仍由完整验收门禁约束。

## 目标与用户价值

让独立账号和工作空间围绕同一任务派单、补充信息、接续处理并共同控制 AI。个人工作台保留责任与参与入口，单据身份和历史持续存在，减少重复复制需求和上下文。

## 术语

`issue` 是承载需求、责任、讨论和交接历史的业务单据；`task` 是一次 AI 执行，一单可关联多次。工作空间是任务/智能体/运行时的资源权限范围，不等同账号或本机目录。个人工作台按账号汇总跨空间待办；当前处理人承担当期责任，协作者按本单权限参与。执行目标是评论明确选择的智能体或小队，不是人类处理人；同单跨目标并行按 R23，两级控制按 R09/R10。

`Aiden` 未确认为固定实体，本任务统一称 AI 智能体。

## 已确认需求

| ID | 需求 | 规则 |
| --- | --- | --- |
| R01 | 独立账号与工作空间 | 不强制参与者共用一个工作空间。需要支持各人拥有个人工作空间的情况，也兼容同空间协作。 |
| R02 | 账号级待办 | 接收人在自己的个人工作台看到分配给自己的跨空间任务。待办由实际处理责任和业务状态决定，不依赖通知是否未读。 |
| R03 | 通用账号转交 | 可以转给产品、测试、其他开发等具体账号，不把流程限制为返回产品岗位。转交保留同一任务的身份及历史，操作权限按 R33。 |
| R04 | 两类交接目的 | 支持请对方补充信息，以及提交本阶段处理结果供对方继续处理。提交给测试或其他开发不自动等于整单完成。 |
| R05 | 本单全过程共享 | 本单专属讨论、尝试、系统已记录的 AI 执行过程和结果向获授权协作者共享；来源工作空间普通成员的既有访问能力按 R36。 |
| R06 | 共同控制 AI | 获授权协作者可以发表评论、按 R24 @智能体/小队提交执行，并选择停止/恢复某个智能体或小队，或停止/恢复本单全部 AI。小队控制包含其派生成员执行；每次操作显示范围及实际结果，普通评论权不等于 AI 控制权。 |
| R07 | 转交后保留协作权限 | 转交改变当前处理责任，已有协作者保留本单查看、评论、指挥、停止和恢复权限，并能从个人工作台持续找到仍有权限的本单，不依赖未读通知保留入口。显式移除和相关指令处置按 R14–R16 处理，主动退出按 R30。 |
| R08 | 同通道合并接续与跨通道并行 | 执行通道按实际根智能体划分，@A 与以 A 为队长的小队共用通道 A（M06）。通道忙碌或暂停时，新输入并入该通道的待执行批次，开始后整批作为一次后续处理（M07），不要求运行中实时插话；小队仍在执行时再 @队长或该小队则并入本组下一次队长续作（M11）；每条输入仍保留作者、快照和目标。不同通道在资源容量和授权允许时可并行，容量不足的等待，不把整单固定成单一串行位置。不得静默改变指令目标，也不得使等待成员结果的队长挡住成员启动。 |
| R09 | 按目标或整单停止并挂起 | M02 已确认两类操作：停止某个智能体/小队，或停止本单全部 AI。前者停止选定目标及其派生执行、挂起后续输入，同一执行通道的目标一起挂起（M06），其他通道的目标保持原状态；后者覆盖本单所有目标和派生工作，暂停期间新增目标也受约束。排队内容保留，@、重连或增加目标不能绕过适用暂停。 |
| R10 | 按明确范围恢复 | 支持恢复选定智能体/小队及恢复本单全部 AI；小队范围覆盖其成员执行。单目标恢复时同通道目标一起恢复，不改变其他通道的未选目标，也不能越过仍有效的整单暂停。恢复全部 AI 时解除整单暂停，逐个恢复证明齐、授权有效的目标（授权无效只挡该目标自身输入），其余保持目标级暂停并说明原因，不显示为全部恢复（M04）。恢复的目标须满足 R17，从下一条有效等待输入接续；不重试已停止/取消指令，不保存失败的自动恢复意愿。 |
| R11 | 转交不改变执行状态 | 转交时保持执行和队列的原有状态：运行中的继续运行，挂起的仍挂起；不因换处理人自动停止、恢复或重启。 |
| R12 | 新增协作者权限 | 仅发起人和当前处理人可以通过邀请或转交让新账号加入本单。当前处理人变更后，按新的处理责任判断这项权限；其他已有协作者不因保留本单 AI 控制权限而获得新增协作者权限。个人运行资源按 R13 授权。 |
| R13 | 按单授权并管理 AI 目标 | M03 采用本单已授权目标清单：仅发起人/当前处理人可组织新增智能体或小队，各实际资源拥有者须先按 R12 作为完整参与者加入本单（获得查看、评论、AI 控制和 R52 通知，M05），再确认所覆盖的目标、运行环境及本单用途；组织目标不自动加人，拥有者退出或被移除按 R31 撤回其全部授权。所需授权齐备后才进入 @候选；已有及以后合法加入的参与者可使用，无须逐人确认。提及不授权、不自动加人，拥有者可撤回；授权不扩展到其他资源、任务、私人会话或整个空间。 |
| R14 | 移除协作者权限 | 仅发起人可以主动移除其他已有协作者，撤销该账号的本单协作身份及由此授予的查看、评论和 AI 控制权限。当前处理人若不是发起人，不因处理责任而获得移除权限。未执行与运行中指令分别按 R15、R16 处理，运行资源授权撤回按 R25，主动退出按 R30。 |
| R15 | 移除后的未执行指令自动取消 | 协作者被移除后，其在本单提交且尚未执行的指令自动取消，包括挂起队列中的指令。保留指令记录、提交人及取消原因；需要执行相同内容时，由当时有权限的协作者重新提交，不采用原指令等待接管的方式。 |
| R16 | 移除后停止并挂起相关工作 | 被移除者的运行指令及其派生工作请求停止，挂起受影响目标/小队；其未执行指令跨目标按 R15 取消，其他协作者的等待输入保留，无关目标保持状态。小队派生执行必须可追溯纳入处置；已开始的合并批次整批停止，同批其他作者的输入随之结束（M07）。受理与真实结束分别表达，不影响其他单据。 |
| R17 | 范围内停止未确认时拒绝恢复 | 所恢复范围内的旧执行及应收尾派生工作尚未确认结束时拒绝恢复，不解除挂起、不保存稍后自动恢复的意愿。单目标停止未确认不阻止其他通道符合条件的目标独立恢复，但整单暂停仍优先约束所有目标。恢复整单时，未确认的目标保持目标级暂停，不阻止解除整单暂停（M04）；已移除目标的遗留屏障继续占用其实际资源直到取得证明。之后仍须有权限者明确恢复。 |
| R18 | 补充完成并交回 | 提供明确的"补充完成并交回"动作，将任务交回提出本次补充请求的账号，当前处理责任及待办随之转回。普通评论不触发交回；该动作只完成本次补充信息交接，不代表整单完成，执行与队列状态继续遵守 R11。 |
| R19 | 整单完成权限 | 普通协作操作中仅发起人可以将整张共享任务标记为完成。当前处理人若不是发起人，不因阶段处理完成或测试验证通过而获得整单完成权限；阶段交接、补充完成及 AI 执行结束均不能替代明确完成操作。整单取消和重开权限按 R34，结束后的执行处置按 R35；发起人被禁用时仅适用 R38 的有限代管例外。 |
| R20 | 提交验收并转交 | 当前处理人准备好最终结果后，通过明确的"提交验收并转交"动作，将当前处理责任和待办一起转给整单发起人，由其承担验收责任并按 R19 确认完成。提交验收本身不完成整单；原处理人保留协作权限，执行与队列状态继续遵守 R11。 |
| R21 | 同一 Server 部署内协作 | 首版限定所有协作者连接同一套 Multica Server 部署，账号和工作空间可以各自独立。不纳入不同独立 Server 之间的派单、身份互信、协作数据同步或执行控制。 |
| R22 | 首版客户端覆盖范围 | Web 和 Desktop 首版提供完整协作功能，CLI/daemon 为相关执行与控制流程配套适配；Mobile 的新协作功能留到后续交付。各入口遵守同一套服务端权限、处理责任和队列规则。 |
| R23 | 同单多目标并行 | 每张协作单允许 @多个不同智能体或小队；M01 已确认不同目标在资源允许时可并行，同一通道的外部输入按 R08 合并接续。各目标身份、真实提交者、过程及结果分别保留，业务单据和人类处理责任保持唯一。同条评论 @A 与 @S（队长 A）合并为一次队长运行（M06）。@小队由队长组织成员，成员不能被等待它的队长阻塞。并行不绕过授权、容量或暂停；会话/队列/执行组依照技术设计实现验证，按已确认 M02 提供目标/小队与整单两级控制。 |
| R24 | @智能体或小队提交执行 | 新评论明确选择并 @具体智能体或小队，发送后自动提交该目标的执行，无须再选择“发给 AI”；同条评论可含多个 AI 目标和人员提及。保留触发预览及取消本次目标，服务端重验权限，反馈等待、暂停或拒绝。普通无 @评论、仅回复 AI、字段/评论编辑继续不自动执行；纯文本名字和未解析为具体目标的 `@AI` 不触发。@不改变负责人、状态或授权，也不恢复暂停。 |
| R25 | 运行资源授权撤回立即生效 | 撤回本单某项资源授权后，立即阻止该授权下的新执行，请求停止使用它的执行及受影响派生工作，保留等待输入并挂起受影响目标/小队（不暂停执行通道）；未使用失效资源且不属受影响派生范围的目标保持状态。重新授权和旧执行确认结束都不自动恢复；资源与成员授权按 R13 逐项核对。 |
| R26 | 手动更换运行环境 | 发起人或当前处理人可为明确的执行范围更换运行环境，须先挂起并确认旧执行结束，取得新环境拥有者的本单授权；更换后仍须明确恢复。@新目标不应被解释为偷偷替换其他目标的环境；控制使用 R09/R10 的明确范围，目标与资源替换须按 R13 取得对应拥有者的新授权。普通转交不切环境，也不重做已停止或取消的指令。 |
| R27 | 通过 Git 或附件准备新环境 | 更换运行环境时，代码和工作文件通过 Git 中已提交的代码或明确交付的附件准备。首版不自动搬运原环境的工作目录或未提交修改，也不新增自动文件迁移、同步及冲突恢复流程。 |
| R28 | 沿用各运行环境的 AI 服务账号 | 各目标及小队成员的 AI 调用沿用其获授权运行环境配置的供应商账号和额度，不因指令提交者或当前处理人变化而切换账号。指令、派生关系和执行记录分别保留真实操作主体与授权来源；环境账号不能替代平台认证，也不能冒充拥有者的业务权限。 |
| R29 | 精确查找接收账号 | 跨空间邀请或派单时，通过完整用户名、邮箱或账号 ID 精确查找同一 Server 中的账号，再明确确认接收人。本功能不提供全站账号目录或按姓名模糊搜索；查找只定位账号，不自动授予本单协作权限或改变当前处理人。 |
| R30 | 协作者主动退出 | 允许非发起人的协作者主动退出本单；当前处理人必须先转交处理责任，发起人不能退出，也不能通过移除自己规避这一限制。退出后撤销其本单协作权限，未执行指令按 R15 取消；若其提交的指令正在运行，则按 R16 请求停止并挂起所属执行通道。环境拥有者退出时还须按 R31 撤回资源授权。 |
| R31 | 资源拥有者离开时撤回本单全部授权 | 资源拥有者退出或被移除时，撤回其为本单提供的全部 grants，覆盖各目标/小队成员实际使用的资源；按 R25 阻止新执行、停止受影响组并挂起受影响目标（不暂停执行通道），其他拥有者的无关有效目标保持状态。本人等待输入取消，其他作者输入与历史保留；重新加入不自动恢复授权或执行。 |
| R32 | 移除当前处理人后交回发起人 | 发起人移除当前处理人时，当前处理责任和待办自动交回发起人，移除与回交作为同一次业务操作生效。发起人接手后可再转交他人；被移除者的协作权限、指令和资源授权仍按既定移除规则处理。 |
| R33 | 普通转交权限 | 仅发起人和当前处理人可以发起普通转交，接收人已是本单协作者时也遵守这一权限。转给新账号还需满足 R12 的新增协作者规则；其他协作者保留已授权的讨论和 AI 控制权限，但不能改变当前处理人。 |
| R34 | 整单取消与重开权限 | 普通协作操作中仅发起人可以取消整张共享任务，或重新打开已完成、已取消的共享任务。该权限不随普通转交转移给当前处理人，其他协作者也不因拥有 AI 控制权而取得这些权限；发起人被禁用时仅适用 R38 的有限代管例外。 |
| R35 | 整单结束时终止全部本单 AI 工作 | 整单完成或取消时，请求停止本单所有目标及小队派生执行，取消全部剩余未执行指令并保留历史。终态任务不接受新的 AI 指令（包括 @触发）或恢复；重开后才可提交新指令，不复活已停止或取消的工作，旧执行仍须按 R17 确认结束。不能只关闭旧单会话字段而遗漏其他目标。 |
| R36 | 来源空间成员保留基础访问 | 来源工作空间中未加入本单的普通成员保留查看和普通评论能力，但不会自动取得本单 AI 控制权或管理权限。空间成员身份与本单协作身份分别判断；退出或被移出协作不撤销仍有效的来源空间成员权限，但不能再借旧协作身份控制 AI 或管理本单。发起人退出来源空间后，账号及本单协作身份仍有效时，继续保留 R19/R34 的整单完成、取消、重开权限；来源成员权限失效，不能再修改 R49/R50/R58 要求来源成员身份的结构字段。退出来源空间不触发 R38 的管理员代管。 |
| R37 | 含共享任务的来源空间禁止直接删除 | 首版只要来源工作空间仍有本功能的共享任务记录，就阻止直接删除该空间，包括任务均已完成或已取消的情况。保留来源空间、共享历史及原有权限关系，不在首版新增删除空间后独立归档或迁移共享任务的流程。 |
| R38 | 发起人被禁用时有限代管 | 仅在发起人账号被禁用时，有相应平台管理权限的管理员可以通过明确的代管操作完成、取消或重开整单。必须记录原因、真实管理员操作人及原发起人，不修改原发起人身份，也不扩大普通协作者权限。代管仅针对这三类业务操作，不能替代运行资源授权或绕过执行与队列门禁。 |
| R39 | 首版仅新建协作任务 | 首版通过明确的新建协作任务入口创建本功能单据，不支持把存量普通任务直接转换为协作任务。存量公开附件、既有执行状态及合并输入的迁移留到后续，不以切换一个标记替代迁移。 |
| R40 | 双禁用时重开并接手 | 发起人和当前处理人均被禁用时，符合 R38 的管理员可在重开时指定已有有效协作者接手；无人可接手则拒绝。重开和责任变更同时生效，保留原发起人；不授予管理员一般转交、邀请或资源权限，不自动恢复 AI。 |
| R41 | 标题与正文修改权 | 有效发起人和当前处理人可以修改协作任务标题、正文，保留真实操作者、时间及修改记录；转交后非发起人的原处理人失去该编辑权。修改不改写已入队 AI 指令快照，也不自动启动或恢复执行。 |
| R42 | 优先级、标签与属性值修改权 | 有效发起人和当前处理人可修改本单优先级、标签及自定义字段的值，沿用来源空间的字段和选项；不因此取得管理来源空间标签或字段定义的权限。转交后非发起人的原处理人失去该编辑权。 |
| R43 | 普通评论作者可修改和删除 | 仍有本单评论权限的作者可修改、删除自己的人类普通评论，保留编辑历史和删除标记。发起人、当前处理人或管理员不因角色取得改写他人评论的权限；不得改写 AI 指令、执行记录或系统审计，也不触发 AI。 |
| R44 | 评论移除后附件继续保留 | 删除评论或从评论中移除附件，仅移除该评论中的展示引用；已交付文件仍保留在本单附件或历史中，按当前本单权限访问。其他评论及 AI 指令的既有文件引用保持有效，不因评论移除删除文件或撤回访问。 |
| R45 | 单条排队指令取消 | 仍有本单协作权限的提交者本人、发起人或当前处理人可取消一条仍在等待队列中的指令，保留原文、作者及取消操作记录；不影响当前执行、其余指令顺序或队列挂起状态。已进入当前执行的指令不能按排队取消处理，仍走既定停止流程；取消不授权修改指令或重排队列。 |
| R46 | 邀请与派单直接生效 | 符合 R12 的邀请或派单在服务端成功提交后直接使新协作者加入，无需接收方接受，离线不影响生效。仅邀请不改变处理责任；同时派单则责任和持久待办一起转移。加入本单不自动授权使用新协作者的个人 AI 运行环境。 |
| R47 | 非终态状态手动修改 | 有效发起人和当前处理人可在来源空间配置的非终态状态之间手动切换，保留真实操作者、时间及前后状态；转交后非发起人的原处理人失去该权限。修改不改变处理人，不触发 AI；标为阻塞不发起补充请求，标为评审中不等于提交验收。完成、取消和重开仍按 R19、R34。 |
| R48 | 开始与截止日期修改权 | 有效发起人和当前处理人可设置、修改或清空本单开始日期与截止日期，保留真实操作者、时间及前后值；转交后非发起人的原处理人失去该编辑权。修改不触发 AI，也不改写已入队 AI 指令快照。 |
| R49 | 项目归属与父任务 | 有效发起人和当前处理人中仍是来源空间成员者，可在创建时或之后设置、修改本单项目和父任务，校验沿用来源空间现有规则，保留修改记录且不触发 AI。非来源成员的协作者（含外部当前处理人）不能修改，只见不可打开的最小引用，不能借此浏览来源空间的项目或任务目录。 |
| R50 | 迭代归属 | 有效发起人和当前处理人中仍是来源空间成员者，可在创建时或之后将本单加入、切换或移出来源空间迭代，沿用现有迭代归属规则（含切换/移出原因），服务端跨期结转照常作用于本单；保留修改记录且不触发 AI。非来源成员只见不可打开的最小引用，不能借此浏览来源空间的迭代目录。 |
| R51 | 协作单下的普通子任务 | 来源空间成员可按普通任务现有规则，把来源空间的普通任务挂到协作单下或移出。子任务仍是普通任务：不进入本单共享 AI 队列，不变成协作单，不对外部协作者共享，也不改变本单参与人或处理人。无来源权限的协作者在本单详情只见不可打开的最小引用。 |
| R52 | 参与者账号级通知 | 本单当前有效参与者在个人工作台收到账号级站内通知，不依赖来源空间 inbox。事件保留派单/转交、补充/交回、验收、邀请/移除、新评论和 AI 结果；@人通知显示“提及了你”，在账号工作台定位原评论，正文提及则定位本单正文或对应修改记录。同一事件对同一接收人仅一条通知，操作者不收自己的通知；移除通知不含本单内容。已读/归档不改变待办、处理责任或权限，不承诺额外邮件、私聊或外部 IM。未参与本单的来源成员仍按来源 inbox 原规则。 |
| R53 | 按单授权的执行身份与机器隔离 | 经本单授权的目标及小队派生执行可按其受控身份读取执行所需内容、记录过程与结果；授权不能仅靠 @文本、普通 agent 凭据或队长身份推断。未纳入本单授权的机器（普通 agent/任务、云节点、plugin、IM 等）仍只得不可打开的最小引用，写入拒绝，出站事件不携带正文/评论/附件。单一共享 AI 身份假设被替换，具体目标与资源授权按 R13、派生执行按 R23 纳入专用执行协议；人类登录会话和个人令牌仍按人类规则。 |
| R54 | 外部人员在来源界面的显示 | 能读本单的人看到外部账号的最小摘要：显示名、头像和“外部”标记，不含邮箱或用户名。来源列表和看板筛选提供“外部协作者”一类。看板上协作卡不能拖到其他负责人列，有转交权限时改为打开转交入口，否则明确提示；状态列拖动只在 R47 允许的非终态之间生效。 |
| R55 | 按对象区分 @提及 | 人员候选只列本单当前参与者，@人按 R52 通知，不邀请、不转交、不授予权限；@all 只指当前参与者。AI 候选只列本单已获完整有效授权的具体智能体/小队，不开放个人或任意空间的其他资源目录。新评论有效 AI 提及按 R24 提交执行；@小队不自动引入其人类成员。正文/评论编辑仅通知新增有效人员，不自动执行。撤权或目标配置失效后不再可选，历史及合法停止入口保留；忙碌、暂停或暂时离线不等于撤权，有效目标仍可选并显示等待。小队授权不自动开放成员的独立智能体目标。 |
| R56 | 不从评论或选区创建子任务 | 首版对协作单关闭“从评论/选中文字创建子任务”的手动与 agent 两种模式：界面隐藏入口，旧接口明确拒绝，不复制评论正文或附件。需要拆分时先新建普通任务，再按 R51 挂到本单下。 |
| R57 | 线程解决与表情回应 | 当前有本单评论权限的人（参与者及 R36 来源成员）可解决、取消解决评论线程，并添加或移除自己对评论和本单的表情回应，记录真实操作者。不影响 AI 指令、不触发执行，不进入 R52 通知；来源空间旧的回应通知对协作单不发。 |
| R58 | 看板列内排序与阶段 | 列内排序是来源看板的布局：来源成员按普通任务现有排序规则调整协作卡顺序，不推进协作版本、不留修改记录、不发通知。父任务下的阶段影响父任务唤醒，按 R49 由仍是来源成员的有效发起人或当前处理人修改并留记录，不触发 AI。 |

## 用户流程示例

产品派单给开发，开发请求补充并接收交回。在同一单内发送“@研发小队 实现导出；@张三 确认字段”时，小队执行请求与张三的账号通知分别产生，当前处理人仍为开发。之后可 @测试智能体参与验证，资源允许时与研发目标并行准备测试；需要等待代码结果的具体工作仍遵守其依赖。之后转给测试或其他开发，最终提交发起人验收。个人工作台展示同一单据及各目标状态；可单独停止测试智能体而保留研发工作，也可停止本单全部 AI。

## 首版范围

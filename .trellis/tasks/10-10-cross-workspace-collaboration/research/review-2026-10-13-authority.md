# Research: 最新需求的权限、数据及人类流转复审

- Query: R40–R58 与 R36 来源成员退出规则的技术一致性，连同 R19/R34 生命周期及来源机器隔离。
- Scope: internal；研究代理已返回具体发现，落盘前因模型限流结束；本报告由主会话依据这些发现并定点复核源码完成，未声称代理完成了独立终审。
- Date: 2026-10-13

## Findings

### AU01：非终态修改必须同时检查当前状态和目标

R47 只允许在非终态之间切换，旧 D04/P2 的主要谓词却只写目标非终态。`server/internal/handler/issue.go:3845` 的既有通用路径解析目标，不承担协作生命周期权限。如果 handler 将已完成单据 PATCH 成 todo，会绕过 R34 的发起人重开和 session reopening。

已修订 D04/P2：锁内检查当前/目标来源类别均非终态、session 未 closed；否则必须走明确生命周期动作。验证 AC77/AC55：非发起人 handler 的 done/cancelled→todo 拒绝，合法非终态切换成功，源目录/关闭竞争不留半更新。

### AU02：评论历史及附件交付缺少明确持久映射

数据契约原本未定义 R43 墓碑/编辑历史和 R44 永久附件交付与多引用。`server/pkg/db/queries/comment.sql:518` 原位更新正文，`:592` 硬删除；comment.revision 已在迁移 351 增加，不能重复建立协作版本权威。仅依赖 attachment.comment_id 无法表示评论删除后仍交付、且其他 command/reference 继续使用同一固定文件。

已修订数据契约/D03/P1：复用 comment.revision，新增 deleted_at，旧 wire 数字不变，新协作 DTO 字符串；collaboration_event 保存受控前后版本和真实操作者，不增加平行历史层。永久 collaboration_attachment 与多引用表区分交付和展示，删除评论只移除展示，已交付文件不被 GC 当孤儿。AC74/75 在 P3 验证，schema 由 P1 提供。

### AU03：机器搜索要在匹配、计数、排序前隔离私有文本

`server/internal/handler/issue.go:1025–1038` 按命中的评论或 description 生成 snippet；仅在 DTO 去掉正文仍会泄漏全文搜索命中、排序和数量。R53 允许的只有最小引用。

已修订 D03/P1：搜索 SQL 与服务在匹配前应用 actor/purpose 投影，机器对协作单只匹配允许的引用字段，不读正文/评论 snippet，也不以它们参与计数或排序。AC84 加正文独有 sentinel 的搜索负例，普通任务搜索保持原规则。

### AU04：线程解决的事务原子性不等于并发唯一性

`server/internal/handler/comment.go:3730` 清其他解决、`:3741` 设目标；虽同事务，却没有覆盖两个不同目标的共同锁。两个目标原先都未解决时，两边可能都清零行再各设自身。

已修订 D03/E02/P3：协作分支 resolve/unresolve 与 edit/delete 共用稳定 issue 锁，锁后重验访问和同单线程，再清旧+设新。AC88 用两个 DB 连接和同步屏障验证不同目标并发解决及撤权竞争，最多保留一个线程解决记录；不把普通路径未改的代码当作协作实现。

### AU05：来源成员退出与协作撤权是两件事

`server/internal/handler/workspace_revoke.go:195–229` 清来源订阅、迭代通知和 member，并未清 issue.creator/assignee；schema 的身份使用 user UUID，无 member FK。已有事实允许 R36，不应在新实现里错误添加“退出来源空间即撤本单参与身份/全账号epoch”。

已补 D03/P1：保留独立 participant、creator、handler 和账号入口；仅来源成员能力失效。若同一事件使运行资源失效，按相关 grant 撤权暂停，不撤无关协作权限。AC27/55 保留生命周期正例，AC80/81/89 拒绝来源结构字段，AC66 不触发管理员代管；客户端接线见 CL03。

## Findings (fixed)

### Repeated cursors could keep a malformed history pageable

- File: `packages/core/collaboration/run-records-queries.ts`.
- Issue: the API rejected an immediately repeated cursor, but a longer cycle
  such as page one -> page two -> page three -> page two was accepted. Query
  consumers could continue traversing that cycle without an unavailable result.
- Fix: stop repeated cursors in `getNextPageParam` and validate the complete
  fetched chain before it enters the Query cache. A cyclic chain raises the
  existing generic `CollaborationUnavailableError`; it is not reported as a
  completed history and does not revoke the otherwise authorized issue.
- Regression: the initial negative test failed; the final regression requests
  ten pages and proves only three requests occur before rejection, with no
  malformed chain cached.

### A later page could replace an immutable recorded entry

- Files: `packages/core/collaboration/run-records-queries.ts` and
  `packages/core/collaboration/run-records-queries.test.ts`.
- Issue: each page enforced unique IDs locally, but a later page with the same
  stable ID and a different body was accepted. Shared rendering's ID merge could
  silently replace the earlier recorded content.
- Fix: compare repeated IDs within the new assembled page chain before cache
  publication. Conflicting content raises the same generic unavailable error;
  identical overlap remains valid. Full refetches are checked independently of
  the old cache, so changed snapshot/page boundaries remain supported.
- Regression: the negative test failed before the fix. It now verifies that
  lawful earlier pages survive the malformed response, the conflicting body is
  absent from observer data and console logs, and subsequent access revocation
  removes both observer and cached data. A positive regression covers identical
  overlap and replacement by a complete refreshed snapshot.

Validation uses the existing Query `structuralSharing` boundary and
`replaceEqualDeep`, keeping one owner for cached page integrity. It adds no
public DTO, dependency, persistent store or separate transcript cache. The
undefined-data path deliberately permits protected access cleanup. It avoids a
throwing `select`, whose memoized last result can outlive cleared query data.

## Findings (fixed by the implementation owner)

### Source actions and detail mounts dropped the selected run

- Files: `packages/views/collaboration/source-bridge.tsx`,
  `packages/views/issues/components/issue-detail-route.tsx`, `issue-detail.tsx`,
  `packages/views/issues/actions/use-issue-actions.ts`,
  `issue-actions-menu-items.tsx` and `packages/views/search/search-command.tsx`.
- Issue: the source bridge and shared actions lost the run fragment, while the
  route read `window.location.hash`, which cannot supply native MemoryRouter
  fragments. Copy/open could therefore reach the issue without its selected run.
- Fix: read the navigation adapter's fragment, validate it through the shared
  account parser, pass the selected run through route and embedded detail props,
  and preserve it in account links. Common menu copy/open actions share one
  constructed destination. They retain the fragment only when the current
  source path matches that exact issue's UUID or identifier; another row cannot
  inherit it. Ordinary links retain their existing source destination.
- Verification: the owner's failing regression run is
  `views/review-fixes-red`; its corrected 285-test run is
  `views/review-fixes-green`. Independent source-route, embedded-detail,
  bridge, common-action/menu and search regressions passed in
  `check-views/recovery-focused`; the source bridge passed again in the final
  focused rerun.

- The composed regression also exposed the notification popover restoring
  focus over the run after navigation. The existing `finalFocus` handoff pattern

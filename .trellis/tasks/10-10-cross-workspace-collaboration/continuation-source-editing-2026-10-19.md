## 本轮行为差距及写入边界

1. **来源页面**：来源任务页应能明确新建协作任务，列表/详情/看板/时间线应识别同一协作单并复用共享详情。外部账号用服务端最小摘要展示；筛选、排序和拖动遵守 R47/R54/R58，不能经普通写入改变负责人或生命周期。责任范围为来源 issue surface、必要 core issue schema/查询及服务端来源投影，新增共享桥接组件。避免重写账号工作台和已验证创建协议。
2. **字段编辑**：复用现有 PATCH/iteration 与原请求恢复，补标签、属性值以及仅来源成员可用的项目/父任务/迭代/阶段选择；创建提供既有 API 支持的初始字段。责任范围为 collaboration workflow/creation 与字段面板、core 字段动作/创建草稿及确有需要的来源选项契约。不得绕过结构字段来源身份或新增定义管理权限。
3. **评论操作**：复用已存在的评论服务，补本人编辑/删除、回复锚点、解决/取消解决和本人表情回应（含单据回应）。责任范围为 collaboration 评论/详情组件、core comment/content queries 和必要读取投影。保留墓碑、历史、其他回复及已交付附件；编辑/回应不创建 AI 执行。
4. 主会话负责跨 lane 接口协调、任务清单与规范、隔离验证环境、集成与独立检查、本地原子提交。共享导出/翻译文件只作局部追加，不覆盖其他人的内容；SQL 生成和迁移由主会话串行处理。

各实现者先核对对应现有 API 和规范，再写有意义的缺口回归。发现跨 lane 契约缺口先报告边界和最小调整，不擅自扩大至运行供应商或代管。新增依赖、存量转换、生产发布及开放默认门禁均不在本轮。

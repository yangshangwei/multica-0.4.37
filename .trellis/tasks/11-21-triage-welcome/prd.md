# 分拣台首次使用欢迎页

## 目标

首次打开分拣台的工作空间成员能理解「先收集，再决定做什么」，并能立即投递第一条待分拣任务或导入 CSV。界面参考智能体、AI 小队和自动化的欢迎页，用一条反馈演示待分拣任务如何在接受后进入正式任务列表。

## 需求

- **R1 首次空白。** 分拣台受支持、已启用，成员有权操作，且默认「可处理」队列首页没有搜索、筛选或详情上下文。成功读取的工作空间未决数与未筛选审核历史总数均为零时，显示欢迎页。审核历史已包含提交过的 CSV 导入批次。
- **R2 首屏内容。** 左侧标题为「先收集，再决定做什么」，说明可以收集新需求、缺陷反馈或导入清单。以「创建待分拣任务」为主要操作，「导入 CSV」为次要操作，并提供「阅读文档」链接。两个操作打开现有弹窗，沿用其提交结果和后续操作。
- **R3 示例。** 右侧以「导出报表缺少日期列」演示手动投递后处于「待分拣」，接受后成为正式任务。明确标记「示例」，并说明接受后保留任务编号、评论和附件。使用现有任务行、状态和图标的视觉语言。
- **R4 日常空态。** 有历史且当前没有可处理项时，显示「当前没有可处理的任务」和「查看审核历史」。只剩稍后处理项时，提供进入「稍后处理」的操作。筛选无结果时保留清除筛选操作。作用于加载、访问失败、关闭或不受支持的现有提示各自处理对应状态。
- **R5 页面适配。** 保留页头和队列标签。宽窗口左文案右示例，窄窗口先显示文案及操作，再显示示例。欢迎页内的创建、导入和文档入口可用键盘操作，支持简体中文、英文以及浅色和深色主题。

## 交付边界

Web 和 Electron 桌面版使用同一个欢迎组件和状态规则。投递、CSV、审核、执行、权限和任务详情继续由各自已有流程负责。分拣台和入门文档沿用已有路由。

## 验收标准

- [x] AC1（R1）清空测试工作空间的未决任务和历史后首次进入，显示欢迎内容。历史或队列尚未确认、有数据、当前是其他标签、附有筛选或指向详情时，显示相应的队列、历史或恢复界面。
- [x] AC2（R2）两个入口可打开现有弹窗。创建第一条任务后，返回队列并按原流程打开其详情。提交首批 CSV 后，新增记录出现在队列。文档入口能打开分拣台说明。
- [x] AC3（R3）示例以同一条反馈串联手动投递、待分拣、接受和正式任务。示例文字可读，步骤本身不进入键盘焦点顺序。
- [x] AC4（R4）审核完最后一条任务后，显示简洁的日常空态。历史、稍后处理和清除筛选入口分别到达对应位置。已加载数据的刷新失败继续显示适用的恢复反馈。
- [x] AC5（R5）在两种语言、两种主题、宽屏和窄屏检查布局。操作在窄屏位于示例之前，标题、按钮和示例没有横向裁切，欢迎页内只显示一组主要操作。

对应测试和浏览器证据见 `evidence.md`。

# 平台管理后台：设计总纲

状态：规划交付，未启动实现。本文串联各设计边界；需求以 [prd.md](prd.md) 为准。

## 方案选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 扩展工作空间设置 | 最少页面改动 | 无法覆盖未入空间用户和跨空间终端，拒绝作为平台管理模型 |
| 独立平台后台、复用现有服务 | 账号一致、可分期、多组织有边界 | 需要新增平台授权和管理查询；采用 |
| 独立控制服务、独立遥测平台 | 后续可以独立扩缩容 | 首期 100–1000 台尚无拆分证据，延期 |

Web 使用 `/admin`；认证沿用 `/login?next=/admin`。首期不增加 Electron 管理路由，桌面只增加必要的可信安装上报和协议支持。普通桌面业务流程保持现有职责。

## 核心决定

- D01：一个用户身份和密码体系；角色不嵌入长期 JWT 当作权限真相。
- D02：平台角色只用于平台能力；原工作空间 membership、私有智能体调用、正文和日志鉴权继续成立。
- D03：先封堵密码模式 PAT→JWT 的凭据升级入口，再赋予平台角色；提升角色会撤销目标旧凭据并要求重新密码登录。须提前提示其在途执行影响。
- D04：组织是未来客户边界；首期固定内部组织。空间归属迁移不改变员工原成员关系。组织归属是资产隔离准备，不能宣传首期已具备 SaaS 隔离验收。
- D05：首期终端主键是经过接入证明的安装实例。物理设备、安装、daemon、runtime 分开；已有统计 install_id 和 device_id 只作来源线索。
- D06：运行元数据可以跨空间汇总，私有内容另验原权限。列表、错误、导出和告警都使用脱敏投影。
- D07：取消立即复用现有 task 终态变更，operation 跟踪确认；停止接单在服务端门禁提交即生效。在途任务继续，运行中暂停/迁移不实施。
- D08：已提交取消不是待下发命令，不因 ack 截止而失效；未应用的未来命令才使用过期丢弃策略。
- D09：声明的操作成功必须有对应证据；服务端门禁生效与终端进程停止使用不同结果码。
- D10：不新增依赖、不拆新服务、不将所有心跳写成历史事件。复用现有指标、日志和任务队列，新增台账、操作、审计与告警必要实体。

## 端到端流程

1. 部署迁移并核验索引 → 修复凭据转换边界 → 受控授予管理员 → 管理员重新登录 → 读取平台角色 → 进入无 workspace 依赖的后台。
2. 员工原流程登录 → 新客户端完成安装接入证明 → daemon 绑定 → 运行时登记/上报 → 后台台账与状态轴展示。旧端继续原业务，后台只读未关联记录。
3. 后台查执行元数据 → 选择具体 task → 输入原因、确认目标 → 服务端授权和状态事务 → 返回 operation → 终端原协议停止 → 回执核验 → 刷新结果与审计。
4. 异常探测 → 持久告警 → 总览/告警列表 → 认领和关联操作 → 恢复观察 → 关闭记录。探测系统自身不可用时展示数据不可用，避免制造批量离线告警。

## 取舍与待验证点

Ed25519 接入证明用于关联凭据持有者，不证明硬件真实性；终端拥有者仍可复制本地凭据。首期不引入 TPM/MDM。

首期读查询使用有界分页；管理页面轮询，无须新增跨组织 WS 推送通道。心跳实时性与查询刷新是两个预算。性能测试如发现瓶颈，先分析索引与查询，而非直接增加缓存和消息系统。

新增组织、角色、终端控制依赖跨层事务和安全发布。并行只在基础契约完成后进行，接口/表结构变化先更新父设计及相应测试规格。

当前完成的是可供实施评审的设计，不代表功能已实现、性能达标或部署通过。

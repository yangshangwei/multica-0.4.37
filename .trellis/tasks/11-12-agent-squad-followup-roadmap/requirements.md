# M1-S1：普通单事项完成授权

日期：2026-11-12。状态：M1-S1 已批准并执行中。归属 PRD 的 F1；不表示已实现或重新验收 v1。

## 目标与首包范围

当前人对普通任务执行一次新的完成操作时，能查看并选择当前交付证据，明确授权该版本到指定完成状态，再提交完成，并查询原操作的实际结果。授权责任、写入结果和任务当前状态分别呈现。

首包覆盖 Web/Desktop 共用的详情状态选择、单任务操作菜单、surface 显式状态选择、子任务显式状态选择，以及 CLI 的普通单任务合同。这些入口只提交 status，不带内容、附件、负责人、项目或位置修改。普通子任务使用自身证据，不借父任务或协作运行的制品。独立 collaboration 不是普通子任务。

新授权流程用于 enforce 项目中的非 done → done 类别转换。off/observe、无项目、非完成转换和 done → done 保持当前合同；不因新增 UI 而改变项目策略或要求所有任务授权。界面使用当前语言状态名，自定义 done 按服务端类别判定。

## 已确认事实与实际缺口

| 编号 | 当前事实 | 首包要补的能力 |
| --- | --- | --- |
| G1 | 已有完整授权创建、按原 key 查询、撤销、事务消费和原收据；提示不具备授权性质 | 消费现有 API，不重建门禁或新建完成写入服务 |
| G2 | 一般审批列表不等于任务证据列表；制品读取权限比一般审批更窄 | 有权限且可分页的任务证据选择，以及当前观察；不能按“最新审批”自动替用户选择 |
| G3 | 授权需精确任务/项目/策略版本、来源和 digest；凭据有效期不全在客户端公开 DTO 中 | 服务端给出同次观察的规范绑定与可请求有效期上限，客户端不猜版本或有效期 |
| G4 | 共享 hook 和 CLI 只传 null evaluation key 获取提示，再调用普通 PUT | 显式授权、携带 completion 绑定、原操作恢复及可靠成功显示 |
| G5 | 已有通用乐观状态更新；查到 issued 不证明原 PUT 不在途 | 首包授权路径等待真实结果，持久保存原操作意图，未知时不换 key 重提 |

证据锚点集中于 [后端研究](research/m1-backend-current-contract.md) 和 [客户端研究](research/m1-clients-current-contract.md)。本表描述缺失的产品流程，不把已验收限制登记成缺陷。

## 需求与可观察验收

| ID | 需求 | 验收条件 |
| --- | --- | --- |
| S1-01 | 证据发现与选择 | 超过一页时可遍历全部当前有权候选；无证据、读取失败、过期和权限拒绝有不同显示。多个候选必须明确选一个；不推断最新即合格，不显示无权候选的 ID、数量、摘要或 digest。 |
| S1-02 | 当前观察 | 选择后显示任务及版本、原状态/目标状态、项目/策略版本、来源 revision、制品与 spec digest、观察时间、证据期限和可授权期限。展示通过/保留/未知的实际检查；当前 pass 仅是观察，不是许可。首包无需制品下载、重新打包或发起模型执行。 |
| S1-03 | 明确人工授权 | 当前签发人即本次 human consumer；填写非空接受理由并看到明确到期时间后，主动点“授权此版本完成”。提示的“继续”不触发签发；后台、刷新、重试查询和 CLI 的常规 status/update 均不自动签发。 |
| S1-04 | 精确绑定 | 授权固定 source workspace、原 operation、任务版本/原状态/目标状态、项目/策略版本、本人 consumer、所选 approval/source/spec/artifact。新完成 PUT 只带 status 与 completion 引用，不能顺带改内容/项目/附件。 |
| S1-05 | 当前检查拒绝 | 对尚未 consumed 的新准入，预览后或授权后发生证据/凭据过期、撤权、撤销、PR head/source/digest 变化、任务版本/项目/策略变化或状态归档，签发或完成按实际阶段拒绝，零新增完成副作用；刷新不能续期旧证据、旧授权或旧评价。已 consumed 的原操作仍按 S1-08 读取历史结果，不能改判未完成；当前读取权限另行复核。 |
| S1-06 | 授权创建未知 | 请求前保留原 Idempotency-Key、operation 和不可变请求；断网/超时后按 source workspace + 原 key 查询。找回原授权不另签，不自动完成；未查到或查询失败仍显示未确认，不当失败或成功。 |
| S1-07 | 完成提交未知 | 请求前保留授权 ID、operation、预期版本和 status；超时/提交不明时按原授权查询收据，并另读任务。issued/not_checked 不能证明可重试；不得自动再次 PUT、更换 operation 或创建新授权。 |
| S1-08 | 已知结果与当前状态 | 仅已确认原收据才宣称本次完成已提交。查询再现同一操作不得增加状态写入、通知、队列或消费；已完成后又重开时，同时说明历史完成与当前未完成。收据与当前读任一失败不得伪造另一项结论。 |
| S1-09 | 重复与并发 | 同一 UI 意图的重复点击仅发一次签发/完成请求；共享入口、多个 detail 宿主及跨标签页即使产生两个意图，服务端精确版本绑定仍只能完成一次。后续旧请求不得当成 done-to-done 新编辑。 |
| S1-10 | 取消与撤销 | 签发前取消不产生授权或完成。签发后“关闭”仅关闭界面；“撤销授权”才调用撤销且保留理由与原撤销 key。与完成竞态以唯一终结事实为准；撤销未知可查询，不能提示已取消完成。组件卸载、切换任务或身份后不继续写入。 |
| S1-11 | 状态生命周期 | 活跃自定义 done 可完成；归档/未知类别不放行。done → done 和自定义 done 互切不签新授权；重开后再次完成需新版本、新证据观察和新授权。 |
| S1-12 | UI 和 CLI 一致 | Web/Desktop 共用核心状态与共享 UI，支持键盘、焦点、长理由/摘要和窄窗；CLI 明确区分观察、已签发、已完成、拒绝和未知，stdout 可解析结果与 stderr 提示分离。两者的授权与恢复字段一致。 |
| S1-13 | 私有信息与会话 | 不要求、传递、展示或复用他人 evaluation key；候选和预览不产生新的持久私有 evaluation。无权访问、切换 Server/身份/工作空间及卸载后不能显示旧证据或触发旧回调；登出按既有规则清理本地意图。 |
| S1-14 | 故障与兼容 | 缺版本、非法/malformed 成功、未知协议、锁冲突和结构化 403/404/409/428/503 均不能退回无授权完成。已存在提示接口对非结构化旧 404/405 的兼容只保留原范围；enforce 授权流程不得借此降级。 |
| S1-15 | 恢复材料可靠 | 本地原意图保存及读回验证失败时不发写请求。页面刷新可恢复原查询入口；CLI 重启可用原 operation 文件恢复。退出登录后的自动跨身份恢复不承诺，用户保留的最小原 key 可在原身份下手工查询。 |
| S1-16 | 交付边界 | v1 的 skip_supported=false / waivable_checks=[] 保持；所有拒绝不得伪装通过。验收使用本地确定性制品、fake/fixture 和任务自有环境，不调用真实 Provider，不开放知识注入/发布/Hosted CI/部署。 |

## 其他入口：现行合同、待设计内容和顺序

| 后续包 | 当前合同 | 待设计范围 | 顺序/依赖 |

S2 → S3 → S4 → S5 → S6 是这些入口内部的建议顺序，不把全部 S2–S6 塞入 S1，也不阻断既定 F2 → F3 → F4 路线。GitHub/VCS 自动消费者保持 v1 已有合同，新增面向它们的授权管理不在首包。

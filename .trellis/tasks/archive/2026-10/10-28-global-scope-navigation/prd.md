# 固定全局切换与工作位置恢复

## Goal

用户从工作空间任务／项目切到账号级协作，再各点击一次回到两边刚才的位置，无须重新寻找内容。Web 和桌面端采用用户已选定的「固定全局切换＋恢复位置」。

## Confirmed facts

- 现有侧栏底部和桌面内容区顶部重复提供协作入口；Web 协作页没有固定返回入口。
- 桌面 tab store 已有账号及工作空间页签、历史、筛选和滚动快照；无参数切换可以复用。缺少上次工作空间指针。
- Web 已有滚动恢复适配器，但以 pathname 保存，所有协作详情会碰撞，且未隔离账号。
- 协作任务由账号授权，访问不依赖工作空间列表加载成功或有工作空间。
- 用户明确要求创建任务、选择该方案，并多次要求继续推进；沿此范围完成设计、实现与检查。

## Requirements

1. 外壳左上方始终有「工作空间」「协作」，两种范围、侧栏展开／收起以及窄窗口下位置稳定；仅保留这一组全局切换。
2. 「工作空间」恢复最近有效空间的原任务／项目页面、桌面活动页签和已有视图位置；「协作」恢复最后视图、任务、搜索、排序、列表与详情滚动。
3. 点击当前已选范围不清空筛选、不重置滚动、不增加无意义历史。
4. 通知、任务内打开协作、复制的任务链接仍精确定位指定任务／锚点；随后通过全局入口返回时恢复用户后来停留的位置。
5. 首次使用采用现有默认列表；上次空间失效时选取当前可访问空间；没有空间时保留创建入口。列表加载或失败时协作仍可进入，并有明确的空间恢复操作。
6. 不跨账号或 Server 复用私人路由／滚动状态；退出与身份切换清理对应瞬态状态。
7. 中英双语、键盘可达、选中态在 hover 时可辨认；桌面拖拽区、红绿灯和原有导航控件不遮挡。

## Acceptance criteria

- [x] 工作空间任务 A → 协作任务 B → A → B，各次全局切换只需点击一次。
- [x] 从非首个空间的项目详情返回时仍是该空间、该项目、该页签。
- [x] 协作「我参与的」及任务选择、搜索、排序、两个滚动容器在往返后保留。
- [x] 重复点当前全局项是无操作；显式链接到任务 C 仍打开 C 和所指定锚点。
- [x] 从带锚点的链接进入并继续滚动后，全局往返不再次抢回旧锚点。
- [x] 零空间、列表加载／失败、空间删除／退出以及身份切换不造成空白或状态串用。
- [x] 两端各只有一组全局入口；侧栏收起、窄窗口、中英与缩放后仍可操作。
- [x] 相关状态／平台／视图回归测试、lint、typecheck 通过，并记录实际界面验证范围和限制。

## Out of scope

- 不合并普通任务与协作工作台，不改变任务数据范围、协作权限或后端协议。
- 不改移动端，不重写桌面 tab store，不保存服务器数据，不新增依赖。
- 不以本任务承诺 Web 浏览器完全退出后仍恢复全部瞬态滚动；本轮保证同一会话往返，桌面沿用既有持久化行为。
- 不包含当前工作树中已有的其他任务改动。

## Blocking questions

无。布局细节沿现有设计语言，技术约束已通过源码研究确认。

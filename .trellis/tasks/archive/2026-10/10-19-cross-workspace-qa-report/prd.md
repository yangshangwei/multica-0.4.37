# 跨工作区协作专项测试与报告

## 目标

验证当前分支跨账号、跨工作区协作的已实现行为，交付可追溯的中文测试报告，让后续工作能区分通过项、产品问题、脚本问题和未覆盖项。

## 背景与授权

- 原始请求：“测试跨工作区间的功能……给我个测试报告，请继续推进”。用户随后明确选择“建立 Trellis 任务，记录测试过程”。本任务补建既有测试工作的记录，不引入新产品设计或实现范围。
- 父任务：`10-10-cross-workspace-collaboration`，保持进行中。本子任务的完成不代表父任务全部验收。
- 当前分支 `codex/cross-workspace-collaboration`；测试基线 `8fc94420221ddde15a02aa8feffea18f55b54f88`。
- 原始证据位于 `.omx/reports/cwc-qa-20261019T082840Z/`，包含任务专用服务、生产模式 Web、真实 macOS Electron 夹具及回归日志。

## 范围

- A、B 拥有各自独立工作区且不互为成员时的派单、补充信息与交回、转交、验收、完成、重开和在线撤权。
- 第三账号访问隔离、普通评论不启动 AI、账号请求不夹带工作区身份、来源页面编辑与私有附件。
- Web 和 macOS Electron 的标准场景，以及相关前端、后端回归、lint、类型与 race/vet 检查。
- 并发版本冲突的首次拒绝、原结果核对、刷新及新请求实际成功。
- 记录完整尝试历史、覆盖限制、服务来源、截图、机器可读结果和后续问题。

## 验收标准

- [x] QA01：报告给出当前提交、运行模式和证据位置，核对运行服务与基线一致。
- [x] QA02：分别记录标准 Web、Electron、前端单测、后端顶层/子测试和静态检查结果，不混合或重复计数。
- [x] QA03：给出独立工作区 A/B/C 主流程、任务身份与访问控制的真实客户端证据。
- [x] QA04：保留全部失败尝试；区分脚本/环境错误与产品版本冲突，明确未修复问题及复现步骤。
- [x] QA05：补测冲突恢复后真实完成请求的成功响应、新请求键和服务端最终状态。
- [x] QA06：明确 Linux、真实 AI/provider、安装包、其他系统及全量验收的覆盖限制。
- [x] QA07：记录测试过程与后续工作；保留证据，仅清理明确属于本轮的服务，不修改产品实现。

## 不在范围内

本轮不修复产品、变更开关默认值、增加依赖、部署或推送，不将离线夹具等同真实 AI 推理，不将移动宽度截图等同 iOS 客户端验收。

## 交付形式

轻量验证与报告任务，采用 PRD 加测试记录；不需要新的产品技术设计。测试计划已保存在原始证据 `plan.md`，本轮沿用并补齐并发恢复断言。产品意图、报告范围和用户授权均已明确，没有待澄清的产品选择。

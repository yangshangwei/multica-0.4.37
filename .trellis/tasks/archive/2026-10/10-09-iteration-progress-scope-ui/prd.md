# 迭代详情：进展与范围变化的信息层级优化

## Goal

让用户进入迭代详情后快速读懂交付结果，并能追查范围为何变化。落实已审计并经用户确认的方案，保留任务、进展、范围变化三个主标签及历史核对能力。

## Background and authorization

用户最初要求以 impeccable 审计「手测-第1期」的进展与范围变化。审计完成后，用户明确要求「创建 Trellis 任务，推进开发」。本任务将上一轮已展示的具体方案转为实现，不重新发起设计方向选择。

审计记录：`.impeccable/critique/2026-10-08T16-00-27Z__packages-views-iterations-iteration-page-tsx.md`，附 1360px/900px 真实截图。

该期冻结事实：原始承诺 4、结束时范围 5、取消任务 1、有效范围 4、已完成 2、原始承诺中完成 1、未完成 2；新增不同任务 1、取消事件 1、期间移出 0、净有效范围变化 0；只有 1 天图表数据、19 条事件；结束时 C 结转到第2期、D 移出。

## Acceptance Criteria

- [x] AC-01 / IPU-01：进展与范围变化进入首屏后，公共头部不重复展示五项通用指标或冻结说明；任务面板仍有所需统计，过滤不改变全迭代统计。
- [x] AC-02 / IPU-02：示例显示有效完成 2/4（50%）、原始承诺完成 1/4（25%）、未完成 2；C/D 的结束去向可核对，不把已完成/已取消任务当成待处置任务。
- [x] AC-03 / IPU-02/IPU-04：关闭时统计、图表与结束处置使用 snapshot；修改当前任务或当前统计不会改写历史显示。“期间移出 0 次”和“结束时移出 1 个任务”分开表达。
- [x] AC-04 / IPU-03：0/1/多天状态有适当展示，语义数据表可键盘展开且保持所有数据；分母为零/历史缺失显示不适用或未知，不伪造零值。
- [x] AC-05 / IPU-04：完整计数仍可访问，新增不同任务数与移出/重入/取消/重开次数不混算，started 不改称进行中。
- [x] AC-06 / IPU-05：19 条原始记录均可在全部活动及操作详情中找到，同次计划更新与开始/承诺记录合理聚合，默认范围视图不被普通标题/负责人更新淹没。
- [x] AC-07 / IPU-06：普通创建/状态更新不再出现无意义来源箭头；保存了前后状态、标题、负责人或日期的事件能解释差异；缺失历史事实不会通过当前实体补造。
- [x] AC-08 / IPU-07：跨服务端分页的记录排序/过滤完整；继续浏览不会丢失已显示记录；陈旧游标最多重启一次，重复游标不会无限请求；暂时刷新错误保留数据并可重试。
- [x] AC-09 / IPU-01/IPU-07：切 tab 保留任务过滤、已访问面板和表单；按 workspace/iteration 身份重置，revision 更新不会丢失编辑状态；无权读取时不显示旧数据。
- [x] AC-10 / IPU-08：已完成中英文、两种主题以及 1360px/900px 的真实渲染核对；展开、筛选和 Enter/Space 键盘操作通过，20 个截图场景均无横向溢出，图形颜色不承担唯一语义。
- [x] AC-11：相关 regression、类型检查、lint、语言键一致性与机械设计检测通过；无新依赖。

## Constraints and Out of Scope

- 保持 API、服务端统计公式、数据库与写操作协议；不扩展服务端排序参数，不改变原始事件。
- 不重新设计迭代总览、任务列表、设置、导航或移动端独立 UI；仅在共享图表复用和展开数据表的现有测试接点做必要适配。
- 不发布、不部署，不修改其他任务的未提交内容。默认视觉沿用 Multica 的 tokens、标准组件和中性色。
- 原始承诺达成使用 original_completed/original；净有效变化使用 effective-initial_effective；结束处置不倒灌到期间统计；未知值不变成零。

# 桌面端自助下载与安装页

## Goal

让首次安装 Multica 的内网用户通过一个静态入口取得正确安装包，按指导独立进入工作台。

需求通过 grill-me 对齐。用户已确认以既有 Web 下载页为基础制作独立内网静态版，并明确要求“按这版完整方案开始实现”。2026-10-13 已通过规划与上下文检查，任务进入 in_progress。

## Background

- 仓库已有 Next.js Web 下载页，入口为 `apps/web/app/(landing)/download/page.tsx:26`，与用户提供的截图内容对应。它与下述 Nginx 文件服务是不同入口；现有布局及公网数据依赖的评估见 `research/existing-download.md`。
- 现有 Nginx 仅提供文件下载，没有面向首次安装者的首页，目录列表关闭。依据：`deploy/desktop-updates/nginx.conf:21`、`deploy/desktop-updates/nginx.conf:34`、`docker-compose.desktop-updates.yml:14`、`docs/desktop-intranet-update-runbook.zh-CN.md` 第 2.4、3 节。
- 发布流程保留带版本号的历史安装文件，先发布完整文件，再切换各平台元数据。依据：上述手册第 4 节、`apps/desktop/scripts/update-artifacts.mjs:167`。页面展示范围不改变文件保留策略。
- 仓库具备多平台构建能力，实际页面开放范围由下方需求限定。依据：`apps/desktop/electron-builder.yml`、上述手册第 3 节。
- 客户端需要业务服务器地址，认证方式由业务服务端统一选择。依据：上述手册开头与第 5 节、`apps/desktop/src/renderer/src/pages/endpoint-setup.tsx:60`。
- 密码注册表单还包含姓名和确认密码；注册成功即建立登录会话。依据：`docs/offline-upgrade.zh-CN.md` 第 7.1–7.2 节、`packages/views/auth/password-form.tsx:95`、`packages/views/auth/password-form.tsx:137`、`packages/views/auth/password-form.tsx:151`、`packages/core/auth/store.ts:169`。
- 进入工作台前可能需要完成上手引导或接受工作空间邀请，不能将注册成功等同于已进入工作台。运行时连接步骤允许稍后处理，因此无需扩展为 AI 工具安装教程。依据：`apps/desktop/src/renderer/src/App.tsx:247`、`packages/views/onboarding/onboarding-flow.tsx:87`、`packages/views/onboarding/steps/step-runtime-connect.tsx:197`。

## Out of Scope

- AI 工具安装和配置教程（D2）。
- Windows 32 位、macOS 和 Linux 安装包的构建、签名及交付；本任务的开放状态按 R2、R5 执行。
- 操作截图和视频制作（D10）。
- 修改桌面安装器、服务端认证或工作空间业务流程。
- 新增登录保护、后台发布管理、工单系统或下载统计系统。

## Deployment Preconditions and Deferred Items

- 管理员在部署时填写真实业务服务器 URL（包含协议及必要端口）。本轮不绑定生产 IP，也不将下载服务器地址自动视为业务地址。
- 业务环境已启用密码认证和自助注册；加入团队需要有效邀请，自行创建须符合现有工作空间策略。静态页仅提供指导。
- 首次上线需准备当前 Windows x64 发布的下载信息；后续正常发布自动更新。实际 Windows 安装和内网使用仍需按实施计划验收。
- Linux 包格式延后决定（D5）。暂沿用用户指定的“x86”标签，实际开放下载前再确认 32/64 位含义和准确包格式；这不阻塞首期待开放展示。

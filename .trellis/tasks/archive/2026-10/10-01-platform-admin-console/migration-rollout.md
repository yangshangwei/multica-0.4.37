# 迁移、发布与回退方案

这是未来实施顺序，本轮未运行迁移、初始化管理员或部署。

## 1. 发布前置

确认目标为自托管 password 模式；记录服务版本、客户端版本、数据库备份位置、恢复演练和 schema_migrations。审核待授予平台角色的现有用户 UUID，不能按非唯一姓名选择，也不能把首个注册者自动提升。

检查现有工作空间与目标内部组织映射；不依据账号邮箱域猜客户。`admin` 已保留，发布前检查是否存在历史异常 slug，发现冲突暂停路由启用并单独处理，不静默重命名。

## 2. 数据迁移

1. 新增组织映射、平台角色、账号禁用字段、安装与绑定、操作与审计、告警必要实体。新表/列 DDL 与每个索引文件分开。
2. 所有唯一和非唯一索引使用单语句 `CREATE [UNIQUE] INDEX CONCURRENTLY`。需要主键时先 concurrent unique index 再绑定约束；不以 inline PRIMARY KEY/UNIQUE 隐式建立普通索引。
3. 所有关系由应用校验，无 FOREIGN KEY/REFERENCES/cascade。索引有效性与重复数据核查通过后才打开写功能；中断的 concurrent index 需要明确运维修复，不能仅凭迁移账本认定成功。
4. 为当前部署生成固定内部组织；分批幂等回填所有 workspace 映射，记录进度。新建 workspace 与组织映射在同一事务，迁移尾扫查漏。
5. 旧客户端日活、device_id、daemon_id 不足以回填可信安装关联，保留未关联记录。历史 task 的创建/执行安装字段可空，不按当前归属重写历史。
6. 迁移编号按实施当日仓库最大值顺延，规划不占用编号。sqlc 从 SQL 生成，禁止手工改 generated。

## 3. 功能启用顺序

- **A：安全基础**。先部署凭据转换约束、账号禁用/版本校验、平台权限与审计，后台开关关闭。验证正常 browser JWT→PAT 登录、PAT→PAT 续期仍可用，PAT→JWT 无法提升。
- **B：管理员初始化**。部署维护命令向现有已完成密码设置的账号授予平台角色。提升版本、撤销旧凭据、审计同事务；提交后断连目标账号。提前展示其会话与在途任务影响，重新密码登录验证。
- **C：只读后台**。少量管理员验证目录、执行元数据、私有内容遮罩、分页/时区和观察者权限。无 workspace 管理员验收。
- **D：安装接入**。先 10 台，再 100 台，最后目标 1000 台，验证 main/daemon 安装证明、绑定冲突、多 profile、旧端未关联和三状态轴。每档记录结果再扩大。
- **E：控制与账号操作**。在具备能力的终端启用单次取消、停止/恢复接单，以及经过密码复核的账号操作。覆盖通知丢失、离线、重启、并发与真实回执。
- **F：告警与总览**。先观察模式校准阈值，再启用后台待办。确认来源不可用不生成全体离线事件；无实际配置的外部通知渠道不显示已送达。

启用开关名、配置解析和公开能力字段在 S01 落定并集中维护，不让 UI、middleware、daemon 各自判断。未支持模式明确关闭后台，原业务认证不受影响。

## 4. 回退分类

| 回退对象 | 可采取动作 | 必须保留 |
| --- | --- | --- |
| Web 管理页面 | 关闭入口或回退兼容页面 | 服务端授权、禁用和门禁仍执行 |
| 统计/告警 | 暂停扫描器或返回不可用 | 已有事件、确认和审计，不能批量错误恢复 |
| 终端控制 UI | 关闭新增写入 | 已 applied cancel 的协调、stopped 门禁、未确认操作 |
| daemon/客户端 | 使用仍遵守绑定/准入的兼容版 | 不允许以旧协议绕过已存在终端限制 |
| 数据库/安全后端 | 优先 forward fix | 不降级到能复活账号/凭据、丢审计或跳过门禁的版本 |

若必须回退不支持门禁的后端，先由授权管理员恢复所有 stopped 状态、处置未确认操作并保存审计，确认业务影响后另行执行。关闭后台显示开关不等于取消安全策略。

含真实凭据、审计、绑定和操作后，破坏性 down migration 明确拒绝。备份恢复必须与 auth_version、角色、绑定 epoch 和审计一起处理，恢复旧数据库可能复活凭据，不能作为无风险快捷回退。

### 4.1 维护窗口与回滚锁

465–511 范围内带数据保护条件的 43 个 down 文件，先按表名字母顺序取得 `ACCESS EXCLUSIVE NOWAIT` 锁，再检查保留记录。检查与对应 DDL 位于同一个 `DO` 块，锁一直持有到该文件的事务结束。已有密码凭据迁移 462–464 的先锁后查模式继续保留；所有 up 文件及独立并发索引创建方式不变。

这层保护解决的是并发首次写入：未提交记录对 `EXISTS` 不可见，若先查后等 DDL 锁，写入方可能先提交，随后被回滚删除。现在遇到占用表的连接立即以 `55P03` 拒绝；若锁内发现保留记录，以 `P0001` 拒绝。不得把拒绝改为自动删数据，也不得强制结束业务事务来绕过保护。

多文件回滚仍必须在维护窗口执行：

1. 记录备份、服务版本、`schema_migrations`、有效索引与未确认操作；核对目标版本仍执行账号撤销、绑定校验和接单门禁。含业务历史的部署优先 forward fix。
2. 停止该部署的所有 API 实例、任务协调器、告警检测器和其他数据库写入进程，并等待连接排空。关闭管理入口或新安装接入开关不等于进入维护状态；取消协调器仍会工作。未确认进程停止的在途任务继续按原语义记录，不能伪造已停止。
3. 在整个批准的迁移范围内保持停止写入，再执行迁移。迁移器的 advisory lock 只串行化迁移器；各文件的表锁不会跨越整个迁移循环。
4. 遇到 `55P03`，排查仍活跃的连接，保持维护状态后重试；遇到 `P0001`，保留证据并改用兼容版本或 forward fix。其他错误核对该文件和之前已提交文件的实际 schema 与账本，不假设整批回滚是一个事务。
5. 重新核验索引、触发器、组织映射及安全版本后，才允许兼容服务恢复监听与后台工作。任何会绕过撤销、丢审计或忽略 `stopped` 的旧版本都不属于安全回退方案。

S07-R01 的两连接回归仅在可丢弃的私有测试 schema 中执行，覆盖首次审计、旧会话撤销标记、安装 challenge 与队列观测。该测试不是实际部署维护、备份恢复或生产回退演练的替代证据。

## 5. 管理员恢复

普通后台不得移除最后一个有效超级管理员；日常由另一位有效管理员协助恢复。唯一管理员丢失凭据时，部署侧受控 break-glass 命令需确认明确用户、原因和影响，密码通过 stdin 输入，原子保存审计并提升版本。具体参数由安全设计约束，本轮不执行。

## 6. 发布证据

归档 schema/index 检查、组织回填结果、安全矩阵、旧/新桌面协议兼容、各领取路径准入测试、操作回执证据、性能实际环境与结果、灰度档位记录、备份恢复演练以及明确未测试项。未完成原生桌面验证时不得声称桌面发布完成。

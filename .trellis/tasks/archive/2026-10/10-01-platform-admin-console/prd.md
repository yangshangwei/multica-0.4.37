# 需求：平台管理后台

状态：规划稿；本轮交付设计与任务分解，不实施业务代码。日期：2026-10-01。

## 目标与用户价值

企业管理者从一个后台识别账号、终端和执行情况，发现异常、执行受控管理动作并验证结果。先覆盖企业内部 100–1000 台桌面终端，后续扩展多个客户组织。

管理员应能回答：谁在用、哪些终端能执行、任务卡在哪里、谁处理异常、处理是否生效。普通员工继续使用现有桌面注册、登录、创建工作空间与任务流程。

## 已确认的用户决定

- U01：同时需要企业内部和多客户管理，先按企业内部场景落地。
- U02：管理员与普通用户共用账号、密码和登录认证，通过独立平台权限区分管理能力。
- U03：首期预计 100–1000 台桌面终端。
- U04：创建 Trellis 任务，完成需求设计、架构设计、详细设计、任务分解等规划交付；当前未要求启动实现。

## 当前基础与约束

源码已有用户名密码认证、运行时注册/心跳、执行反馈、重试/取消、工作空间级统计。尚无完整平台管理员授权、终端资产关联和全局管理查询。依据集中于 research/current-state.md。

沿用现有注册规则：用户名、密码、姓名；注册后自动登录，用户自行创建工作空间。不新增邀请码、账号审批或默认加入其他人的工作空间。注册与空间创建仍由部署配置控制，后台首期只读展示当前规则。

角色与内容边界：平台管理角色与工作空间角色独立；平台运维权限不自动赋予私有任务正文、日志、产物和智能体调用权限。平台读取运行元数据；内容读取继续要求原业务可见性。组织级客户管理和支持访问授权在后续阶段补充。

## 角色与核心场景

| 角色 | 核心需要 |
| --- | --- |
| 普通员工 | 使用同一账号跨设备登录；正常创建任务；知道终端和任务的实际状态 |
| 平台超级管理员 | 查看内部企业全局运行情况；管理账号、接入与执行；追踪每次操作 |
| 平台只读观察者 | 查看运行摘要和告警；不能写配置、修改账号或停止执行 |
| 后续组织管理员 | 只管理授权客户组织内的用户、终端与配额 |
| 部署维护人员 | 受控初始化/恢复管理员、发布服务、备份与恢复；不通过普通注册自动提升权限 |

| R03 | 后台有独立入口，首期总览、账号与组织、终端管理、任务与执行、监控与告警、系统管理六个一级菜单。 | P1 |
| R04 | 查询全局账号、所属工作空间和状态；显示注册规则；支持受控禁用/恢复及账号恢复，保留历史和业务归属。 | P1 |
| R05 | 首期只有一个内部组织；新旧空间归属明确；不将“一个工作空间”定义为“一个客户”；后续组织管理可扩展。 | P1 基础 / P3 |
| R06 | 建立受管理安装实例台账，关联负责人、终端组、桌面版本、daemon 与运行时；未知关联单列，不按名称/IP 自动合并机器。 | P1 |
| R07 | 分别展示客户端活跃、daemon 可达、执行准备度、数据新鲜度；重装、多用户、多运行时不会重复计算同一已确认实例。 | P1 |
| R08 | 全局任务与执行列表支持分页和组合筛选；区分业务任务、聊天/自动化来源、执行尝试及创建端/执行端。 | P1 |
| R09 | 执行详情展示状态时间线、耗时、失败原因、重试关系和可见范围内的日志/结果；无权内容不可经导出或链接绕过。 | P1 |
| R10 | 支持单次执行取消、终端停止接单/恢复接单；每次操作展示受理、送达和实际结果；离线、超时和重复请求有明确反馈。 | P1 |
| R11 | 支持执行中终端失联、排队超时、执行失败三类告警；提供确认、负责人、处置关联和恢复状态，避免正常下班离线告警泛滥。 | P1 |
| R12 | 总览展示终端、在途/排队执行、失败、未处理告警和基础用量；每项可下钻，并显示统计范围、时区与刷新时间。 | P1 |
| R13 | 敏感管理操作与凭据恢复可追溯到具名管理员；记录对象、范围、原因、变化摘要及结果，不保存密码、token 或私有正文。 | P1 |
| R14 | 旧客户端仍可正常工作，能力缺失显示不支持/未上报；只有已具备接入证明和协议支持的安装实例可接受终端级控制。 | P1 |
| R15 | 能力与策略中心统一管理智能体、skill、MCP、模型、功能开关和配额；展示策略目标版本与实际生效状态。 | P2 |
| R16 | 独立统计支持采用率、效果、性能、容量、版本及估算成本分析；重试与任务数分开、缺失用量不算零费用。 | P2；P1 基础 |
| R17 | 提供终端版本分布；后续支持升级批次、维护窗口、失败恢复，区分桌面、Multica CLI 与执行引擎版本。 | P1 只读 / P2 |
| R18 | 后续支持组织管理员、组织隔离、组织配额及显式支持访问；商业结算仅在另行确认后规划。 | P3 |

## 非功能需求与容量目标

- N01：以 1000 个受管理安装实例设计；健康上报错峰，断线重连有退避，不让集中重连压垮认证与数据库。
- N02：关键列表在约定测试环境下、100 万条历史执行和 10 名并发观察者时，API P95 目标 ≤ 800 ms；这是拟定验收目标，不是已测性能。UI 首屏目标 ≤ 2 s，不计外部身份服务或网络不可达时间。
- N03：在线状态在最后有效心跳超过判定窗口后能明确转为未知/离线；实时状态与日活统计使用不同口径。
- N04：管理写请求无确认结果时可以查询，不能盲目重复造成额外执行；状态、审计、操作结果保持一致。
- N05：首期仅本地/自托管密码模式验收；原有其它认证模式不回归，平台后台在未支持模式下明确禁用。后续 SaaS 身份联邦单独设计。
- N06：不引入新依赖；优先复用现有 Go、PostgreSQL、Web、Query、日志和指标体系。权限、组织归属、状态规则均由服务端判断。

## 验收标准

| AC | 可观察结果 | 对应需求 |
| --- | --- | --- |
| AC01 | 同一合法管理员账号登录桌面与后台；无工作空间仍可进入后台；普通用户和空间 admin 直接请求管理 API 被拒绝。 | R01–R03 |
| AC02 | 角色撤销后下一次管理请求拒绝；管理员名下的 PAT/task/daemon 凭据不能继承后台权限。 | R02 |
| AC03 | 禁用账号后原会话与派生凭据不能继续访问；恢复账号不复活旧凭据；恢复密码仅进入强制改密流程。 | R04 |
| AC04 | 终端台账能对应安装实例、账号和运行时；一台已关联终端的多个 runtime 不重复计数；旧数据标注未关联。 | R05–R07、R14 |
| AC05 | 客户端关闭但 daemon 仍运行，与客户端在线但引擎不可用分别正确展示；未上报值不显示成 0 或正常。 | R07 |
| AC06 | 从提交来源查到每次执行及目标终端；重试次数与业务任务数独立；页面与服务端分页、筛选一致。 | R08–R09 |
| AC07 | 停止接单能阻止新领取并保留在途执行；取消在途执行显示终端确认；离线时不虚报已停止。 | R10 |
| AC08 | 同一操作重发不重复执行；已应用取消超过确认截止仅显示未确认，重连继续协调该终态；未来未应用命令才过期丢弃；已完成执行不被迟到取消改写。 | R10、N04 |
| AC09 | 三类告警能触发、确认、关联操作、恢复；正常空闲下班离线不触发严重事件；重复检查不重复刷屏。 | R11 |
| AC10 | 总览与下钻使用相同范围、时区、终态口径；未知用量单列；未授权正文、日志和产物无法通过管理入口获取。 | R09、R12、R16 |
| AC11 | 账号、角色与终端控制均有审计和结果；敏感信息不进入响应/日志/导出；最后一个有效超级管理员不可被普通后台操作移除。 | R02、R04、R13 |
| AC12 | 新旧客户端混跑，旧端保持原业务能力，后台将缺失能力明确标注；升级可回退显示层而不丢台账与审计。 | R14、R17 |
| AC13 | 完成 1000 安装实例、集中重连、历史分页和撤销竞态测试；记录实际环境、吞吐、时延和差异，不以目标替代结果。 | N01–N04 |

## 首期不包含

完整桌面远控、任意 shell、远程查看员工桌面、跨机器执行迁移、运行中任意暂停/恢复、物理硬件盘点、CPU/内存等尚无采集的数据、自动批准新能力、复杂部门树、平台默认读取私有正文、SaaS 计费、SSO、移动端后台、多客户可正式上线承诺。

批量操作、人工重跑与复杂调度放 P2；首期优先把单次取消与停止接单做成可验证闭环。管理员重置密码的执行细节和有限权限由 security-design.md 定义，不提供查看原密码。

## 规划完成与实施边界

本轮完成标准是：需求、架构、详细设计、测试规格、迁移方案、依赖分解和上下文清单完整且相互一致；源码事实与新设计明确区分；独立审阅问题已处理。父任务保持 planning，不将文档交付误标为业务实现完成。

容量已由用户确认。部署硬件、执行并发和日志大小未给定，按 capacity-plan.md 中的工程假设建模，实施压测时记录实际环境。所有新增的数值目标、角色名称、接口和数据模型属于本轮工程方案，进入实现前以最终设计评审为准。

# 协作单共享的 AI 工作上下文

## 文档状态

- 创建：2026-10-26；状态：`planning`。需求由 2026-10-26 的逐轮访谈确认（决策 Q01–Q24 与 O01–O02，见文末），用户已确认整体理解一致。尚未编写技术设计和实施计划，未修改产品代码。
- 依赖[跨账号协作单](../10-10-cross-workspace-collaboration/prd.md)的权限、生命周期与代管规则（文中 R 编号均指该 PRD），以及[跨平台协作执行修订](../10-24-cross-platform-collaboration-runtime/prd.md)的普通本机执行路径（H 编号）。本任务在两者之后实施。
- 现状核查见[基线调研](research/context-baseline-2026-10-26.md)。

## 目标与用户价值

同一张协作单上，不同参与者的智能体在各自机器、各自供应商账号上接力（R28），换环境不搬运工作目录（R27），provider 会话也不跨机器延续。后一个智能体不知道前一个查到了什么、定了什么、踩过什么坑，只能从评论里重新拼。

本功能为每张协作单提供一份由执行智能体维护、人可纠错的共享活文档，让每个开工的智能体直接拿到本单的当前状态，接力不再丢失前序发现与决定。

## 术语

- **协作上下文**（英文界面 Shared context，代码标识符 `memory`）：每张协作单恰好一份的 Markdown 活文档，表达本单当前状态。
- **版本**：协作上下文的每次写入、恢复都生成一个不可变版本，带写入者署名。
- **当前版本**：最新的版本，即开工注入和面板默认显示的内容。
- 已有的 `CollaborationContext`（`server/internal/cli/collaboration.go:27`，运行身份环境变量）与 `/api/collaboration/runtime/runs/{id}/context`（本次 run 的输入视图）不是本功能，命名须避开。

## 现状

- 协作 run 之间目前只靠评论传递信息：`/context` 返回最近 200 条评论；run 结果写入 `collaboration_run_event`，后续 run 读不到。
- 换到另一参与者的运行时或机器时，provider 会话与工作目录都不延续。
- 协作 run 拿不到普通任务的工作空间上下文、项目上下文和 metadata；配置了 skills、MCP 的智能体会被拒绝启动协作 run，因此使用说明只能写在平台固定文字中。
- 运行时 CLI 白名单只有 `issue get`、`issue comment list/add`、`squad activity`。
- Mobile 当前没有任何协作单代码；服务端的账号工作台与协作单详情接口可供人类账号调用。

## 已确认需求

### 范围与内容

| ID | 需求 | 规则 |
| --- | --- | --- |
| C01 | 仅限协作单 | 只为跨空间协作单提供协作上下文，普通任务不纳入。新建与已有协作单都从空文档开始，不从正文自动生成，已有单无须迁移。 |
| C02 | 单份活文档 | 每张协作单一份 Markdown 文档，表达本单当前状态。写入方把过时结论改掉、把已完成项移出，不按条目追加；历史由版本和既有 run 记录承担。 |
| C03 | 自由格式 | 服务端只校验长度，不强制章节。推荐骨架（当前状态 / 关键决定和理由 / 代码发现 / 坑 / 下一步）写在平台固定的智能体说明里。 |
| C04 | 只放文字和指针 | 内容只含文字，以及指向 commit、分支、本单附件、路径、评论的指针。不承载文件本体、代码补丁或凭据；代码与文件仍按 R27 经 Git 或附件交付。完整排查过程可写成评论，文档只留结论和指针。 |
| C05 | 版本与署名 | 每次写入或恢复都生成新版本，记录写入者（人或具体智能体）、来源 run（AI 写入时）和时间。版本数量不设上限，首版不自动清理。 |
| C06 | 长度上限 | 按 UTF-8 字节计算，默认 128 KB。部署环境变量 `MULTICA_COLLABORATION_MEMORY_MAX_BYTES` 可调，范围 32–512 KB，越界时服务端拒绝启动，修改后重启生效。超限写入一律拒绝并返回当前大小与上限，不截断。上限调低后，已超限的文档照常可读、照常注入，下一次写入须符合新上限。 |
| C07 | 上限可见 | 服务端在接口中返回当前上限，Web 与 Desktop 的用量显示读取该值，不在客户端写死。管理后台设置页只读显示当前值，`.env.example` 与离线升级文档同步说明。 |

### AI 读写

| ID | 需求 | 规则 |
| --- | --- | --- |
| C08 | 开工注入 | run 在启动准备阶段（取得启动许可之后、组装提示词之前，不在排队时）读取当前版本放入本次 run 的输入，并记录起始版本号；同一 run 内的重试沿用这个起始版本。内容不写入本机工作目录的 CLAUDE.md/AGENTS.md 等会被复用的文件。 |
| C09 | 运行中读取 | 已受理的 run 可通过 `multica collaboration memory show` 读取最新版本，供并行通道互相看到对方的更新。 |
| C10 | 带基线写入 | 智能体通过 `multica collaboration memory update` 写入整份文档，须携带所基于的版本号。当前版本已变化时拒绝写入，提示重新读取、合并后再写。不按通道分段，不允许后写静默覆盖先写。 |
| C11 | 引导而非强制 | 平台固定说明要求智能体开工先读、结束前至少更新一次、不写入凭据。未更新不影响 run 结束状态，也不与 R17 的终态判断耦合。 |
| C12 | 小队成员 | 本单已受理的队长 run 与小队派生的成员 run 都可读写，冲突按 C10 处理。 |
| C13 | 写入门禁 | 只接受本单当前已受理且未停止的 run 写入。run 被停止、取消或因授权撤回终止（R16/R25/R35）后，迟到的写入一律拒绝。普通 agent/task、plugin、IM 等未授权机器只得最小引用（R53），不能读写。 |
| C14 | 执行路径 | 只接入 10-24 的普通本机执行路径。旧 Linux namespace run 不注入、不可写。 |
| C15 | 不由服务端代写 | 不使用服务端辅助 LLM 自动总结或改写协作上下文，避免把跨空间内容发往资源拥有者未授权的供应商（与 R28 一致）。 |
| C28 | 不支持的运行时 | 不认识协作上下文的 daemon 和旧 Linux 执行路径照常执行协作 run，不因此阻断；run 记录标出"运行时不支持协作上下文"，与"未更新上下文"区分。 |
| C29 | 升级不重新授权 | daemon 是否支持协作上下文不进入运行时能力声明与授权指纹。升级到支持的版本不推进配置纪元、不撤回授权、不挂起目标，资源拥有者无须重新确认（协作上下文只是本单业务身份下的读写通道，不扩大本机权限，不属于 R13 的失效情形）。前提是先升级服务端再升级 daemon。 |
| C30 | AI 写入脱敏 | AI 写入的内容在存储前经平台现有的共享执行记录脱敏处理（与 host 对 AI 输出的处理一致），令牌、API key、JWT 等替换为占位符。人的写入不处理。这不是新的凭据扫描，C19 的"首版不做自动凭据扫描"不变。 |

### 人的权限与生命周期

| ID | 需求 | 规则 |
| --- | --- | --- |
| C16 | 读权限 | 可见范围与本单 AI 执行记录一致（R05/R36）：参与者与来源空间成员可读；与本单无关的账号不可读。 |
| C17 | 写权限 | 对本单有 AI 控制权的参与者可直接编辑和恢复版本（与 R06 同级，普通评论权不等于此权限）。R36 来源空间成员只读。人的保存同样携带基线版本，当前版本已变化时拒绝并提示重新加载，不静默覆盖 AI 刚写入的内容。 |
| C18 | 恢复版本 | "恢复为此版本"生成一个内容相同的新版本，不删除中间版本。 |
| C19 | 清除历史版本 | 有效发起人可清除单个历史版本的正文，留下"已清除"标记，记录操作人、时间与原因。当前版本不能直接清除，须先编辑生成新版本。发起人被禁用时，有相应平台管理权限的管理员可按 R38 代管清除，记录原因、真实管理员与原发起人；资源拥有者不因写入 run 属于自己而获得清除权。首版不做自动凭据扫描（AI 写入沿用现有脱敏，见 C30）。 |
| C20 | 编辑无副作用 | 人或 AI 编辑协作上下文都不触发 AI 执行、不解除暂停、不发 R52 通知、不进入任务活动流；审计以版本历史为准。目标停止后，人仍可编辑其上下文。 |
| C21 | 生命周期 | 整单完成或取消后协作上下文只读，重开后恢复可写。例外：C19 的清除历史版本在终态下仍可执行，只读约束的是内容编辑，不约束凭据处置。被移除或主动退出的协作者，其已写版本保留署名，不回滚、不抹除。来源空间删除受 R37 约束，不新增独立处置。 |
| C22 | 不外泄 | 协作上下文不进入搜索索引，不随插件事件、出站事件或 IM 发出（R53）。 |

| ID | 需求 | 验收 |

| CA01 | C02/C08/C10 | 换机接力主场景：A 的智能体在运行时 X 写入决定和发现生成 vN；转交后 B 的智能体在运行时 Y（另一台机器、另一供应商账号）开工，输入中含 vN，并基于 vN 写入 vN+1；面板显示两次署名。 |

| CA03 | C09/C10/C12 | 两个并行通道（含小队成员）基于同一版本写入：后到者被拒绝，重新读取合并后成功，两边内容都在；成员写入的署名为成员智能体及其 run。 |
| CA04 | C13/C14 | 已停止、已取消、授权已撤回的 run，旧 Linux run，未受理身份，普通 agent/task、plugin 令牌：写入全部被拒绝且不产生版本；未授权机器读取只得最小引用。 |
| CA05 | C06/C07 | 超限写入被拒绝，错误含当前大小与上限；环境变量越界时服务端拒绝启动；调低上限后旧文档可读可注入、下次写入须符合新上限；Web 与 Desktop 的用量显示与服务端上限一致，管理后台只读显示当前值。 |
| CA06 | C16/C17 | 有 AI 控制权的参与者可编辑和恢复；来源空间成员只读；无关账号不可读。人保存时基线已变化则被拒绝并提示重新加载。 |
| CA07 | C01/C05/C18 | 新建与已有协作单的协作上下文初始为空，普通任务没有协作上下文；每次写入、恢复都生成带署名的新版本；恢复不删除中间版本。 |
| CA08 | C19/C21 | 发起人清除历史版本后正文不可再读、留有"已清除"标记与审计；当前版本不能直接清除；发起人被禁用时管理员代管清除并记录真实操作人；非发起人（含资源拥有者）清除被拒绝；整单完成或取消后仍可清除。 |
| CA09 | C20/C22 | 人或 AI 编辑后：无 AI 执行、无暂停解除、无通知、无活动流条目；搜索、插件与出站事件中不出现上下文内容。 |
| CA10 | C21 | 整单完成或取消后人和 AI 都不能编辑或恢复版本，重开后可写；被移除者写过的版本仍保留署名。 |
| CA11 | C11/C24/C28 | run 记录正确标出起始版本、写入版本或"未更新上下文"，并可跳转到对应版本；未更新的 run 结束状态不受影响。不支持协作上下文的运行时照常执行，run 记录标出"运行时不支持协作上下文"，不显示为"未更新上下文"。 |
| CA12 | C25 | 本任务不修改 `apps/mobile`，Mobile 现有行为不变。 |
| CA13 | C26/C27 | 新接口的畸形响应测试通过；旧客户端打开协作单不报错。en 与 zh-Hans 文案分别为 "Shared context" 与"协作上下文"，术语表已收录。 |
| CA14 | C23 | Web/Desktop 面板显示当前版本及写入者、来源 run、时间；有写权限者可编辑，无写权限者看不到编辑、恢复入口，非发起人看不到清除入口；版本列表可查看任意版本并恢复；用量显示正确，超限时出现"需要精简"标记；另一写入者更新后，开着的面板无须手动刷新即显示新版本。 |
| CA15 | C03/C04/C11/C15 | 服务端接受任意结构的 Markdown，只校验长度；写入接口只收文本，不收文件或附件。平台固定说明包含推荐骨架、开工先读、结束前更新、不写凭据、细节写评论只留指针。协作上下文的读写不经过服务端辅助 LLM（`server/pkg/llm` 的调用方清单不新增）。 |
| CA16 | 测试约束 | 默认测试使用测试创建的假智能体可执行文件，不调用用户安装的智能体 CLI；界面覆盖 Playwright e2e。真实智能体冒烟测试置于 `agentintegration` 标签后，仅在用户明确授权时运行。 |
| CA17 | C29 | 运行时从不支持升级到支持协作上下文后，其配置纪元、授权与目标挂起状态都不变化；升级后的下一次 run 注入协作上下文且 run 记录不再标"运行时不支持"。 |
| CA18 | C30 | AI 写入含 API key、JWT 或 mcb_/mct_ 令牌时，存储与展示的内容为占位符，字节上限与幂等按脱敏后内容判断；人写入的同样内容原样保存。 |

## 首版范围

纳入：跨空间协作单的协作上下文，Web 与 Desktop，配套运行时 CLI 与 daemon 注入。

不纳入：服务端 LLM 自动总结；自动凭据扫描；强制章节结构；版本差异对比；版本自动清理；普通任务；外部系统接入；跨 Server（R21）；管理后台在线修改上限；Mobile（含协作单入口与协作上下文，C25）；把来源空间的工作空间/项目上下文带进协作 run（会越过 R49 边界，另行讨论）。

## 设计阶段核实结果

- 来源空间成员在 Mobile 普通任务列表中能看到协作单，打开后进入普通详情，评论、编辑等写操作被服务端以 409 拒绝。这是本任务之前就存在的问题；Mobile 首版不做（C25），本任务不处理，留到 Mobile 协作功能交付时解决。
- 开工注入的落点：取得启动许可之后、组装提示词之前（见 design"开工注入"与 C08）。

## 决策记录

2026-10-26 访谈确认：Q01 解决 AI 接力断层；Q02 仅协作单；Q03 自建；Q04 新建独立任务；Q05 单份活文档；Q06 执行智能体经 CLI 写入；Q07 读随执行记录、写需 AI 控制权；Q08 只放文字和指针；Q09 带基线版本整篇写入；Q10 写入门禁与生命周期；Q11 发起人清除历史版本；Q12 Web/Desktop 面板与版本恢复；Q13 自由 Markdown、空文档起步；Q14 界面"协作上下文"、代码 `memory`；Q15 小队成员可读写；Q16 run 记录标记；Q17 换机接力验收与假智能体测试；Q18 发起人被禁用时管理员代管清除；Q19 启动准备时注入并可刷新；Q20/Q23 上限 128 KB（用户曾提出 512 KB，因共享文档须照顾最小窗口模型、成本按读取次数倍增而改定）；Q21 只接普通本机路径；Q22 原定 Mobile 最小入口加完整上下文能力，设计阶段用户改为 Mobile 首版不做（C25）；Q24 上限经部署环境变量调整，范围 32–512 KB。

写 PRD 时补充确认：O01 清除历史版本在整单终态下仍可执行（C21 例外）；O02 不支持协作上下文的运行时照常执行并在 run 记录中标出（C28）。

设计阶段补充确认：Q25 daemon 每次领取 run 时声明支持协作上下文，不写入能力声明，升级不重新授权（C29）；D-Q1 AI 写入沿用现有脱敏，人的写入不处理（C30）；用户撤回 Mobile 范围（C25 改写，原 D-Q2 Mobile 文案语言随之取消）。

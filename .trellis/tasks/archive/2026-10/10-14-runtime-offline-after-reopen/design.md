# 技术设计：复用已有凭据恢复修复

## 结论与边界

现场版本已确认为 v0.6.5。该版本的 Desktop 凭据恢复存在已知缺口，用户脚本恰好覆盖“换凭据并替换旧 daemon 进程”的恢复动作。v0.6.6 已包含提交 `296c377a4`，首先验证该修复的交付和实际恢复行为，不重复实现。

目前能确认“旧版本恢复链路有缺陷”，不能确认“本次旧 token 因自然到期失效”。过期、撤销、账号凭据版本变化及单纯进程恢复需要故障前证据区分。

## 数据流和职责

1. Desktop renderer 提供当前用户会话；Main 针对所选 server/profile 读取缓存 daemon PAT。
2. Main 用缓存 PAT 请求 `/api/me`。2xx 继续复用；确认 401 才用当前有效会话创建新 PAT；网络和 5xx 保留原凭据。
3. 新 PAT 创建成功后写入原 profile，通过现有 lifecycle gate 重启旧 daemon。相同用户更换 token 也必须触发此路径；异步操作不得越过退出登录或切换服务器。
4. 新 daemon 读取 profile，先续期检查、再注册工作区运行时。正常 ACK 抑制重复 HTTP 心跳；服务端恢复运行时状态，客户端通过注册通知和查询同步状态。
5. Agent 可用性跟随绑定 runtime。一个跨工作区共享的用户 PAT 失效，可同时影响日志中的两个工作区；Qwen 的独立版本门槛不参与 Claude 的凭据恢复。

## 选择与取舍

| 选择 | 理由 |
| --- | --- |
| 先验收 v0.6.6 已有修复 | 相关变更已存在且目标回归通过，避免引入重复机制。 |
| 保留心跳间隔、续期窗口和身份校验 | 当前日志没有证明其异常；延长 TTL 不能修复撤销或旧进程仍持旧 token。 |
| 新凭据成功后再替换和重启 | 网络故障时保留可恢复状态，避免先清空配置。 |
| 心跳恢复通知缺口作为条件性后续 | 只有同一时刻 API 在线、UI 离线才将其纳入本故障修复。 |

## 兼容、交付和回退

- 修复主体在 Desktop Main。仅升级 daemon CLI 或服务端不能替代桌面凭据同步修复。
- 验收保留原用户、工作区和 profile；记录安装包与实际 Desktop/daemon 版本，避免误用默认 profile。
- 无需迁移数据库、放宽 Qwen 版本门槛或新增依赖。
- 若部署新版后仍复现，先保留脱敏诊断并按认证/进程/显示状态分类；凭据不回退到已撤销值。
- 本轮不安装、不发布、不执行现场恢复脚本。计划审阅后的下一阶段再确定交付和现场验收动作。

## 验证范围

已有 56 项协调者执行的相关单测通过，覆盖旧 PAT 被拒后的替换、同用户重启、保留凭据、会话失效分类、续期和 WS/HTTP 回退。另有服务端研究执行的 5 项 WS/TTL 测试通过。它们不等同于用户 Windows 的真实次日重开验收。

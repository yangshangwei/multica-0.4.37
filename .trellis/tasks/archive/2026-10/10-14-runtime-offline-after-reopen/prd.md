# 排查 Windows 次日重开后运行时与智能体离线

> 2026-10-15：按用户要求归档并结束追踪。Windows 现场验收 AC4、AC5 未完成，原始凭据失效原因仍未确认；以下保留原诊断与需求记录。

## Goal

解释 Windows v0.6.5 次日重开后运行时和智能体离线、通过重新登录并重启 daemon 恢复的现象，验证已有凭据恢复修复是否覆盖该场景。用户已有有效桌面会话时，失效的 daemon 凭据应能恢复，相关运行时和智能体应重新显示可用。

## Confirmed Facts

- 用户确认现场各组件为 0.6.5，不是当前工作区版本。日志中的 Windows daemon profile 为 `desktop-10.100.160.112-8080`。
- 10:30:03 daemon 启动并认证成功；10:30:10 在两个工作区分别注册一个 Claude 运行时，并连接 task wakeup WebSocket。
- Claude 版本为 2.1.228；Qwen 0.8.2 低于最低要求 0.20.0，明确被跳过注册。
- 10:30:14 至 10:33:04 持续输出 `heartbeat: skipping HTTP tick, WS recently acked`，续期接口报告有效期到 2027-01-12；用户没有将这段日志与离线时刻对齐。
- 用户的恢复脚本执行“停止旧 daemon → 重新登录/refresh token → 重启 daemon”，之后恢复。这个组合操作无法单独证明自然到期或单纯重启中的哪一步起效。
- v0.6.5 桌面存在同账号盲目复用缓存 PAT、同账号凭据变化未必重启后台、启动快速失败未及时暴露认证恢复状态的缺口。提交 `296c377a4` 修复了这些路径，已包含在 v0.6.6；详见 `research/version-and-recovery.md`。
- GC 对一个缺少有效任务所有权的目录跳过清理；日志没有表明这阻断了心跳。
- 用户已同意创建 Trellis 任务并进入规划；本轮仅形成诊断、复用已有修复的方案及验证证据。

## Requirements

- R1：逐项区分正常日志、明确错误和未证实的离线原因，避免将健康的 WebSocket 心跳误判为故障。
- R2：以 v0.6.5 源码解释凭据失效如何同时影响多个工作区运行时及其绑定智能体，区分旧凭据为何失效与失效后为何未自动恢复。
- R3：优先复用 v0.6.6 的已有修复，在隔离环境验证再做现场验收；仅在已有修复未覆盖问题时提出增量变更。
- R4：保留版本、身份、撤销和到期校验。网络或 5xx 不能被当作确认的认证失效；取新凭据失败时保留旧配置和用户会话。

## Acceptance Criteria

- [x] AC1：正常心跳、Qwen 版本错误、GC 所有权警告分别解释，不将它们直接当作 Claude 离线原因。
- [x] AC2：报告包含版本差异、源码锚点和未能确定原始凭据失效原因的限制。
- [x] AC3：形成需求、技术设计、实施计划、研究和子代理上下文清单，保持 `planning` 待审阅。
- [ ] AC4：在 Windows 验收中，同账号旧 daemon 凭据遭拒且桌面会话仍有效时，应用使用新凭据恢复受影响运行时及智能体，无需外部脚本。
- [ ] AC5：正常重开不反复创建凭据；网络/5xx 不清空有效凭据；真实会话失效给出重新登录路径；Qwen 旧版本仍受版本门槛约束。

## Out of Scope

- 本轮安装或部署到用户 Windows 主机、升级其全局 CLI、删除任务目录或变更生产数据库。
- 重构心跳系统、增加依赖、改变智能体产品语义；未有现场证据的心跳恢复通知问题另行评估。
- 修改当前工作区其他任务的未提交变更。

## Risks and Deferred Evidence

- 当前没有脚本执行前的 401、撤销记录或同时刻 API 状态，不能断言 token 每天自然过期，也不能完全排除旧进程或显示缓存问题。
- 本机访问现场服务器 `/health` 超时，仅代表无法远程验收，不代表现场宕机。
- 本地回归证明当前源码覆盖目标恢复分支；安装包行为及 Windows 次日重开仍需验收。

# 第二阶段验收：内置安全漏洞修复小队

第二阶段实现与验收完成。用户在了解模拟与真实模型的区别后明确授权推进；本次以模拟、产品契约和以下检查作为准入，不将真实模型门槛改记为通过，也没有调用真实运行时或模型。

## 交付内容

- 新增第九个内置小队 `security-remediation`，版本 1，中英文目录可发现，并可应用到项目。
- 新增未列出的 `security-remediation-lead`，版本 1、Coordinator、并发上限 2；复用七个现有成员角色，没有新增工作角色、role skill、依赖、数据库结构或执行模型。
- 覆盖依赖、代码和其他安全风险的分诊、修复、独立验证与人工交接。生产、凭据和客户数据风险交既有人工/incident/release 路径；成员自己的停止规则保留，诊断角色不会被强行要求越过安全停止。
- 明确状态归属：只有任务实际分配给本小队，且注入协议授予状态管理权时，leader 才能修改状态；访客 @mention 和无归属的快速创建只交付评论与 activity。
- 保留私有创建、现有角色内容/绑定复用、旧模板版本和未知模板描述回退。更新共享图标/文案、中英文文档、内置 skill 说明及三页中文嵌入文档。

## 验证过程中的调整

1. 原 `scripts/check.sh` 已完成静态、TS、Go race/vet 和隔离 API 阶段，但现有 `work-management-local` 占用主工作区的 Web 构建。没有停止该环境，而是在忽略目录下创建独立工作树、离线冻结安装依赖，继续生产构建和浏览器验收。
2. 复制验证配置时残留的端口别名在测试前被规范化，隔离 API/Web 使用一致的地址。最终 30 个产品/测试文件逐一与主工作区比对摘要一致。
3. 独立复核发现新提示词无条件要求改任务状态，与访客小队协议冲突。两份提示词均已增加归属限定，并补充真实 owning/guest briefing 组合测试。
4. 新 E2E 最初把已保存的 `state: configured` 写成了 `ready`。按 core 类型、handler 和 `getProjectSquadReadiness` 的现有契约修正测试，保留其余采用/权限/复用断言，重跑中英文两项通过。没有为 fixture 启动真实运行时。

原流水线的环境阻塞与首轮 E2E 的两项失败都保留在记录中，不冒充一次无失败的整包运行。产品构建和所有相关用例已在隔离续跑中完成。

## 范围与后续

这是模板、提示词、目录、文档及契约测试交付，不是漏洞扫描器或自动生产补丁系统。模板说明不构成操作系统沙箱，也不保证模型判断和指令遵守；这些真实模型行为仍未验证。此项限制已知并保留，用户授权的第二阶段无需等待真实模型调用。

临时 API/Web、测试数据库和验收工作树在取证后清理；日常运行环境未被本次验收替换。未进行生产部署或发布。

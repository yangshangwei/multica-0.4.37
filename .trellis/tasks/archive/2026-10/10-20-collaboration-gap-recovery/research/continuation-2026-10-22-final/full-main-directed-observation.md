# Directed workflow observation boundary

The new six-write first-version workflow sequence follows current human forms,
not TestApiClient mutations. First and second directed attempts each actually
posted Request information through the full packaged Main with HTTP200 and
information_requested, correct original revision/status-options and no renderer
errors. Their later refresh helper matched/read an issue response whose CDP body
had been retired by renderer navigation. This is a harness observation failure;
the submitted operation receipt and new stored request remain valid.

No failed attempt is promoted as the complete workflow. The helper is being
changed to observe actual post-navigation GET completion and then use the
current renderer's own authenticated read to confirm the same issue/status,
rather than retain a pre-navigation CDP response body. UI form writes, version
observations, prescribed statuses and exact original receipts remain asserted.
No product code, native IPC, user configuration or production/provider gate changes.

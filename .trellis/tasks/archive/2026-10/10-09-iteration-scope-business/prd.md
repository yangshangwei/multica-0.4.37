# 迭代范围变化：按阶段解释承诺与变更并关联任务

## Goal

使 Web 与桌面端迭代详情准确区分计划调整、开始后的承诺变化和结束时的冻结事实，让成员从变化摘要找到相关任务并理解业务影响。

## Background and authorization

- 2026-10-09 用户提供“手测-第2期”的计划中页面：初始有效范围 0、当前有效范围 2、净变化 +2，同时新增不同任务为 0。
- 前一轮业务评审提出阶段化口径、变化影响、指标关联任务与技术审计分层；优先修复计划阶段，再实现变化影响和指标明细。
- 用户本轮明确要求“请根据计划，新建个trellis任务 进行需求分析 方案设计 和代码开发 及 测试验证”，授权创建任务及完整执行，不需要重复询问是否进入开发。
- 业务依据：`docs/plans/2026-10-04-work-management-prds/iterations-prd.md:122` 在实际开始时冻结原始承诺；`:150` 计划调整保留活动但不算开始后的范围变化；`:154` 两类完成率并存；`:170` 结束快照不被后续任务变化覆盖。
- 现有页面 `packages/views/iterations/iteration-events.tsx:59` 无阶段区分地呈现范围统计；后端 `server/internal/iteration/history.go:275` 对未开始迭代不计算开始后的变化事件。

## Requirements

| ID | Requirement |
| --- | --- |
| ISB-01 | 未开始迭代显示当前计划任务与尚未形成承诺的解释；范围区及计划事件使用计划调整语义，不以 0 基线或 +N 净增暗示已经发生范围膨胀；计划移空后仍可查看历史调整。 |
| ISB-02 | 进行中使用开始时/当前范围，结束后使用开始时/结束时范围；从未开始的已取消计划不能伪装成已开始迭代。真实零承诺的已开始迭代仍按现有统计规则呈现。 |
| ISB-03 | 重要变化清楚展示加入、移出、取消、恢复、结转的业务含义与可证明的有效范围影响；沿用已有操作者、来源/去向和原因，不从缺失历史或任务标题推断事实。 |
| ISB-04 | 可明细化的范围指标可打开相关任务/变更明细，并从有可靠身份的任务跳转当前任务；明确任务去重与事件次数的区别，以及历史事实与当前任务的区别。 |
| ISB-05 | 业务记录可按变化类别及任务搜索定位，任务明细可按有据的项目/负责人缩小范围；顶部整体统计不因明细筛选变化。提供清空筛选、零匹配提示及加载/失败/失权处理；不重置主任务页的筛选与分页。 |
| ISB-06 | 调整“新增不同任务”等术语并说明开始后的统计窗口；将 UUID、操作号、原始类型、采样时刻和原始记录保留在技术审计层，业务信息优先。 |
| ISB-07 | 保持 Web/Desktop 共用、双语、键盘可操作、窄窗口可用，保留现有权限、完整活动读取、事件顺序及历史冻结规则。 |

## Acceptance Criteria

- [x] AC-01 / ISB-01：计划含两个任务时显示计划任务 2 与开始后才形成承诺的解释，不显示初始 0、范围净增 +2 或开始后新增 0；计划移空后的变动仍可追溯。
- [x] AC-02 / ISB-02：进行中、已结束、开始后取消、开始前取消和真实空承诺开始的呈现有各自正确语义。
- [x] AC-03 / ISB-03：新增、移出、取消、取消恢复、普通完成/重开、计划活动、批量结转和未知/缺字段事件均不制造错误范围影响。
- [x] AC-04 / ISB-04：每个可点击计数显示与其口径相符的明细；去重任务数不混同事件次数；无法证明完整性的历史明确提示而非伪造匹配列表。
- [x] AC-05 / ISB-04：任务链接经过平台导航适配，历史信息保持冻结；删除或失权任务不泄露信息也不补写历史。
- [x] AC-06 / ISB-05：变化筛选与任务搜索可组合和清空，任务明细的项目/负责人筛选使用已知事实，不改顶部全迭代计数或主任务页筛选，空结果、重试及失权路径保持可用。
- [x] AC-07 / ISB-06：中英文口径一致，技术审计可访问且默认收起，业务记录优先展示原因、归属与影响。
- [x] AC-08 / ISB-07：针对业务矩阵的核心单测、共享组件回归、lint、TypeScript 检查及浏览器场景验证通过，并留存证据。

## Out of scope

- 不引入新依赖、数据库迁移、审批流、自动排期、容量/工时估算、绩效评分或新的目标实体。
- 不改变原始承诺、范围统计、完成率或结转次数的服务端计算口径，不重算历史快照。
- 不依据任务数量推断工作量，也不从任务名称推断阻塞状态。
- 不改移动端 UI、迭代设置、生命周期写入权限或已有用户的未提交修改。

## Confirmed decisions and limits

- `research/data-contracts.md` 确认：任务集合沿用完整 original/current 查询，历史直接取快照；活动沿用完整分页读取与既有解码，数值不由前端重算。
- `research/ui-verification.md` 确认：主任务页已有筛选与历史/当前比较，技术审计本已折叠。本任务只增加范围页内明细和清晰命名，复用导航和披露样式。
- “开始后新增”按首次加入的任务去重，包含后来已移出的任务；移出/重入/取消/重开按事件次数。净变化不是任务集合，不把其绝对值当明细条数。
- 取消恢复到已完成扩大有效范围但不计重开；已完成重开到待办计重开但不扩大范围。开始边界按事件序号判定，计划活动及结束后的成员释放不得进入本期变更指标。
- 实时任务明细只在点击时读取，必须核对集合版本和计数；历史直接读取同一快照。活动与摘要来自独立读取，相关活动不冒称实时同版本任务集合，证据不足明确提示。
- “已开始任务数”缺少完整逐任务执行事实，保留为现有详细计数而不提供伪造明细。不新增后端接口来弥补该非核心指标。
- 本次为范围页的增量改善，进展页继续负责两类完成率和结束去向；日期、生命周期操作与项目目标系统保持既有职责。
- 需求、兼容、权限和范围已由前一轮评审及用户本轮完整执行指令确定，无待用户决定的阻塞项。技术选择已按仓库证据收敛。

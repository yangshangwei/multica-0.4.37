# 迁移、发布与回滚

## 原则

保留用户 UUID 和业务归属，不按姓名/设备名认领他人账号，不自动合并同一人历史上产生的多个设备账号。设备 ID 不再是注册或找回凭证。

## 旧账号分类

| 状态 | 处理 |
|---|---|
| 有有效旧设备 JWT，尚未绑定 | 切换后仅允许受限绑定流程，设置用户名、密码、姓名，复用原 UUID。 |
| 已绑定密码 | 正常用户名密码登录；旧设备 ID、旧 JWT 不再可用。 |
| 旧 JWT 过期/丢失，仅剩设备 ID | 不开放 device recovery；部署维护人员线下核对后运行受控恢复步骤。 |
| 同一个人有多个历史设备账号 | 用户选择要保留的账号，其他账号不自动迁移或合并；后续单独处理。 |
| 目标部署存在邮箱/OAuth 历史用户 | 切换前盘点；依据有效用户会话绑定或运维恢复，禁止切换后被遗漏锁死。 |

旧 JWT 本身继承旧设备认证的信任强度，绑定只能保证保持既有会话连续性，不能证明现实身份。部署前通知用户保留已登录客户端，维护人员核对关键账号；对身份有疑问的账号走人工运维核验而不是自助认领。

## 绑定事务

1. password 模式下设备接口已经关闭；不为迁移重新开放。
2. 只接受必填 iat/exp 合法且 iat < 固定 cutoff、now < exp、now < deadline 的旧用户 JWT/cookie。起止配置跨重启/副本保持一致；未配置时关闭自助绑定，推荐 7 天须由部署者填入绝对时间。详见 security-contract.md 第 1 节。
3. 缺失 auth_version 的旧会话只允许 me/setup/logout；不允许 mint/renew PAT、执行任务或修改普通资料。
4. 验证输入、生成哈希；事务锁用户，检查未绑定，创建 credential(version=1)、更新 name，撤销存量访问凭证。
5. 保留 email（旧设备映射仅作历史资料），不依赖它识别绑定后账号。
6. 提交后发新 JWT；清缓存并按现有 onboarding 状态恢复。如果回包丢失，用户用新密码登录，不重复创建。
7. 同时提交两次仅一次成功；第二次不得覆盖密码。

## 发布顺序

- [ ] 盘点历史账号数量、未完成 onboarding 的账号、有效会话、PAT/daemon/cloud/task/plugin 凭据、运行任务、Web/移动端使用情况；不得记录秘密值。
- [ ] 做 DB 备份并演练恢复；确定维护窗口、账号恢复责任人、迁移起止时间。
- [ ] 部署兼容新字段的后端，执行 additive/nullable migrations，核验所有索引 valid。password 模式暂不开。
- [ ] 发布支持密码表单、绑定和新 /api/config 的 Desktop/Web，核验最小支持版本提示。
- [ ] 在维护窗口完成模式切换：显式 password、开放 signup、允许 workspace creation；关闭 device/mail/OAuth 人类登录入口。
- [ ] 停止或排空旧运行任务和长连接，确保被撤销令牌不会被续签；新会话建立后再恢复 daemon。
- [ ] 验证全新用户、旧用户绑定、换设备登录、服务器切换、欢迎引导和错误恢复。
- [ ] 观察失败率、限流、未绑定账号数量；迁移截止后移除旧会话自助绑定权限，只保留运维恢复。

## 运维密码恢复（实施时必须提供）

第一版不创建公开重置密码 HTTP 端点或管理后台。提供只可在受控服务端环境执行的管理命令/脚本：准确定位 user UUID、显示 username/name 供人工核对、交互式无回显输入临时密码、事务更新哈希/版本并撤销全部旧凭据。密码不得出现在命令参数、shell history 或输出。

对尚无 credential 的旧账号，命令必须同时交互式设置唯一用户名，事务创建 credential(version=1, must_change_password=true)；姓名和业务归属保持不变，不能另建 user。对已有 credential 的账号，保留 username，更新哈希、递增版本并设置 must_change_password=true。用户名冲突时不写入任何更改。

临时密码必须在下一次登录后强制修改才开放业务访问；这是恢复分支，不给正常注册增加步骤。完整受限会话和修改端点契约见 design.md 的运维恢复补充。本方案包含最小运维命令和临时密码修改表单，不包含系统管理员后台。

## 回滚边界

新密码用户的 email=NULL、credential 和版本字段意味着旧二进制未必兼容。禁止直接回滚到旧应用并删除凭据表，也不能重新打开设备免登录绕过故障。

推荐回滚到本次迁移兼容的修复版本，保留数据和 password 策略；必要时暂停注册/进入维护状态。收紧 email NOT NULL 前必须确认没有 NULL，否则不可回滚 DDL。数据库备份恢复只作为停机灾难恢复，明确会丢失备份后写入，需部署者另行批准。

## 部署兼容矩阵

| 客户端 / 服务端 | 预期 |
|---|---|
| 新客户端 + password 后端 | 注册、登录、绑定、欢迎引导完整可用 |
| 新客户端 + 老后端 | 不显示不存在的密码能力，原 legacy 行为不变 |
| 老客户端 + password 后端 | 服务端不给设备/邮箱绕过；要求升级，发布前确认可见提示而非无限加载 |
| Web + password 后端 | 同一认证策略与账号，cookie 正常工作 |
| 移动端旧版本 + password 后端 | 不支持新入口；不得放宽认证，发布前明确告知兼容边界 |

## 评审补充的发布检查

- password 首版仅本地/自托管；MULTICA_CLOUD_URL 必须为空，关闭 Fleet 云节点能力，先排空旧云任务。
- 检查新增 PAT/task/daemon 凭据版本字段与 member callback 版本接线；迁移前无版本凭据不能直接复用。
- 明确本次撤销会停止该用户运行环境中的执行，可能包括其他成员提交的任务；保留历史，不自动重放外部操作。独立插件安装与后台回调不受个人改密影响。
- 不能用成员移除流程代替改密撤销，验收 membership、智能体和其他 owner 运行环境仍在。
- 显式填写 limiter single/shared，并与部署副本数核对；应用不能自动发现未声明副本。
- WS 撤销验收覆盖静默订阅与另一副本的新事件；区分提交前已授权的网络数据和提交后新事件。
- 所有新增配置需同步 .env.example、compose、离线部署说明；迁移兼容后端先发布，未升级客户端不得成为放开旧登录入口的理由。

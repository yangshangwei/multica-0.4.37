# 协作接收人选择器

## Goal

把协作任务的接收人从“输入完整用户名、邮箱或账号 ID 后查询”改成统一的可搜索选择器，让用户能快速从可用账号中选择目标，同时保留精确查找兜底，并把相同体验用于新建、邀请/转交/请求补充信息和成员属性三个入口。

## Background and confirmed facts

- 父任务是 `10-10-cross-workspace-collaboration`，本子任务独立负责接收人发现与选择体验。
- 现有 `POST /api/collaboration/recipients/resolve` 已实现精确查找，并被旧 Desktop 依赖，必须保留。
- 现有三个入口仍在使用完整标识输入：`creation-form.tsx`、`workflow.tsx`、`field-inputs.tsx`。
- 2026-10-29 已确认：默认允许列出同一 Server 的可用账号，提供部署级开关；三个入口一期统一替换；列表只显示姓名、头像和必要的“外部”标记。
- 选择候选人本身不能新增协作者、转交责任或绕过服务端权限；提交动作必须再次校验当前授权。

## Requirements

### R1. 统一选择器入口

提供一个共享 `CollaborationAccountPicker`，接入：

1. 新建协作任务：默认显示“我自己”，允许选择外部账号。
2. 邀请、转交、请求补充信息：允许选择外部账号，不提供“自己”快捷行。
3. 成员类单选/多选属性：只允许来源工作空间成员，不能选择外部账号。

三个入口必须使用同一套发现、选中、去重、错误和键盘交互规则。

### R2. 分组与选择顺序

无搜索词时按“自己（仅新建）→ 已选 → 最近协作 → 全部”展示；同一账号只出现在最前面的分组。新建入口默认选中本人，已选账号固定在前面。

### R3. 搜索、分页和精确兜底

- 列表支持姓名子串搜索，忽略首尾空白；搜索结果采用稳定 keyset 分页，默认 30 条，最大 50 条。
- 空搜索首次返回最多 5 个最近共同协作账号；切换搜索词或翻页时不返回 recent。
- 搜索不匹配邮箱、用户名或账号 ID；搜索结果底部提供现有精确查找入口，支持完整用户名、邮箱或账号 ID。
- 翻页、换词和请求取消不得让旧结果覆盖当前选择器状态。

### R4. 可见范围与隐私

- `MULTICA_COLLABORATION_DIRECTORY_ENABLED` 默认开启；关闭后只列出与当前用户共享工作空间或共同参与过协作单的账号，其他账号仍可精确查找。
- 账号不可用条件与现有 resolver 一致：停用、待改密、密码模式下无凭据或应急停用账号不出现在列表中。
- 返回内容只允许 `user_id`、`name`、`avatar_url`、`external`；不得返回邮箱、用户名、工作空间或个人资料。
- 只有来源工作空间成员能看到 `external=true/false`；非来源成员看到 `external=null`。
- `members_only=true` 且调用者不是来源成员时返回空的 200 结果，不以 403 表示。
- 列表和精确查找都只接受人类账号，拒绝 agent/task 身份；服务端查询前后都要复核权限。

### R5. 提交与兼容

选择只更新表单草稿，不自动创建参与关系、不自动转交、不自动发送通知。提交时继续走既有服务端写事务和幂等键。旧草稿中的 `recipientQuery` 必须继续可解析；新表单不再依赖它。

### R6. 可用性与无障碍

- 搜索防抖 250ms；已有结果在翻页或换词期间保持稳定，加载失败保留可重试入口。
- 支持上下键移动、回车选择、Escape 只关闭选择器；不破坏外层对话框。
- 触控目标至少 44px；中英文文案通过 parity 检查；窄屏下列表和提交按钮可达。
- 外部账号显示“外部”标记；`external=null` 时不显示该标记。

### R7. 验收与观测

必须补齐 core、views、Go 服务/handler、真实数据库分页和至少一条 Web E2E；覆盖权限撤销/过期响应、重复姓名、空结果、分页边界、精确查找、成员属性限制、键盘操作和窄屏布局。上线前保留部署开关、查询错误日志脱敏和列表请求的基础耗时/错误观测。

## Acceptance Criteria

- [ ] AC1：三个入口均显示共享选择器，不再要求先输入完整标识才能浏览候选人。
- [ ] AC2：新建入口默认选中本人；自己、已选、最近、全部分组顺序稳定且不重复。
- [ ] AC3：空搜索分页稳定；可加载下一页，最大页大小和游标非法输入被拒绝。
- [ ] AC4：姓名子串搜索正确处理大小写、空白、`%`、`_` 和 `\`；不把邮箱/用户名/ID 当模糊搜索字段。
- [ ] AC5：最近协作按最近共同参与时间排序，最多五人，调用者本人不出现。
- [ ] AC6：目录开关开启/关闭时范围符合约定；关闭后仍可精确查找未列出账号。
- [ ] AC7：停用、待改密、缺密码凭据和应急停用账号在 SQL 分页前被排除，分页不会漏项或出现短页。
- [ ] AC8：非来源成员看不到来源成员关系；`external` 被正确裁剪；成员属性入口拒绝外部账号。
- [ ] AC9：agent/task 身份、失权、撤权和查询期间权限变化均被拒绝或安全清空，不产生写副作用。
- [ ] AC10：选择候选人不会自动授权、邀请、转交或发通知；实际提交继续使用现有幂等写流程。
- [ ] AC11：旧 Desktop 的精确 resolver 和已有草稿继续兼容。
- [ ] AC12：键盘、Escape、焦点、44px 触控目标、中英文和窄屏行为通过组件测试与浏览器验收。
- [ ] AC13：相关 Vitest、Go race/handler、typecheck/lint、真实数据库分页测试通过；已有无关失败被单独记录。

## Out of scope and deferred

- 本期不做常用联系人收藏、拼音首字母搜索、`pg_trgm` 索引；只有账号规模或 p95 超过约定阈值后另立任务。
- 重名脱敏标识先通过生产只读重名率查询决定，当前只显示姓名、头像和外部标记。
- 不新增自动授权、接收方接受状态、跨 Server 搜索或 Mobile 新界面。
- 不改变协作任务的处理人、资源授权、通知和执行语义。

## Risks and evidence

- 全局目录开启时，自助注册用户可看到可用账号姓名和头像；启动日志需要警告，部署可关闭目录。
- 真实数据库 handler 验收需要带完整迁移的隔离数据库，不能用未迁移的默认测试库代替。
- 结果正确性由自动化测试、数据库约束与分页查询、权限复核、独立检查、脱敏日志和浏览器可观察流程共同证明。

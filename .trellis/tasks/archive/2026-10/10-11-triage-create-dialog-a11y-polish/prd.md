# 优化待分拣任务创建弹窗

## Goal

让成员可以在桌面和触控窄屏上清楚理解、填写并提交待分拣任务；表单控件对键盘和屏幕阅读器可识别，校验错误能直接指导修正。

## Background

- 审计目标是 `packages/views/triage/triage-create-dialog.tsx` 对应的创建弹窗。
- 当前标题编辑器使用 placeholder 作为可见提示，但描述编辑器没有传入 `aria-label`；元数据字段由普通 `div` 标签包裹，多个 picker 的可访问名称只包含当前值。
- `candidate_project_id` 与 `candidate_assignee_id` 是待审核候选值，当前中文界面显示为“项目”和“执行负责人”，容易被理解为已正式关联。
- 创建按钮在标题为空时禁用，但没有持久的必填说明；日期顺序和原始链接格式由服务端校验，前端只展示一个全局错误。
- 弹窗整体滚动，底部操作区不固定；共享 Dialog 的关闭按钮没有本地化文案，当前触控命中区没有针对该弹窗显式放大。

## Requirements

- **A11Y-1 表单命名**：标题、描述、优先级、候选项目、候选执行负责人、标签、开始日期、截止日期和原始链接都必须拥有与可见标签一致的可访问名称；标题标记为必填。
- **COPY-1 候选语义**：创建弹窗显示“候选项目”和“候选执行负责人”，并保留“接受前不会正式关联或启动执行”的明确说明；接受流程中的正式字段保持现有文案。
- **VALID-1 字段校验**：客户端在提交前检查标题、HTTP/HTTPS 原始链接和开始/截止日期顺序；错误显示在对应字段附近并通过 `aria-invalid` / `aria-describedby` 暴露。服务端返回的已知 4xx 校验错误也映射到对应字段，未知错误仍保留全局可读提示。
- **LAYOUT-1 响应式操作**：弹窗主体可独立滚动，取消/创建操作在长内容和窄屏下始终可到达；创建弹窗关闭按钮在 coarse pointer 下有至少 44px 命中区，并使用当前语言的可访问名称。
- **DISCOVERY-1 交互可发现性**：元数据 picker 具有可见的控件边界、焦点状态或等价提示，不能只呈现为静态文本；附件入口保留图标按钮语义并补充必要的可见/辅助说明。
- **REGRESSION-1 兼容性**：不改变待分拣任务 API payload、候选字段的业务含义、重复提交保护、上传流程和正式接受流程。

## Acceptance Criteria

- [x] 空表单中，标题和描述都有持久可见标签；标题控件被读作必填，描述控件被读作“描述”。
- [x] 创建弹窗的项目和负责人字段在中英文中均明确为候选值；接受弹窗仍显示正式字段文案。
- [x] 空标题、非法 URL、非法日期顺序不会发起请求，并在对应字段下显示可操作错误；输入内容保留。
- [x] 已知服务端 4xx 校验错误不会只显示原始英文字符串，而会定位到对应字段；网络/未知错误仍显示全局 alert。
- [x] 所有元数据 picker 的触发器可通过键盘聚焦，具有字段上下文的 accessible name，并在视觉上与普通文本区分。
- [x] 窄屏或长描述滚动时，底部操作区仍可到达；触控设备关闭按钮命中区至少 44px，中文界面屏幕阅读器不会读到硬编码英文 Close。
- [x] 现有 triage、editor、UI 类型检查和相关测试通过；机械检测无新增 finding。

## Out of Scope

- 不重做整个分拣台视觉系统，不修改其他弹窗的布局。
- 不修改 Go API、数据库字段、待分拣准入规则或接受/执行流程。
- 不在本任务内完成完整真实设备、屏幕阅读器和深色主题验收；这些作为验证记录中的剩余风险。

## Open Questions

无。用户已确认按审计建议优化，并同意创建 Trellis 任务。

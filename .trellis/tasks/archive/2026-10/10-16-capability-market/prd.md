# 能力市场整合：MCP 与 Skill 市场独立入口

## 状态与授权

- 2026-10-16：用户要求探索和规划，将现有 MCP 市场和 Skill 市场提取到单独的“能力市场”菜单。
- 用户已同意创建任务、保存规划文档，并确认：**只整合市场，保留资源管理入口**。
- 用户已于本轮明确要求“请根据文档，继续推进开发”，批准按最终方案实施。

## 目标与价值

让用户从统一入口发现、预览和添加 MCP 与 skill，继续在熟悉的技能库和 MCP 页面管理已添加资源。

## 背景

两个市场目前都与资源管理页面组合，已有独立的目录查询和可复用的组件。Web 和 Desktop 共享业务页面。市场来源为平台内置和部署提供的模板。具体代码证据和约束见 [research.md](./research.md)。

## 产品要求

| ID | 要求 |
| --- | --- |
| R1 | 增加“能力市场”独立侧边栏入口。建议放在“资源与连接”分组，页内使用 MCP / Skills 两个标签页。 |
| R2 | 集中承载现有目录浏览、搜索、来源及分类筛选、预览和添加，保留平台内置与部署提供的内容。 |
| R3 | “技能库”和“MCP”继续管理已有资源；原市场区域移到新入口，管理页提供进入对应市场的操作。空库显示空态，不自动跳走。 |
| R4 | skill 模板创建为独立工作空间副本，成功后留在市场并提供打开副本的操作。普通新建、导入、编辑、详情继续由技能库承载。 |
| R5 | MCP 沿用填写配置、保存工作空间实例、显式分配给智能体的流程。可以仅保存，部分分配失败可重试。 |
| R6 | 保留智能体内的上下文 MCP 发现/配置弹窗，以及已有 skill 挂载入口；不增加创建后自动绑定智能体的行为。 |
| R7 | 使用当前工作空间及现有权限；不同能力的创建、管理、分配权限分别沿用已有规则。 |
| R8 | Web / Desktop 的入口、刷新、返回、工作空间切换和产品语义一致；支持中英文、窄屏和键盘。 |
| R9 | 保持加载、无结果、目录故障、模板撤下及已有资源未知状态的区别；继续保护草稿、敏感输入和创建恢复流程。 |

## 实施验收标准

以下标准均已按实际验证回填；单测、静态检查、production Web 和原生 Electron 的结果及限制见 [verification.md](./verification.md)。

- [x] AC1（R1、R8）：两端侧边栏和命令搜索可打开能力市场；类型可由 URL 恢复，刷新、前进后退及桌面标签正常。
- [x] AC2（R2）：两个目录保留来源、分类、搜索、预览和已有副本/实例关联；一个目录失败不阻止访问另一个。
- [x] AC3（R3）：原技能库、MCP 管理及详情链接可用；管理页不再嵌入独立市场 Tab，空库通过明确操作进入市场。
- [x] AC4（R4、R9）：市场创建 skill 后留页，提供打开副本的操作；普通创建/明确打开恢复结果仍进入详情；dirty / unknown-result 保护有效。
- [x] AC5（R5）：MCP 可仅保存并从管理页继续分配；部分失败只重试失败项，不重复创建实例，不自动启用已有 disabled 分配。
- [x] AC6（R6、R7）：管理员、普通成员、智能体所有者的权限与现有行为一致；上下文入口保留目标智能体及运行时信息。
- [x] AC7（R8）：工作空间切换不串用数据、筛选或草稿；中英文、窄屏、键盘和关闭弹窗后的焦点恢复通过验证。
- [x] AC8（R9）：首载失败可重试，刷新失败保留缓存，隐藏市场不持续轮询。MCP 模板修改需重新审阅、撤下禁止保存旧模板；Skill 预览模板撤下禁止采用，已采用的独立草稿仍可编辑，目录刷新不覆盖草稿。
- [x] AC9（R3、R8）：旧 libraryView 偏好不能将技能库重新变成市场；来源/分类偏好继续按工作空间保留。
- [x] AC10（R7、R9）：无需新增 API 或迁移；模板发布、实例身份、授权和凭据保护保持原契约。

## 决策与边界

已确认仅合并市场，原资源管理入口保留。建议一个入口加两个页内标签，保持工作空间作用域，复用现有领域组件。首期覆盖 Web / Desktop，Mobile 独立 UI 后续另立范围。

本期不包含：已安装管理整体迁移、通用能力实体/统一后端、外部市场接入、公开投稿/审核/付费/排行、插件/智能体/小队/自动化模板整合、新的自动绑定或连接探测、重写创建状态机。

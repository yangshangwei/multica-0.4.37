# MCP 市场部署提供目录

## Authorization

2026-10-04 用户在审阅本会话设计后要求“请新建一个 trellis任务推进”。实施范围以 design.md 为准；实施、测试及必要的可逆工作区操作已获授权。

## Outcome

部署管理员将 mcp.json 投放到 API 服务器 MULTICA_MCP_TEMPLATE_DIR/<key>/，Web/桌面端在 MCP 市场的“部署提供”发现模板，填写参数、保存工作空间配置，并明确分配给智能体。

## Acceptance

- [x] AC1. 已挂载目录中新建/更新/删除文件可通过列表请求发现，无需 API 重启；市场可见时 30 秒轮询且切换部署来源立即刷新。
- [x] AC2. 内置与部署来源按 source+key 区分，保存来源持久化；重命名保留、替换配置清空。
- [x] AC3. 部署内容生成稳定 SHA-256 版本；陈旧/撤下保存返回稳定 409；目录 IO/限额故障返回 503 并保留客户端缓存/草稿。
- [x] AC4. 文件数量/大小/深度受限；重复键、未知字段、非法路径、符号链接与特殊文件拒绝；坏条目不破坏其他模板。
- [x] AC5. 支持 stdio/HTTP 与受限 env/arg/header 输入映射；公开列表不包含部署 config/target/用户凭据。
- [x] AC6. 权限、只写摘要、明确保存与分配、旧实例不自动升级的现有规则保持。
- [x] AC7. 新旧客户端兼容；无来源能力的客户端不将部署实例关联成同 key 的内置实例。
- [x] AC8. 目录热更新在 Web 与 Electron 真实流程验收；不执行第三方 MCP 程序。
- [x] AC9. Go/TS 回归、类型检查、lint、静态检查及部署文档完成；记录基线问题和未测边界。

## Constraints

无新依赖、目录数据库、上传后台、运行时安装器或自动分配。复用现有 API、配置表、共享 views/core。当前工作区其他改动必须保持。

# 添加电脑弹窗设计记录

2026-10-11 · 已批准设计，进入功能实现

## 目标与视觉依据

使用场景是用户在 A 的桌面端添加 B 的执行能力。页面采用 impeccable 的 Operate 模式：让用户选对环境、复制正确命令、识别真实连接结果。

视觉依据是用户提供的现有弹窗，以及 `packages/ui/styles/tokens.css`、共享 Dialog/Tabs/Button 组件。本次是局部适配，不更换产品设计语言。保留单列、白色浮层、浅灰命令区和中性色按钮；警告用现有 warning 语义，成功用 success 语义。

## 阅读顺序与结构

1. 标题「添加电脑」；说明「选择目标电脑的系统，再到那台电脑上运行以下命令。」
2. 「目标电脑系统」分段选择：Windows / macOS / Linux。
3. 对应终端和环境提示。
4. 「1. 安装 Multica CLI」及命令、复制按钮。
5. 「2. 登录并连接电脑」及命令、复制按钮。
6. 中性的「等待电脑连接」状态。
7. 默认折叠的「没有浏览器或还没连接上？」。
8. 底部「关闭」；提示关闭弹窗不会停止已连接的电脑。

建议弹窗宽度约 640px，最大高度遵循当前 85vh 约束，内容区滚动，标题和页脚保持可用。图稿展示完整内容，不代表小屏窗口必须一次展示全部内容。

## 系统选择

推荐首次打开不预选系统，不用 A 的 user agent 推断 B。选择后显示两步命令，不增加「下一步」按钮。同一次打开中切换系统保留帮助展开状态，并清除旧命令的「已复制」反馈；关闭后重新打开回到未选状态。

| 目标系统 | 操作提示 | 安装脚本 |
| --- | --- | --- |
| Windows | 在目标电脑上打开 PowerShell。 | `install.ps1` |
| macOS | 在目标电脑上打开「终端」。 | `install.sh` |
| Linux | 在目标电脑上打开终端，或通过 SSH 连接。 | `install.sh` |

Windows 下补充「Agent 装在 WSL 中？请切换到 Linux，并在 WSL 内运行。」macOS/Linux 下提示使用已安装并登录 AI 编程工具的系统账号。是否使用可点击的「切换到 Linux」可在实现时沿用共享文本按钮；不需要另加第四个平台。

## 命令与复制

- 每个命令区顶部标注 PowerShell 或终端，右侧使用可见的「复制」文字与图标。
- 图稿中的 URL 换行是视觉软换行，不能把换行或额外空格写进 URL。实际 `setup` 复制为完整单行，避免依赖 Bash 或 PowerShell 的续行字符。
- 长 URL 优先在路径分隔处软换行，完整参数优先整体展示；极窄窗口可允许代码区水平滚动，不能挤出复制按钮或截断复制内容。
- 保留代码字体与禁用连字的现有规则，避免 `--` 等参数字符失真。
- 复制成功时当前按钮显示「已复制」约 1.5 秒；复制失败时保留选中文本的能力，提示「复制失败，请选中命令复制」。按下复制不会变成「安装中」或「连接中」。
- 公开网络使用仓库已有脚本。内网优先使用管理员提供的安装来源，不静默回退到 GitHub；不能通过把自定义命令中的 `.sh` 替换成 `.ps1` 来猜测 Windows 安装方式。
- 目标系统的内网安装来源缺失时，安装步骤显示「此系统的安装方式尚未配置」和现有 CLI 安装说明入口，不显示另一系统的命令。

## 地址待配置

截图中的 `http://localhost:18572`、`http://localhost:13492` 无法直接作为 B 访问 A 的地址。检测到 localhost、127.0.0.1 或 `::1` 等回环地址时，在第二步展示警告和当前 API/Web 地址，并提供「查看地址配置说明」。

该状态保留第一步，暂不展示可复制的 setup 命令，等待文案改为「配置可访问的服务地址后，即可获取连接命令」。帮助中的令牌路径也不能绕过该地址问题。

入口应复用现有自托管文档。弹窗不自动探测/猜测 A 的 IP，不修改部署配置，不新增无后端支持的「保存地址」按钮。通过 SSH 隧道有意使用回环地址是高级场景，交给文档说明；本提案针对截图中的普通跨电脑接入。

## 无浏览器与排查

帮助保持在原弹窗中展开，图稿单独绘制只是为方便阅读。展示：

1. 在当前电脑的「设置 → API 令牌」创建令牌。
2. 在目标电脑配置 API/Web 地址；两条非交互配置命令可以一起复制。
3. 单独复制 `multica login --token`，按终端提示粘贴令牌并等待登录成功。
4. 登录成功后再复制 `multica daemon start`。

排查命令保留 `multica daemon status` 和 `multica daemon logs -f`。不要在普通命令文本里插入真实令牌，也不要把启动命令排在同一次粘贴的交互式登录后面。

## 连接状态

| 状态 | 用户可见内容 | 行为 |
| --- | --- | --- |
| 未选择系统 | 三个系统选项及提示 | 暂不显示安装/连接命令 |
| 等待 | 中性时钟、「等待电脑连接」 | 监听真实接入；复制命令不改变连接状态 |
| 长时间未出现 | 「尚未检测到新电脑」及排查入口 | 不推断安装失败，不承诺固定完成时长 |
| 页面连接中断 | 「连接状态暂时无法更新」 | 提供恢复/重试，不能将页面断线等同于 B 离线 |
| 地址待配置 | warning 提示、地址和配置说明 | 不复制无效 setup 命令 |
| 成功 | 真实电脑名、实际系统、可用运行时 | 主操作「创建智能体」，次操作「查看电脑」 |

普通等待文案不再使用绿色圆点或「通常不到一分钟」。只有确认新接入电脑后进入成功态；现有电脑的普通重连不应被展示为本次新增成功。成功页展示实际识别的系统，不直接复用用户选择值作为设备事实。没有足够的确认数据时继续等待，不填造设备名。

## 可访问性与适配

- 系统选择复用共享组件的标准键盘语义；初始未选状态应使用支持空值的受控选择，不能视觉未选而语义已选。
- 选中状态同时由字重、文字颜色和底色表达，hover 后仍清晰可辨；保留焦点环。
- 复制按钮有包含用途的可访问名称，例如「复制 Windows 安装命令」。状态更新用温和的 live region；复制后不移动焦点。
- 模态内焦点约束、Esc 关闭、关闭后焦点归还触发按钮沿用共享 Dialog。
- 窄窗口保持三系统选择和单列流程；命令区可滚动，页脚帮助换行，不出现页面级横向溢出。触屏模式提供至少 44px 的点击区域。
- 跟随现有深浅色语义 token；本次浅色设计稿以用户截图为依据，不新建独立配色。
- 中英文文案通过现有 i18n 提供；不依赖固定中文字符长度实现排版。
- 动效只用于真实状态反馈，遵循 reduced-motion；等待状态不使用持续绿色闪烁。

初始阶段已完成静态设计。本轮用户明确批准「按现有设计推进功能实现」，以下设计为实现依据。

实现计划见 implement.md。静态检查不能替代真实剪贴板、辅助技术和三系统双机验收。

## 实现契约（2026-10-11）

- 配置新增可选 `cli_install_commands` 对象，键为 `windows` / `macos` / `linux`，值为完整命令。对应环境变量 `MULTICA_CLI_INSTALL_COMMAND_WINDOWS` / `_MACOS` / `_LINUX`。保留 `cli_install_command`，供旧客户端及 Unix 安装兼容；显式系统命令优先。
- 新 store 字段 `cliInstallCommands` 使用同样的键，缺省为空对象。schema 对非法值逐字段降级，不将网络响应强制转换为类型。重载配置需清空旧值。
- 只在完全没有自定义安装来源时使用公开默认脚本；只要存在任一自定义来源，缺少对应命令就显示缺失提示。旧单一命令只供 macOS/Linux 使用，不推测 Windows。
- Unix/PowerShell 的 URL 参数分别进行正确 shell 引用。URL 必须为可用 HTTP(S) 地址，不允许回环/通配主机、凭据或控制字符；自托管部分字段缺失不能悄悄转云端。
- 连接确认复用 workspace-scoped React Query 和现有 WS 状态。获取打开时的可靠电脑基线，按 daemon/machine 身份区分新增和已有电脑新增 provider，且只展示当前用户能确认的在线 local runtime。WS 通知仅触发刷新；成功事实来自 schema 解析后的查询结果。首次基线不完整时保持等待。
- UI 使用现有 Dialog、可空值系统选择控件及共享命令样式。成功详情复用 runtime machine 工具；不创建持久 store。
- Web/Desktop 已调用同一个弹窗，不新增路由。文档链接必须指向部署内可用的现有 reader。
- 部署转发清单、离线打包与说明中凡已有旧安装变量的地方同步新变量，避免配置写入但容器收不到。
- 回滚为撤销本功能相关代码和新增环境字段；无迁移或数据回滚。旧客户端忽略新响应字段。

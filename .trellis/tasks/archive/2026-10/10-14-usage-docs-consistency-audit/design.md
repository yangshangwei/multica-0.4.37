# 审计方法与修订设计

## 证据链

从当前嵌入包 manifest 确认用户能访问的页面，再对应 MDX 原文、共享前端入口/API 调用、Go handler/service/CLI/config 实现。代码是实际行为依据；测试用于佐证，不以旧任务设计替代代码。

## 分工

| 范围 | 页面数 | 负责者 |
| --- | --- | --- |
| 工作空间、成员、任务、分拣台、项目、迭代、评论、对话、收件箱、小队 | 12 | business 只读审计子代理 |
| 智能体、skills、触发、分配、执行、运行时、工具、自动化、CLI | 11 | runtime Trellis research 子代理 |
| 自托管、登录、令牌、平台后台、安全、配置、排障、桌面、Git 集成 | 9 | deployment Trellis research 子代理 |
| 欢迎、概念、工作原理、教程、三篇开发说明；包与链接校验 | 7 | 主会话 |

所有子代理共享当前工作区，只可写入各自研究文件。主会话复核高影响发现、去重并整合报告。

实际执行中，子代理发生调用限流，后备角色也遇到模型服务不可用。主会话接手其余核查并复核已有证据；最终结论不依赖失败子代理的完成状态。

## 判定标准

- 高：文档指引导致关键流程无法完成、错误管理权限或安全隔离认知、危险的运维操作。
- 中：在明确适用条件下产生错误结果、找不到所述入口、配置不生效或遗漏关键前提。
- 低：局部过时措辞、信息不足但存在明显替代路径。
- 证据不足：代码有多种分支或需运行环境才能判定时，不计入确认错误。

## 验证策略

- 使用临时目录运行现有 generator，对比当前嵌入包的文件和字节，避免覆盖用户的生成内容。
- 读取生成页面正文与 TOC，检查内部目标页、锚点、图片资源及产品持有的文档链接。
- 执行相关 Vitest 文档测试和无数据库的 Go 文档测试；不为只读审计运行无关全仓构建。
- 记录分支、提交和文档内容哈希；并行会话变化可能影响行号，最终汇总前重新确认引用。

## 边界与回退

无 API、数据结构、产品行为或部署变更，无迁移。输出仅位于本任务目录，删除这些输出即可撤销本次文档记录；不得重置现有工作区。

## 阶段 B：文档修订边界

现有差距是文档对产品的描述失真，实际行为位于审计已引用的前后端代码。保持这些实现，只修正说明与生成内容。原始审计和证据保留为阶段 A 的历史记录。

每组由一个原生 `trellis-implement` 子代理负责。子代理只改归属自己的源文件和组内修订记录，不启动其他代理、不生成共享文档包、不改任务状态。主会话整合后统一生成嵌入包，由独立 `trellis-check` 复核。

### 内容决策

- 明确 URL 导入只识别实现支持的来源，内网离线使用本地包导入；不虚构内网镜像 URL 可被解析。
- 区分分配/状态触发与评论触发，`@all` 与 `/note`，运行时离线显示与在途执行回收。
- 按设备、密码和邮箱认证模式描述登录与限流；将 HTTPS 安全建议与客户端实际连接条件分开。
- 区分普通托管目录、worktree 与 `local_directory/in_place`，准确描述目录级串行而非独立副本。
- 保留 API/CLI 标识符；中文界面入口和内置标签使用当前 locale。开发规范英文源仅同步这些相同契约。
- 教程截图若仍带旧导航，核对相关图片并在邻近正文标出当前入口，不伪称截图已更新。

### 验证与回退

修订前的源文档和引用代码哈希、生成文件哈希及工作区状态保存在 `research/remediation-baseline.json`。18 个预期 MDX 源文件在该时点均无既有未提交修改。整合时对比该基线，保留已存在的其他文档及生成内容。只撤销本轮明确拥有的修改即可回退，不使用整仓 reset。

先核对每项语义，再统一生成包，执行现有 docs 测试、docs typecheck/MDX 编译、Go docs 测试以及链接和字节一致性检查。不新增仅断言文案字符串的测试。数据库 Docs handler 测试在可用的隔离测试数据库运行，条件不足则明确记录。

复核补充：`project-resources.zh.mdx` 中同一 D13 串行承诺也需限定到非对话执行。该文件修订前无差异，补充哈希已加入基线，由 check 子代理按确认的源码契约修正。最终范围为 18 篇中文及英文规范，共 19 个 MDX。

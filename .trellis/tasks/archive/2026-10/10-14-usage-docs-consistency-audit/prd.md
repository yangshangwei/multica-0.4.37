# 使用说明与当前代码的一致性审计及修订

## 目标

回答应用内“使用说明”是否与当前代码一致，给出可追溯、可修订的审计结果，帮助维护者避免向用户提供失效的操作步骤或错误的权限、执行和部署说明。

## 已确认背景

- 用户原始要求：“请审计下 使用说明里的文档，是否和当前代码实现一致？”
- 用户已于 2026-10-14 同意创建任务并进入规划阶段。
- 应用内中文文档以 `apps/docs/content/docs/**/*.zh.mdx` 和 `meta.zh.json` 为来源，经 `scripts/generate-docs-bundle.mjs` 生成并嵌入 `server/internal/docs/content/`。
- 当前清单发布 39 篇中文文档；英文公开站文档不进入应用内文档包。
- 审计基于当前工作区（包括既有未提交修改），不以旧版本目录名称或已归档需求作为实际行为依据。

## 阶段 A：只读审计要求（已交付）

- R1：覆盖文档清单中的全部 39 页，对具体功能、操作步骤、权限、命令和配置项追踪当前实现。
- R2：每项确认的不一致必须同时提供文档原文位置和实现位置，说明影响与建议修改内容。
- R3：区分已确认错误、重要缺漏和未验证风险；不将文档未穷尽所有实现细节直接判为错误。
- R4：检查源文档与嵌入内容是否同步，检查目录、内部链接、锚点和引用资源是否可解析。
- R5：保留其他会话及用户的现有修改；本任务仅编写规划、研究及审计报告。

## 阶段 A 验收标准

- AC1（R1）：报告有逐页覆盖清单，并明确主要已核对行为及核查限制。
- AC2（R2、R3）：确认问题具有严重程度、文档位置、代码证据、用户影响和具体修订建议。
- AC3（R4）：保存文档包一致性、内部链接和适用文档测试的实际执行结果。
- AC4（R5）：没有修改业务代码、现有文档正文、生成包或他人的任务文件。
- AC5：最终回复直接回答是否一致，列出优先修订问题，并链接完整报告。

## 阶段 A 范围外

- 修复文档或产品实现、改变功能语义、提交/发布/部署。
- 全站视觉审计、截图重新制作、真实账号或外部 AI 服务执行。
- 英文公开文档站、发布产物和正在运行的服务器与当前代码之间的版本一致性证明。

若审计发现需要改变产品行为的选择，仅记录建议，另行确认修复范围。

## 阶段 B：文档修订

2026-10-14，用户要求“继续推进 /10-14-usage-docs-consistency-audit 这个任务”。在已完成审计的基础上，继续将 D01–D18 修订为与现有代码相符的说明。采用文档修订这一最小范围，不引入审计中尚未实现的产品能力。

### 要求

- R6：修复 D01–D18 对应的 17 篇中文文档，以及 D13 直接关联的 `project-resources` 页，说明可用操作、适用条件和重要副作用；不得通过修改业务实现来迎合旧文档。
- R7：中英文 `developers/conventions` 同为根 `CLAUDE.md` 指定的权威来源，同步修正其 API 字段、Query key 和状态/角色显示契约；不扩展为全站英文文档审计。
- R8：保留内网部署约束。内网地址可达不等于 URL 解析器支持；为不受支持的 URL 导入提供现有本地文件导入步骤。
- R9：重新生成中文嵌入包，保证目录、产品深链接、正文链接和资源可解析；保留其他任务已有的文档更新。
- R10：保留原始审计证据，新增逐项修订与验证记录，区分源码核对、自动检查和未执行的运行验证。

### 验收标准

- AC6（R6、R8）：18 项发现都有修订位置、当前实现依据和明确的关闭结论；优先关闭 D01–D04。
- AC7（R7）：中英文开发规范对数据字段、查询键及展示标签不再相互矛盾，且与现有实现一致。
- AC8（R9）：生成包与当前中文源逐字节一致，39 页保持可达，内部链接/锚点/图片和产品深链接验证通过。
- AC9（R9、R10）：文档测试、适用的类型检查、MDX 编译及 Go 嵌入包测试通过；记录没有独立 docs lint 的情况和其他检查限制。
- AC10（R10）：本轮修改仅包含上述 MDX、对应嵌入包、本任务记录和直接相关的 docs spec；其他会话改动完整保留。

### 范围外

业务代码/API/数据库/权限/执行策略变更、增加任意内网 URL 导入能力、新依赖、全站英文修订、重新制作截图、真实 AI 调用、发布或部署。原始审计不回写为“当时无问题”；修订结果单独记录。

补充范围说明：修订 D13 时确认对话执行会跳过原地目录锁，而其链接的项目资源页仍将串行规则用于全部执行。因此同步修正这一页的适用条件，仍不改变运行策略。

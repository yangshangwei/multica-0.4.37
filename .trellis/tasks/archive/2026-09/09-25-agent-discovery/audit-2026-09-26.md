## Additional defects found and repaired

### Role metadata failure produced false results (P2)

A failed initial template request was treated as an empty catalog. Persisted
specialist/coordinator filters could report no matches; Other could include real
template agents, and role/squad-name searches could report false empty results.

The repair distinguishes unavailable metadata from usable cached data. It keeps
unfiltered saved agents available, temporarily suppresses untrustworthy grouping
and role counts, gates dependent filter results and selection, retains All roles
and the squad picker, and retries without rewriting user preferences. Existing
cached catalogs remain usable during a failed background refresh.

Files: `packages/views/agents/components/agents-page.tsx`,
`agent-discovery-toolbar.tsx`, and `agents-page.test.tsx` in the same directory.

### Gallery restoration used an obsolete card-click position (P2)

The custom gallery view-state overrode newer platform scroll capture after a user
returned from a template, scrolled elsewhere, then left through sidebar/tab
navigation. It now records actual gallery scrolling, including zero, and ignores
loading/error layout events until restoration and content are ready.

Files: `packages/views/agents/create/template-create-agent-page.tsx` and its test.

Seven new regression cases failed on the prior implementation and passed after
repair. A loading-layout scroll event also exposed an overwrite before the guard
was added; that regression passes. The final independent review found no blocking
issues in the repairs.

The changes reuse existing query, filter, navigation, and view-state mechanisms.
No dependencies, data migrations, new state stores, or alternate navigation paths
were introduced. The localized test fix changes only the two-step menu entry.

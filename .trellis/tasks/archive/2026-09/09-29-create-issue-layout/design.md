# 新建任务弹窗布局优化方案

状态：方案待评审；不包含本轮代码实施。
目标：用户能快速确认 AI 回填结果、补充关键事实、创建可执行任务。
范围：Web / Desktop 共享手动与智能体创建弹窗；沿用现有颜色、字体、组件和数据契约。

## 已核对的现状
- packages/views/modals/create-issue.tsx:1433：手动模式默认 h-96（384px），展开后 h-5/6。
- packages/views/modals/create-issue.tsx:947：正文和 AI 区域共用纵向滚动容器。
- packages/views/modals/create-issue.tsx:1384：底部操作已在滚动容器外，shrink-0；无需另加 fixed 定位。
- packages/views/modals/quick-create-issue.tsx:692：智能体正文有 140px 最小高度，底部同样独立布局。
- packages/views/modals/create-issue-dialog.tsx:159：智能体默认上限 80dvh；两模式尺寸规则不一致。
- packages/views/editor/content-editor.tsx:997：编辑器容器带 min-h-full；调整必须限定创建场景，避免影响聊天和详情编辑。
- packages/views/modals/issue-description-assist.tsx：问题使用两行输入框、独立委托按钮和状态段落，尚无折叠；合并后问题消失。

## 推荐方案：单列正文 + 紧凑补问 + 独立底栏
保留单列阅读顺序。双栏虽能同时展示正文与问题，但会压窄 Markdown 且增加窄屏适配成本；另开补问弹窗会打断输入，均不采用。

1. 顶部：保留创建模式、关闭、展开；手动模式保留标题输入，不强迫智能体模式补标题。
2. 中间：正文为第一视觉区域，AI 工具条紧接正文，必要时显示补问。只有中间区域随内容滚动。
3. 属性：复用现有属性行；核心选择可见，低频项沿用已有更多菜单，避免重复建设。
4. 底部：保留现有独立底栏和移动端换行，创建为唯一主按钮，附件、切换模式、连续创建为次级操作。

## 尺寸建议（待完整弹窗截图校准）
- 桌面常规宽度沿用约 672px；简单输入初始高度约 440px。
- 出现补问或流式预览时，弹窗允许一次扩展到约 600px，上限 85dvh；不随每个 token / 输入字符反复改变高度。
- 保留手动展开；用户手动展开后不因状态变化自动收缩。
- 正文初始可见区域约 140–180px；短视口以所有关键操作可达为先，不强制最小高度导致溢出。
- <640px 宽度保持两侧 12px 留白，以动态视口限制高度；触屏按钮可点区域至少 44px。
- 普通正文及问题使用同一滚动区；输入框超出合理行数后才允许内部滚动。

## AI 工具条
- 默认「帮我完善」，辅助说明「生成后直接替换，可撤销」。
- 生成中「正在完善… / 取消」，流式内容只预览，不进入正文；预览限高，避免逐 token 撑开页面。
- 完成有问题：「已完善 / 撤销」，下方展开「补充关键信息 · 2」。
- 完成无问题：「已完善，可创建 / 撤销」，不出现空问题卡片。
- 输入再次修改后改为中性状态，避免继续声称新内容已由 AI 检查。
- 错误、内容已变化和上传冲突仍就地说明，保留原文和现有防覆盖机制。

## 紧凑补问
- 每轮最多两题。题目为真实 label，输入默认一行（多行 textarea 自动增高，约四行后内部滚动）。
- 每题旁提供「由执行者判断」次级操作；窄屏换到下一行，不挤压题目和输入宽度。
- 标题可折叠/展开，aria-expanded；折叠时显示未补充数量，已输入答案不丢失。
- 「补入正文」为次级按钮；无答案时禁用。只合并已回答项，剩余问题保留。
- 全部合并后收起表单并提示「已补充 2 项信息 · 撤销」。正文中的内容继续直接编辑。
- 撤销合并恢复原正文、问题和已填答案；再次合并不重复。
- 始终允许跳过补问直接创建，不新增评分、合格徽章或强制门槛。

## 焦点与滚动
- 自动回填后让正文起始处可见；仅当焦点仍在 AI 操作区时将焦点返回编辑器。用户已转去标题/属性/底栏时不抢焦点。
- 补问不自动抢焦点，按 Tab 顺序自然进入。
- 补入正文后定位新增内容，保留撤销入口；折叠收起不改变正文光标。
- 减少动态动画；尊重 prefers-reduced-motion。

## 验收标准
- 手动/智能体两模式在 1440×900、1280×720、390×844、375×667 下均无横向溢出。
- 两道普通长度问题展开时，桌面 720px 高视口仍能看到正文首段、问题入口及创建按钮。
- 底栏不随正文滚动；长正文、附件、长问题不会遮挡创建或关闭入口。
- 动态视口缩小时，所有控件仍能通过滚动/键盘访问；真实软键盘另需设备验证。
- 折叠/展开不丢答案；合并、撤销、再次合并无重复；新编辑不被异步输出覆盖。
- 流式生成不写入草稿，取消/失败不丢原文；生成中仍可按现有规则创建。
- 用户在其他字段输入时 AI 完成不抢焦点；有 label、可见 focus 和状态播报。
- 运行相关 Vitest、views typecheck、作用文件 ESLint、git diff --check；视觉验证必须使用完整创建弹窗，不把独立组件结果当作完整弹窗证据。

## 风险与控制
- 增高导致位置跳动：只在阶段切换时扩展一次，保留用户展开状态。
- 编辑器最小高度影响其他页面：限定创建场景，不全局修改编辑器默认行为。
- 收起掩盖尚未合并的答案：显示未补充数量并保留表单状态，不自动提交。
- 范围扩张：本期不改 API、AI 提问策略、移动端原生界面或任务创建业务规则。

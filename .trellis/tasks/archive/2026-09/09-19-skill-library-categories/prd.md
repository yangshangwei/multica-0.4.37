# 技能库分类、图标与卡片视图

## Goal

技能数量增长后，技能库页面仍能按分类快速浏览和汇总；每个技能有一个与分类呼应的图标，页面在视觉上接近参考产品的「左侧分类导航 + 图标卡片网格」效果，同时完整保留现有列表视图与批量操作能力。

## Background

- 当前技能库是一个虚拟化表格（名称 / 使用者 / 来源 / 创建者 / 更新时间 / 创建时间），只有搜索、来源等筛选和排序，没有分类维度。
- 技能数据模型只有 `name`、`description`、`config`（JSONB），没有分类、标签、图标字段。
- 全站技能实体统一使用一个 `SkillIcon`，是为避免图标漂移而刻意收敛的；本任务要在保持「技能实体图标」概念不变的前提下，为「单个技能」引入可区分的展示图标。

## Decisions (confirmed with user)

1. 分类采用**固定分类集 + 工作区标签**：每个技能归属一个预置分类；标签复用现有工作区标签系统（`resource_type = skill` 作用域），不再引入自由文本标签。（2026-09-19 变更：原方案的自由标签与现有「标签」系统冲突，用户决定改用现有工作区标签。）
2. 图标采用**分类默认图标 + 可选 Lucide 覆盖**：技能未设置图标时使用分类图标；可从一份精选 Lucide 白名单中挑选覆盖；颜色始终跟分类走。
3. 布局采用**左侧分类栏 + 卡片/列表可切换**：现有列表视图完整保留，新增卡片视图；视图模式持久化。
4. 分类与图标存储在 `skill.config.presentation`，不新增数据库列；标签关系走现有 `skill_to_label` 表。

## Requirements

### R1 分类集

- 固定 6 个分类，key 为稳定英文标识，显示名走 i18n（zh-Hans / en / ja / ko）：
  `research`（研究分析）、`writing`（写作沟通）、`engineering`（编程开发）、`operations`（运维发布）、`data`（数据处理）、`other`（其他）。
- 未设置分类或分类值非法的技能一律视为 `other`。存量技能不做自动归类。
- 8 个内置角色技能模板各自预设分类；投放到工作区时写入 config。

### R2 图标

- 每个分类有一个默认 Lucide 图标和一个语义色（使用设计 token，不写死颜色）。
- 技能可在精选白名单（约 40 个 Lucide 图标）中选择覆盖图标；白名单外的值视为未设置。
- 图标形状可覆盖，颜色不可覆盖，始终由分类决定。
- 内置角色技能模板各自预设图标。

### R3 标签

- 技能标签就是设置页「标签」中 `skill` 作用域的工作区标签；不新增自由文本标签，`config.presentation` 不存标签。
- 技能列表接口内嵌每个技能已挂接的标签（id / 名称 / 颜色），前端不得逐技能拉取。
- 卡片与列表用现有 `LabelChip` 展示标签，颜色随标签本身。
- 标签名参与搜索匹配；工具栏筛选新增「标签」维度，与其他维度求交。
- 工作区尚无 skill 标签时，选择器显示现有的「请先在设置中创建标签」提示。

### R4 数据存储与校验

- 存储位置：`skill.config.presentation = { category?: string, icon?: string }`。
- 服务端在创建、更新、导入（含模板投放）路径对 `config.presentation` 做白名单校验：分类必须在枚举内、图标必须在白名单内；不合法则返回 400，说明具体字段。
- 新建技能请求可带 `label_ids`；服务端在创建事务内校验每个 id 属于当前工作区且作用域为 `skill`，否则 400；校验通过则与创建原子挂接。
- 前端解析必须容错：字段缺失、类型错误、值非法均回退到默认值，不能让列表崩溃。
- 导入的 SKILL.md 若在 frontmatter 的 `metadata` 中带有 `category` / `icon`，导入时作为种子写入 `config.presentation`（仅当请求未显式提供时）；frontmatter 不是存储真源。frontmatter 的 `tags` 不再读取。
- 导出 zip 时 `config.presentation` 随现有 config 一起导出，无需额外处理。

### R5 页面布局

- 容器宽度 ≥ `@2xl`：左侧固定分类栏，包含「全部」和 6 个分类（各带计数），下方「来源」二级组复用现有来源筛选（点击等价于切换该来源筛选项）。
- 容器宽度 < `@2xl`：左栏折叠为顶部横向可滚动分类 chips。
- 工具栏保留搜索、筛选、排序、列设置，新增「卡片 / 列表」视图切换。
- 分类作为筛选的新维度 `categories[]`，与其他筛选维度求交；「清除筛选」同时清除分类。
- 视图模式与筛选状态持久化到现有技能视图 store（按工作区隔离）。

### R6 卡片视图

- 卡片内容：分类色底图标、名称、最多两行描述、标签 chips（超出折叠为 +N）、使用该技能的智能体头像叠放与数量、来源小图标、锁定/只读状态标识（沿用列表语义）。
- 卡片 hover / 聚焦时显示操作菜单，复用现有行操作组件。
- 卡片可勾选，支持现有批量操作。
- 卡片网格虚拟化，几百个技能时滚动流畅。
- 点击卡片进入技能详情，行为与列表行一致（支持 Cmd/Ctrl 点击新开）。

### R7 列表视图

- 名称列前显示彩色图标。
- 新增可隐藏列「分类」「标签」，默认显示「分类」、隐藏「标签」。
- 其他行为不变。

### R8 编辑入口

- 新建技能对话框：新增分类（默认「其他」）、图标两个字段，以及工作区标签选择器（草稿模式，随创建请求一并提交）。
- 技能详情页：可编辑分类、图标；标签沿用已有的 `ResourceLabelPicker` 行；头部显示大图标。
- 批量工具栏：新增「设置分类」，对选中技能批量写入分类（保留各自的图标；标签关系不受影响）。
- 无编辑权限的技能这些字段只读。

### R9 空状态

- 某分类下无技能时，显示该分类的空状态提示，并提供「新建技能」入口（预填该分类）。

## Constraints

- 不新增数据库列或迁移。
- 不做工作区自定义分类、自动归类、上传图片图标。
- 不改动 `apps/mobile/`。
- `packages/views` 不引入 `next/*` 或 `react-router-dom`；导航走 `useNavigation()` / `<AppLink>`。
- 颜色与字号只用 `packages/ui/styles/tokens.css` 中的语义 token。
- 全站「技能实体图标」`SkillIcon` 的用途和使用点不变。
- 图标白名单以显式命名导入方式引用，不得整体导入 `lucide-react`。

## Acceptance Criteria

- [ ] 分类枚举、图标白名单、`config.presentation` 解析器有单元测试，覆盖缺字段、错类型、非法值回退。
- [ ] 服务端对非法 `config.presentation` 返回 400，合法值原样落库；有表驱动测试。
- [ ] 内置角色技能模板投放后，落库 config 带有预设分类与图标。
- [ ] 导入含 `metadata.category/icon` 的 SKILL.md 后，config.presentation 被种子填充。
- [ ] 技能列表响应内嵌 `labels`；创建请求带非法 `label_ids` 返回 400，合法时创建后已挂接。
- [ ] 技能库页面在宽容器显示左侧分类栏并带正确计数，点击分类只显示该分类技能；窄容器显示顶部 chips。
- [ ] 卡片 / 列表切换后刷新页面仍保持所选视图；切换工作区互不影响。
- [ ] 卡片视图显示图标、名称、描述、标签、智能体头像、来源，支持勾选与批量操作，操作菜单与列表一致。
- [ ] 列表视图名称列前显示图标，新增「分类」「标签」列可显示/隐藏。
- [ ] 新建对话框可设置分类/图标并选工作区标签，详情页可设置分类/图标并持久化；批量「设置分类」生效。
- [ ] 工具栏「标签」筛选与搜索按标签名匹配生效。
- [ ] 分类空状态显示且「新建」入口预填分类。
- [ ] 四种语言的 `skills.json` 新增文案完整，`parity.test.ts` 通过。
- [ ] `pnpm typecheck`、`pnpm test`（views/core 相关）、`make test`（handler 相关）通过。

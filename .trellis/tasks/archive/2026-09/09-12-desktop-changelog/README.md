# 桌面端变更说明与自动发版日志

目标：用户在左侧“帮助 → 变更说明”中了解 Multica 的更新。新客户端首次打开即可读取本部署的记录；已经打开的页面也会自动检查后续发布，无需为了更新说明重新安装客户端。

## 产品行为

- 帮助菜单中的“变更说明”打开应用内页面，按版本、日期和“新功能 / 改进 / 修复”阅读。
- 官方 `v0.4.37` 说明标注来源；本地已提交增强标为“未发布”，不把导入的上游标签当作本分支发布。
- 当前客户端版本、服务端版本和最新稳定版本分别显示。
- 打开页面时每 60 秒检查；重开、恢复焦点、重连和手动刷新也会检查。
- 读取失败时保留已加载记录并提示；恢复后继续更新。

## 发版机制

提交记录和上一份累计历史生成 JSON 与 Markdown。CI 在构建前生成一次，成功后发布同一份产物。发布前还会核对当前历史，防止旧任务重跑覆盖新记录。

内网通过现有交付方式接收产物，再原子更新服务端的日志文件。客户端只访问本部署，不依赖官网或 GitHub。离线安装器复用已导入的前端镜像执行发布，目标机无需额外安装 Node。

实际操作见 [发版说明](../../../../../.github/RELEASING.md)、[自托管说明](../../../../../SELF_HOSTING.md) 和 [离线升级指南](../../../../../docs/offline-upgrade.zh-CN.md)。创建真实生产版本、推送标签和生产部署不属于本次实现操作。

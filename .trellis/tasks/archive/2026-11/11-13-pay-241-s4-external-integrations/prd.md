# S4 外部系统集成验收

## 目标

以真实支付沙箱、代码仓库/PR/CI和非生产发布/回滚环境证明PAY-241闭环。配置不足时先完成独立研究与接入准备，保留NOT_RUN/缺陷，不用本地模型替代真实交易或流水线。

## 已知事实与边界

用户已授权本阶段开发、测试与本地提交。当前未提供支付沙箱及发布/回滚目标；根环境GitHub App字段为空，未发现支付/发布键。此结论只是已检查配置的可用性，不推断所有加密连接或账号不存在。现有GitHub/GitLab读取和签名回调应复用；Git物料发布、需求合并与D8编排仍由原规划任务负责。

## 验收要求

- [ ] E01 / TC06/07/08：真实仓库、分支、PR、head、CI检查集合和制品互相对应；重投/旧head/撤换连接不复活旧批准。
- [ ] E02 / TC09：沙箱正常支付最终订单为已支付，记录环境版本、支付/订单/履约身份及观察结果。
- [ ] E03 / TC10：同一回调投递3次，仅一次扣款、订单有效更新和履约；分别查询各域权威账本。
- [ ] E04 / TC11：真实45秒延迟、先超时后成功、乱序与消费失败恢复；失败与补偿历史保留。不能采用模拟时钟作为真实延迟证据。
- [ ] E05 / TC17：QA越权发布被拒绝且留痕；批准绑定真实代码/构建/目标环境，执行前重新核权。
- [ ] E06 / TC18：真实异常指标产生回滚建议，经人工确认后仅执行批准的目标，记录实际回滚与核对结果。
- [ ] E07 / TC19/20：实际发布/回滚、验证、当前有效人工决定与精确交付关联；未知或未执行不能显示成功。
- [ ] E08：独立检查通过并保留真实来源证据后才关闭本阶段；缺配置/授权/失败继续开放。

## 授权范围

本轮不授权生产发布、真实资金操作或真实模型账号调用。测试账号签字标明模拟人工；正式业务签字由指定人员在真实环境完成。真实支付系统接口/目标不是本仓库内新增电商业务的授权。

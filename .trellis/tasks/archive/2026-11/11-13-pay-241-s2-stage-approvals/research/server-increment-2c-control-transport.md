# S2 2c test-only JSONL transport

Frozen mechanical handoff, 2026-11-14. This supplements the internal source/control contract. It is not a public HTTP API or production simulation option. The coordinator owns the long-lived harness and its private Unix-socket bridge; E2E only sends requests through that bridge.

The test executable writes one ready line prefixed `COLLABORATION_STAGE_READY ` with JSON `{version:1, api_url, pid}`. Every subsequent machine reply is prefixed `COLLABORATION_STAGE_REPLY `; ordinary test logs are not protocol messages. Input is one bounded JSON object per line (maximum64KiB), with duplicate/unknown fields rejected by a closed per-action decoder. Request and server-owned object IDs are canonical UUIDs; versions are canonical positive decimal strings. Native IDs are nonempty strings up to256UTF-8 bytes, not UUIDs.

Request envelope is flat: `{request_id:<UUID>, action:<name>, ...action fields}`. Reply echoes `{request_id, ok:true, result:{...}, calls:{count:<nonnegative integer>, last:<safe invocation|null>}}`, or `{request_id, ok:false, code:<content-free code>, calls:{...}}`. `last` contains only `intent_id`, `kind`, `target_digest`, `artifact_digest`, `external_request_key`, and `conditional_version`. It never contains source proof bytes, credentials or private target-source configuration. The invocation count counts actual entry into the controlled adapter, not an authenticated result lookup.

The outer `request_id` is the production original execution request ID for prepare/receipt. A bridge must therefore correlate each pending send and allow later re-use of an already-completed ID for exact historical receipt. It must never generate a replacement key, replay prepare after an uncertain reply, or translate a disconnected pipe into success. Repeated receipt calls have no adapter invocation. Other actions use independent transport IDs.

`source.configure` verifies the two distinct real database integration rows, workspace and current trust generations before installing the controlled fixture. They are synthetic source configuration, never seeded human approvals, deployment facts or metrics. The code PR integration is independently configured. Root/E2E fixture setup owns those source configuration rows; no real credentials are required. The harness supports the current repository's `github_installation` identity/trust table for these **two distinct controlled source identities** and does not interpret a GitHub PR proof as execution or metric evidence.

Changing source configuration changes the reviewed target digest but does not change the physical concurrency identity when remote instance/tenant/target remain the same. An unresolved old intent still blocks a new binding. Successful controlled execution changes its conditional version and current artifact; the reviewed configuration digest excludes those evolving target-state fields. Rollback uses the exact recorded predecessor and original deployment's conditional after-state.

`source.behavior=not_started` supplies authenticated controlled-source proof of zero external execution after adapter entry; its calls counter may be1. The production service's pre-entry cancellation/expiry zero-call branch is separately covered by Go tests and must not be confused with this provider result. `execution.observe` and `metrics.observe` first create authenticated captures inside the private controlled source and then call production Record methods. They never insert execution or metric ledger rows directly. Their supplied results are synthetic test-source behavior, not caller-asserted facts on a public endpoint.

The harness test is `TestCollaborationStageExecutionHarness`, admitted only with the test binary's `MULTICA_TEST_STAGE_HARNESS=1`. Root supplies its dedicated database, private HOME/TMP, mail/real-integration disabling environment and artifact staging/output paths. E2E reads only `COLLABORATION_STAGE_CONTROL_SOCKET`, which points into the coordinator's private0700 directory and0600 socket. Public A7/A8/A9 remain ordinary authenticated routes, and source build creation/human artifact approval/local packaging use the existing actual artifact API. Policy enabling still waits for2d.

## Coordinator-owned startup and listener supplement

The long-lived test harness honors the existing `PORT` environment variable only when `MULTICA_TEST_STAGE_HARNESS=1`: it binds exactly `127.0.0.1:<PORT>` and refuses an invalid or occupied port. `ready.api_url` reports this listener and `ready.pid` remains the test binary's actual PID. This lets root finish API-address-bound production Web/Desktop builds before starting the harness. Normal Go fixture tests still use fresh ephemeral loopback listeners.

Root compiles the dedicated current-source `./cmd/server` test binary first, then runs that binary directly with `-test.run '^TestCollaborationStageExecutionHarness$' -test.timeout=0` and the recorded private environment/stdio bridge. Disabling the Go test process's aggregate timer is specific to this intentionally persistent API harness, whose lifecycle belongs to the coordinator's `shutdown`/owned-process cleanup. It does not change any E2E case timeout, the Host Provider budgets, runtime freshness, the30-second callback-entry horizon or the5-second finalization deadline. Root must retain the original scenario denominator and stop the listener/background workers after the cases, including failure paths. The separate default TestMain listener is closed on test-process exit.

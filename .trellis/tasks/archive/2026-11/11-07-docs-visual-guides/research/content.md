# 文档图示内容与语义边界

核查基准：2026-11-07 当前工作区中文文档、源码，以及 `docs/audits/2026-11-07-user-docs-coverage.zh-CN.md`。仅内容调研，不构成运行时验收。

建议首批覆盖 **10 页、12 张图**：多数页面一图，协作与架构各两图。图紧邻解释它的正文；已有位图/ASCII 架构图直接替换，避免重复。文档首页、统计和权限表暂不额外堆图。

## 页面与图示清单

### 1. concepts.zh.mdx：核心对象关系

- 位置：替换开头 `concepts-core-objects.webp` 关系位图。
- 类型：对象关系图，回答“这些名词分别是什么”。
- 节点：工作空间 → 任务；项目 → 任务（可选组织）；任务 → 多次执行；智能体配置 → 执行；skill → 智能体；执行 → 运行时。
- 边界：项目不是任务必需归属；触发可能合并；协作空间是账号入口，不是第二个存储空间。跨空间权限边界留正文解释，不塞进大图。

### 2. how-multica-works.zh.mdx：一次执行的完整链路

- 位置：替换“一次执行的完整链路”下的旧流程位图。
- 类型：四泳道时序图，回答“点击分配后发生什么”。
- 参与者：用户、服务端、守护进程、AI 编程工具。
- 顺序：用户分配/提及 → 服务端检查并入队 → 唤醒守护进程 → 守护进程领取 → 准备并启动工具 → 进度与结果上报 → 用户收到实时更新。
- 边界：WS 用于唤醒与事件，不把领取/上报一概画成只经过 WS；task 完成不直接连到业务任务“已完成”。

### 3. developers/architecture.zh.mdx：部署与代码分层

本页两图，替换既有 ASCII 图，不改变正文技术层级。

- 部署图位置：页首。
- 节点：Web/Desktop/Mobile/CLI → Go API；Go API ↔ PostgreSQL；实时客户端 ↔ realtime WS；守护进程 ↔ daemon HTTP/WS；守护进程 → provider → 本机目录。
- 边界：PostgreSQL 是业务权威；CLI 不一概使用实时 WS；本地目录不是系统沙箱；Redis 只作可选侧注。
- 依赖图位置：“Web 与 Desktop 的代码共享”。
- 节点：Web 平台适配、Desktop 平台适配 → views → core 与 ui；Mobile 虚线连接 core，标注“仅类型/纯函数”。
- 边界：core 与 ui 互不依赖；Mobile 不复用共享 React 页面；不要画反向依赖。短 backend pipeline 保留文字即可。

### 4. tasks.zh.mdx：执行状态

- 位置：“执行过程”表格前。
- 类型：状态流转简图，回答“卡在哪一步”。
- 主线：可选 deferred → queued → dispatched → running → completed。
- 分支：dispatched → waiting_local_directory → running；失败/取消作为侧支；失败后的重试指向“新 task”。
- 边界：等待目录不是必经步骤，也不回到 dispatched；重试不覆盖旧记录；排队不等于离线失败；不要画业务 issue 状态同步变化。所有细节超时仍在既有表格中。

### 5. collaboration.zh.mdx：人工交付与共享 AI

本页两图，人工责任流转与 AI 授权分开。

- 人工流程位置：“处理、转交与补充信息”前。
- 节点：发起 → 当前处理人 → 处理；请求补充信息 ↔ 返回信息；提交结果 → 发起人验收 → 完成；退回修改 → 指定修改接收人。
- 边界：待验收不能随意转交；发起人兼处理人可“记录结果并完成”，用图下注释表达；AI 成功不替代验收。
- AI 流程位置：“配置共享 AI 资源”。
- 节点：邀请资源拥有者 → 添加/提供并采纳资源 → 各拥有者授权 → 显式恢复 → 提及与发送预览 → 确认发送 → 查看执行。
- 边界：采纳不等于授权，授权不等于恢复；普通评论不一定是 AI 指令；重新授权/切换配置不自动恢复。

### 6. collaboration-knowledge.zh.mdx：知识形成与运行使用

- 位置：“提出知识候选”前。
- 类型：形成与使用流程图，回答“哪些结论会进入下一次执行”。
- 节点：指定来源版本（上下文/评论/运行）→ 候选 → 有权人员审阅 → 已确认贡献 → 本次使用条件检查 → 可用于本次执行；不满足条件 → 不提供。
- 边界：确认不是验证真实性或已注入；启用开关、来源权限、有效期、provider/模式都属于使用检查；撤回/到期影响以后使用，不抹除历史。

### 7. squads.zh.mdx：队长协调

- 位置：“分配后的执行流程”。
- 类型：队长协调流程图，回答“谁先运行、结果怎样回来”。
- 节点：分配给小队 → 队长领取 → 选择成员 → 派活并逐目标检查回执 → 成员执行 → 结果评论 → 按路由条件回流 → 队长评估/提交审核。
- 边界：一次分配先启动队长，不同时启动所有成员；回执受理不代表开始；受限审查员不自动唤醒队长；in_review 不关闭子任务阶段屏障。图下注释说明例外，不把整张路由规则表塞进图。

### 8. mcp.zh.mdx：从配置到使用

- 位置：“从模板添加”。
- 类型：双入口汇合的操作流程图，回答“怎么从模板得到可用工具”。
- 节点：模板选择 / 自定义添加 → 填写并保存到 MCP 库 → 显式分配 → 启用绑定 → 运行时环境和 provider 满足要求 → 后续执行使用。
- 边界：保存不会安装程序/登录服务；分配不改变智能体 Access；部分失败只重试失败项；同名覆盖留既有文字，不再增加图。

### 9. triage.zh.mdx：接纳与执行选择

- 位置：“接受、项目、迭代和执行”。
- 类型：决策流程图，回答“审核之后是否马上运行”。
- 节点：手动投递/CSV → 待分拣 → 人工审核；拒绝/重复/稍后处理为支路；接受 → 正式任务；接受并执行 → 正式任务 + 明确执行确认 → 尝试入队。
- 边界：普通接受即使选智能体也不启动；过去的提及不补跑；分拣责任人与执行负责人不同；执行失败不撤销已接受事实。

### 10. iterations.zh.mdx：结束与交接

- 位置：“结束与安排下一期”前。
- 类型：生命周期与任务去向图，回答“结束一期后任务去哪”。
- 节点：计划 → 预览并开始 → 进行中 → 选择去向并预览 → 确认结束 → 历史快照；未完成 → 计划中的下一期 / 无迭代；已完成和已取消 → 仅保留本期快照。
- 边界：操作须显式确认；普通结束不启动下一期；“结束并开始下一期”另作标注支路；不改任务状态、不停止执行、不允许重开已关闭迭代。

## 视觉与内容约束

- 使用现有文档字体与语义颜色，中性背景、主路径强调色、少量状态色，避免每节点不同颜色。
- 主流程控制在 6–9 个主节点，节点使用短动作/对象标签；条件写在线上，细则放图下注释。
- 操作图优先纵向或紧凑分支；架构用分组边界；完整时序图只在执行原理页使用。避免过宽图缩成难读小字。
- 图前一句话说明阅读目的，图后一两句指出边界；保留既有步骤列表，图是概览而不是唯一说明。
- 验证中文字体、箭头交叉、深浅主题、窄窗口和放大阅读。默认显示图，不默认展示 Mermaid 源码。

# 发布设计

冻结单一源码提交：先验证修复合并，再从 origin/main 创建受管 worktree。版本和发布文档修改独立提交，最终以该 SHA 构建全部构件和标签；审计历史基线和最终源码差异。

三条独立研究线负责 SQL、配置与服务端离线交付、桌面/下载服务，主会话负责集成、顺序与发布。研究只写本任务 research。正式构建仅一个执行者，避免资源争用。

发布门槛：源提交 → 迁移/配置清单 → 完整构建 → 隔离旧版升级及健康/登录验收 → 桌面更新源校验 → 标签/CI/Release → 线上本地摘要核对。发布失败保留证据并重试安全步骤，不覆写不同内容同名资产。

升级保留真实 .env 与存储；模板只是参考。数据库恢复需要升级前数据库备份及对应镜像，不把换旧镜像描述为 schema 回滚。下载元数据最后切换，保留历史安装包和管理员配置。没有真实 Windows 机器时不声称安装成功。

## 独立评审后的发布顺序修正

release-changelog prepare 依赖远端标签且含生成时间。冻结源码、完成静态门槛及必要候选预验后推送标签；下载该次 CI 唯一 release-changelog 三文件，再以其 JSON 构建正式离线包。CI 自动发布基础 Release 不表示本任务交付完成，所有附件和验证通过后才报告完成。Windows 从同一冻结 SHA 的分支执行原生验收，候选版本显式 0.8.8；保留其确切构件，不重新打包替换。

最近正式基线 v0.6.7 (9caea35808afc8d05fb6135bfc74d4bfb0b45cf1)，最近实际交付 dist/release/0.6.7。独立审计指出 fork 标签流程跳过 GoReleaser/Desktop，需补充 CLI 交付；CLI公网自更新仍指向upstream，内网按受控文件替换说明操作。下载页仅注释变化，无功能升级，交付同源部署材料并明确该结论。

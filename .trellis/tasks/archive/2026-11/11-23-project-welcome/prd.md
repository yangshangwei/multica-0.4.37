# 项目首次使用欢迎页

## Goal

当项目目录为空时，用介绍和注册激活案例帮助用户理解项目如何组织共同目标下的任务，以及单个智能体与 AI 小队分别承接任务的方式，并引导创建第一个项目。

## Background

- 用户提供的项目页面仅有“还没有项目”、一行提示和创建按钮。
- 用户认可参考迭代与分拣台的介绍加示例布局，并于 2026-11-23 明确要求将案例换为“注册激活”，介绍补充单个智能体，“请新建任务，继续推进”。该后续指令授权按修订后的方向实施。
- 页面由共享的 `packages/views/projects/components/projects-page.tsx` 承载，Web 与 Desktop 共用。

## Requirements

- R1：只在成功读取且真实项目目录为空时展示欢迎页。首次加载、读取失败、权限丢失、占位数据与刷新失败不能被当作成功空目录；已存在项目但筛选无结果时保留原有恢复操作。
- R2：介绍明确包含任务、单个智能体与 AI 小队。说明任务可分别分配给成员、单个智能体或 AI 小队；不得暗示一个任务会同时广播给多个执行者，或创建项目就会启动执行。
- R3：采用与迭代、分拣台一致的介绍与案例并列布局。介绍包含项目目标与共享上下文、任务分配、进度跟进三个简短要点。
- R4：案例固定为“注册激活”，展示流程梳理、注册接口与激活邮件、异常场景验证三条任务，以及单个智能体和 AI 小队的不同承接方式、状态与一致的进度。明确标记为静态示例，浏览不读写真实示例数据。
- R5：欢迎页的主要按钮为“创建第一个项目”，打开现有创建项目弹窗；提供现有项目文档的“了解项目”链接。欢迎页内避免与页头重复展示创建按钮。
- R6：完整支持英文和简体中文、浅色和深色主题、宽屏并列与窄屏上下布局、键盘访问。沿用语义令牌和共享原子控件，不增加依赖或持久化引导状态。

## Acceptance Criteria

- [x] AC1 / R1：成功空目录显示欢迎标题、说明、注册激活示例和创建入口；存在项目时显示原有列表。
- [x] AC2 / R1：加载、首次错误、缓存空目录刷新失败与权限丢失保留对应反馈；有项目而筛选无匹配时保留清除筛选操作。
- [x] AC3 / R2–R4：两种语言均明确呈现单个智能体和 AI 小队；案例任务名称、负责人、状态和进度相互一致，无真实数据或执行副作用。
- [x] AC4 / R5：唯一的页面主要创建入口打开原有弹窗；项目文档链接使用共享导航，在当前工作空间打开既有项目指南。
- [x] AC5 / R6：宽屏介绍与示例并列，390px 窄屏无横向溢出，标题和任务内容可读，操作目标至少 44px，示例不进入键盘操作顺序。
- [x] AC6 / R6：相关组件与目录状态测试、locale parity、lint、typecheck 通过；保存实际界面截图及有界视觉检查证据。

证据与实际验证边界见 `research/verification.md`。

## Out of Scope

- 不改项目创建表单、项目执行小队设置、任务分配规则、API、数据模型、平台路由或 Mobile 界面。
- 不新增教程轮播、模板导入、自动执行、真实示例数据或首次使用完成标记。
- 不重构其它欢迎页、共享布局或全局样式，不修改工作区既有无关改动。

## Constraints

- 项目负责人和执行者是不同概念；每条任务仍只有一个选定负责人。
- 仓库为可选资源，不在文案中要求用户必须先添加仓库或小队。
- 只修改共享 views、项目的两种 locale、相关验证与本任务文档；不得新增依赖。

## Decisions and deliberate evidence limits

- D1: `cohort-as-of-v1`, exact workspace/project and current ordinary report; independent collaboration issues have separate authority and are outside this ordinary cohort; stock_as_of separate from window events. Explicit UTC start/end and IANA timezone from the human capture request, not guessed from prompt/trigger time. Request period_mode is explicit/rolling_24h/rolling_7d/calendar_day/calendar_week and validated against resolved boundaries. [start,end), start<end<=DB as_of. No-project snapshots describe current report scope only and project metrics are not_applicable.
- D2: preserve minimum health Input (sanitized References.Facts: only validity/environment booleans plus already-permitted assignee/lead refs, never runtime or roster IDs) plus issue identities/revisions/origin/admission/status/category/time/project, report classification evidence, bounded activity from/to/identity/time, source read proofs and gaps. Current report and server-provenance daily/weekly automation report issues are excluded; custom/legacy automation provenance ambiguity stays unknown. No title heuristic. Nonautopilot rows lack generic proof they are not manually created reports; keep their business/report classification unknown unless a trusted recorded classification exists. Preserve a separately named formal_stock baseline with explicit ordinary_formal_as_of scope (independent collaboration excluded), including ordinary formal records; it is not qualified business throughput. Classification-based business metrics retain unknown. The taxonomy is versioned. Public Timeline is not the collector. Activity producer lacks a complete project/category/causal history, so production window metrics requiring it remain unknown, with observed records retained but no inferred exact totals. Pure verified fixtures can exercise complete-history reducer behavior; those fixtures do not upgrade production source authority.
- D3: no automatic retention purge in this increment. Retain minimal frozen facts until explicit owning report/workspace deletion, cleaned in the owning deletion transaction. Source deletion/move does not alter frozen content while current report/project authority permits it. No raw comments, attachments, external credentials, hidden directory payload, or arbitrary JSON source bodies. Bound sealed canonical payload to 16 MiB, candidates to 10,000, activity facts to 100,000; source overflow records explicit gap/unknown where seal remains meaningful, whole payload overflow refuses sealing. These are engineering limits, not shared project policy.
- D4: canonical report UUID routes, no query, no HEAD alias or encoded/extra path variants. Reporter exact GET current/by-ID only; human actors may capture and read for review under existing current issue/workspace authority. All machine/legacy/reviewer impersonation is denied for capture and for new snapshot reads except verified Reporter. Human and Reporter reads use the same per-request RR data+authority scope appropriate to their principal. Original conflicting actor/workspace headers for these routes are rejected before Auth overwrites them, against verified identity; do not globally change existing Auth behavior.
- D5: explicit human POST capture, never GET generation. Original request key bound to actor/workspace/report and strict canonical payload. A canonical cycle identity binds workspace/report/project/period/timezone/start/end; one root snapshot per cycle, corrections explicitly link to the current snapshot for that cycle. Duplicate same-cycle requests do not silently produce another root. Same request-key replay remains distinct from same-cycle conflict. All collect/build/insert/current selection commit atomically under one RR cut and current authority. Replay same key returns original snapshot under current authority without recollecting. Different payload same key conflicts. Correction is explicit new key plus correction_of belonging to same report/project; not an automatic retry. Current selection uses a committed per-report sequence/atomic record (latest sequence in the immutable table, no second pointer table); report lock serializes insertion, but sequence/request uniqueness races in RR must retry the entire transaction with the original key; it never depends on timestamp/UUID as a source commit watermark. No background jobs or scheduler integration.
- D6: typed metrics and per-metric coverage from reviewed research; source+result digests independently canonical, whole snapshot digest includes immutable identity. Verify counts against original projecthealth.Compute on identical ordinary-only frozen inputs before applying report exclusions; enumerate the scope difference from unfiltered project-health rather than claiming project-wide parity; project bool/enum/time metrics use dependency coverage. No model call is part of parity.

Unknown history is an explicit supported result, not unfinished collection disguised as zero. A known empty scope may produce exact zero only where all required source evidence is complete. Invalid/expired/mismatched reader authority always denies with no snapshot body; it never rewrites coverage. RR authorization linearizes at the new read cut, not the historic capture as_of or final network send.

## HTTP and consumer surface

- POST `/api/issues/{reportID}/report-snapshots` human only. Header `Idempotency-Key`: canonical nonzero UUID. Strict body protocol_version=1, expected_issue_revision (positive int64), timezone, start/end (UTC microseconds), period_mode, correction_of (explicit nullable snapshot UUID). Source facts, project IDs, actors, semantics versions, completeness flags and result JSON are server-owned, never supplied by caller. Human capture declares the target as this report, not other cohort rows as business by fiat. Capture current report must be an ordinary issue, exact current project locked/rechecked.
- GET `/api/issues/{reportID}/report-snapshots/current`: current sealed snapshot or minimal404, no side effects.
- GET `/api/issues/{reportID}/report-snapshots/{snapshotID}`: same-report/frozen-project immutable identity, current human or exact verified Reporter authority. No global/project inventory. No query. `Cache-Control:no-store`.
- Successful body protocol_version=1, snapshot (full bounded sealed typed object), replayed boolean for POST. GET uses the same envelope with replayed=false; the snapshot body/digests themselves do not vary. POST initial201/replay200. Invalid400, unauthenticated401, forbidden403, missing/mismatched snapshot404, stale/key conflict409, source/payload/cut unavailable503. Do not disclose body/digests on errors.
- CLI `issue report-snapshot capture <canonical-report-uuid>` requires explicit request key, expected revision, timezone/start/end/period mode and optional correction. Reads `issue report-snapshot show <canonical-report-uuid> [--snapshot <UUID>]` (default current). Capture never auto-generates a key or retries on uncertainty; user retains original key/payload. Show is GET-only. JSON typed validation binds report/snapshot and validates supported versions/digests before success. No UI redesign/new frontend routes are required for this API/CLI capability; existing human reports remain unchanged.
- Reporter builtin role skill/source map points to GET consumer and explains no snapshot -> evidence unavailable/request human capture, never POST. Existing inert current-report comments remain unchanged; no automatic report publishing.

## Data and transaction constraints

Persist one immutable snapshot row with ID/workspace/report/project/revision/creator/request identity/payload hash, report sequence, captured_at, canonical snapshot bytes or jsonb preserving typed decoding, and digests. Unique concurrent indexes enforce original key, per-report sequence, cycle root/correction uniqueness as needed. All ID/uniqueness indexes follow the separate CONCURRENTLY migration rule; do not introduce inline primary-key/unique indexes. IDs are validated server UUIDs; no FK/cascade. All indexes, including uniqueness/new tables, get separate single-statement CONCURRENTLY migrations; coordinate from migration794. SQLc source and generated output stay synchronized. No new dependencies.

The engine owns types/canonicalization/validation/reducer and tests in `server/internal/reportsnapshot/`. Extract reusable `projecthealth.CollectInput` only as needed, preserving existing Collect error/empty behavior. A service owns source collection and persistence, using caller tx/q only. The handler owns HTTP/current human or task authorization and supplies the same tx to service. Source identity native revisions are preserved; content digests explicitly identify snapshots of sources without revision. Read source completeness and producer history completeness are distinct. Abort/SQL errors cannot seal within failed tx; use narrowly scoped savepoints only when preserving an optional-source gap is sound, otherwise fail whole capture.

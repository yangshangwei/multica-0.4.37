# Git 物料协作实施设计

日期：2026-11-26。状态：已确认需求到方案审核闭环，进入实现；沿用父任务 D1–D10。产品能力以本次验证结果为准。

## Current behavior and gap

当前已有普通项目、多仓资源、协作上下文、版本化方案审批、执行权限和完成证据。尚无 Git 工程物料领域模型、受控提交/合并 provider 与持久化对账。`collaboration_stage_actions.go` 创建的方案子任务是未指派的 `todo`；后续普通指派仍可能执行，因此其现有行为不能独立保证 D8 的等待人工启动。

项目详情由 web/desktop 共享。GitHub 的 App 安装鉴权与 GitLab 的加密连接可以提供集成基础，但当前只读 token 验证不证明具备发布/合并能力。既有插件 SDK 也尚无物料 action。

## Domain ownership

- 项目配置：物料资源、provider/仓库稳定身份、目标分支、系统根、人类审核者、方案执行目标、`auto_start_plan`、配置版本及启用状态。凭据仍在专用加密集成存储，响应不返回密钥。
- 物料：稳定 ID、项目归属、固定路径、候选修订指针、正式基线指针。路径由可信配置和服务端分配 ID 构建；不接受模型任意写入路径。
- 修订：完整 Markdown、内容摘要、工程来源清单、验收项与可评审检查结果。已发布修订不可原地改写。
- 审核：人类身份、决定、理由、修订/HEAD、权限和配置版本、原始 request ID；撤回或失效追加事实，保留历史决定。
- 操作：发布/审核同步/合并/基线核对/方案交接的持久化意图、稳定幂等键、尝试与阶段回执。状态区分待处理、等待门禁、结果不确定、冲突和已核对完成。
- 方案阶段：绑定物料及获批基线、同一个业务任务、启动方式、等待人工标识与真实运行引用；创建任务不等于已运行。

Git 保存定义和获批内容；数据库中的修订快照用于审核/恢复，不得成为能绕过 Git 基线独立改写的第二正式来源。

## API and UI boundaries

建议在现有项目 API 下新增物料配置及列表/详情，并提供候选修订、评论/决定、恢复和方案启动命令。客户端所有写入携带 `request_id` 与预期版本，审核人只从认证上下文取得。具体字段在范围确认后的合同评审中冻结，避免提前向 SDK 发布未完成接口。

共享客户端放 `packages/core/materials/`，业务组件放 `packages/views/projects/`；直接接入共享 `ProjectDetail`，无需增加平台专用路由。React Query 管所有服务端事实，编辑器仅保留本地未提交草稿。正文、来源、版本差异、审核和阻塞原因在同一详情中阅读。

保留插件交付方向：宿主实现窄 API、权限与持久化，插件经 SDK/bridge 访问。不能将高权限审核伪装成无来源的 iframe 调用；扩 SDK 前核验 capability 和当前人类身份合同。不绕过现有插件边界直接 import 宿主内部模块。

## Publication and merge

1. 校验来源、允许路径、正文/验收项和阻塞项，冻结修订及目标配置，在数据库提交发布意图。
2. 后台领取意图，复查当前权限/配置，先查询远端是否已完成；否则创建确定命名的需求分支、提交物料、创建或恢复同一 PR/MR。
3. 产品审核绑定真实远端 HEAD；审核变更是新事实。批准后记录审核同步和合并意图，不直接写正式基线。
4. 合并前复核完整变更、允许文件、精确 HEAD、目标仓/分支、当前批准/权限和原生门禁。任何未知或不满足条件保留阻塞状态，不降级成强制合并。
5. 带预期 HEAD 调用 Git 平台合并。入队或超时进入待核对；成功后读取实际合并事实及固定版本文件，核对摘要，再建立基线。
6. 对账不依赖 Webhook 必达；Webhook 只加快原意图处理。物料 PR 不走会自动关闭开发任务的普通 closing-intent 链。

Provider 是新窄合同：读取精确修订/完整变更、恢复或发布候选、同步业务审核、观察门禁、按 HEAD 合并、核对实际合并内容。保持现有 `vcs.Provider` webhook 接口及 GitHub 读取路径。

对远端数据分页完整性、未知门禁状态、符号链接/子模块、正文限额、重定向及自建实例出站策略必须明确拒绝/阻塞，不将部分响应当成完整允许变更。不得关闭 TLS 校验。

## Stage handoff and execution

以“项目 + 物料 + 获批基线 + 方案阶段”定位唯一任务。完整 PRD、固定版本来源、摘要及验收项构成运行输入；加载失败时不派发。事务中记录任务与启动意图，后台幂等派发。

关闭开关时保留 `todo` 和持久化等待人工标记；创建、指派、恢复及领取必须经过同一个服务端执行判定。人工启动需要当前基线、当前调用权限和已存在运行检查。重新开关不批量启动旧待办，运行中停止继续复用既有操作。

方案产出包含设计与任务定义的 Git 候选、所采用的需求基线和版本审核。复用既有方案/阶段审批的当前版本和权限模式，但不能把旧协作审批记录直接当作物料批准。编码只消费当前获批方案；物料基线不是代码合并授权。

## Storage, concurrency and recovery

新增领域表和 sqlc 查询，不新增外键或级联操作；每条并发索引独立迁移。作用域查询均包含 workspace/project。配置、修订、决定和执行边界采用版本条件、唯一约束及事务锁；多进程后台领取需要持久化租约/可恢复 claim，不能只用进程内 mutex。

远端网络操作前持久化意图；不承诺跨 Git/数据库原子事务。任何超时先查事实，不重复盲写。配置/权限撤销禁止新的副作用；已产生的远端事实仍保留审计。对未配置此功能的普通项目不引入新的全局完成或派发语义。

## Verification and rollback

开发使用 fake/HTTP provider 与独立数据库，覆盖结果丢失、重复/乱序、并发编辑、撤销和同一意图恢复。客户端通过真实 API 合同测试及共享 UI 验证，web 用生产构建。

回退先关闭新发布/合并/派发，保留历史记录和在途核对，不删除共享分支或改写已合并历史。真实平台/自建实例/模型效果需要单独可追溯证据，不用模拟测试代替。

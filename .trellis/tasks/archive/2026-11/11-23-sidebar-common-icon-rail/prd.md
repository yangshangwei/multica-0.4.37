# 折叠侧栏时保留常用入口图标

## Goal

点击左上角折叠按钮后仍能直接使用常用入口，让用户获得更多内容空间，同时避免反复展开菜单。Web 和 Desktop 使用一致的方案 A。

## Background and approval

- 用户先要求几个方案且不建任务，随后明确选择方案 A，授权“新建个任务，然后推进”，并要求“先不提交”。此次执行沿用上一轮已展示的设计，无需重复确认。实现验收完成后，用户明确要求“提交吧”，授权本地提交与任务收尾。
- 已确认的预览：`artifacts/design/sidebar-collapse-options-20261123/sidebar-collapse-options.html`，A 页签。
- 当前 `AppSidebar` 使用默认 offcanvas 折叠，底层 `Sidebar` 支持 icon 折叠。完整导航已有分组、固定项和工作空间/账号范围区分。

## Requirements

- R1：大屏 Web/Desktop 收起后保留约 64px 图标栏；再次点击原折叠按钮恢复完整侧栏和已有展开宽度。
- R2：常驻入口为新建任务、AI 对话、协作通知、工作空间选择、我的任务、任务、项目、智能体、“更多”，底部保留设置、帮助和个人账号。
- R3：“更多”可访问其余既有导航：发起协作、当前/参与协作、收件箱、迭代、分拣台、AI小队、自动化、资源与连接及统计。可以按现有分组组织短菜单；功能开关和权限仍适用。
- R4：图标采用现有路由图标；悬停及键盘聚焦显示名称和必要范围说明；当前目的地与正数未读状态在图标模式可辨认。
- R5：常驻入口保留原行为和范围。新建任务保留草稿/跨范围交接，AI 对话仍属于当前显示的工作空间，协作通知仍为账号范围。未选择工作空间时相关入口保持现有禁用/恢复语义。
- R6：紧凑/移动视口保持完整导航抽屉；折叠图标栏用于大屏，Desktop 顶部拖动区域、窗口按钮、历史与标签栏不互相遮挡。
- R7：折叠/展开不更改分组偏好、固定项、路由或服务端数据；菜单关闭与路由切换恢复合理焦点。保留现有窄桌面自动折叠规则。

## Acceptance Criteria

- [x] A1（R1/R6）：Web 和 Desktop 的大屏折叠仍看到约 64px 图标栏，主内容获得剩余宽度；展开恢复；紧凑屏幕打开完整抽屉。
- [x] A2（R2/R5）：常驻图标均可直接使用；新建任务、协作通知和 AI 对话的范围行为未改变。
- [x] A3（R3）：其余入口可通过“更多”进入；禁用的迭代/分拣台不被意外显示；支持无工作空间和列表恢复。
- [x] A4（R4/R7）：当前项和未读提示可辨认；键盘可打开/关闭菜单，名称可访问，Escape/路由跳转没有焦点落在隐藏内容中。
- [x] A5（R6）：Desktop 的窗口控制、拖动、历史、标签栏与图标栏在宽/窄视口不重叠；浅/深主题无布局问题。
- [x] A6：相关单元测试、lint、typecheck 和 Web/Desktop 定向旅程通过；保留结果与截图证据，更新适用导航契约。
- [x] A7：实现验收期间保留未提交；收到用户明确授权后仅提交本任务改动，不覆盖此次执行开始前的用户修改。

## Out of scope

- B 分组作为唯一常驻入口、C 用户自定义固定图标、完全隐藏的第三种显示状态。
- 移动端原生应用、服务端/API/数据库修改、依赖更新、导航内容或权限体系重设计。
- Git push、发布、合并及无关现存修改。本地提交已在验收后得到明确授权。

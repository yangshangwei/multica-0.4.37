# Capability market welcome design

**Change boundary:** The shared market root already owns the active catalog and URL semantics, but its header and underline tabs give no help choosing a capability. The UI gap closes in `packages/views/marketplace/marketplace-page.tsx` and a local welcome component with styles; translations in both layout resources describe one illustrative task. The retained `AgentTemplatesMarketPanel` needs only a leading content slot so the narrow example can scroll inside its existing scroll root. No other catalog or platform adapter changes.

The first viewport uses Multica’s existing neutral canvas, blue state color and task vocabulary. On a wide pane, an introduction and four directory entries sit on the left. On the right, one task ticket shows what to configure and what that enables. The selected entry’s blue marker and the capability annotation in the ticket connect the two. The catalog begins directly below. A narrow pane lays out the entries in two columns; a native disclosure before the catalog keeps the example optional and within the existing catalog scroller. At very short viewport heights, the compact treatment leaves space for results. No forced welcome step, transient onboarding preference, carousel, or external asset.

Keep the horizontal Base UI tab relationship and manual keyboard activation. Presentation can use the existing Base UI primitives with market-local styles; keep the category title as its accessible name and use the short purpose as a description. Bind the example to the committed URL-derived category, alongside the active panel. The presentation does not read or write server state. Use the existing workspace navigation and documentation adapters; where the collection header previously deep-linked just MCP, the case can link to the applicable docs for the selected category.

Keep current visited panel mounting and `hidden`/`inert`/`active` ownership. Remove scroll-to-selected code that was needed for the old horizontal strip: entries now wrap. The compact disclosure must be in the existing catalog scroll region, including the distinct agent-template scroll root; do not add a second overflow container or change restoration keys. No backend changes, migrations, dependencies, or changes to the in-flight agent-template behavior. Reverting the welcome shell, local CSS, locale keys and presentation tests restores the previous UI while preserving those catalog changes.

# P1 actual-platform harness

Task-local `scripts/real_platform_harness_test.go` has `agentintegration && !windows` and is overlaid into `server/cmd/server/zz_secrem_real_harness_test.go`. Production sources are unchanged. Entry points are `TestSecurityRemediationP1Fake` and `TestSecurityRemediationP1Real`. Real mode checks `MULTICA_RUN_REAL_AGENT_SMOKE=1` before reading registration or discovering providers. TestMain still requires the exact migrated owned database, so absent opt-in is not a database-free startup.

Configuration is a private0600 JSON bound by `SECREM_HARNESS_CONFIG` and `SECREM_HARNESS_CONFIG_SHA256`. The config names the owned database, fresh output directory, claim-manifest directory, exact host CLI and wrapper hashes, task-only Codex seed configuration, transport configuration, model/effort/account, source commit and file hashes, fixture inventory, test binary and reviewed admission. The full transport JSON hash is checked; its admission projection removes only registration_file and registration_sha256, then canonical compact sorted JSON is hashed. This breaks registration/admission circularity without leaving runtime policy fields unbound.

The fixture creates a distinct synthetic human/workspace/runtime/daemon credential using testutil. Template staffing, human security-owner seat, model/effort configuration and assigned P1 issue use actual router handlers. The issue description is the exact frozen P1 string. The fixture preserves its rows for root-controlled database cleanup, rather than deleting evidence before examination. Human JWT and mdt never enter the role environment; actual Claim mints the mat used by the ordinary daemon Run and real CLI transport.

`RK1KnowledgeDriver` is reused only as a tagged bridge to ordinary production Claim/Run/Report, not its knowledge scenarios. One wire detail is important: ordinary issue claims include is_leader_task and full injected briefing but do not currently return squad_id; the harness validates persisted agent_task_queue.squad_id and uses that ID in the nonsecret transport manifest, without rewriting daemon.Task or provider input.

Before Run, `<claim_manifest_dir>/<task_id>.json` binds scenario=P1, issue/squad/agent/workspace, role, owner IDs and read_only_code=true. Actual generated AGENTS remains unprojected. The HTTP trace durably stores sanitized request/response bodies and credential kind. Database snapshots cover the entire workspace's issues, tasks, comments, activity, receipts, agents, squads, members and subscriptions. Complete keyed add/remove/change maps are saved. Automatic assertions reject other issues/tasks, member dispatch, off-issue effects and roster/configuration drift. Human review still must inspect known/unknown facts, prohibited actions, incident handoff, no risk-fixed claim, broker audit and filesystem evidence.

# Acceptance fixtures

`repos/` is the only material copied into role workspaces. All content is
synthetic. The dependency fixture reuses the locally vendored material from the
2026-10-27 pilot; its source hashes are preserved. The code fixture removes the
old prewritten failing tenant test so this trial can observe the independent
verifier producing it.

`expected-actions.json` is the evaluator's preregistration. Never mount it, task
planning documents, scoring logic, expected patches or earlier model reports in
a role container. Issue text supplies the problem and safety boundaries; ordinary
platform injection supplies the role, squad protocol and member roster.

`freeze.sha256.json` binds the scenario expectations and repository sources.
After isolated fixture validation, the main session reviews and binds this
digest into the private launch registration with the integrated product commit,
model, account alias, hard budgets and complete runtime/isolation manifest.
Changing any frozen input after the first real attempt creates a new recorded
experiment; it must never rewrite an earlier expected result.

## material_fixes

1. **P1 — 修复应用暗色图的白色画布。** `native-dark-how-multica-works-0.png` 中参与者标题尚可读，但消息标签与箭头接近白对白，关键执行过程不可读；`native-dark-concepts-0.png`、`native-dark-triage-0.png` 和架构图也出现明显白色矩形。让 iframe 内部画布跟随当前深色表面，连线与文字跟随前景色，并去掉本不需要的灰色标签补丁感。验收：暗色时序图所有标签和箭头都可读，整体无白底闪块；切换主题后同样成立。

2. **P1 — 限制应用阅读器的最小内容宽度，让横向滚动只发生在图内部。** `native-light-narrow.png` 的段落在右侧被截断，右上工具栏离开视口，页面底部出现全页横向滚动条；这超出了允许的图内自然尺寸滚动。修复阅读区/内容列的收缩边界，保留图的自然字体和独立滚动。验收：520px 及 390px 下正文正常换行、右侧工具可见、页面 `scrollWidth <= clientWidth`；宽图仍可内部滚动至最右节点。`public-dark-narrow.png` 的图内裁切本身不是缺陷，不要求把全部时序列挤进窄屏。

3. **P2 — 提高承担语义的节点、决策菱形和分组边界对比。** 当前形状填充基本等同画布，边界过淡，协作/MCP 的决策菱形和架构职责区域难以一眼识别。原图像素抽样：native light 的节点边界 `(236,236,239)` 对画布 `(251,251,251)` 约 **1.14:1**；public dark 的节点边界 `(33,27,25)` 对画布 `(21,17,14)` 约 **1.10:1**。这些是语义图形，不是外层装饰边框。沿用各端中性灰色系，适度加强图形描边或填充区分；需要形状传达意义的边界以 **3:1** 为验收目标，外容器边框仍可安静。保留现有清晰文字和连线，不增加多色编码。

4. **P2 — 让公共架构图的分组背景遵守已定中性色系。** `public-light-developers-architecture-0.png` 的两块职责区域为浅蓝 `(227,238,252)`，暗色对应深蓝 `(28,47,70)`；其他公共图与应用架构图均没有这套蓝色语义。改用公共站现有暖色 muted 表面，并配合上一项保留明确的区域边界。这里修复的是新增图形中的无意义颜色差异，不是抹平公共站与应用各自的主题。

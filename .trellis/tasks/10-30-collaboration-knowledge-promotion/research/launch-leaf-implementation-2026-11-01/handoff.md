# C1 implemented leaf contract

This batch implements the agent leaf only. It does not inject knowledge, enable G2, authorize a source, persist a session pointer, or certify a real Provider/version/platform combination.

## Integration surface

- `ExecOptions.Knowledge *KnowledgeLaunchIntent` opts into the guarded path. `ConfigurationID` is the admitted opaque namespace. `Session` contains `Kind` (`fresh` or `resume`), the **scope** `Generation`, and `NativeSessionID` (empty for fresh). A claim generation belongs to the server observer and is not interchangeable with this generation.
- `KnowledgeInvocationFingerprint(provider, cfg, opts)` validates and fingerprints the app-managed invocation without executing a CLI. Set its result in `KnowledgeLaunchIntent.InvocationFingerprint` before negotiation. Claude recomputes it against the options actually used for its command. It covers executable path/version, provider/mode, cwd, raw default/custom args, model/thinking/max-turns, managed MCP bytes and settings path. It excludes the prompt, native session selection, credentials and liveness limits. This hash is not a freeze of external host config or the settings file's contents; integration still owns runtime/account and managed-file admission.
- `KnowledgeLifecycleSupported(provider, mode, builtinRuntime)` accepts only built-in local Claude. The trusted runtime discovery path must establish `BuiltinRuntime`; a custom command using `protocol_family: claude` cannot set it merely by that name. Any configured launch prefix is refused, including one removed by the ordinary prefix filter. Other providers fail before lookup/start if given knowledge options.
- `ValidateKnowledgeSessionArgs` is the reusable argument policy when a controlled selection is required. Its guarded Claude subset permits bounded `--verbose`, `--model`, `--max-turns` and `--max-budget-usd`. Selectors, cwd/remote overrides, subcommands, unknown flags, missing values and flag-looking values are refused, never stripped. It is not generic proof that a custom executable or another provider starts fresh. Legacy execution with nil `Knowledge` keeps its existing arguments and behavior.
- Use `NewOrdinaryLaunchLifecycle(observer)` for ordinary tasks. It retains the command's already assembled ordinary environment exactly. Its observer must leave `LaunchCallbacks.Environment` empty; even an unrelated addition is rejected before native start. `NewLaunchLifecycle` retains collaboration filtering/refresh semantics.
- Use **one lifecycle per logical input**, retaining it across any independently permitted physical attempts. `BeforeLaunch` receives a value-copy `LaunchInfo` with `Provider`, `Kind`, a new `Attempt {Sequence, Nonce}`, and copied `Knowledge`. It authorizes before the process starts. Bind the server's complete claim/preparation/scope identity in the returned closures. Preparation helpers do not consume a knowledge intent.
- The closures `Started` and `Terminated` still describe actual native process observations. A knowledge provider launch additionally requires `NativeSessionObserved`. It synchronously receives raw Claude system/result IDs, the exact command attempt/intent, the previous accepted native ID, source (`system`/`result`) and `MatchesIntent`. Callbacks should use the `BeforeLaunch` context and bounded network operations; the parser waits for their completion.

## Session and refusal semantics

Native observation happens before public status messages and before legacy `resolveSessionID` fallback. A full public message channel cannot drop it. Duplicate equal IDs are idempotent. The first observed fresh ID can bind that admitted generation; an exact resume must observe the requested ID. A changed/mismatching ID is delivered as `MatchesIntent=false`, then causes `knowledge_context_changed` even if the observer returns nil and the Provider reports nominal success. Retain this as an unapproved/uncertain observation; do not move the prior session's exposure to the new ID.

Malformed or oversized native-ID fields refuse without forwarding arbitrary stream bytes to the metadata callback. The admitted generation remains uncertain and the actual process facts are retained. This final tightening and its fake-executable regression are covered by `agent-race-bounded-final.jsonl`; the earlier complete package run's exact source snapshot is recorded separately.

Unknown fresh sessions and requested resumes with no actual raw observation return no native pointer. PID, process start, a requested ID and a result fallback are not native-session proof. A callback failure seals the lifecycle, terminates the owned process, and prevents another permit/start through that lifecycle. An early callback failure is not evidence that an already started process received no input. Process start/end facts remain separate.

`KnowledgeLaunchError {Reason, Err}` and `KnowledgeFailureReason(error)` preserve typed refusal through wrapped Execute errors. Reasons include `knowledge_context_changed`, `knowledge_authorization_denied`, `knowledge_unavailable` and `knowledge_invocation_unsupported`. The original cause is inspectable but not rendered in its content-free error string. Callback errors without a specific knowledge reason become unavailable.

For a running session, `Result.KnowledgeFailure` carries the reason and `Error` carries the same safe string. The knowledge refusal always has failed status and clears `ResumeRejected`. `ProcessExited`, `Usage`, previous accepted session observation and prior messages remain facts. `Result.Output` keeps the existing empty-on-failure final-answer contract. `Result.KnowledgeOutput` retains already observed result text (or the last eligible assistant text if no result arrived) separately, avoiding a kill/natural-exit race. Both new fields have `json:"-"`.

**C2/C3 must preserve the reason in terminal DTOs, exclude all knowledge refusal from automatic fresh/requeue/task retry, and retain `KnowledgeOutput` as failure evidence/transcript only, avoiding duplication of text already recorded.** They must atomically persist admitted native observation/exposure before ordinary pin/complete/fail/cancel pointer publication. Do not use the existing lossy asynchronous first-only status pin as this observer. No automatic base-only downgrade is introduced here.

## Evidence and limits

The new test executable is the Go test binary selected through a dedicated test-only environment marker before normal flag parsing. It records real argv/stdin/environment and emits deterministic stream events. No installed CLI is resolved; broader commands use the repository agent-CLI guard. `fail-first.log` records the original ordinary credential loss. `agent-race.jsonl` records the discovered kill/output timing failure; the final code retains failure text separately and `agent-race-final.jsonl` passes.

The tests cover exact environment preservation, forbidden observer replacements, unchanged collaboration filtering, per-command immutable intent and distinct attempt handles, a full public channel, result-only callback publication barrier, duplicate/missing/changed IDs, exact resume argv, invalid intents, missing callbacks, configuration drift, custom/remote/other-provider refusal, ordinary base/legacy behavior, and first/later launch refusal with actual start counts and retained work facts.

Leaf first/later launch tests are not the approved G2 ordinary-entry service/daemon tests. C2/C3 still own all claim surfaces, exact cumulative history, prepare/authorize transactions, durable observation/receipt recovery, failure normalization and pointer writers. No model comprehension, actual paid account execution, or Windows/Linux native runtime acceptance is claimed by cross-compilation.

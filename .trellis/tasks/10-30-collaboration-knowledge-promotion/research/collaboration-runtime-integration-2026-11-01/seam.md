# C4 collaboration knowledge runtime seam

The current A2 resolver supports collaboration audiences but no collaboration
host consumes its contributions. Ordinary C2/C3 claims cannot substitute for a
run identity or use the collaboration business and termination capabilities.

The proposed integration keeps the existing claim, handoff, physical-launch
permit, observation, recording and proof lifecycle. A managed-daemon claim URL
negotiates knowledge version 1 without changing old strict JSON request shapes.
The first claim freezes a metadata-only descriptor; replay cannot upgrade an
old claim or downgrade a knowledge claim. Private preparation and authorization
are separate managed-daemon endpoints. The business token alone cannot request
either operation.

Preparation resolves every accepted input author, the actual runtime owner and
the destination collaboration audience from database state. It retains only the
exact manifest, request identity and frozen handoff identity. Replays reauthorize
that manifest instead of replacing it. Each actual provider launch binds the
same manifest, exact application prompt digest and existing permit sequence and
nonce before process start. Private contribution bodies exist only in that
bounded response and in-memory per-turn prompt, never in stable brief files or
operation receipts.

Initial support is built-in local Claude with an explicit safe argument policy.
Every admitted run uses a fresh host directory/session namespace containing its
run identity. It never reads or saves a reusable native-session pointer. No fresh
vendor flag is invented; actual argv must have no resume, continue or selection
override. Legacy and downgraded runs cannot select the knowledge namespace.

Shared-file allocation was requested from main before source edits. New protocol,
service, handler and host-knowledge files and this evidence directory are owned
by C4. Ordinary daemon/task/Core/UI files, sqlc generation, production enablement
and formal G2 status stay with their existing owners. No Provider call or commit
is authorized in this lane.

Validation will use a new C4-only database and fake executable. It must cover
state/expiry/purge, multi-author and audience authority, exact stdin and stable
files, both first and later launch refusals, lost replies/original identities,
fresh namespace and downgrade, retained accepted input/delegation, and independent
stop/recording/proof progress. Saved command results are evidence only for their
recorded source snapshot; they do not establish model comprehension.

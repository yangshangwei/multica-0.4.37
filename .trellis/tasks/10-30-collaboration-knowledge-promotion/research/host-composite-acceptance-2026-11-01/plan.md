# C4 real server and host composite

Only a new `knowledgeintegration`-tagged cmd/server test and this evidence
directory are writable. Production C4/C3 code is frozen. Any product failure
will be reported with its owning seam before a fix is attempted.

The fixture reuses real managed enrollment and owner authentication setup, then
creates a new collaboration source, approved A2 contributions, built-in Claude
runtime capability and explicit owner-consented target. `NewRouterWithOptions`
provides the real Handler for setting its instance-only knowledge test gate.
All runtime HTTP requests use that production router and real database service
transactions. A transparent observing transport may lose an actual response,
but cannot replace a service response with fake JSON.

The only synthetic component is an absolute test-owned executable copied from
the test binary. An init marker dispatches child execution before TestMain, so
the child cannot initialize or reset database fixtures. It captures actual
stdin/argv and emits controlled output/stderr. No installed CLI or Provider is
called.

First prove claim → frozen handoff → exact knowledge preparation → authorization
→ actual stdin → physical termination → proof, including canonical multi-target
contributions and multiple accepted authors. Then exercise real withdrawal,
purge, expiry and authority loss before launch, original-key response-loss
recovery, downgrade/nonnegotiation, metadata recovery and generic-log privacy.

The dedicated database is `multica_knowledge_host_composite_20261101_efb9efe6`.
Every execution command verifies its identity before running. Tagged/race tests
must have a nonempty inventory and no unintentional skip. Source hashes and all
failed/passing outputs are retained; this evidence does not prove model
understanding or installed native-platform rollout.

# Authoritative F3 hook inventory

Every source producer appends a `scan` in its existing business transaction. It does not query candidates, target counters, target parents, or target hints. Scans never reconstruct history through current membership/source joins.

## Deliberate no-op or unreachable source paths

- Ordinary `DeleteIssue` reaches `loadIssueForUser`/`rejectLegacyCollaborationAccess`; non-GET collaboration operations are refused. Batch deletion has `rejectLegacyCollaborationBatch`. Legacy comment deletion explicitly calls `rejectLegacyCollaborationWrite`. There is no supported collaboration hard-delete API to hook; these protections are unchanged. The maintenance-deletion regression removes the actual source rows to prove retained routing still works, but is not claimed as a human hard-delete flow.
- `DeleteWorkspace` still refuses `WorkspaceHasCollaborationRecords`. `DeleteProject` still refuses project associations containing collaboration issues. Their new target cleanup rolls back with those refusals; it does not bypass them.
- An ordinary collaboration comment edit creates a retained before/after event. A2 `KnowledgeSourceAvailability` reconstructs that exact historical version and compares its hash, while a tombstone suppresses all versions. `TestKnowledgeCommentEditRetainsSourceUntilDelete` drives CreateComment → EditComment → source-available/no scan → DeleteComment → unavailable/exact scan → target hint. Edits do not make an already-restorable source unavailable.
- Memory updates/restores append versions and do not destroy historical material. Run recording/checkpoint writers append retained facts; there is no supported destructive version/event writer in the query inventory. No invented cleanup endpoint was added.
- Time expiry is enforced by current reads/runtime and the frontend lease; it does not require scanner/sweeper progress.
- Emergency deployment environment changes and natural token expiry have no authoritative database write transaction. Current read/send authorization and the finite UI lease handle these; no synchronous scan is claimed for process configuration changes.

## Lock graph and failures

Source additions end at a single new scan INSERT. Scanner uses own job SKIP LOCKED → workspace KEY SHARE NOWAIT → optional project KEY SHARE NOWAIT → independent counter UPDATE NOWAIT. Candidate routing reads have no row locks and include only `published_target_revision IS NOT NULL`. Start persists a fixed ID upper bound in its own short transaction; each subsequent transaction handles at most one candidate/target, with at most 100 transactions per turn. Revision, cause/target hint and cursor advance commit atomically. A busy/missing-live-counter target retains its old cursor and returns an error; another job can progress. Deleted parent is processed without counter initialization.

Delivery locks one pending hint, publishes exactly `{target_kind,target_id,knowledge_revision}` through existing `PublishWithID` using `<original hint ID>:target`, and only then marks delivered. A publish/commit failure rolls back, records attempt time and retains the original ID. Publisher acknowledgement is not browser consumption acknowledgement. No new broker, dependencies, or source-event delivery changes.

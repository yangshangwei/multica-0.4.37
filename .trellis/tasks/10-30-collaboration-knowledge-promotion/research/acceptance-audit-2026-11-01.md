## Required missing regression evidence

**A — Approved service-level concurrency rows (AC2/AC3/AC11; implement §2 and F1/F2).** Current `server/internal/service/collaboration_knowledge_concurrency_test.go` exercises source-project edit ordering, source participant removal versus approval in both commit orders, sequential stale correction approval, and held owner approval versus raw project-description UPDATE. `server/internal/migrations/collaboration_knowledge_queries_test.go:186` holds raw `issue_counter`/description updates and invokes *only the generated parent-lock queries*. Neither test executes `PrepareTaskKnowledge` under those writers. The current tests do not exercise:

- Full preparation while a real issue-number allocation or project-description writer is uncommitted; actual approval held while unrelated create/project-association/triage/iteration writers complete.
- Approval versus disabled actor, target membership/role/human-lead change, source purge/comment edit/delete, withdrawal/correction approval, or project deletion in both required orderings.
- Concurrent same-lineage correction version allocation. The initialization race itself already has real generated-query evidence and does not need to be rerun merely for its planned name.

Minimal followup: extend the existing transaction-gate fixture into parameterized actual-service writer cases. Preserve bounded refusal/current-role checks, one approved version, one revision/hint/receipt, and no orphan active target. Do not replace these with another generic full suite or pure lock query. F3's real delete/purge cases prove outbox behavior, not approval interleavings.

**B — Negative recovery identity matrix (AC4; F4/K5).** `collaboration_knowledge_authority_test.go:230` rejects another actor but never supplies a valid different candidate with the original actor's request. The write namespace matrix never calls `GetKnowledgeOperation` with a memory/command UUID. Minimal followup: existing valid candidate B + candidate A's request, and a valid candidate + its actor's existing memory/command request each return content-free `operation_not_found`, without a new operation/candidate/hint. The recovery implementation was previously reviewed; this is missing direct regression evidence, not a claimed predicate defect.

**C — Narrow explicitly named scenarios currently represented by adjacent proofs.** The name `TestKnowledgePreparationVersusWithdrawAndSourceRevoke` (`task_knowledge_concurrency_test.go:42`) has only `withdraw`/`prepare` branches; it has no source-revoke branch. The real ordinary composite revokes source participation **after disclosure**, which proves the launch check but not the planned preparation/source-revoke interleaving. `TestKnowledgeClaimFinalizationDisclosesNoPrivateFields` does not mutate authority between build and finalize. The human purge-projection test does not exercise deleted-comment/source detail/history even though the common availability helper separately rejects a deleted comment. Minimal followup: add those branches to existing fixtures, without duplicating the full five-surface or parser matrix. The source must be initially eligible, then be revoked/deleted at the named boundary; inspect actual projection/response for body/summary/ref sentinels.

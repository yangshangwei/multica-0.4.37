## Implemented boundaries

- Source-free negotiation uses the one shared HTTP/batch/WS claim builder. Every legacy/unsupported claim also checks retained history. Finalization persists negotiation in its existing runtime/task transaction, including non-comment tasks, without loading private sources.
- The exact selected native binding retains provider/runtime/agent/configuration/scope/server UUID generation. Claim generation is a separate decimal value. All-status history includes older, cancelled, failed, reclaimed and NULL-native turns; it does not filter away original runtime identities after rewrites.
- Private metadata has explicit claimed/disclosed phases, bounded retained claims/attempts, immutable manifests/digests and per-attempt process/native observations. Valid empty or claimed-only history is distinct from private exposure; malformed or truncated proof is refused.
- Legacy/unsupported selection cannot use a different task scope or runtime profile to evade known provider history. The bounded namespace query includes original/current runtime, current agent binding, immutable daemon/provider and runtime-owner/provider identity. Explicit unsafe v1 selectors are refused before fallback. Ordinary negotiated `--no-session-persistence` remains refused; C4's separate non-reusable policy must not broaden ordinary resumable support.
- Prepare/authorize borrow the source resolver under independent user/credential → ordered workspace KEY SHARE/member fences → project KEY SHARE/independent target revision → consumer/Chat/source/candidate → runtime/installation/agent/task NOWAIT ordering. Source hints are metadata only. Complete response material/wire limits, including envelope metadata and newline, are checked before commit; no truncation or snapshot substitution occurs.
- Body disclosure happens only after commit. Original-key preparation replay revalidates the same manifest and preserves contribution order. Authorization binds exact preparation, manifest, prompt, invocation and physical attempt identity and rechecks current eligibility.
- Native observation binds exposure and the task pointer in one Chat→task transaction. Started, native identity and termination remain separate. Valid mismatches are retained then refused; original accepted/refused observation receipts remain stable on replay.
- Start, pin, complete and fail accept `knowledge_fence {claim_generation,dispatched_at}`. HTTP always passes one value (including nil for legacy); no argument is explicitly reserved for trusted server transitions. Supplied fences are checked even without current positive negotiation, and retained negotiated rows cannot be silently downgraded to unfenced clients. Start checks under its existing task lock; terminal/pin writers check under their existing transaction. Completion's failure reroute preserves the fence, while stored public result strips it.
- Five canonical knowledge failure reasons survive normalization and remain outside automatic retry. First-party ordinary credentials remain their existing task/daemon scopes; private endpoints accept current scoped daemon credentials, not PAT/JWT fallback.

Wire details and C3/C4 ownership are in `c3-wire-handoff.md`. C4 must independently close its Provider history isolation or cross-store downgrade proof; the ordinary runtime-history query reads ordinary task metadata only.

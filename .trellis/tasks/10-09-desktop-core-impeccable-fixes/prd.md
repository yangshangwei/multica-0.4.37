# 桌面核心页面 impeccable 审计修复

## Goal

让桌面核心页面可以可靠地通过键盘操作，并正确表达请求失败、状态文字、分页和动效偏好。关闭聊天后不能进入不可见内容；请求失败不能被误认为业务数据为空；大日期跨度不能造成无界日期 DOM。

## Background and authorization

源报告：`docs/audits/2026-10-09-desktop-core-impeccable.md`。审计评分 13/20，P1 六组、P2 四组、无 P0，包含 32 张截图及 DOM/焦点/故障/对比度记录。

用户于本轮明确要求「先创建一个新的 Trellis 任务并进入 planning，然后推进开发」。这是在已展示问题、修复顺序和范围后的任务创建及开发授权。按该指令先完成计划与审查，再自动进入执行，不重新请求相同授权。

任务创建前的工作副本已有这十组问题的修复及若干回归测试，且混有其他任务改动。本任务先核实这些现有实现，保留正确实现，补齐实际缺口；不会把旧报告的“未修改产品代码”当作当前源码状态。基线和文件摘要保存到 evidence/，原报告作为审计时事实保留。

## Acceptance Criteria

- [ ] AC-01 / DCF-01：关闭聊天后的 Shift+Tab/Tab 不进入隐藏窗口，无障碍树不含关闭聊天；打开、关闭、会话切换和已打开菜单有正确焦点与内容保留回归。
- [ ] AC-02 / DCF-02：冷缓存 500 显示错误和重试，成功后恢复真实内容；后台 500 保留已读内容与选择，详情 404 与 500 文案不同，权限状态仍按现有保护契约处理。
- [ ] AC-03 / DCF-03/04：任务、智能体、项目选择控件有描述范围/资源的名称；Tab 聚焦后可见，Space 改变选择；项目标题 Enter 只导航一次。
- [ ] AC-04 / DCF-05：真实 Electron 计算样式测得所有状态文字两种主题均至少 4.5:1，保留状态图标/文字语义和现有视觉体系。
- [ ] AC-05 / DCF-06/08：左右移动可用键盘和点击完成且遵守现有边界；智能体/技能 Tabs 可用方向键、Home/End、Enter/Space 操作，并有关联 panel；桌面当前项向辅助技术可知。
- [ ] AC-06 / DCF-07/09：窄窗/200% 中启用分页与聊天入口不重叠；reduce 下布局在启动和动态切换均无中间动画帧，普通偏好仍可用。
- [ ] AC-07 / DCF-10：十年以上日期跨度及大量任务中 DOM 受可视区域限制，三种缩放可滚动至末端，行键盘导航可越过虚拟边界。
- [ ] AC-08：实际行为回归、语言键一致性、相关包/工作区类型检查、定向 lint、detector 和 diff 检查通过；完成一次批量真实 Electron 复核及独立审查，记录剩余环境/辅助技术覆盖限制。
- [ ] AC-09：更新适用 code-spec 与修复追踪报告，明确每个问题的状态和证据；提交只包含本任务确认的改动，保留其他未提交任务内容，不发布/部署。

## Constraints and out of scope

- 维持现有视觉体系、token、信息层级与 Web/Desktop 共享边界；不重新设计核心页面。
- 不添加依赖；优先已有 Base UI Checkbox/Tabs、AppLink、CollectionPageState 与虚拟化库。
- 不修改 Go API、数据库、业务统计或写操作协议；复核不发送消息、运行智能体或写入用户业务数据。
- 不清理无关 lint 警告、不修改移动端、不合并或归档其他任务。
- 验收限于审计问题复核；不将定向复核冒称完整发布验收或全平台 WCAG 合规认证。

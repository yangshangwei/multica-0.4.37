## Requirements

- G1（D1–D4、R7–R13）：普通项目显式绑定物料输出仓与稳定根目录；工程探索输入和物料输出分开。物料身份、路径和来源仓完整修订可追溯，标题与业务状态变化不改身份。
- G2（D2、PAC1–PAC4）：可评审候选具备完整正文、稳定验收项、工程依据及无未解决阻塞项；形成候选后自动进入持久化发布流程。普通讨论、不完整草稿不触发远端提交。Agent 可提交候选内容，不能配置目标权限或作人工批准。
- G3（D1/D7、PAC2–PAC5/PAC8）：每个冻结修订对应一次可恢复的发布意图，生成需求分支和 PR/MR，禁止直接写默认分支或 force-push。真实远端回执与本地意图分开，超时先核对事实再恢复。
- G4（D5–D7、PAC9–PAC11）：仅有权人类可在 Multica 阅读、评论、批准或退回明确修订，不需要个人 Git 账号。决定保存真实身份、版本与时间；同步到 Git 的是明确署名的系统记录，不冒充原生人类 review。
- G5（D7、PAC5/PAC10）：有效批准触发系统自动合并；再次核对当前 HEAD、完整变更路径、目标配置、当前权限、原生门禁。旧批准、内容变更、夹带文件、冲突或原生审批不足均不能推进。实际合并结果及内容核对通过才建立正式基线。
- G6（D3/D10、PAC6/PAC7/PAC15）：讨论、分派、进度和归档只由 Multica 管理；纯状态变化不写 Git。物料合并不完成开发任务；保留历次修订、退回和过期决定，支持原意图恢复。
- G7（D8、PAC12/PAC13）：项目自动启动方案开关默认开启，显式关闭持久化。关闭时创建同一基线的 `todo` 方案任务并保持等待人工启动，创建、指派、恢复和领取均不能绕过。开关开启但缺少可用执行身份/输入时保留可解释的阻塞状态。
- G8（D8、PAC14）：手动启动复用原任务并重新检查输入和执行权限；重复事件、重复点击和响应丢失不重复建任务或并发运行。方案和任务计划绑定所用 PRD，当前方案未经审核不得编码。
- G9：沿用工作空间/项目访问控制、原始请求恢复及共享 core/views 边界；新响应必须经过 schema 解析并覆盖异常响应。未配置物料流程的项目行为不变。

## Implementation policy details

在已确认范围内采用以下保守实施规则；它们不改写父任务 D1–D10：

- 首期同时实现 GitLab（含显式配置的自建实例）与 github.com；不宣称 GitHub Enterprise 或任意 GitLab 版本已经验收。
- 配置由工作空间管理者管理，并显式指定当前项目的人类审核者和方案执行目标；服务端每次实际推进重新核验当前权限。配置成功不等于目标已具备写入、合并或执行能力。
- 重新开启自动启动仅影响后续新阶段；旧待办继续人工启动，避免批量释放积压工作。已经运行的任务沿用独立停止/取消操作。
- 方案尝试已失败、取消或结束但未提交方案时，有权人类可显式重试；复用原方案任务、保留历次运行记录，并重新检查基线与执行权限。恢复网络、后台对账和重新开启开关均不得自动重跑。存在活动运行或已进入方案审核时不得重复启动。
- 需求/方案修订失效与归档分别管理；不新增自动归档策略，也不扩大全局 `done` 语义。
- 方案及拆解在协调物料项目中形成，模块引用保留固定版本；跨模块自动编码、QA 自动修复和发布编排另做后续任务。

## Acceptance Criteria

- [x] A1：同一需求修订重复送达只产生一条远端评审链；两平台分别覆盖分支、文件、PR/MR 和回链。
- [x] A2：正文不完整、有阻塞项、越界路径、规则文件或无权来源不能发布；无效输入不产生远端副作用。
- [x] A3：有权且没有 Git 账号的人类可完成审核；机器凭据、伪造审核人和权限撤销均被拒绝。
- [x] A4：只有当前获批版本且原生门禁满足才合并；HEAD 变化、配置变化、外部夹带变更、冲突和撤回覆盖失败矩阵。
- [x] A5：PR/MR 创建或合并成功但响应丢失后，恢复原意图；入队、超时、批准和外部未经审核合并不能误报正式基线。
- [x] A6：基线交接完整固定版本 PRD、验收项与工程来源；正文不可读或摘要不符时不就绪，长正文不能静默截断。
- [x] A7：默认开启只启动一次方案阶段；关闭、刷新、预分派和恢复保持 `todo` 不执行，手动启动复用原任务；项目之间互不影响。
- [x] A8：方案修订/依据变化使旧批准失效；当前方案未获批不产生编码执行。
- [x] A9：Web/Desktop 共用入口能清晰区分草稿、候选、批准、合并/阻塞、基线及方案运行；失败可恢复，权限丢失不展示旧私有数据。
- [x] A10：定向 Go/Vitest、异常 API 响应、lint/typecheck、必要静态检查和集成链路通过；记录真实执行命令、环境与未覆盖范围。

# 物料仓库初始化与独立规则维护流程

状态：planning。2026-11-27 用户明确要求新建任务，按前一条完整目录方案设计并开发初始化流程。本任务沿用已确认的运行时 Git 方向，不要求 GitHub App，也不重复实现另一会话负责的物料运行时调度。

## 目标

首次绑定仓库、物料根和执行运行时后，自动检查格式与基础文件；缺失文件形成独立初始化候选，经有权人类审核、运行时合并及实际字节核对后，标记初始化完成并允许正常需求发布。已有内容和历史完整保留，重复调用不重复创建。

## 已确认范围

- 用户已认可完整逻辑目录：README.md、AGENTS.md、material.yaml、.material/schemas/、.material/templates/、modules/、requirements/、issues/、releases/、contracts/、specs/、decisions/、knowledge/。
- 初始化只产生有用的基础说明、schema 和模板；版本、模块、需求、问题及阶段产物按需创建，不虚构版本或空业务文档。
- releases/<version>/ 包含 release.yaml、test-plan.md、acceptance.md、baseline.yaml 的职责与模板；此次不将整个产品版本管理系统扩入初始化任务。
- Git 操作交给用户选定的底层运行时；服务端负责权限、状态、审核、调度和结果核验，不托管 Git 凭据。
- AGENTS.md、模板、schema 以及 material.yaml 属于独立初始化/规则维护流程，普通需求发布不可修改。
- 真实测试仓 yangshangwei/test--multica 和现有 uat/、PR #1–#6、Multica 测试项目全部保留；本任务不重排、删除或自动归属旧物料。

## 需求

- R1：保存首次有效仓库/根/运行时绑定后，发起一次仓库检查；身份、能力不足或运行时离线时显示明确可恢复原因。
- R2：检查完整目标树和基础文件，区分已兼容、缺失、冲突/未知格式；兼容仓复用，缺失内容形成确定性补齐方案。
- R3：已有文件不得静默覆盖、移动或删除。冲突保留现场并要求维护处理；无关目录如 uat/ 完全保留。
- R4：初始化候选与普通物料修订分离；展示完整文件差异、模板/格式版本、精确源 HEAD 和当前执行状态，接受当前有权人类的批准/退回。
- R5：仅当前有效批准且原生门禁满足后，由所选运行时执行合并；实际合并提交和全部预期文件核对通过才 ready。
- R6：普通需求允许整理草稿，但远端发布和后续阶段推进必须经过已初始化门槛。初始化尚未完成、配置变更或规则不兼容时不得绕过。
- R7：同一仓库绑定/初始化版本的重复检查、点击、回执和恢复复用原意图；响应丢失先对账，不重复 PR、任务或运行。失败/退回保留历史。
- R8：后续规则版本升级走独立维护候选、审核和核对，不混进 PRD 发布；当前版本无差异则不建 PR。
- R9：schema/template 覆盖产品版本引用、稳定物料身份、需求/问题/模块、验收和发布基线；不保存 token、私钥或实时任务状态。
- R10：共享 Web/Desktop 提供一致状态、差异、审核、重试入口；旧项目与旧物料不被自动迁移或误标 ready。

## 验收条件

- [ ] A1：新绑定检查一次，缺失基础文件生成一条独立评审；同一初始化重放无重复副作用。
- [ ] A2：已有 README、AGENTS、模板、业务内容及 uat 数据被保留；符号链接、路径越界、未知格式或内容冲突明确阻塞。
- [ ] A3：兼容仓无需新 PR，通过当前固定版本核对后可就绪；不把设置保存或运行 exit0 当 ready。
- [ ] A4：错误人类权限、机器自批、旧 HEAD、配置改变、额外路径、未知门禁均不可推进；历史记录保留。
- [ ] A5：合并响应丢失恢复同一意图，实际合并字节不符不能 ready；普通发布在 ready 前被服务端拦截。
- [ ] A6：运行时选择/授权来自项目配置，不新增 App、服务端 token 或第二套调度器。
- [ ] A7：初始化模板包含 releases 与版本引用合同；没有虚构产品版本、业务模块或空验收结论。
- [ ] A8：维护变更走独立流程，普通需求只可写本物料允许的文档。
- [ ] A9：受影响 Go/TS 测试、静态检查和必要共享 UI 验证通过；运行时链路与真实账户测试分别记录。

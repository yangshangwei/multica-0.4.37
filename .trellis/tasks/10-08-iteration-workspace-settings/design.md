# 迭代设置方案

状态：实施收尾中；用户已于 2026-10-09 授权按父任务 [closeout-plan.md](../10-08-iteration-workspace-settings/closeout-plan.md) 完成修复、验证、提交和归档。此前的规划状态由该授权取代。

## 1. 方案选择

| 方案 | 结果与代价 |
| --- | --- |
| 只搬到设置页，保留部署开关 | 入口更清楚，但仍需改配置，未满足本次要求。 |
| 工作空间独立控制，启停与时区分开操作（推荐） | 满足页面直接管理；复用已有安全事务，避免时区成功而启用失败的组合保存问题。 |
| 工作空间独立控制，新增统一保存事务 | 可照搬分拣台的统一保存按钮，但需合并共享项目时区与迭代事务、增加 API 合同，成本与风险不匹配本次收益。 |

沿用用户截图的现有界面规范，不引入新的视觉风格。使用场景是成员在桌面应用的工作空间设置中完成管理，优先可发现性、明确的保存状态和熟悉的控件。

## 2. 信息架构与页面

- 设置导航：“工作空间”下按现有顺序保留通用、成员、标签、分拣台，其后新增“迭代”；直达 `/{workspaceSlug}/settings?tab=iterations`。
- 标题：迭代设置。
- 说明：按周期安排任务，跟踪范围变化，并在结束时处理未完成的工作。
- 第一张卡片：启用迭代开关；当前进行中/计划数量及管理入口；只读手动管理方式。
- 第二部分：规划时区，说明与项目规划共用、旧迭代保留原时区；现有 TimezoneSelect；保存时区和取消修改。
- 页尾简短说明：开始/结束/关闭不会启动或停止执行，历史记录会保留。
- 不放默认协调人、周期长度、自动推进或容量占位配置；名称、日期、协调人属于每个迭代，由业务页维护。

### 视觉与适配

复用 SettingsTab、SettingsSection、SettingsCard、SettingsRow、Switch、Button、Dialog 和 TimezoneSelect。沿用 semantic tokens、项目字号、字体、边框与圆角；不新增 UI 依赖。不新增自造的产品级视觉系统。

桌面端设置目录与内容双列；窗口变窄时使用现有 SettingsPage 的目录折叠行为，行内标签和输入上下排列。所有开关有文字标签和状态说明，对话框保持键盘焦点，状态反馈使用 live region，错误使用 alert。中文和英文同步。

## 3. 交互合同

### 开启

1. 显示当前服务支持情况、设置状态、已保存共享时区；缺少这些数据时不可修改。
2. owner/admin 点击启用，使用明确显示的已保存时区和对应设置 revision 发起原有 enable 命令。
3. 等待期间控件禁用；成功后开关才确认为开启，显示反馈并刷新入口。
4. 409 说明状态/时区已改变，重新获取并让管理员明确重试；不自动以更新过的版本替旧意图提交。
5. 开启不产生迭代、任务或执行。

### 保存时区

- 单独编辑并保存，当前值/浏览器值/完整 IANA 列表使用现有选择器。
- 有未保存修改、正在保存或结果待确认时，启停开关不可操作，给出简短原因。
- 保存成功后重新读取共享时区和迭代设置，再解除启停限制；不要仅把本地草稿当作服务器最终值。
- 失败保留输入。响应不明时先重新读取：值已匹配则确认保存；否则保留草稿供明确重试，不自动回滚服务器值。
- 背景远端更新不覆盖脏草稿；清洁状态跟随最新值。沿用现有 planning-timezone API 的并发语义，不假装有其并未提供的 revision CAS。

### 关闭

1. 点击开启状态的开关后，保持开关显示开启，打开关闭预览。
2. 使用完整服务端预览，展示全部受影响周期和任务数量，可展开具体明细；数量加载失败时不显示零。
3. active → completed 并保留快照；planned → cancelled；任务只清除当前迭代归属。填写关闭原因，明确“再次开启不会恢复旧周期”。
4. 管理员确认后以原 preview_hash 和持久 request_id 提交现有 disable 操作。
5. 任一冲突需重新预览；超过 2,000 条任务只给出先整理的可操作提示，不分批执行。取消或失败后仍显示真实服务端状态。
6. 保留原子历史、归属、回执与通知合同。运行中的执行保持不变。

### 状态与导航

| 状态 | 设置页 | 工作侧边栏与历史 |
| --- | --- | --- |
| 首次未启用 | 开关关闭，展示时区与说明 | 不展示日常迭代入口，从设置启用 |
| 已启用 | 显示开关、准确的当前数量、管理链接 | 显示迭代入口 |
| 已关闭 | 允许再开启，显示查看历史链接 | 隐藏日常入口，设置和旧链接仍能读历史 |
| 普通成员 | 相同信息只读，说明由所有者/管理员修改 | 遵守现有成员读取权限 |
| 旧后端不支持 | 设置目录仍可找到，显示版本不支持与重试 | 不提供启用操作，不把 401/403/撤权误判为旧版 |
| 操作结果未知 | 恢复提示独立于 enabled/支持判断挂载 | 原身份恢复，不自动提交新意图 |

历史链接在禁用状态保留，即使没有历史也进入正常空列表，不为可发现性新增 has_history API。日常侧边栏只跟随已确认的 supported/manual/enabled 状态；新设置入口保持可发现。

旧迭代页的配置折叠区域替换为“迭代设置”链接；禁用状态有设置引导并保留列表/历史。不制造第二套启停控件。历史页对元数据编辑继续遵守既有权限与生命周期规则，本次不改变其合同。

## 4. 前后端边界

### 后端

- 删除 iterations_i1 与 IterationService.Available 运行时依赖，覆盖能力、管理、任务归属、分拣接受与通知 runner。
- 保持能力接口响应字段与 schema_version=1：supported/manual/atomic_handoff 为实现能力，enabled 直接来自工作空间设置。
- 保留所有工作空间 membership、稳定人类 actor、owner/admin、disabled assignment、单一 active、锁顺序和重试约束。
- 不增加迁移，不更改现有设置行或默认值；不做恒 true 的内部兼容 shim。
- 启用成功后复用已有提交后 iteration:updated 发布模式，确保其他已打开客户端更新；不能在提交前发布，重试通知仍幂等。

### 共享客户端

- 新增 `packages/views/iterations/iteration-settings-tab.tsx`，SettingsPage 注册并复用已有路由；导航文案放 settings.json，业务文案放现有 projects iterations namespace。
- 启用和关闭沿用 useIterationCommand 的 `enable`、`disable:workspace` scope，保留原始完整 payload；设置页独立挂载 IterationRecovery。
- IterationOperation 只作必要的触发器/受控打开扩展，默认用法保持；共享核心只存业务和请求，不持有 UI 状态。
- 本地启停及 realtime 更新同时刷新 iterations 与分拣台迭代能力；时区更新刷新项目及迭代设置，避免无效的关联数据镜像。
- 大量集合的完整性沿用现有分页/预览 helper，不用当前可见页算关闭影响。

## 5. 兼容、升级和风险

- 新桌面 + 旧后端：保留现有能力检测和明确不支持状态；不提示用户修改配置文件。旧服务要支持新行为需升级服务。
- 旧桌面 + 新后端：保持 API 路径/响应与旧配置控件行为可用；新后端按 workspace enabled 约束。
- 旧部署残留 FF_ITERATIONS_I1 将不再控制能力；更新现行自托管样例、离线升级文档和受影响规范，历史发布证据不回写。
- 曾被总开关隐藏但 enabled=true 的工作空间升级后重新可用，通知 worker 可能继续投递已有 outbox；明确写入升级说明并验证。未启用的空间绝不自动开启。
- 撤回实现可以回退代码；若同时回退到旧后端，其旧部署 gate 会重新生效。不能用盲目关闭全部空间作为回退方式。

## 6. 设计交付与验证边界

`preview/iteration-settings.html` 是对话内交互方案；其中计数与周期名均为示例数据，不连接真实后台。包含已启用、首次使用、禁用历史、普通成员、旧服务五种可切换预览状态。时区预览仅列少量选项，生产实现复用完整选择器。

预览验证包含开关、关闭原因、关闭后历史入口、重新启用、时区保存/取消、深浅色和窄窗口。正式版本仍必须经过 implement.md 的 API、组件、权限、并发恢复和真实 Web/Desktop 验收。原型通过不等于功能已经上线。

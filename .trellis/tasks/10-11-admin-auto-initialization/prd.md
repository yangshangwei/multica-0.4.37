# 升级时自动初始化专用超级管理员

## Goal

在密码模式且后台已启用的部署中首次创建 platform_admin，生成独立随机初始密码并要求首次改密；重复升级保留已有管理员和凭据。

## Background

旧环境升级后目前需要先注册密码账号、查询 UUID，再运行部署维护命令授予平台角色。用户希望升级包提供可直接登录的专用管理员，减少这些人工步骤。

2026-10-11 用户已确认固定用户名、每套部署独立随机初始密码、服务器受限文件交付、首次强制改密、已有管理员不覆盖，以及仅在密码模式且后台开启时初始化；本轮明确授权创建任务并进入实现规划。

当前事实：人工 `Bootstrap` 要求指定的已有账号已完成密码设置（`server/internal/service/platform_admin.go:491`），受限会话已有服务端门禁（`server/internal/auth/password_session.go:142`），离线升级在迁移健康成功后报告完成（`scripts/offline-upgrade.sh:242`）。详细证据集中在 `research/`，不把现有人工初始化当作已实现的自动功能。

## Requirements

- R1：符合条件的部署首次完成离线升级时，自动建立用户名为 `platform_admin` 的专用超级管理员，无需用户手工注册、查询 UUID 或执行角色授权；升级后才开启后台时可运行同一个维护脚本补做初始化。
- R2：每套部署生成独立随机初始密码，交付到业务部署目录的 `admin-initial-password.txt`（默认 `/opt/multica/admin-initial-password.txt`），仅部署维护者可读；密码不进入源码、镜像、升级归档、普通日志或命令参数。
- R3：首次登录必须修改密码，改密之前不能进入管理后台、读取业务数据或生成可绕过该限制的凭据。
- R4：已存在的平台角色（包括观察者）、账号密码和权限保持不变；重复升级、重复初始化、重启和多个初始化进程不会重置密码或产生额外管理员。既有管理员停用、撤权或删除后，仍以保留的初始化历史判定，不能自动重建。
- R5：仅 `MULTICA_AUTH_MODE=password` 且 `MULTICA_PLATFORM_ADMIN_ENABLED=true` 时执行；不自动切换旧设备认证，不更改原有注册策略，也不扩大普通账号权限。
- R6：失败或中断后可辨识实际初始化状态并安全重试，不遗留“管理员已创建但密码尚未落盘”的故障窗口。对已提交后被外部删除的文件明确要求受控恢复，不自动重置密码；已经改密的账号不再依赖初始文件。
- R7：升级文档和交付校验同步更新，说明首次取密、改密登录、已有管理员的升级行为，以及异常恢复边界。

## Acceptance Criteria

- [x] AC1（R1、R5）：密码模式且后台开启时由离线升级/独立维护脚本创建专用账号，无需开放普通注册；CLI、服务和脚本边界已覆盖。
- [x] AC2（R2）：每次初始化使用独立随机密码；凭据文件权限、归属、打包排除和日志/回执秘密边界已有测试。
- [x] AC3（R3）：临时账号仅允许改密；强制改密、旧会话撤销、角色保留和后台会话路径已有服务端/客户端回归。
- [x] AC4（R4）：既有角色/历史、待改密账号、重复/并发初始化及永久标记保留已有服务、迁移和 CLI 测试。
- [x] AC5（R4、R5）：同名普通账号冲突、设备模式和后台关闭均 fail closed，不会提权或写凭据文件。
- [x] AC6（R6）：文件/事务/审计/响应中断、缺失凭据及不确定提交均有可核对状态和安全重试行为。
- [x] AC7（R7）：升级包文档、平台管理双语文档、桌面交付清单和内置文档已同步；人工 bootstrap 保持受控。

## Out of Scope

- 在升级包中内置所有部署共用的固定密码。
- 自动把设备账号切换成密码账号，或自动修改现有后台开关。
- 重置已有管理员密码、把已有同名普通账号提升为管理员。
- 新增公共 HTTP 管理员创建接口、修改工作空间权限模型或实现新的身份提供方。
- 本轮构建、发布升级包或对真实旧部署执行升级。
- 普通 API 启动时自动开户、无升级脚本的新安装自动引导，以及还原被人为销毁的全部历史初始化证据。

## Key Decisions and Limits

- 自动入口是离线升级后的部署维护步骤；所有注册和管理员 HTTP 接口保留原有授权边界。
- 初始密码写入目标部署的私有文件；不使用共享默认密码、不在数据库存储可逆密码，已存在账号不被接管。
- “首次初始化”依赖永久记录和保留的管理员证据，与“当前有效管理员数”分离。
- 首次改密必须使用不同的新密码，服务端负责校验；沿用共享登录表单及受限会话流程。
- 备份回档、外部删除初始文件或清除旧管理员全部历史属于运维恢复边界，不能承诺从密码哈希还原原始秘密。

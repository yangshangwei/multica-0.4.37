# 设计方案：让模板预览与实际执行使用同一份中文正文

## 现状与选择

服务端 `builtin_autopilot_templates/<key>/PROMPT.md` 是执行正文的唯一来源。模板列表直接返回正文，`CreateAutopilotFromTemplate` 把它写入 `autopilot.description`；调度时原样进入执行上下文。前端只负责展示，界面语言只控制名称、摘要和分类。当前 9 份正文和 4 个 `IssueTitleTemplate` 是英文。

选择与已有智能体和 role skill 一致的方案：在服务端直接维护简体中文正文。中文语句按业务重写，正文中明确中文交付要求，保留技术字面量。中文目录文案与正文同步；4 个持久化任务标题使用中文加日期占位符。

对比过的替代方案：仅翻译前端预览会使实际执行继续收到英文；增加按语言选择的正文集合会引入多份业务规则和新的创建逻辑。两者均不适合本次以中文作为共同工作语言的目标。继续保留现有多语言目录标签，不引入新的语言配置。

## 数据流与兼容性

`嵌入的中文 PROMPT.md → 模板列表 prompt → 只读预览 → 服务端按 key 复制 → autopilot.description → 运行上下文`

`IssueTitleTemplate` 仍为单个字符串，4 个汇总模板使用 `中文名称 — {{date}}`。现有 `interpolateTemplate` 按触发时区生成日期。`run_only` 继续存 NULL，不生成空跑任务。

请求字段与响应 schema 不变。客户端不能决定模板正文、标题模板、周期或输出模式；未知请求字段继续按现有行为忽略，不能借本任务改变兼容性。创建仍使用同一事务，保留成员权限、执行人就绪检查、规则版本、订阅和事件发布。

更新模板只影响新建实例。旧实例是工作区持有的快照，无启动回写、无自动迁移、无随查看语言变化的正文重写。

## 内容规范与业务边界

每个模板围绕「做什么、查什么、交付什么、哪些动作不能做」组织；面向实际工作，不逐句照搬英语修辞。

5 个巡检统一保留：先检索当前工作区中本自动化创建且尚未关闭的任务；已有任务覆盖问题时补充证据；只有未被覆盖的实质问题才新建任务；没有实质问题时「不创建任务，也不发表评论」。巡检没有预先创建的汇总任务，不能要求向不存在的当前任务交付。

视觉验收发现中文输出模式原说明为「静默运行，不创建任务」，容易误读为巡检发现问题后也不能建任务。将该说明精确为「直接运行，不预先创建任务」，与 run_only 的派发语义和正文中的按需建任务一致，不改变功能。

4 个汇总明确「本次汇总任务已由系统创建」，在该任务发表评论。空时段也有结果，但不凑发现、不另建汇总任务。发布决策、代码修改、合并、重新分配和状态变更仍不属于这些模板的职责。

保留各模板独立阈值：工作日巡检关注超过 2 个工作日的停滞变更、落后至少 2 个主版本的依赖；PR 提醒为超过 24 小时且未获评审的非草稿 PR；依赖专项为落后超过 2 个主版本；每日回顾为近 24 小时；文档与周报为近 7 天。

研究发现缺陷模板将 `critical` 严重程度直接交给 priority 有歧义，而实际 API 仅接受 `urgent/high/medium/low/none`。中文模板明确映射：严重→`urgent`、高→`high`、中→`medium`、低→`low`，并保留 `contributor` 写入与 `observer` 建议的权限边界。该模板版本升为 2，记录此业务修正；其余 8 个语言与表达调整保留版本 1。

## 验证设计

1. 注册表测试：9 个正文的中文章节、全部模式与周期、中文日期标题、巡检去重及静默约束、汇总交付对象、缺陷优先级映射。
2. 真实数据库 handler 测试：全部模板读取与创建、prompt 与数据库一致、合法时区和 next_run、来源与订阅、用户编辑不被后续目录读取覆盖；现有权限与事务回滚测试继续运行。确认没有数据库不可用而跳过的假通过。
3. 执行测试：两种模式实际派发，中文正文进入 task/issue，中文标题按时区展开日期，run_only 无预建任务。使用隔离假运行时，不调用真实模型。
4. 浏览器验收：中文目录与预览显示完整，真实模板 API 创建后在详情编辑并读取；原有 mock 请求边界测试继续保留。屏幕截图需检查中文换行、滚动与窄视口溢出。
5. 独立内容复核：逐份对照旧正文与业务合同，检查阈值、去重、静默、权限、证据和中文版可执行性。字串测试只保护合同锚点，不能代替语义审查。
6. 运行项目 lint、typecheck、TS/Go 测试及 Go vet。任何非本任务引入的失败也需查明，不将跳过或弱证据算作完成。

## 交付与回退

变更集中在 9 份正文、注册表、相关测试和 Trellis 记录；只修改接口文件中过时的英文正文注释，不新增业务分支。新版本需重建并重启当前 checkout 的开发 API 才能读取新的嵌入内容。回退这些内容文件并重建即可恢复新建默认内容，已有实例保持其独立快照。

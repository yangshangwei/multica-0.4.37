# 内置自动化模板中文化与业务验收

## 背景

中文工作区中，自动化模板的名称和界面已经显示中文，但「交给智能体做的事」仍是英文。用户需要像此前的智能体和 skill 一样，直接阅读、采用和维护符合中文团队工作方式的内置内容。

需求来源：用户本轮请求及截图 `/Users/artisan/.codex/attachments/15822f0d-ce5f-4c97-9d2e-96f1ac097784/image-1.png`。用户已明确要求生成需求、制定方案、推进实现、使用 Trellis 并完成验收，包含本任务的创建与执行授权。

## 目标与范围

覆盖全部 9 个内置自动化模板的执行正文、中文名称与摘要，以及自动生成任务的默认标题。中文正文应说明目标、实际检查方法、交付内容和操作边界，保留必要的命令、标识符和协议值。

| 模板标识 | 中文名称 | 业务结果 |
| --- | --- | --- |
| workday-repo-audit | 工作日仓库巡检 | 检查依赖、测试和滞留变更；有实质问题才建任务 |
| release-readiness | 发布准备检查 | 每周汇总可发布内容、阻塞与风险，给出有依据的建议 |
| daily-change-review | 每日变更回顾 | 回顾最近 24 小时变更，报告正确性、体验与测试覆盖风险 |
| hourly-queue-check | 每小时队列巡检 | 发现停滞任务、不同步的生成文件和持续失败的快速检查 |
| stale-pr-reminder | PR 评审提醒 | 汇总超过 24 小时未获评审的非草稿 PR，提醒相关人员 |
| bug-triage | 缺陷分级 | 对尚未分级的缺陷评估影响、设置合法优先级或给出建议 |
| weekly-progress-report | 每周进展报告 | 汇总近 7 天完成、进行中、阻塞任务与可核对的数量 |
| dependency-audit | 依赖审计 | 检查真实可达的漏洞与严重落后的依赖版本 |
| documentation-check | 文档同步检查 | 核对近 7 天变更与文档，报告用户会遇到的真实缺口 |

## 验收标准

- [x] R1：9 个模板的执行正文、章节和交付格式均为自然的简体中文；任务、工作区、智能体、自动化等用语符合产品规范，技术命令和协议值保持有效。
- [x] R2：中文目录名称、摘要与正文业务一致；4 个汇总模板生成中文任务标题并保留 `{{date}}`；5 个巡检模板不设置任务标题模板。
- [x] R3：预览的正文与创建后持久化的正文一致，实际运行收到该正文；所有模板仍能创建、编辑和运行，时区、调度、订阅及来源信息正常。
- [x] R4：保留巡检去重、无问题不发任务或评论、汇总每次产出结果、只引用真实证据，以及原有检查范围和时间阈值。
- [x] R5：缺陷分级明确严重程度到合法优先级 `urgent/high/medium/low` 的映射；证据不足保持未分级；`observer` 只评论建议，权限不足不会谎称已修改；其余权限不扩大。
- [x] R6：模板更新不覆盖已有自动化或用户自定义内容；语言切换不重译持久化正文；接口形状、稳定 key、顺序、执行模式和周期保持兼容。
- [x] R7：有可复核的注册表、真实数据库、创建及运行链路和中文浏览器验收证据；相关测试、lint、typecheck 和静态检查通过；需求、设计、实施记录和验收结果纳入 Trellis。

## 非目标与约束

不增加依赖、数据表、迁移或新执行模式。不批量修改已创建的工作区实例。保留进入本轮之前的其他未提交工作。自动化测试使用隔离工作区和假运行时，不向真实团队发送测试评论，不启动真实智能体账号执行。

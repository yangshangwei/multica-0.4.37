# 多账号多 Agent 跨空间协作闭环测试

## Goal

在隔离环境模拟多个账号与 Agent，验证跨空间任务创建、资源授权、执行交接、退回修改和最终验收，输出可追溯测试报告。

## Background

- 用户已批准创建本任务并进入测试规划；本阶段没有执行测试，也没有测试结论。
- 现有 `e2e/collaboration-memory-runtime.spec.ts:45` 验证两个独立运行环境在同一任务中通过实际 CLI 接续共享上下文，但不包含交付验收。
- `e2e/collaboration-detail-journey.spec.ts:37` 覆盖人工退回、重新提交和验收，明确排除 AI 执行，且环境使用 legacy 认证。
- `e2e/collaboration-host-squad.spec.ts:16` 覆盖真实调度器下的小队委派和继续执行，但其成员同属一位资源拥有者。
- 因此，完整证明本次目标需要一条新的同任务主线，现有分层用例仅作为补充回归。

## Requirements

- R1：模拟产品、研发、测试三个账号，分别归属不同工作空间；另设无关账号检查访问边界。
- R2：使用隔离测试数据完成同一条协作任务的创建、参与者加入、请求/返回信息、转交、提交结果、退回修改、再次提交及最终验收。
- R3：三个账号分别提供需求、修复、验证模拟 Agent，分别授权后显式恢复，通过提及和预览发送驱动实际调度、执行、回写；验证共享上下文和结果交接。
- R4：验证未授权、无关账号、授权撤回、停止/恢复、重复请求等边界，不将入队或模拟回执视为执行完成。
- R5：交付中文测试报告，记录环境及源码身份、账号/资源拓扑、步骤、预期/实际结果、日志/截图、问题复现、未覆盖项和执行命令。
- R6：复用现有测试设施；本次只测试与报告，不修改产品行为，不调用用户已登录的真实 AI 服务或发送外部消息。

## Acceptance Criteria

- [x] AC1：报告可追溯到本次执行，三个协作账号、三个工作空间、三个模拟 Agent 和一个无关账号有明确身份及资源归属。
- [x] AC2：同一条主线任务串起多方处理与一次退回修改，最终由发起人验收；Agent 成功与业务完成分别断言。
- [x] AC3：实际观察模拟 Provider 进程启动、运行结果及回写，验证 Agent 间上下文接续；分层回归不得冒充同一任务闭环。
- [x] AC4：权限与生命周期检查逐项记录通过、失败、阻塞或跳过；失败保留原始证据和复现步骤。
- [x] AC5：测试只写入明确归属本任务的环境，保留原有工作区修改，凭据不进入报告。
- [x] AC6：中文报告提供总体结论、覆盖矩阵、问题列表及模拟测试的证据边界，不把未测项标为通过。

## Out of Scope

- 真实付费模型质量/配额验证、跨服务器协作、移动端和安装版客户端全面验收、产品缺陷修复及上线。

## Decisions and Evidence Limits

- 以 Web 的三个独立浏览器会话覆盖主线，底层使用真实 API、数据库、调度器和 CLI，以及确定性的模拟 Provider 子进程。
- 使用合成的订单去重协作材料和预设 Agent 输出，验证协作编排、权限、上下文传递和交付记录；不声称证明模型推理或实际支付系统修复质量。
- 三个运行环境在同一物理机器上隔离配置和工作目录；不宣称三台物理机器或操作系统沙箱验证。
- 环境依赖已完成只读检查；真正执行前仍须证明新数据库、端口、服务进程和构建产物属于本任务。
- 无待用户决定的产品或范围问题；下一道流程门是最终测试计划审阅。

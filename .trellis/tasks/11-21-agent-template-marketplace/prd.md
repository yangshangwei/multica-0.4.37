# 将智能体角色模板纳入能力市场

## Goal

让用户在能力市场统一发现智能体角色模板，并能从智能体管理页直接开始模板创建；已创建成员继续由智能体目录管理，创建过程保留原有配置和小队上下文。

## Background

- 用户通过当前「创建智能体 / 选择角色」截图提出将模板页面纳入能力市场，并于 2026-11-21 授权创建任务、推进设计规划。
- 当前市场包含 MCP、Skills、AI小队模板，选中类型由 URL 持有，Web/Desktop 共享页面。证据：`packages/views/marketplace/marketplace-page.tsx:18`、`:27`、`:59`。
- 当前智能体模板选择与配置共用 `/agents/new/template`，通过 `template` 参数区分阶段；已有成员链接和小队上下文已有回归保护。证据：`packages/views/agents/create/template-create-agent-page.tsx:36`、`:183`、`:217` 及对应测试 `:154`、`:254`、`:290`。
- 仓库规格目前限定角色模板仅存在于创建流程，本任务需同步更新这一归属，继续禁止将模板混入智能体成员目录。证据：`.trellis/spec/views/frontend/agent-discovery.md:3`。
- 更完整的现状、约束和测试证据见本任务 `research.md`；相邻任务为 `11-21-squad-marketplace`，本任务在其现有市场分类机制上增量规划。

## In Scope

- Web/Desktop 共享能力市场中的「智能体模板」分类及其到模板配置的路径。
- 共用角色模板卡片与模板查询，保留现有快捷创建入口的上下文、实例链接和配置行为。
- 分类路由、返回行为、生命周期、英中本地化、定向测试及规格同步。

## Requirements

- **R1 — 模板发现。** 能力市场新增「智能体模板 / Agent templates」，展示现有服务端模板的角色名称、描述、头像与已识别的权限范围，卡片主动作「使用模板 / Use template」进入该模板的创建配置。市场浏览不创建智能体、不加入小队。
- **R2 — 模板与成员边界。** 市场分类不展示已有智能体列表、已创建数量或「尚未创建」提示，也不依赖智能体列表请求。原创建选择器保留已有实例链接及显式「创建 / 再创建」行为，成员编辑和日常管理仍由智能体目录/详情承担。
- **R3 — 双入口、同一内容。** 智能体页的创建按钮及创建方式页继续直接到现有模板选择器；与市场复用同一套领域卡片和查询，不复制角色清单，不强制绕经市场。手动创建、AI 创建及现有欢迎页主动作不变。
- **R4 — 现有创建语义。** `squad` 在原创建选择/配置之间保留。普通创建成功进入新智能体详情；小队创建仍尝试添加成员并回小队。创建失败保留输入；加入小队失败不得把已成功创建的智能体当作创建失败重试。
- **R5 — 返回来源。** 市场进入配置时携带受限的来源标识。其返回动作优先采用既有应用内历史；没有可用历史时回市场的智能体模板分类。原创建配置仍返回原模板选择器并保留 `squad`。来源参数不能成为任意返回 URL，也不进入 API 请求。
- **R6 — 市场生命周期。** 新分类使用 `type=agent-templates`；缺失/未知 type 仍默认 MCP，既有分类顺序保持，新分类追加。类别切换保留其它 query/hash，浏览器前进/后退恢复选中类别。面板首次访问后保留挂载，隐藏时不可交互且停用该面板的模板查询观察者；不得改变共享模板缓存或其它活动消费者。
- **R7 — 状态与隔离。** 模板加载、失败可重试、成功空目录分别呈现；未知权限不虚构标签，未知模板 key 不进入配置或触发写入，沿用现有安全回退。工作空间变化重建控制器；目录内类别往返保留滚动，跨路由/桌面标签切换沿用现有平台恢复，不新增全局草稿持久化。
- **R8 — 一致性与范围控制。** 英文与简体中文同步，标签键盘语义和窄屏可达性沿用现有组件；更新归属规格，不改后端角色内容、权限或响应模型。

## Out of Scope

- 不修改角色模板内容、权限模型、后端接口或数据库。
- 不重做智能体目录、详情页、手动创建、AI 创建或小队配置流程。
- 不调整 MCP、Skills 和 AI小队模板的业务行为、默认类别或既有相对顺序。
- 不删除或重定向旧 `/agents/new/template`，不把小队招募流程送入市场。
- 不新增模板搜索、收藏、排行、预览弹窗、外部注册中心、移动端页面或通用市场框架。
- 不新增依赖，不引入跨路由草稿自动保存或任意 `returnTo`。

## Approved Key Decisions

- 采用「市场负责发现、创建器负责配置、目录负责成员管理」及共享内容双入口方案；市场展示方式与原创建器可以不同，但不复制模板卡片实现。
- 市场卡片移除实例信息，原创建器保留已验证的防重复创建能力；这是对现有功能影响最小的边界。
- 延用现有配置 URL，增加受限来源值区分返回；不新增页面路由、服务端模型或重定向。
- 保持当前视觉系统和市场分类顺序，第四类追加智能体模板。

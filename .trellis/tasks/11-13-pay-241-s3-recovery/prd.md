# PAY-241 S3 执行与协作恢复

## 目标

证明协作在超时、失败、取消、断线与并发修改后可以恢复原意图，且不重复派发、评论、附件、结果或通知；恢复重新核对当前权限，保留原始失败与历史身份。

## 背景与边界

父任务为 `../11-13-pay-241-collaboration-acceptance`。用户已授权 S3 规划、实现、测试、本地提交和独立检查后归档。当前先开展不依赖 S2 职业规则的研究与验证准备；不会据此跳过 S2 或关闭父任务。已有 outbox、workflow operation、run/command history、Stop/proof/Resume 复用，不重建恢复机制。

## 要求与验收

- [ ] R01 / TC14：真实启动受控进程并触发超时、失败及取消竞争，保留原 run/attempt/request 身份，明确终结证明；真实模型质量/账户调用另列。（部分：timeout-proof已证明受控执行deadline、Stop两种先后顺序与原回执跨进程恢复；本条在S3全范围验收前保持未勾选。）
- [ ] R02 / TC14：未知响应、重复请求、迟到结果和显式重试均不能重复派发或重复保存评论/附件/结果；新成功不改写旧失败。
- [ ] R03 / TC15：多条离线事件补读后持久ID/顺序/最终状态完整且无重复，不能只验证一个WS帧或一条评论。
- [ ] R04 / TC16：负责人和优先级同版本竞争明确拒绝冲突；协作与普通子任务分别验证，不掩盖普通可选expected_revision的边界。
- [ ] R05 / TC21：断线、排队和恢复期间撤权后，任务、附件、原运行和间接读取均不得泄漏受保护内容。
- [ ] R06 / TC22：人员提及、Agent提及和订阅通知目标准确，以原事件身份去重；重放/重连不产生第二通知或执行。
- [ ] R07 / TC23：阻塞原因、责任人、解除条件与预计解除时间完整；解除记录实际人、时间和恢复状态。新增规则与 S2 阶段合同一致。
- [ ] R08 / TC20：所有恢复动作有来源版本、当前身份与权威证据链接；失败保留，不能把未知写成未执行后重新发出。
- [ ] R09：独立新DB与源码匹配的API/production Web/Desktop验证，原执行gate恢复；原生Trellis独立检查通过后才可关闭本包。

## 不纳入通过结论

真实模型超时/质量、支付和履约幂等、生产发布/回滚、100协作者性能不由本包测试推断。S3局部断言只能推进父矩阵对应子断言，原24例未满足部分继续开放。

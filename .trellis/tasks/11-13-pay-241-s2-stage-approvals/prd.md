# PAY-241 S2 角色审批与阶段门禁

## 验收标准

- [ ] A01：角色配置、稳定责任与当前处理人可分辨；配置、变更、撤权均按当前权限处理并留痕。
- [ ] A02：建议接受/修改/拒绝的正反路径与精确版本；并发/重放仅产生同一子任务，拒绝或未批准零派发。
- [ ] A03：PR/CI 缺失、失败、版本不符时明确拒绝代码评审且阶段不变。
- [ ] A04：无人工代码评审批准拒绝 QA；自评、伪造人类、撤权签字被拒绝。
- [ ] A05：失败运行、失败用例、日志绑定，QA 退回与重新测试历史保留；Agent 覆盖人工结论请求被拒绝。
- [ ] A06：无 QA 批准或构建不符拒绝发布批准；QA 越权发布被拒绝并留痕。
- [ ] A07：回滚建议不能执行；人工批准绑定原部署及回滚目标，不能当作已执行结果。
- [ ] A08：上游版本或审批配置变化、撤权、过期批准、旧键变更载荷均被正确拒绝；同键原意图可按当前读权限恢复。
- [ ] A09：完成的每种实际入口都无法跳过阶段证据，原 M1/off/observe/enforce 与管理员例外边界不被放宽。
- [ ] A10：跨空间或中途撤权读取无私有证据泄漏；许可判断基于真实主体。
- [ ] A11：生产 Web 与匹配源码的 Desktop 在独立环境验证配置/批准/拒绝/恢复，测试账号签字明确为模拟人工。
- [ ] A12：独立 Trellis 检查通过，更新父矩阵和缺口；不把 S2 通过标为真实支付、部署或全部24例通过。

## 范围边界

本包新增业务阶段所需的最小持久授权和共享操作界面，复用现有身份、事件、原键恢复、子任务和完成事务。真实支付、远端仓库/CI、发布执行由 S4 验证，100 人性能由 S5 验证；可消费其精确证据合同但不凭手填记录宣称集成通过。不调用真实模型账号、真实资金或生产发布，不改写旧证据，不新增依赖。

## 已确认产品规则（2026-11-13）

用户分别确认“采用推荐边界，保留人工手建”和“采用推荐的审批隔离规则”。

- 项目显式启用阶段门禁，默认关闭，复用现有政策的明确启用/回退方式；任务指定真实人类责任人与签字人，职业名称不赋权。
- 允许显式兼任；实现责任人不能评审自己的代码，QA与发布审批由不同人承担。最终验收仍为当前发起人，失能管理沿用R38，不新增任意代理验收。
- 来源workspace当前owner/admin、且具备当前任务参与/管理权限的人配置角色和稳定业务责任；候选签字另查指定角色、参与者/账号/凭据代际。未配置或已失效则显示缺项。
- 保留原人类手建child权限。AI建议自动物化须指定产品人对精确版本批准；人工创建不是AI建议的批准，不生成其物化映射。

- PR及基础CI齐备才进入代码评审，人工评审通过才进入QA。上游内容/代码/构建、当前权限或审批配置变化使相关旧批准不再适用。

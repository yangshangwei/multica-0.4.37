# 修复与交付计划

1. 从远端日志逐项确认失败；保护现有未提交内容。
2. 核验移动端 triage 标签、内置 skill 章节提取、审计版本 schema 和配套 E2E 草稿。重新生成已落后于中文源的内置文档包。
3. 独立数据库复现分拣提醒及生命周期删除竞态，先证明失败再最小修复，重复 race 回归。
4. 运行静态检查、TS/Go 测试、生产 Web 构建与分拣 E2E；独立评审所有发布修复。
5. 逻辑分组提交、推送修复分支与 PR，等待远端检查，合入 main 后核对同提交检查。
6. 按仓库 vX.Y.Z 补丁规则创建新 tag，等待发布完成，核验 Release 和镜像摘要及 changelog 身份，更新 T1 台账。

已有行为保护：移动端完整类型映射、内置模板 500 行预算、审计 schema 隐私回归、分拣提醒精确数量、删除竞态不允许半写。不得通过放宽这些行为约束让 CI 通过。

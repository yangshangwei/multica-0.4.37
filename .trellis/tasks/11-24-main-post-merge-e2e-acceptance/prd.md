# main 合并后完整端到端验收

## Goal

判断刚完成合并的 main 在核心业务、协作与知识流程、权限隔离、实时一致性和各客户端上的实际可用性。先形成全面且可追溯的测试计划，再执行本地隔离验证，给出有证据的验收结论、缺陷和覆盖缺口。

## Background

- 用户明确要求新建任务，先列全面测试计划，再做完整端到端测试。
- 本次基线为 main 的 `103e2bc32`；创建任务前没有已跟踪文件的未提交修改。已有大量历史 QA 产物，本次证据使用独立目录，旧报告只作为风险输入。
- 项目包含 Go API/CLI/daemon、Web、Electron、独立 Expo 移动端、文档和共享包。用户可见的端到端行为与单元测试、构建结果分别记录。
- 现有默认检查固定 legacy 认证，仅配置 Chromium，且关闭 managed installations、knowledge context、platform admin、device auth；默认检查不能代表这些配置场景已通过。
- 本机为 macOS arm64；缺少完整 Xcode 和 iOS 模拟器。现有桌面包的版本与本次 main 不一致，不能作为本次安装包验收证据。

## Requirements

- R01：先产出领域覆盖矩阵、环境矩阵、执行顺序、验收标准和证据规则。测试范围同时覆盖正常路径、拒绝/失败路径、边界条件、并发和恢复。
- R02：测试实际执行的源码、API、生产 Web、桌面资产和 CLI 都能绑定本次 main 基线；开始和结束分别检查来源，不能继承旧候选绿灯。
- R03：覆盖账号认证与恢复、工作区/组织与成员、任务和子任务、项目、迭代、筛选搜索、评论附件、Inbox、Agent/小队、Chat会话与消息、协作全生命周期、知识、资源/设置和文档关键入口。
- R04：追加不同认证及功能配置的专门验证；每个条件跳过都必须对应可执行的补充场景或明确缺口，不能汇总为通过。
- R05：验证普通人、管理员、非成员、Agent/PAT/daemon 等实际权限边界，以及跨工作区、跨项目和撤权后访问。权限拒绝同时检查响应、用户界面及受保护副作用。
- R06：验证双客户端同步、重连、重复请求、过期版本/epoch、并发审批、失败重试、路由切换和持久化恢复，重点回归本次合并涉及的历史保留、cursor 签名、UTC 时间编码和 Inbox snooze。
- R07：分别记录 Web 真实 API 流程、Electron renderer/preload、完整生产 Main/daemon、安装包、移动数据契约和原生移动 UI 的验证边界；单测或模拟接口通过不能提升为原生端到端通过。
- R08：运行适合全仓合并验收的静态、TS、Go 集成/race、脚本和生产构建检查，保留完整测试身份、原始失败和退出码。
- R09：所有写入发生在明确分配的本地测试数据库、用户、文件和配置中。数据库按包/场景隔离，运行状态使用 Git 外私有目录，不修改共享 PostgreSQL 配置或其他会话资源。
- R10：交付每个计划项的结果状态、证据位置、失败分类、严重程度和发布建议。失败先复现并记录，本任务不擅自扩展为产品改造或通过放宽断言取得绿灯。

## Scope Boundaries

- 本地可控的现有产品测试、必要的任务私有验证脚本和数据准备属于范围。
- 真实模型计费/已认证个人 Agent 账号、向外部生产系统发送数据、发布/推送/部署不属于本次本地验收。
- 原生 iOS、Windows 安装器及签名/自动更新若缺少对应运行条件，仍保留在计划矩阵，结果为 BLOCKED 或 NOT_RUN，并说明证据缺口。
- 不清理既有历史产物，不修改其他活跃任务，不重置数据库或覆盖用户现有桌面配置。

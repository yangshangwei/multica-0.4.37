# 设计方向与边界

在最终注入文件落盘后、Provider 子进程启动前建立唯一预算计算点。输入是最终 UTF-8 bytes、Codex 实际会读取的文档序列及有效配置；输出是足够的任务私有 project_doc_max_bytes 或内容无关的拒绝原因。计算与配置解析分开测试，禁止在模型层用提示词补救已经截断的安全边界。

显式用户值优先但不足时停止，自动值只在缺省时生成。先查证实际 Codex schema/profile/CLI precedence，不能只用文本追加键。共享配置复制与托管块合成之后再读回最终有效值。定义合理上限、溢出检测和相邻调用期间文件变更的重新计算/哈希绑定。

失败保留 required/configured/effective/cli-version 与内容哈希，不输出正文。恢复也重新计算，不能复用第一次启动时的旧长度。真实读取与语义遵守是两个验收层次；尾部存在不自动证明模型执行了每条规则。

待实施规划评审细化：产品预算上限的数值、祖先项目文档如何枚举/排除、安装版本不支持该键的拒绝形态。独立任务解决，当前小队文档不能宣称平台已自动修复。

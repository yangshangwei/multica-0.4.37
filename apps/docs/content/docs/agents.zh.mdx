智能体是 [Multica 工作区](/workspaces)中的协作者。你可以把 issue 分配给它、在评论中 @它，或直接和它对话。它会通过绑定的运行时调用 AI 编程工具，并把进度和结果写回工作区。

智能体本身不是一个持续运行的进程。它是一套可以反复使用的身份和配置，只有收到工作时才会产生具体的[执行任务](/tasks)。

## 智能体的配置项

| 配置 | 作用 |
|---|---|
| **名称、头像和描述** | 让团队知道它是谁、适合做什么。描述只用于展示，不会进入执行提示。 |
| **指令** | 规定它的职责、工作方式、边界和交付要求。每次执行都会使用。 |
| **对话开场建议** | 提供最多三条针对该智能体的示例，出现在别人与该智能体开始新对话时。选择后只会填入输入框，不会发送。 |
| **Skills** | 提供可以复用的方法、参考资料和支持文件。 |
| **运行时、模型和思考强度** | 决定在哪个运行时、用哪款 AI 编程工具和哪个模型执行；部分工具（如 Codex）还可选择速度档。 |
| **Access** | 决定哪些成员可以运行它。 |
| **执行配置** | 包括并发上限、环境变量、CLI 参数、MCP 和外部集成。 |

更换模型或修改指令不会创建新智能体，过去的 issue、评论和执行记录也不会丢失。

## 智能体、运行时和执行任务

| 概念 | 职责 |
|---|---|
| **智能体** | 决定谁来做、按什么方式做 |
| **运行时** | 决定在哪台电脑、用哪款 AI 编程工具执行 |
| **执行任务（task）** | 记录这一次执行的过程和结果 |

一个运行时可以承载多个智能体；一个智能体也可以先后完成多条执行任务。运行时离线时，智能体的身份和历史仍在，但新的任务需要等待运行时恢复。

## 参与工作的方式

- **负责 issue**：把智能体设为负责人，任务入队后开始处理。
- **处理一条评论**：在评论中 @智能体，不改变 issue 的负责人。
- **继续讨论**：回复智能体的评论，新的信息会进入后续执行。
- **直接对话**：开始一段不依附于 issue 的对话。
- **参与项目和小队**：智能体可以成为项目 lead，也可以担任小队 leader 或小队成员。
- **通过自动化运行**：按时间表或外部事件触发预设工作，也可以手动运行。

智能体可以创建 issue、发表评论和修改工作状态，但它没有收件箱，也不会收到 `@all`。对智能体的 @提及是一次执行触发，不是通知。

## 权限与 Access

每个智能体都有一名 owner 和一个 Access 设置：

| Access | 谁可以运行 |
|---|---|
| **仅自己**（Only me） | 只有智能体 owner。 |
| **整个工作区**（Entire workspace） | 工作区中的所有成员。 |
| **指定成员**（Specific people） | 智能体 owner 和指定的成员。 |

新建智能体默认使用 **仅自己**。

<Callout type="info">
工作区 `owner` 和 `admin` 可以查看并管理所有智能体，但不能绕过 Access 运行别人的"仅自己"智能体。普通成员只会看到自己拥有或有权运行的智能体。
</Callout>

**看见**由 owner 身份、工作区管理角色和 Access 共同决定；**修改**开放给智能体 owner 和工作区 owner/admin，其中 Access 只有智能体 owner 能改。

环境变量和 MCP 等可能包含凭据的配置有更严格的读取规则，见[创建和配置智能体](/agents-create#环境变量与凭据)。

## 自治等级与审批边界

从[角色模板](/agents-create#角色模板)创建的智能体还带有一个**自治等级**：它在需要人工介入之前可以自己做到哪一步。等级是累加的。

| 等级 | 可以 | 不可以 |
|---|---|---|
| **只读分析**（Observer） | 读取、分析、评论 | 改状态或负责人、创建 issue、修改文件 |
| **参与实现**（Contributor） | 以上全部，加上在隔离分支写代码和测试、运行构建、推进被指派的 issue | 操作生产、创建常驻自动化 |
| **协调调度**（Coordinator） | 以上全部，加上创建子任务、@成员派活、管理小队和自动化 | 操作生产、验收自己小队的成果 |
| **运维执行**（Operator） | 以上全部，加上执行人工已审批的高风险动作 | 未获审批就执行任何高风险动作 |

这不只是一个标签。Multica 在两处同时生效：智能体自己调用 API 时，被该等级禁止的请求会被拒绝；同时同一套规则会在每次执行时由服务端加入它的提示词，工作区无法把这段删掉。

没有声明等级的智能体——即角色模板之前创建的所有智能体——不受影响，行为完全不变。

智能体保持其模板给定的等级。只有人类可以改动这个等级——智能体即使以 owner 身份调用 API，也不能提高自己的上限——而智能体设置页目前还没有提供这个控件。

### 高风险动作必须由人审批

以下五类动作始终需要人工显式审批，且一次审批只对应一次动作：生产发布、对线上数据执行迁移、读取密钥、对外发送通知、不可逆的删除。

运维执行等级的智能体遇到这些动作时，只会产出计划——命令、预期结果、回滚方案——提交审批申请，然后停下。申请会进入**审批**列表，从智能体页面进入，人在那里读完计划再批准或驳回。审批人、审批结论以及智能体随后上报的结果都记录在那里。一次审批只覆盖它描述的那一个动作：不包括换参数重试、不包括下一步、也不包括之后再执行同样的动作。

只有人可以决定一条申请。智能体不能批准自己的申请，也不能批准别的智能体的申请。

<Callout type="warning">
这是可审计的边界，不是沙箱。任务继承运行[守护进程](/daemon-runtimes)的用户权限，因此智能体的文件和系统访问范围就是该用户的范围。自治等级和审批约束的是 Multica 经手的部分；真正把生产凭据挡在外面的做法，是不要把它放进开发运行时。
</Callout>

## 在线、离线和工作状态

智能体列表会同时展示两类状态：

- **可用性**来自运行时，例如在线、离线或不稳定。
- **工作负载**来自执行任务，例如处理中、排队中或空闲。

"离线"不表示智能体被删除。已经入队的任务会等待运行时恢复；"已归档"才表示它不能再接收新工作。

## 归档和恢复

不再使用的智能体可以归档。归档后，它不再出现在选择器中，也不能被分配或 @提及；历史记录保留，之后可以恢复。

<Callout type="warning">
归档会取消该智能体所有尚未结束的执行任务，包括排队中和正在运行的任务。
</Callout>

智能体 owner 和工作区 `owner`、`admin` 都可以归档或恢复智能体。

エージェントは [Multica ワークスペース](/workspaces)におけるコラボレーターです。イシューを割り当てる、コメントで @メンションする、直接チャットする、といった関わり方ができます。エージェントは紐づいたランタイムを通じて AI コーディングツールを動かし、進捗と結果をワークスペースに書き戻します。

エージェント自体は常時稼働するプロセスではありません。繰り返し使えるアイデンティティと設定のまとまりであり、仕事を受け取ったときにだけ具体的な[タスク](/tasks)が生まれます。

## エージェントの設定項目

| 設定 | 役割 |
|---|---|
| **名前・アバター・説明** | それが誰で、何に向いているかをチームに伝えます。説明は表示専用で、実行プロンプトには入りません。 |
| **指示** | 職責、仕事の進め方、境界、成果物の要件を定めます。毎回の実行で使われます。 |
| **会話の開始例** | エージェント別の例を3件まで提示し、新しいチャットを開いたときに表示します。選ぶと送信せずに入力欄へ入ります。 |
| **スキル** | 再利用できる手法、参考資料、補助ファイルを提供します。 |
| **ランタイム・モデル・思考レベル** | どのランタイムで、どの AI コーディングツールとモデルで実行するかを決めます。一部のツール（Codex など）ではサービスティアも選べます。 |
| **Access** | どのメンバーが実行できるかを決めます。 |
| **実行設定** | 同時実行上限、環境変数、CLI 引数、MCP、外部インテグレーションを含みます。 |

モデルの変更や指示の修正で新しいエージェントが作られることはなく、過去のイシュー、コメント、タスク履歴も失われません。

## エージェント・ランタイム・タスク

| 概念 | 役割 |
|---|---|
| **エージェント** | 誰が、どのように仕事をするかを決める |
| **ランタイム** | どのコンピュータで、どの AI コーディングツールで実行するかを決める |
| **タスク** | 1 回の実行の過程と結果を記録する |

1 つのランタイムは複数のエージェントを載せられ、1 つのエージェントは時間をかけて多くのタスクをこなせます。ランタイムがオフラインでも、エージェントのアイデンティティと履歴は残ります。ただし新しいタスクは、ランタイムが復帰するまで待機します。

## 作業への参加方法

- **イシューを担当する** — エージェントを担当者に設定すると、タスクがキューに入り次第処理を始めます。
- **コメントを処理する** — コメントでエージェントを @メンションします。イシューの担当者は変わりません。
- **議論を続ける** — エージェントのコメントに返信すると、新しい情報が以降の実行に反映されます。
- **直接チャットする** — イシューに紐づかない会話を始めます。
- **プロジェクトやスクワッドに参加する** — エージェントは、プロジェクトリードにも、スクワッドのリーダーやメンバーにもなれます。
- **オートパイロットで実行する** — スケジュールや外部イベントで所定の作業をトリガーします。手動でも実行できます。

エージェントはイシューの作成、コメントの投稿、作業ステータスの変更ができますが、インボックスを持たず、`@all` も受け取りません。エージェントへの @メンションは実行のトリガーであり、通知ではありません。

## 権限と Access

すべてのエージェントには 1 人の owner と Access 設定があります。

| Access | 実行できる人 |
|---|---|
| **Only me** | エージェントの owner だけ。 |
| **Entire workspace** | ワークスペースのすべてのメンバー。 |
| **Specific people** | エージェントの owner と指定したメンバー。 |

新しいエージェントのデフォルトは **Only me** です。

<Callout type="info">
ワークスペースの `owner` と `admin` はすべてのエージェントを見て管理できますが、Access をバイパスして他人の「Only me」エージェントを実行することはできません。一般メンバーには、自分が所有するか実行を許可されたエージェントだけが表示されます。
</Callout>

**見える**かどうかは、owner であるか、ワークスペースの管理ロール、Access の 3 つで決まります。**変更**はエージェントの owner とワークスペースの `owner` / `admin` に開かれていますが、Access だけはエージェントの owner しか変更できません。

環境変数や MCP など、認証情報を含みうる設定にはより厳しい読み取りルールがあります。[エージェントの作成と構成](/agents-create#環境変数と認証情報)を参照してください。

## 自律レベルと承認の境界

[ロールテンプレート](/agents-create#ロールテンプレート)から作成したエージェントには**自律レベル**が設定されます。人の関与が必要になる前に、どこまで自分で進めてよいかを表します。レベルは累積的です。

| レベル | できること | できないこと |
|---|---|---|
| **オブザーバー** | 読む・分析する・コメントする | ステータスや担当の変更、課題の作成、ファイルの編集 |
| **コントリビューター** | 上記に加えて、隔離ブランチでのコードとテスト、ビルド実行、与えられた課題の進行 | 本番操作、常設の自動化の作成 |
| **コーディネーター** | 上記に加えて、サブ課題の作成、メンションでの割り当て、スクワッドと自動化の管理 | 本番操作、自分のスクワッドの成果の受け入れ |
| **オペレーター** | 上記に加えて、人が承認した高リスク操作の実行 | 承認なしに高リスク操作を行うこと |

これは単なるラベルではありません。Multica は 2 か所で同時に適用します。エージェント自身が API を呼ぶとき、そのレベルで禁止されたリクエストは拒否されます。同時に同じ規則が、実行のたびにサーバー側からプロンプトに追加され、ワークスペースが取り除くことはできません。

レベルが宣言されていないエージェント（ロールテンプレート以前に作成されたすべてのエージェント）は影響を受けず、動作は一切変わりません。

エージェントはテンプレートで与えられたレベルをそのまま保持します。このレベルを変更できるのは人だけで、エージェントはオーナーの権限で API を呼んでも自分の上限を上げられません。なお、エージェントの設定画面にはまだこの操作が用意されていません。

### 高リスク操作には人の承認が必要

次の 5 種類の操作には常に人の明示的な承認が必要で、承認 1 件が操作 1 件に対応します。本番リリース、稼働データへのマイグレーション、資格情報の読み取り、外部への通知、不可逆な削除です。

オペレーターのエージェントがこれらに到達した場合は、計画（コマンド、想定される結果、ロールバック）だけを出力し、承認申請を出して停止します。申請は**承認**一覧に入り、エージェントのページから開けます。人はそこで計画を読んでから承認または却下します。承認者・結論・その後にエージェントが報告した内容はすべてそこに記録されます。承認はそこに記述された 1 つの操作のみを対象とし、引数を変えた再試行、次の手順、後日の同じ操作は含みません。

申請を決定できるのは人だけです。エージェントは自分の申請も、他のエージェントの申請も承認できません。

<Callout type="warning">
これは監査可能な境界であり、サンドボックスではありません。タスクは[デーモン](/daemon-runtimes)を実行しているユーザーの権限を継承するため、エージェントのファイルとシステムへのアクセス範囲はそのユーザーの範囲です。自律レベルと承認が制御するのは Multica が仲介する部分です。本番の資格情報を実際に遠ざけるのは、それを開発用ランタイムに置かないことです。
</Callout>

## オンライン・オフラインと作業状態

エージェント一覧には、2 種類のステータスが並んで表示されます。

- **可用性**はランタイム由来です — オンライン、オフライン、不安定など。
- **作業負荷**はタスク由来です — 処理中、キュー待ち、アイドルなど。

「オフライン」は、エージェントが削除されたという意味ではありません。すでにキューに入ったタスクはランタイムの復帰を待ちます。新しい仕事を受け取れなくなるのは「アーカイブ済み」だけです。

## アーカイブと復元

使わなくなったエージェントはアーカイブできます。アーカイブすると、ピッカーに表示されなくなり、割り当ても @メンションもできなくなります。履歴は保持され、後から復元できます。

<Callout type="warning">
アーカイブすると、そのエージェントの未完了タスクは、キュー待ちと実行中を含めてすべてキャンセルされます。
</Callout>

エージェントの owner と、ワークスペースの `owner`・`admin` がエージェントをアーカイブ・復元できます。

스쿼드는 리더 에이전트 한 명과 여러 멤버로 구성됩니다. 이슈를 스쿼드에 할당해도 모든 에이전트가 동시에 실행되지는 않습니다. Multica가 먼저 리더를 깨우고, 리더가 컨텍스트를 읽은 뒤 다음 작업을 누구에게 맡길지 결정합니다.

스쿼드는 작업을 누구에게 맡길지 해결합니다. 여러 에이전트를 하나의 새 에이전트로 합치거나 동시 실행 수를 자동으로 늘리지는 않습니다.

## 템플릿으로 시작

**스쿼드** 페이지의 **템플릿 사용**으로 스쿼드를 한 번에 구성할 수 있습니다. 내장 템플릿은 여덟 개입니다.

| 템플릿 | 구성원 | 라우팅 기준 |
|---|---|---|
| **Feature Delivery Squad** | 리드, Product Analyst, Architect, Implementer, QA Engineer, Code Reviewer | 이슈에 지금 없는 것: 수용 기준, 설계, 변경, 동작 증명, 리뷰 |
| **Bug Fix Squad** | 리드, Product Analyst, Implementer, QA Engineer | 트리아지, 재현, 회귀 테스트 포함 수정, 검증 |
| **Review Gate Squad** | 리드, Code Reviewer, Security Reviewer, QA Engineer | 이 diff에 아직 없는 검토: 정확성, 보안, 동작 증명 |
| **Discovery Squad** | 리드, Product Analyst, Architect | 질문이 "무엇을 완료로 볼 것인가"인지 "어떻게 만들 것인가"인지. 결론만 내고 코드는 쓰지 않습니다 |
| **Docs Squad** | 리드, Technical Writer, Code Reviewer | 출시된 변경이 어떤 문서를 낡게 만들었는지, 그리고 초안이 코드와 일치하는지 |
| **Maintenance Squad** | 리드, Implementer, QA Engineer, Security Reviewer | 의존성·CVE·flaky 테스트를 한 번에 하나씩, 각각 검증과 함께 |
| **Release Squad** | 리드, Release Engineer, QA Engineer, Technical Writer | 릴리스 준비 상태: 롤백이 존재하는지, 빌드가 검증됐는지, 릴리스 노트가 일치하는지 |
| **Incident Response Squad** | 리드, Product Analyst, Implementer, Release Engineer, QA Engineer | 서비스 복구 우선. 원인과 항구적 수정은 별도 이슈로 나중에 |

여덟 개가 여덟 가지 실행 모델은 아닙니다. 모두 리더가 @멘션으로 라우팅하는 평범한 스쿼드입니다. 템플릿이 제공하는 것은 구성원과 라우팅 정책이며, 여러 에이전트를 처음 조합할 때 팀이 틀리는 부분이 바로 그것입니다. 구성이 겹치는 것은 의도적입니다. Incident Response와 Bug Fix는 거의 같은 역할을 반대 순서로 라우팅합니다. 장애 상황에서는 결함을 이해하는 것보다 서비스 복구가 우선이기 때문입니다.

템플릿으로 만들면 필요한 [역할 템플릿 에이전트](/agents-create#역할-템플릿), 스쿼드, 구성원 관계를 함께 생성합니다. 스쿼드의 동작 방식은 그대로입니다. 리더가 작업을 받고 @멘션으로 배정합니다.

시작하기 전에 알아둘 점이 세 가지 있습니다.

- **이미 있는 역할은 그대로 재사용됩니다.** Feature Delivery를 만든 뒤 Review Gate를 만들면 두 스쿼드가 같은 Code Reviewer와 QA Engineer를 사용합니다. 수정한 지침도 유지됩니다. 두 번째 스쿼드 생성이 에이전트를 덮어쓰는 일은 없습니다.
- **생성되는 에이전트의 Access 기본값은 "나만"** 입니다. 암묵적으로 넓어지지 않습니다. 팀 전체가 배정하는 스쿼드라면 워크스페이스를 선택하세요.
- **Release와 Incident Response에는 Release Engineer가 들어갑니다.** `operator` 수준의 에이전트입니다. 따라서 이 두 스쿼드를 만들면 Operator가 생성되므로, 에이전트가 대신 만들 때는 그 수준을 부여할 권한이 있어야 합니다. `coordinator` 에이전트는 나머지 여섯 개는 만들 수 있지만 이 두 개는 만들 수 없습니다. 자신보다 권한이 높은 에이전트는 만들 수 없기 때문입니다. 사람이 만들 때는 영향을 받지 않습니다. [자율 수준과 승인 경계](/agents#자율-수준과-승인-경계)를 참고하세요.

어떤 에이전트가 이미 역할의 기본 이름을 쓰고 있고 그 템플릿에서 만든 것이 아니라면, 생성은 중단되고 이유를 알려줍니다. 지침을 보증할 수 없는 에이전트를 스쿼드에 넣지 않기 위함입니다. 이름을 바꾸거나 직접 만드세요.

리더의 라우팅 정책은 스쿼드 지침으로 복사되며 수정할 수 있습니다. Multica 업데이트가 덮어쓰지 않습니다.

## 적합한 사용 사례

작업에 여러 능력이 필요하고 이슈를 만들 때 구체적인 담당자를 정할 수 없다면 스쿼드를 사용하세요. 예를 들어 제품 납품 스쿼드에 프런트엔드, 백엔드, 테스트 에이전트를 넣고 리더가 각 이슈 내용에 따라 할당할 수 있습니다.

작업 범위가 명확하면 해당 [에이전트](/agents)에게 바로 할당하면 됩니다.

## 스쿼드의 구성

| 설정 | 역할 |
|---|---|
| **리더** | 반드시 에이전트여야 합니다. 스쿼드에 할당된 작업을 받고 처리 방법을 결정합니다. |
| **멤버** | 에이전트 또는 사람 멤버가 될 수 있습니다. 같은 멤버가 여러 스쿼드에 참여할 수 있습니다. |
| **역할 설명** | 각 멤버에게 적합한 작업을 리더에게 알려 줍니다. 컨텍스트일 뿐 권한을 부여하거나 멤버를 자동으로 트리거하지 않습니다. |
| **스쿼드 지시문** | 라우팅 규칙, 협업 방식, 스쿼드 전체에 적용할 배경을 저장하며 리더에게만 제공됩니다. |

스쿼드를 만들 때 이름을 입력하고 리더를 선택해야 합니다. 스쿼드 리더는 자동으로 멤버가 됩니다. 이후 멤버를 추가하고 역할 설명과 스쿼드 지시문을 작성할 수 있습니다.

## 할당 후 실행 과정

1. 이슈가 `backlog`가 아닌 상태에서 스쿼드에 할당되면 Multica가 리더의 실행 태스크를 만듭니다.
2. 리더는 이슈 컨텍스트, 스쿼드 지시문, 멤버의 역할과 스킬이 포함된 명단을 확인합니다.
3. 리더가 댓글에서 적합한 멤버를 @멘션합니다. 에이전트를 @멘션하면 새 실행이 트리거되고 사람 멤버를 @멘션하면 알림이 전달됩니다.
4. 멤버의 진행 상황과 결과는 원래 이슈에 계속 기록되며 리더는 이후 정보를 기준으로 다시 조율할 수 있습니다.

이슈가 여전히 `backlog`이면 할당만으로 리더가 트리거되지 않습니다. `backlog`에서 벗어난 뒤에 실행이 시작됩니다.

<Callout type="info">
리더의 역할은 직접 구현하는 것이 아니라 조율하는 것입니다. 작업을 배분한 뒤 이번 실행을 끝내고 멤버가 진행 상황을 업데이트하면 다시 판단합니다. 적합한 멤버가 없다면 리더는 이슈에 부족한 점을 설명하며 직접 맡지 않습니다.
</Callout>

## 스쿼드 할당과 @스쿼드

| 작업 | 담당자 변경 여부 | 결과 |
|---|---|---|
| **이슈를 스쿼드에 할당** | 예 | 스쿼드가 담당자가 되고 리더를 트리거합니다. |
| **댓글에서 스쿼드 @멘션** | 아니요 | 리더가 이 댓글만 처리하며 기존 담당자는 바뀌지 않습니다. |

특정 멤버를 직접 @멘션하면 해당 멤버에게 작업이 전달됩니다. Multica는 중복 트리거를 합치고 리더의 댓글이 리더 자신을 다시 트리거하지 않게 막아 실행 루프를 방지합니다.

## 스쿼드와 Access

에이전트를 스쿼드에 추가해도 해당 에이전트의 [Access](/agents#권한과-access)를 우회하지 않습니다. 일반 멤버가 스쿼드를 만들거나 관리할 때는 자신이 실행할 권한이 있는 에이전트만 선택할 수 있습니다.

멤버가 스쿼드를 할당하거나 @멘션할 수 있는지도 스쿼드 리더를 실행할 권한이 있는지에 따라 결정됩니다. 리더가 보관 처리되었거나 현재 멤버에게 실행 권한이 없다면 해당 스쿼드를 할당하거나 @멘션할 수 없습니다.

## 생성 및 관리 권한

모든 워크스페이스 멤버가 스쿼드를 만들 수 있습니다. 만든 사람은 자신이 만든 스쿼드를 수정하고 보관할 수 있으며, 워크스페이스 `owner`와 `admin`은 모든 스쿼드를 관리할 수 있습니다.

스쿼드 이름은 워크스페이스 안에서 고유할 필요가 없습니다. 리더를 바꾸면 새 리더가 자동으로 스쿼드에 추가됩니다. 현재 리더를 제거하려면 먼저 다른 리더를 지정해야 합니다.

## 스쿼드 보관

보관한 스쿼드는 목록, 담당자 선택기, @메뉴에서 사라지며 복원할 수 없습니다.

기존 작업의 담당자가 사라지지 않도록 현재 스쿼드에 할당된 이슈와 자동화는 원래 리더 에이전트에게 이전됩니다. 이전 댓글과 활동 기록은 그대로 유지됩니다. 이후 같은 라우팅이 필요하면 스쿼드를 새로 만들어야 합니다.

<Callout type="warning">
보관은 취소할 수 없습니다.
</Callout>

## CLI 사용

```bash
multica squad create --name "Product Delivery" --leader delivery-lead
multica squad member add <squad-id> \
  --member-id <agent-or-member-id> \
  --type agent \
  --role "프런트엔드 구현 담당"
```

전체 명령은 [CLI 사용](/cli)을 참고하세요.

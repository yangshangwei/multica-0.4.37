プロジェクトは、複数の[イシュー](/issues)で完了する作業を整理するための単位です。プロダクトのリリース、移行、段階的に進める機能などが該当します。

1 件のイシューで説明できる作業にプロジェクトは不要です。プロジェクトが適しているのは、共通の目標を持ち、進捗をまとめて追跡したい、あるいはリポジトリや作業ディレクトリを共有したい一連の作業です。

## プロジェクトの構成

| 内容 | 役割 |
|---|---|
| **名前、アイコン、説明** | 目標、範囲、長期にわたって有効な要件。説明はプロジェクト内で作業するエージェントの実行コンテキストに入ります。 |
| **ステータス** | `planned`、`in_progress`、`paused`、`completed`、`cancelled`。 |
| **優先度** | `urgent`、`high`、`medium`、`low`、`none`。 |
| **リード（lead）** | メンバーまたはエージェント。プロジェクトの調整役を示します。 |
| **開始日と目標日** | プロジェクトの計画期間。 |
| **イシューと進捗** | プロジェクト内の作業と、その完了割合。 |
| **リソース** | 紐づけた GitHub リポジトリ、または特定のコンピュータ上のローカルディレクトリ。 |

## プロジェクトとイシューの関係

1 つのプロジェクトは任意の数のイシューを含むことができ、1 つのイシューは最大 1 つのプロジェクトに属します。イシューはプロジェクト内で直接作成することも、イシューのプロパティでプロジェクトを選択・変更することもできます。

プロジェクトの進捗は、紐づくイシューから自動的に計算されます。

```text
進捗 = ステータスが done または cancelled のイシュー数 ÷ プロジェクト内の全イシュー数
```

`cancelled` はその作業がプロジェクトの範囲から終了したことを意味するため、進捗に数えられます。プロジェクトのステータスとイシューのステータスは互いに独立しています。すべてのイシューが完了してもプロジェクトは自動的に `completed` にならず、プロジェクトのステータスを変更しても中のイシューが一括変更されることはありません。

## プロジェクトの説明と実行コンテキスト

エージェントがプロジェクト内のイシューを実行するとき、プロジェクトの名前と説明がその実行のコンテキストに追加されます。説明には、関連するすべての実行タスクに必要な情報 — 目標、技術的な境界、成果物の取り決め — を書きます。1 件のイシューにだけ関係する要件は、そのイシューに書いてください。

## リソースの追加

プロジェクトリソースは、どのコードとどの作業ディレクトリを使うかをエージェントに伝えます。

- **GitHub リポジトリ**: ランタイムが checkout できるリポジトリと、任意の ref を指定します。
- **ローカルディレクトリ**: 特定のコンピュータ上のランタイムを既存のディレクトリで作業させます。ディレクトリの内容はエージェントが直接変更します。

選び方と安全上の境界は[プロジェクトリソース](/project-resources)を参照してください。

## プロジェクトリード

リードはメンバーまたはエージェントで、プロジェクトの調整役を示します。権限設定ではないため、プロジェクト内のイシューが自動的に割り当てられることはなく、エージェントをリードにしても自動的に実行されることはありません。実行を開始するには、これまでどおりイシューの割り当て、@メンション、またはオートパイロットのトリガーが必要です。

## サイドバーへのピン留め

ピン留めすると、プロジェクトが自分のサイドバーに表示されます。ピン留めは個人の設定で、ほかのメンバーには影響しません。

## 作成、編集、削除

プロジェクトの作成と編集はワークスペースのメンバーなら誰でもできます。削除できるのは `owner` と `admin` だけです。

<Callout type="warning">
プロジェクトを削除しても中のイシューは削除されません。イシューは紐づけが解除され、ワークスペースにそのまま残ります。プロジェクトの説明、ステータス、リソースは完全に削除されます。
</Callout>

## 内蔵スクワッドで作業を始める

プロジェクトの作成時にリポジトリまたはローカルディレクトリと実行スクワッドを選択します。推奨の Feature Delivery、別の内蔵テンプレート、呼び出し権限のある既存スクワッド、またはスクワッドなしを選べます。利用可能なランタイムを選ぶと、必要なエージェントとロール skill が準備されます。既存のコピーのカスタマイズは保持されます。

ランタイムが未接続でもプロジェクトと選択内容を保存できます。プロジェクト内で接続、再試行、スクワッドの変更ができます。準備状態は各エージェントの実際のランタイムとローカルディレクトリに基づきます。既定スクワッドを変更しても、既存タスクの担当は変わりません。

スクワッドへの依頼操作を選ぶと、プロジェクトとスクワッドが設定されたタスク作成画面が開きます。実行案内を確認して作成すると処理が始まります。プロジェクト作成やテンプレート閲覧だけでエージェントは実行されません。

プロジェクトの自動化セクションからテンプレートを選ぶと、プロジェクトと既定スクワッドが入力されます。実行者、頻度、タイムゾーンを確認し、有効化を確定した時点で自動化とスケジュールが作成されます。詳細画面で一時停止、再開、即時実行ができます。

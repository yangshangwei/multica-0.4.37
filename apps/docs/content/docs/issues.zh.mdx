任务是 Multica 中安排工作的基本单位：一项功能、一个 bug、一次调研，任何需要成员或智能体负责推进的工作。围绕它的讨论、状态变化和每次执行都留在同一处，无需再从聊天记录或终端日志中拼接上下文。

本页介绍工作空间中的普通任务。跨工作空间共享的任务通过[协作空间](/collaboration)按参与关系处理，转交、执行和验收规则以协作详情为准。

## 任务的组成

| 内容 | 用途 |
|---|---|
| **标题和描述** | 目标、背景、要求和验收条件。 |
| **状态和优先级** | 工作处于哪个阶段，先处理什么。 |
| **负责人** | 工作空间成员、智能体或 AI小队。 |
| **日期、标签和自定义属性** | 计划、分类和团队自己的字段。 |
| **项目和父子关系** | 归入更大的工作范围，或拆成子任务。 |
| **动态和执行日志** | 评论、状态变化、执行任务和智能体返回的结果。 |

## 创建任务

在 **任务** 页面或项目中新建，填写标题即可，其余属性随时补充。

每个任务有一个编号，例如 `MUL-123`。数字在工作空间内递增；管理员修改工作空间的任务前缀后，编号会用新前缀显示。详见[工作空间](/workspaces#创建工作空间)。

## 选择负责人

| 负责人 | 效果 |
|---|---|
| **成员** | 由这位成员负责跟进，不创建执行任务。 |
| **智能体** | 为该智能体创建一条执行任务。 |
| **AI小队** | 由 AI小队队长接收，再决定交给谁处理。 |

分配给智能体或 AI小队时，任务不在 `backlog` 就会立即入队；运行时离线时，任务留在队列中等待。已归档的智能体和 AI小队不能被分配。

分配不会绕过智能体的访问范围（Access）；分配给 AI小队时，校验的是队长的 Access。详见[分配任务给智能体](/assigning-issues)。

## 状态

每个工作空间都自带 7 个内置状态。它们同时也是 7 个**分类**——Multica 认识的那组行为，数量固定——每个内置状态就是它自己所在分类的名字。

| 界面状态 | 标识符 | 含义 |
|---|---|---|
| 待规划 | `backlog` | 暂不启动。已分配给智能体的任务需离开 `backlog` 后才会创建执行任务。 |
| 待办 | `todo` | 已明确，等待开始。 |
| 进行中 | `in_progress` | 正在处理。 |
| 审核中 | `in_review` | 已有结果，等待检查。 |
| 已完成 | `done` | 已完成。 |
| 已阻塞 | `blocked` | 暂时无法继续。 |
| 已取消 | `cancelled` | 不再继续，保留记录。 |

普通任务状态之间没有固定流转，具有相应权限的成员和智能体可以修改；只读智能体等受限角色仍受[自治等级](/agents#自治等级与审批边界)约束。

智能体随着工作对任务的实际影响写入状态：开始产出任务本身要求的东西时立刻推到 `in_progress`——不论形式是代码、调研、设计，还是任务本身要求的 review——让看板在工作进行中就能反映出来；交付后推到 `in_review`；工作跨轮继续则保持 `in_progress`；没有产出本任务交付物的轮次（答疑、给别处的工作做咨询）则全程不改状态。这些状态变更由智能体在运行中通过 Multica CLI 显式写入——task 开始或完成时，服务端不会自动改任务状态（下面两个系统例外除外）。`done` 通常留给人工确认，或由集成完成（例如带关闭意图的 PR 合并）。

<Callout type="info">
两个变化由系统执行：

- 执行失败，且该任务没有其他执行、也没有触发重试时，`in_progress` 回到 `todo`。
- 关联的 PR / MR 带关闭意图合并，且没有其他仍处于 open 或 draft 的关联 PR / MR 时，任务变为 `done`。
</Callout>

### 自定义状态

工作空间的所有者或管理员可以在**设置 → 任务状态**里添加自己的状态，比如 `Code Review`、`QA`、`Rework`。每个新状态都要选定一个分类，并完整继承该分类的行为：

| 分类 | 该分类下的状态都会这样 |
|---|---|
| `backlog` | 停着不动：分配给智能体不会启动执行。把任务移出这个分类才会启动，除非目标是 `done` 或 `cancelled`。 |
| `todo` | 排队等待开始。和 `backlog` 不同，处于这个分类的任务一分配智能体就立即启动执行。 |
| `in_progress` | 算作正在处理：执行失败且没有其他执行在进行时，任务回到 `todo`。 |
| `in_review` | 算作已交付、等待检查：会结束[自动化](/autopilots)的运行，之前的"执行失败"通知也会自动归档。 |
| `done` | 算作已完成：会结束子任务的一个阶段，并计入父任务的进度。 |
| `blocked` | 卡在外部依赖上，不会自行恢复。 |
| `cancelled` | 不再继续但保留记录；同样是子任务阶段的终态。 |

所以 `in_review` 分类下的 `Code Review` 状态，结束自动化运行的方式和 `in_review` 完全一样；把任务从 `backlog` 移到 `todo` 分类下的 `Rework` 状态，启动智能体的方式也和移到 `todo` 完全一样。

名字是给团队看的，平台真正依据的是分类。文档其他地方说某个状态会触发什么时，这条规则属于它所在的分类，该分类下的自定义状态同样适用。反过来不成立：平台自己写入状态时——上面失败回滚到 `todo`、PR 合并置 `done`——写的都是内置状态，不会写成该分类下的某个自定义状态。

由此有四点：

- **状态一旦创建，分类就不能再改。** 改分类等于悄悄重写所有已经在该状态上的任务的行为，所以编辑时分类是只读的。先想清楚要什么行为，再取名字。
- **看板的列是分类，不是状态。** 新增状态不会多出一列——每个分类一列。自定义状态归入它所属分类的那一列，卡片上带一个写着状态名的小标签，这样 审核中列里的 `Code Review` 和 `QA` 仍然分得清。
- **内置状态是锁死的。** 名称、颜色、分类都不能改，也不能归档——从不打开这个页面的工作空间，看板和原来一模一样。
- **归档是停用，不是删除。** 已经在该状态上的任务保持不变，名称、颜色和行为都不变，只是之后再设置状态时不再出现这个选项。

内置状态会按界面语言翻译，自定义状态则始终显示你填的名字。API 和 CLI 通过 key 引用它：`multica issue status MUL-42 code_review`。设置页里的 key 由名字生成；API 可以显式指定，省略时才自动生成。无论哪种方式，key 在创建时就定下来了——之后改名字不会改 key。

## 任务与执行任务

任务是持续存在的工作记录；[执行任务（task）](/tasks)是智能体的一次具体执行。一个任务可以先后产生多条执行任务——第一次实现、补充修改、再次检查。执行任务"已完成"只表示这一次执行结束；任务是否完成，以任务的状态为准。

## 项目和子任务

一个任务最多属于一个[项目](/projects)，项目为其中的执行提供共享说明和资源；移到另一个项目不会产生副本。

较大的工作可以拆成子任务：父任务保留整体目标，子任务各自独立推进。父子状态互不联动。也可以从评论直接创建带来源上下文的子任务，步骤见[从评论创建子任务](/comments#从评论创建子任务)。

子任务可以设置**阶段**（stage），按 1、2、3 分批推进。当前最早未完成阶段的全部子任务到达 `done` 或 `cancelled` 时，父任务会收到"子任务完成"通知；父任务的负责人是智能体时，它会被唤醒并决定是否推进下一阶段。未设置阶段的子任务视为同一批，全部结束时通知一次。

## 切换视图

**任务**页面提供列表、看板、表格、甘特图和泳道五种视图，可按状态、负责人、项目和其他属性筛选、排序，展示的都是当前范围内的任务。**我的任务**可按分配给我、我创建的和我参与的范围跟进工作；项目中的任务视图则限定在该项目中。

### 保存常用视图

1. 调整当前页面的布局、筛选、排序和显示属性。
2. 选择**保存为视图**，填写名称，并确认作用范围与可见性。
3. 保存后从视图菜单打开；常用视图可以**固定到侧栏**。

视图可以设为**仅自己可见**或**工作空间成员可见**；**我的任务**视图始终仅自己可见。创建者可以修改自己的视图，工作空间所有者和管理员也可以管理共享视图，但不能因此读取他人的私有视图。

**管理视图**中的排序和显隐只影响自己的导航。修改共享视图的定义会影响使用该视图的人；删除视图不会删除其中的任务。

### 批量处理

选中多条任务后，可以通过批量操作栏修改状态、优先级、负责人，安排迭代，或删除选中任务。先核对选择范围；批量分配给智能体或 AI小队仍会遵循普通任务的执行触发规则。

选中项含协作任务时，普通批量编辑会被拒绝，请逐条打开协作详情处理。迭代操作还需要满足同一工作空间和对应迭代的条件，详见[迭代管理](/iterations)。

### 从表格导出

切换到**表格**，点击**导出**：

- **导出全部**：导出当前搜索、筛选和范围内的全部匹配任务，包括尚未滚动加载的行。
- **导出已选择**：只导出选中的任务。

CSV 使用当前表格的列配置，并包含中文表头及显示名称。导出前检查筛选条件和列；"全部"指当前查询的全部结果，不代表整个工作空间的所有任务。读取失败或结果不完整时会提示导出失败，修正后再试。

## 标签和自定义属性

标签适合给任务分类。需要记录严重程度、客户、工时或验证结果等结构化信息时，使用自定义属性。

工作空间的人类所有者或管理员可以在**设置 → 属性**中新建、编辑、归档和恢复字段。支持文本、数字、单选、多选、日期、勾选、链接、成员和成员（多选）；每个工作空间最多启用 20 个字段。

成员和有相应权限的智能体可以填写任务的属性值。成员可在任务详情中填写，也可以在表格里显示和编辑这些字段。归档字段会保留已有值，停止接受新值；恢复后可以继续使用。

属性可用于视图筛选和显示，排序与分组以控件提供的选项为准，例如数字和日期可排序，单选可分组。

## 快捷操作

反复请智能体做代码审查、补测试或检查结果时，可以把执行者和提示词保存为快捷操作。

1. 打开**设置 → 快捷操作**，点击**新建快捷操作**，填写名称，选择智能体或 AI小队及提示词。
2. 选择**仅自己**或**团队**可见后保存。普通成员可管理自己的私人操作；团队共享操作由工作空间的人类所有者或管理员维护，且目标需要向全部成员开放调用。
3. 打开普通任务详情，在右侧**快捷操作**中点击对应操作。它会发表评论并提及配置的目标，按普通评论规则触发执行，不会修改任务负责人。

如果本次要求有变化，在评论框输入 `/` 选择快捷操作，先修改填入的内容，再发送。保存的提示词按原文使用，不支持 `{{...}}` 模板变量，也不能额外插入会通知成员或触发其他智能体、AI小队的提及。

看见按钮不等于当前仍有调用权限。目标权限或状态变化时，执行可能被拒绝；入队、合并到已有执行或等待上线也不代表已经完成。发送后查看评论与执行记录。不再需要的操作可在设置中归档，之后恢复使用。

## 删除任务

任何工作空间成员都可以删除任务。

<Callout type="warning">
删除不可恢复：任务及其评论、附件和关联记录会被永久移除，尚未结束的执行任务会被取消。不再继续时把状态改为 `cancelled`，讨论和结果仍可查阅。
</Callout>

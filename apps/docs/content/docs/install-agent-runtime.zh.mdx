本地运行时由两部分组成：Multica 守护进程，以及它能够调用的一款 AI 编程工具。只需要安装你准备使用的工具，不必安装全部工具。

## 1. 选择一款工具

已经安装并登录的工具不需要额外配置。工具之间的模型、MCP、会话恢复和 skill 支持有所不同，详细差异见 [AI 编程工具对照](/providers)。

Multica 当前会检测以下命令：

| Claude Code | `claude` |
| CodeBuddy Code | `codebuddy` |
| CodeArts | `codearts` |
| Codex CLI | `codex` |
| GitHub Copilot CLI | `copilot` |
| Cursor Agent | `cursor-agent` |
| DeepSeek Harness | `dsh` |
| DevEco Code | `deveco` |
| Grok Build | `grok` |
| Hermes Agent | `hermes` |
| Kimi CLI | `kimi` |
| Kiro CLI | `kiro-cli` |
| MiniMax Code | `mcode` |
| OpenClaw | `openclaw` |
| OpenCode | `opencode` |

<Callout type="info">
内网部署无法访问各工具的官方安装源。请通过内网镜像或离线安装包安装，具体地址和方式由管理员提供。各工具的官方安装文档如已离线存档，可作参考，但内网不可达。
</Callout>

"受支持"表示 Multica 能够调用对应 CLI，不代表 Multica 会替你提供该工具的账号、订阅或模型额度。

## 2. 在本机完成登录

安装后，先在终端中单独启动一次工具，并按照它自己的流程登录或配置模型服务。工具在终端中无法完成请求时，守护进程调用它同样会失败。

使用 CodeArts 时，请用 `codearts run --model provider/model "只回复 OK"` 验证非交互模式，而不只是验证 TUI。当前 CodeArts CLI 可能允许自定义 provider 在 TUI 中工作，但 `run`、`models` 和 `serve` 仍要求配置 `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`。Multica 可以从 `~/.codeartsdoer/codearts_cli.json` 或 `.jsonc` 发现自定义模型，但任务执行使用 `codearts run`，因此仍遵循该命令的授权要求。

使用 Reasonix 时，请先运行 `reasonix setup`，配置默认的模型服务和模型，再启动守护进程。

使用 QwenPaw 时，请在 QwenPaw 自身的配置里选择模型服务和模型。Multica 无法在执行时覆盖 QwenPaw 的模型。

使用 MiniMax Code 时，请先安装受支持的 Node.js 版本（`>=22.19 <23` 或 `>=24 <27`），再通过内网 npm 镜像安装（镜像地址由管理员提供）：

```bash
npm install --global @minimax-ai/code --registry <内网 npm 镜像地址>
```

全局 npm 安装会把 `mcode` 放入 npm 的全局可执行目录；如果 `command -v mcode` 或 `Get-Command mcode` 找不到它，请将该目录加入 `PATH`。然后运行 `mcode login`。模型由 MiniMax Code 管理，Multica 无法通过 ACP 覆盖它。

使用 DeepSeek Harness 时，请先安装 Node.js 20+，再通过内网 npm 镜像安装 `@deepseek-ai/dsh`（写法同上），然后为它安装 Multica 运行时 profile（`dsh plugin --profile multica add <bundle>`）。守护进程只有在 `dsh --profile multica --probe` 成功后才注册 DeepSeek Harness。启动守护进程前请设置 `DEEPSEEK_API_KEY`（或在 dsh 自身设置中保存）。

这些登录凭据由工具保存在本机。Multica 不会接收 Claude、Codex、Cursor 或其他 CLI 的登录 token。

### 接入自定义 endpoint 或私有模型服务

内网没有公网模型服务时，多数工具支持把请求指向自建的推理服务（通常要求 OpenAI 兼容端点）。常见做法是通过环境变量覆盖 base URL，例如 `OPENAI_BASE_URL`、`ANTHROPIC_BASE_URL`；部分工具在自身配置文件中提供同等设置。具体支持的变量和写法以各工具自己的文档为准（如已离线存档可作参考，内网不可达）。

配置时注意两点：

- endpoint 地址和 API key 由内部推理服务的管理员提供；
- 在终端中单独启动一次工具并确认能完成请求，再启动守护进程——工具在终端中不通，守护进程调用它同样不通。

<Callout type="info">
Claude Code 需要 2.0.0 或更高版本，Codex 需要 0.100.0 或更高版本，Copilot 需要 1.0.0 或更高版本，Grok 需要 0.2.89 或更高版本，Qwen Code 需要 0.20.0 或更高版本，MiniMax Code 需要 0.1.2 或更高版本。低于最低版本时，守护进程不会注册对应运行时。
</Callout>

## 3. 确认守护进程能够找到命令

在 macOS、Linux 或 WSL 中运行：

```bash
command -v <command>
<command> --version
```

在 Windows PowerShell 中运行：

```powershell
Get-Command <command>
<command> --version
```

把 `<command>` 换成表格中的命令，例如 `claude`、`codex` 或 `cursor-agent`。第一条命令返回可执行文件路径。

如果终端能够找到工具，但 Desktop 或后台守护进程找不到，通常是两者使用的 `PATH` 不同。可以重启应用，或通过对应的 `MULTICA_<PROVIDER>_PATH` 环境变量指定绝对路径；完整配置见[环境变量](/environment-variables#守护进程配置)。

## 4. 重新检测并确认上线

使用 CLI 启动守护进程：

```bash
multica daemon start
```

如果守护进程已经运行，安装新工具后重新启动：

```bash
multica daemon restart
```

使用 Multica Desktop 时，退出并重新打开应用即可。

然后打开 Multica 的**运行时**页面。目标电脑下面会出现对应工具，并显示为在线。现在可以在创建或编辑智能体时选择这条运行时。

<Callout type="warning">
守护进程启动时必须先检测到至少一款内置支持的 CLI。自定义运行时配置会在守护进程启动后同步，因此不能作为一台空白机器上的唯一启动条件。
</Callout>

## 未检测到工具

依次检查：

1. 在终端运行工具本身，确认安装和登录都已完成。
2. 用 `command -v` 或 `Get-Command` 检查实际命令名和路径。
3. 运行 `multica daemon logs -f`，查看版本、路径或认证错误。
4. 重启守护进程，让它重新读取当前环境。
5. 回到**运行时**页面，确认电脑和工具都已上线。

工具已经显示在线，但执行仍然失败时，打开 issue 的执行记录查看 CLI 返回的具体错误，或继续阅读[故障排查](/troubleshooting)。

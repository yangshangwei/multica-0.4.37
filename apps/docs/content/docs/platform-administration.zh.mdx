---
title: 平台管理后台
description: 在自托管密码部署中管理账号、安装实例、执行、告警和审计。
---

平台管理后台位于 Web 的 `/admin`，适用于使用用户名和密码登录的自托管部署。工作空间的 owner 或 admin 不会自动获得平台权限。平台管理员即使没有加入工作空间，也能进入后台。

## 启用后台

先应用与服务端版本配套的数据库迁移。升级时保留数据库、`JWT_SECRET` 和固定的部署 UUID。服务端会检查必需的索引和触发器；缺失或无效时拒绝启用。迁移账本中有记录，不代表并发索引已经构建成功。

```dotenv
MULTICA_AUTH_MODE=password
MULTICA_DEVICE_AUTH_ENABLED=false
MULTICA_PLATFORM_ADMIN_ENABLED=true
MULTICA_DEPLOYMENT_ID=<固定的部署 UUID>
MULTICA_PASSWORD_LIMITER_MODE=single
MULTICA_MANAGED_INSTALLATIONS_ENABLED=true
```

`MULTICA_CLOUD_URL` 保持为空。`single` 只适用于一个 API 进程；多副本部署需要统一设置 `MULTICA_PASSWORD_LIMITER_MODE=shared`，并连接同一个 `REDIS_URL`。Redis 不可用时，密码请求会被拒绝。修改配置后重启 API。安装上报需要兼容版本的桌面端和守护进程。

先创建实名密码账号，完成必要的密码修改，再在受信任的 API 主机上使用服务端可执行文件，沿用该部署的数据库和密码模式配置：

```sh
server platform-admin bootstrap --user USER_UUID --reason "Initialize deployment administration"
```

按已有账号的 UUID 选择目标。初始化不会自动提升首个注册用户，也不会按显示名称挑选账号。操作与审计会一并记录，账号授权版本会提升，旧凭据会撤销。重新输入密码登录后访问 `/admin`，并安排第二位实名超级管理员协助恢复访问。

## 角色和内容权限

| 角色 | 权限 |
| --- | --- |
| `platform_observer` | 查看平台元数据、告警、健康状态和审计摘要 |
| `super_admin` | 具有观察者权限，并可执行允许的账号、角色、安装、执行和告警操作 |

后台要求完整的人类密码会话。个人访问令牌、task 或守护进程凭据、历史会话和临时密码会话不能执行平台管理。服务端会在后续请求及写入事务中重新检查角色和账号限制。

查看平台元数据不会授予私有任务标题、提示词、评论、日志或产物的访问权限。打开原始内容仍需通过原有工作空间和内容权限检查。

## 查看安装与执行

一个安装实例可以包含多个运行时和工作空间绑定。客户端、守护进程和执行引擎分别记录状态：桌面窗口打开，不代表守护进程或引擎正常。缺失或过期的观测会保留为未知或陈旧状态。旧客户端和历史 task 可能没有安装关联，系统不会把历史 ID 追认为可信安装证明。

一个业务任务可以产生多次 task 执行尝试。执行列表和详情展示已记录的来源、目标、状态及用量。结果统计使用所选的完成时间窗口；当前排队和运行中的数量包含所有仍活跃的执行。下钻链接保留对应窗口和时区。缺失用量保持未知，token 数量不等于账单。

## 操作与不确定结果

停止接单会阻止安装实例领取新执行，已经运行的执行继续进行。准备好后需要明确恢复接单。

取消操作区分服务端 task 状态变化与执行进程停止确认。客户端离线、等待超时、缺少观测或旧协议，都不能证明进程已经退出。请查看操作回执；未确认的结果可能需要人工排查。

每次管理写入都包含原因和请求标识。响应丢失时，保留回执页面或刷新，查询同一请求的实际结果。不要因结果不确定就重新提交另一笔操作。后台会保留待确认请求并恢复查询。

禁用账号、调整角色和恢复密码可能撤销目标账号的凭据，并影响其运行时拥有的执行。提交前查看确认表单中的影响范围。恢复账号不会恢复旧凭据。普通管理操作不能移除或禁用最后一位有效超级管理员。

## 处理告警

首期规则覆盖长时间排队、单次执行失败，以及有在途执行时已证实的安装失联。确认告警表示已经接手处理；负责人只能选择符合条件的活跃超级管理员。故障恢复由独立的来源观测决定。

执行失败是一条历史事实。关闭时需要选择处置结论；选择重试成功，需要关联已验证成功的后续重试。关闭失败告警不会清除去重记录。其他告警在观测到恢复后才能关闭。来源不可用时，检测器暂停新建与恢复判断，不会据此把所有安装标成离线或恢复。

## 健康、审计和保留策略

健康页面使用数据库、心跳、后台任务、取消协调器和告警检测器的实际观测。尚未运行过的组件显示未知。审计仅展示受控元数据；有记录时展示当时的操作者名称，历史缺失值保持未知。

可以配置后台展示的保留天数：

```dotenv
MULTICA_ADMIN_CONFIRMED_OPERATIONS_RETENTION_DAYS=90
MULTICA_ADMIN_ALERT_RETENTION_DAYS=90
MULTICA_ADMIN_AUDIT_RETENTION_DAYS=365
```

这些配置不会启用自动删除。待确认操作和既有业务历史仍然保留。

## 恢复访问与回退

日常恢复优先由另一位活跃超级管理员处理。部署维护命令可以按明确原因恢复已有账号：

```sh
server password-recover --user USER_UUID --reason "Approved account recovery"
```

临时密码从受保护的标准输入读取，不接受命令参数或环境变量。只有尚无密码凭据的历史账号才需要额外传入 `--username NAME`。恢复最后一位有效超级管理员还需要 `--break-glass`；该用户完成强制改密前，部署暂时没有有效管理员。

关闭后台不会撤销账号限制、恢复接单或终止待确认取消的协调。回退页面时应保留具备安全约束的服务端及已有数据。已有凭据、审计、安装绑定和控制历史会阻止破坏性 down 迁移。维护回退前停止所有写入进程，优先向前修复。恢复旧数据库可能重新激活已撤销凭据，需要单独制定恢复方案。

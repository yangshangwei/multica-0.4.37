Skill 是工作区中可以复用的一组工作方法。它以 `SKILL.md` 为主文件，也可以附带脚本、模板和参考资料。

把 skill 添加到[智能体](/agents)后，智能体会在执行相关任务时使用其中的说明。相同的方法不必分别复制到每个智能体的指令中，修改时也只需要维护一份。

## Skill 与智能体指令

| | 智能体指令 | Skill |
|---|---|---|
| **适合保存** | 这名智能体长期不变的职责、边界和交付要求 | 某类工作可复用的步骤、资料和工具 |
| **使用范围** | 只属于一名智能体，每次执行都会提供 | 可以添加给多名智能体，并单独启用或停用 |
| **例子** | "只审查前端代码，不直接修改" | 一套无障碍检查清单和报告模板 |

## 创建或导入 skill

在工作区的 **Skills** 页面选择"新建 skill"，可以使用五种方式：

| 方式 | 适合什么情况 |
|---|---|
| **手动创建** | 从空白的 `SKILL.md` 开始编写。 |
| **从模板中修改** | 预览内置模板，修改副本后创建自己的 skill。 |
| **从本地导入** | 选择包含 `SKILL.md` 的文件夹，或这台电脑上的 `.skill` / `.zip` 压缩包。 |
| **从 URL 导入** | 从内网可达的 URL 导入 skill 压缩包，例如托管在内网 Git 服务上的地址。 |
| **从运行时复制** | 扫描连接电脑上的 skill，并把选中的内容复制到工作区。 |

公网的 skill 市场在内网不可达；团队要共享的 skill 由管理员或成员维护在内网 Git 服务上，再用上面的方式导入。

从运行时复制的是当时的文件快照。之后本地文件发生变化，不会自动更新工作区中的版本；需要重新导入或在 Multica 中编辑。

同一套压缩包格式也可以用 CLI 导入：

```bash
multica skill import --file ./review-helper.skill
```

导入时如果工作区已经存在同名 skill，可以停止导入、覆盖原内容、使用新名称保存，或跳过。通过导入覆盖仅限该 skill 的创建者本人；工作区 `admin` 即使可以在应用内编辑它，也不能用导入的方式覆盖。要为已在工作区里的 skill 拉取新版本，请改用[更新已导入的 skill](#更新已导入的-skill)。

## 从模板中修改

选择**从模板中修改**，从七个内置角色模板中选择一项并阅读正文。点击**使用此模板**后，可以修改副本的名称、描述和 Markdown 正文。点击**创建 skill**才会保存，并打开新 skill 的详情页；浏览或取消不会创建记录。

副本需要使用独立名称，例如 `multica-code-review-copy`。它是一份普通、可编辑的 skill，原模板和已有工作区 skill 保持不变，也不会复制智能体绑定或权限。创建后再按需要分配给智能体。后续模板更新不会覆盖你的副本。

返回模板列表会保留草稿；换用其他模板或关闭时，有手工修改才会提示是否放弃。如果创建请求超时，请先点击**核对创建结果**，再决定是否重新提交。停止等待不代表服务端已撤销创建，找到的候选结果会提供给你打开核对。

## 更新已导入的 skill

从 URL 导入的 skill 会记住它的来源地址（必须是内网可达地址，例如内网 Git 服务上托管的压缩包）。要拉取最新版本，在 skill 页面点击**更新**（或在列表行菜单里选「从来源更新」），也可以用 CLI：

```bash
multica skill refresh <skill-id>
```

Skill 会从来源重新下载并就地替换：

- **保留**：skill 的身份 —— 智能体分配、标签、创建者和创建时间。智能体无需重新添加。
- **替换**：名称（来源改名时跟随）、描述、`SKILL.md` 和全部支持文件。对 skill 的本地修改会被覆盖。

Skill 的创建者以及工作区 `owner`、`admin` 都可以从来源更新。手动创建、从压缩包导入、或从运行时复制的 skill 没有托管来源，无法这样更新 —— 请重新导入。

要一次更新多个 skill，在列表中选中它们，然后在选择工具栏中点击**更新**。所有选中的、有托管来源的 skill 都会从来源重新下载；没有托管来源的会被跳过。

## Skill 的内容

每个 skill 都包含一个主文件 `SKILL.md`。在这里写清：

- 这个 skill 的适用场景；
- 开始前需要检查什么；
- 执行步骤；
- 结果应以什么形式提交；
- 哪些情况需要停止并向成员确认。

还可以添加支持文件，例如：

```text
SKILL.md
references/api-conventions.md
templates/review-report.md
scripts/check.sh
```

`SKILL.md` 是保留路径，不能再创建同名支持文件。支持文件会和主文件一起提供给智能体。

## 添加到智能体

创建或导入 skill 后，还需要把它添加到具体的智能体。你可以在 skill 页面选择智能体，也可以打开智能体的 **Skills** 标签页进行管理。

- 一名智能体可以使用多个 skill；
- 同一个 skill 可以供多名智能体使用；
- 暂时不需要时，可以停用绑定，而不必删除 skill；
- 修改后的内容从后续执行开始生效，不会改变已经运行中的任务。

只有有权修改该智能体的成员，才能为它添加、移除或停用 skill。

## 工作区 skill 和仓库中的 skill

工作区 skill 保存在 Multica 中，适合由团队共同维护，并添加给不同智能体。

部分 AI 编程工具也会直接读取代码仓库中的项目级 skill，例如 `.claude/skills/` 或 `.agents/skills/`。这些文件仍由仓库管理，Multica 不会自动把它们登记为工作区 skill。具体支持方式取决于使用的工具，见 [AI 编程工具对照](/providers)。

连接电脑上已安装的运行时本地 skill（Claude Code 和 Codex）会显示在智能体的 **Skills** 标签页中，可以按智能体单独停用。停用同样需要有权修改该智能体。

## 组织 skill

**Skills** 页面沿三个相互独立的维度组织技能库：唯一的主分类、任意多个标签，以及 skill 的来源。把它们分开，才能在库很大时浏览，而不会把"归属哪里""关于什么""从哪来"混成同一维度。

### 主分类

每个 skill 只有一个主分类，回答"这个 skill 在软件研发与交付体系中主要归属哪里？"前五项构成从规划到发布的主交付链路，后三项是贯穿全流程的支撑能力。

| 分类 | 覆盖范围 |
|---|---|
| **需求与规划** | 需求澄清、范围界定、验收标准 |
| **设计与架构** | 技术设计、架构决策记录、接口设计 |
| **开发与集成** | 编写与集成代码 |
| **测试与质量** | 代码审查、安全审查、测试、质量报告 |
| **发布与运维** | 发布检查、部署、运维 |
| **协作与知识** | 文档、进展报告、团队沟通 |
| **数据与自动化** | 数据处理、脚本、自动化 |
| **通用工具** | 无法归入以上单一阶段的其他情况 |

在 skill 的创建页或详情页选择主分类，或用选择工具栏的 **设置分类** 一次性为多个 skill 设置。跨阶段的 skill 保留一个主分类，其余属性通过标签表达。

### 标签

标签是多选的横向维度，回答"它适用于什么领域、平台、工作方式、交付物或风险场景？"一个 skill 可以有多个标签，列表页可以按标签筛选和搜索。

一套可读的命名约定按维度对标签分组。系统把整个名称视为不透明字符串——不解析前缀、不替你创建这些标签、也不给它们附加任何行为，因此只采用团队真正需要的部分：

- **领域**：`领域/产品`、`领域/前端`、`领域/后端`、`领域/数据`、`领域/AI`、`领域/安全`、`领域/基础设施`、`领域/文档`
- **平台**：`平台/Web`、`平台/Desktop`、`平台/Mobile`、`平台/Server`、`平台/CLI`、`平台/Cloud`
- **方式**：`方式/分析`、`方式/生成`、`方式/审查`、`方式/自动化`、`方式/报告`
- **产物**：`产物/PRD`、`产物/ADR`、`产物/API`、`产物/代码`、`产物/测试`、`产物/发布包`、`产物/运行手册`
- **风险**：`风险/生产操作`、`风险/安全敏感`、`风险/破坏性`

在 skill 详情页添加标签，或用选择工具栏的 **管理标签** 一次性处理多个 skill：点击某个标签会把它添加到所有可编辑的选中 skill；若它们全部已有该标签，则改为移除。

<Callout type="warning">
标签只用于组织和查找 skill。`风险/生产操作` 或 `风险/破坏性` 之类的标签记录的是意图——它不授予任何权限，也永远不能替代智能体仍须经过的执行审批与安全边界。
</Callout>

## 修改权限

任何工作区成员都可以创建或导入 skill。创建者和工作区 `owner`、`admin` 可以修改或删除它；其他成员可以查看和使用，但不能覆盖内容。

删除是永久操作，同时会从所有智能体上移除该 skill。

<Callout type="warning">
从外部导入的 skill 可能包含脚本、命令或不安全的指令。Multica 不会替你审查、签名或隔离这些内容。导入的内容会原样提供给智能体执行，来源需要可信。
</Callout>

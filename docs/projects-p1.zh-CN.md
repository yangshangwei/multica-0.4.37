# 项目增强 P1 使用与升级说明

P1 沿用现有项目，增加目标模板、正式任务统计拆分、健康概览、手动进展和目标验收记录。Web 与桌面端共用界面；移动端保持项目读取和原属性操作兼容，新进展编辑在 Web／桌面端完成。本文是功能和升级说明，实际验证与部署状态见 [P1 验收记录](../.trellis/tasks/10-05-projects-p1/verification.md)。

## 目标、进度与验收

项目描述仍是目标、范围和验收标准的唯一编辑来源。目标模板先预览再追加所选章节，不覆盖已有正文；保存后的描述继续进入项目任务的执行上下文。

统计只计算同工作空间、实际归属该项目且准入为 `not_required` 或 `accepted` 的任务。待分拣、拒绝、重复及候选项目不计入，分拣开关不改变这个规则。

- 完成数只计 `done`；取消数只计 `cancelled`。
- 范围闭合为 `(完成 + 取消) / 全部正式任务`；原 API 的 `done_count` 保留此分子含义。
- 没有正式任务时比例不适用；父任务与子任务各计一次。
- 健康、范围闭合、项目状态和人工验收彼此独立，不自动启动执行或代替验收。

健康卡片显示阻塞、逾期、未分配、待验收及其去重风险。截止日早于工作空间规划基准日才逾期；今天到期不算。有效但离线的智能体仍属于已分配，环境不可用另行提示。工作空间 owner/admin 可设置 IANA 规划时区，未配置明确使用 UTC，历史快照不会随新设置改写。

## 手动进展

通过记录进展或记录验收填写内容，预览证据、自动统计及提及接收者后发布。通过／部分通过的验收需要证据或可复核说明，并绑定当时的描述版本。目标变化后旧验收仍可读，但不能代表新目标已经通过。

更正需要原因，保留所有旧版本；P1 不提供单条进展的无痕删除。请求丢失响应后重试同一意图会返回原记录，不重复发布或通知。提及成员只发站内通知，提及智能体只作为引用；不会发送外部邮件／聊天消息或启动智能体。

内部证据按来源类型打开对应任务或执行查看器，每次读取都重新校验权限。某个来源不可访问时可保留自己的草稿、移除引用后重试；失去工作空间成员资格时则清除受保护内容。

## 并发编辑与 CLI

项目响应包含 `revision` 和独立的 `description_revision`。描述真实变化必须携带自己实际读取过的描述版本；冲突后先比较与合并，不自动采用最新版本号强行覆盖。

```bash
multica project get <project-id> --output json
multica project update <project-id> --description "<已核对的正文>" --expected-description-revision <description_revision> --output json
multica project update <project-id> --due-date 2026-10-30 --expected-revision <revision> --output json
```

版本参数为正的安全整数。旧 CLI 无版本描述写会得到 428 和升级／补充版本提示；409 冲突不自动重试。非描述的原有属性操作仍可使用。图标等变更不改变 `description_revision`，不会令目标验收过期。

## 状态与删除

项目完成前显示未结束任务、取消数和验收情况，仍允许有权限成员明确继续。暂停、取消、完成或重开项目不批量修改任务、不停止正在运行的执行。

只有 owner/admin 可以删除项目。删除会解除任务项目关联，清理项目描述、资源、专属进展／验收、项目视图和偏好；保留任务、评论、执行历史及共享小队／智能体／物理目录。关联自动化暂停并记录 `project_deleted`，其触发器禁用，防止删除后继续产生新工作。

## 升级与回退

1. 在目标环境按正常迁移流程应用完整 536—549 序列。新增索引各自独立 `CREATE INDEX CONCURRENTLY`，失败重试通过已注册的无效索引清理 hook 恢复；不能仅凭 migration ledger 或 `IF NOT EXISTS` 认定索引有效。
2. 既有描述内容保持原样，版本从 1 开始。既有进行中项目无法推断历史开始时间，七日提醒从迁移基线计时并明确标记；不伪造过去的开始时间。
3. `FF_PROJECTS_P1=false` 可以撤下新概览／进展界面并停止新进展写入；已有记录、历史和安全请求重放仍可读取，描述 CAS 保持。它不是删除历史数据的开关。
4. 已有 P1 历史、请求、通知、非默认版本或规划配置时，down migration 会拒绝。只在隔离、空白维护环境且所有 writer 停止时演练受控回退；实际升级优先保留数据并向前修复。
5. 旧后端能力缺失与权限／网络／协议失败分开处理。缺失新统计字段不能被解释成实际完成为零，也不能由旧 `done_count` 猜出完成和取消分项。

本期不实现迭代 I1、AI 进展草稿、组合时间线或里程碑。真实迭代归属／结束快照的集成验收由 I1 接续；不以不存在的表或模拟字段声称已通过。

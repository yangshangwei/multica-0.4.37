## 技术问题

### 1. [P1] 模板卡片的键盘焦点对比度不足

- 分类：可访问性。
- 位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L209)，[tokens.css](../../packages/ui/styles/tokens.css#L198)。
- 证据：卡片使用 `focus-visible:outline-ring`，浅色 `--ring` 为 `oklch(0.705 0.015 286.067)`。将 OKLCH 转为线性 sRGB 并计算相对亮度后，与页面底色对比度为 **2.54:1**，与白色 raised surface 为 **2.63:1**。卡片的半透明白色背景处于两者之间，因此仍低于 3:1。
- 影响：用 Tab 浏览模板时，低视力用户不易确定当前操作对象。涉及 WCAG 2.2 **1.4.11 非文本对比度（AA）**。此处已有焦点轮廓，问题是颜色对比度，不是完全没有键盘支持。
- 建议：为卡片提供与相邻背景达到至少 3:1 的焦点颜色。若调整共享 `--ring`，同时检查其他控件和两种主题，避免只为当前页面改动整个系统。
- 建议命令：`$impeccable harden`。

### 2. [P2] 窄屏和触控设备的小控件目标偏小

- 分类：响应式。
- 位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L134)，[mcp-tab.tsx](../../packages/views/settings/components/mcp-tab.tsx#L228)，[button.tsx](../../packages/ui/components/ui/button.tsx#L45)，[input.tsx](../../packages/ui/components/ui/input.tsx#L12)。
- 证据：分类和添加按钮采用 `size="sm"`，对应 `h-7`，通常为 **28px**；搜索框为 **32px**。全局粗指针规则调整输入字号，没有扩大点击区域。
- 影响：窄屏页面虽能换行，触屏点选仍容易误触。
- 建议：在粗指针设备上将目标扩展至至少 **44×44 CSS px**，可扩大命中区域，不必把桌面界面同步变大。
- 标准说明：44px 是本次审计采用的触控建议，也对应 WCAG 2.5.5 的增强目标；**不能把低于 44px 直接认定为 WCAG AA 违规**，2.5.8 AA 的尺寸及间距条件不同。
- 建议命令：`$impeccable adapt`。

### 3. [P2] 搜索和筛选结果没有动态播报

- 分类：可访问性。
- 位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L170)。
- 证据：搜索框有正确的 `aria-label`，加载与错误也有 `status`/`alert`；但结果列表更新和“没有匹配的模板”没有 live region，亦没有结果数量状态。
- 影响：读屏用户修改搜索或分类后，需要手动探索后方内容才能得知结果是否变化。
- 建议：增加一个持久的 `role="status"`/`aria-live="polite"` 区域，简短播报“找到 2 个模板”或“没有匹配的模板”。避免给整个卡片列表设置 live region，以免每次输入朗读全部内容。
- 标准参考：WCAG 4.1.3 状态消息；此报告确认缺少结果播报，实际读屏体验仍需验证。
- 建议命令：`$impeccable harden`。

### 4. [P2] 配置名称的字符限制在提交后才出现

- 分类：实现一致性 / 表单可访问性。
- 位置：[mcp-setup-dialog.tsx](../../packages/views/mcp/mcp-setup-dialog.tsx#L159)，字段位于同文件第 334 行。
- 证据：校验只接受 `[A-Za-z0-9_-]`，字段旁没有提前说明；已有辅助文字只解释保存与分配流程。
- 影响：中文界面中的“配置名称”容易被理解为可自由填写的显示名称；输入中文后才报错，增加返工。
- 建议：字段旁增加“仅支持英文字母、数字、连字符和下划线”，通过 `aria-describedby` 关联，并明确必填。保留已有报错关联与错误后聚焦。
- 标准参考：WCAG 3.3.2 标签或说明。
- 建议命令：`$impeccable clarify`。

### 5. [P2] 智能体侧复用配置时缺少进行中反馈

- 分类：实现一致性 / 交互状态。
- 位置：[mcp-agent-discovery.tsx](../../packages/views/mcp/mcp-agent-discovery.tsx#L170)。
- 证据：分配请求设置 `busy` 后禁用操作及完成按钮，按钮文字却仍显示“分配给…”，没有 spinner 或“正在分配”状态。共享 Button 不会自动补充 loading。
- 影响：慢网络下用户只看到控件变灰，无法明确区分正在处理和不可操作。
- 建议：正在处理的配置显示“正在分配…”及状态提示；完成后更新为“已分配”，必要时用 status 区域播报。
- 建议命令：`$impeccable harden`。

## 截图中的体验建议

这部分是视觉与信息架构判断，不属于机械检测结果。

### [P2] 模板入口与自定义添加入口的关系不明确

位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L204)、[mcp-tab.tsx](../../packages/views/settings/components/mcp-tab.tsx#L225)。

截图中，唯一显式动词按钮是“添加 MCP Server”，实际打开的是自定义编辑器；模板卡片虽然整张可点击，常态只显示图标、名称和说明。用户可能先进入手动配置，再发现可以从模板开始。

建议把顶部入口明确为“自定义添加”，模板卡片补充轻量的“查看配置 →”提示。保留整卡点击，避免嵌套按钮。可考虑将“工作空间”标签改为“已配置”，使它与市场的关系更直接；需与产品术语统一。建议 `$impeccable clarify`。

### [P2] 两个浏览器模板缺少便于扫描的选择依据

位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L198)。

Chrome DevTools 与 Playwright 使用相同 Globe 图标，用户需要逐句阅读说明才能区分。已有描述包含差异，但主要用 DOM、协议、快照等实现术语呈现。

建议把现有能力概括为一行用途：Chrome DevTools“检查页面、调试浏览器”，Playwright“自动操作网页、填写表单”。运行要求继续放在配置弹窗，需要时仅在卡片提炼关键前提。无需为三个模板引入一套复杂分类或添加未经证实的“推荐”标签。建议 `$impeccable clarify`。

### [P3] 卡片垂直空间与内容量不匹配

位置：[mcp-market.tsx](../../packages/views/mcp/mcp-market.tsx#L209)、[settings-layout.tsx](../../packages/views/settings/components/settings-layout.tsx#L18)。

模板卡片采用图标独占一行、`min-h-36` 的排列，说明文字使用 12px caption；截图中仅有三个模板，卡片底部仍有明显空白。内容较少的“顺序思考”尤其明显。

建议将图标与标题并排，适当压缩卡片高度，腾出的空间优先用于用途和动作提示。保留应用现有黑白风格、边框和字号体系；这属于密度优化，不能仅凭截图把整体居中位置或宽度判为错误。建议 `$impeccable layout`，最后 `$impeccable polish`。

## 应保留的实现

- Base UI Tabs/Dialog、原生卡片按钮、搜索标签和分类 `aria-pressed` 提供了良好的语义基础。
- 模板和工作空间列表具备加载失败重试，空搜索结果允许清除筛选。
- 单列/双列响应式、工具栏换行、弹窗内容滚动与操作区分离已经实现。
- 当前浅色正文 `--muted-foreground` 对页面背景约 **5.70:1**、对白色表面约 **5.89:1**，无需仅因视觉上偏灰而统一加深。
- 模板查询按语言缓存 30 分钟；目前只有三个轻量模板，没有证据支持引入虚拟列表或增加 memo 层。
- 保存与分配分步完成；部分分配失败的正常路径保留成功结果，只重试失败项，已有测试保护。

## 建议顺序

1. `$impeccable harden`：先修焦点对比度，再补搜索结果和分配状态反馈。
2. `$impeccable clarify`：明确自定义入口、模板用途和名称规则。
3. `$impeccable adapt`：扩大粗指针设备的触控目标，并验证窄屏与文本缩放。
4. `$impeccable layout`：压缩无信息的卡片留白。
5. `$impeccable polish`：统一细节收尾。

这些改进可以逐项或合并执行；完成后重新运行 `$impeccable audit`，并补上浏览器验证。若后续需要跨页面持续设计，可用 `$impeccable init` 补充 PRODUCT.md；当前局部审计不依赖它。

## 修复结果

已处理上述 5 项技术问题和 3 项体验建议：

- 卡片焦点改用前景色；真实浏览器稳定状态测得浅色 **19.49:1**、暗色 **17.27:1**，均为 2px 实线。
- 搜索结果使用常驻计数播报；复用配置时有“正在分配…”和完成播报。
- 名称字段提前显示格式与必填说明，并在出错时保留说明关联。
- 入口区分为“共享配置 / MCP 市场”和“自定义添加”；模板卡片增加“查看配置”，浏览器工具的用途与图标分开表达。
- 触控适配覆盖页面、配置弹窗和自定义编辑器；抽查控件的实际点击区域达到 44px。
- 卡片图标与标题并排，移除固定最小高度，说明使用正文级字号；根据容器宽度切换单双列。
- 浏览器检查额外发现并修复保存后的焦点丢失：进入分配步骤时聚焦“选择智能体”，下一次 Tab 进入首个智能体复选框。

**最终验证：**73 项组件/语言测试通过；定向 ESLint、views 类型检查、Go 内置模板测试、Impeccable 检测通过。隔离 Chromium 最终一轮 **65 项检查通过、0 pageerror**，覆盖 320/390/720/1440px、中英文、明暗主题、粗指针、长内容及配置/分配流程。

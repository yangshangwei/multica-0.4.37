## 发现与修复

### ISSUE-001：MCP 路由遗漏诊断形状，阻断 main 的全量检查

- 引入点：新增 MCP 导航的 `978b5ed4a` 更新了 `paths.ts`，未同步 `diagnostic-context.ts`。
- 复现：`pnpm -C packages/core exec vitest run diagnostics/diagnostic-context.test.ts`。
- 实际结果：`unrecognized: /workspace-slug-value/mcp`，返回 `/:slug/*`；期望保留已知页类型 `/:slug/mcp`。
- 影响：CI/本地检查失败，MCP 页诊断失去可识别的页面类别；不是用户标识泄漏。
- 修复：工作区路由形状增加一行 `["mcp"]`，不放宽未知路由的隐私掩码规则，不增加依赖、不做重构。
- 验证：原有穷举路由构造器的测试先失败再通过；core 2,157 tests 全通过，独立审查确认未知子路径仍被掩码。
- 提交：`cf80c0274`，仅在测试分支。

### ENV-001：初次 Electron 测试端口未加入隔离 API 的 CORS

- 初始 API 只允许 Web 的 `http://localhost:13418`，桌面 fixture 使用 `http://127.0.0.1:51337`。
- 证据：OPTIONS 请求没有 `Access-Control-Allow-Origin`；桌面截图显示重新连接，语言用例的 preflight 断言直接失败。
- 处理：只在本次隔离环境配置中增加该 loopback origin；preflight 随后返回匹配来源，6 条 Electron 重跑全通过。
- 未修改产品 CORS 实现。保留原始失败截图/trace，未把测试环境错误算作产品缺陷。

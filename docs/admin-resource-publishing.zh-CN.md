# 从管理后台发布 Skill 与 MCP

后台资源发布将文件保存到 API 服务器的独立持久化目录，使连接此部署的工作空间在现有市场发现资源。它不会安装软件包、执行上传脚本、写入桌面个人目录或覆盖已添加的配置。

## 启用

需要包含资源发布功能的服务端，以及已支持部署模板来源的 Web/桌面客户端。平台管理仍要求密码认证模式和已配置的超级管理员。普通成员、工作空间管理员和只读观察者不能发布部署资源。

Docker 部署使用专用覆盖文件：

```sh
docker compose -f docker-compose.selfhost.yml -f docker-compose.resource-publishing.yml up -d
```

覆盖文件只增加 `managed_resources` 持久化卷与 `MULTICA_RESOURCE_PUBLISH_DIR=/app/data/resources`，原有 Skill/MCP 手工投放目录继续只读。不要把容器整个 `/app/data` 或源码目录设为后台可写。

原生服务部署需先创建仅服务账号可读写的持久化目录，再设置 `MULTICA_RESOURCE_PUBLISH_DIR` 为该目录的绝对路径。空变量表示未启用，已有市场功能照常工作；目录不可读、不可写或损坏会明确报错，不会假装成空目录。

同一目录只能属于同一部署的内部组织。多 API 实例必须使用同一份持久化内容，并保证跨进程/主机文件锁、原子重命名和同步语义。普通单机 Docker 卷符合本地使用场景；不支持这些语义的网络文件系统不应启用多节点写入。不要给不同 API 节点各自配置独立本地卷。

## 操作

1. 超级管理员进入“系统管理 → 资源发布”，选择 Skill 或 MCP。
2. 填写资源标识并选择文件。标识是稳定目录身份，不是任意服务器路径。
3. 校验预览正文及完整文件清单。文件不合法时不会发布残缺内容。
4. 填写操作原因并确认发布。更新已有条目时必须基于最新修订重新预览。
5. 成员在现有市场“部署提供”中发现资源；刷新/重新进入可立即读取，停留前台的市场约30秒轮询。
6. Skill需要复制到工作空间再绑定智能体；MCP需要填写参数、保存并明确分配。MCP命令和依赖必须在智能体执行机器上可用。

平台内置与手工投放条目只读。后台创建的条目可以更新或撤下。撤下只停止后续发现/添加，保留已复制的 Skill、已保存 MCP 配置及其绑定。

## 文件格式

Skill可上传 `SKILL.md` 或 ZIP/`.skill` 包，压缩包根目录或唯一外层目录中必须有 `SKILL.md`。支持 UTF-8 文本说明、脚本和引用文件；二进制内容、符号链接、路径穿越、重复/大小写别名、冲突路径或超额文件会整包拒绝。

限制：压缩上传16MiB，主文件和单个附件1MiB，支持文件合计8MiB，全文本合计9MiB，257个文件、512个ZIP条目（包括目录）。

MCP上传标准 JSON manifest，最大64KiB；格式沿用 [MCP目录发布规范](mcp-catalog-publishing.md)。支持 stdio 和 Streamable HTTP。凭据通过输入项声明，由工作空间配置时填写；公共文件不能包含真实令牌。上传配方不会在服务器或桌面自动执行命令。

管理目录最多256条资源、64MiB活动正文；MCP部署目录还遵守256项/4MiB扫描预算。管理索引包含保留的操作回执，最大16MiB；容量到达上限会拒绝新写入，不会自动丢失幂等记录。

## 一致性、失败与审计

内容指纹与管理修订不同：相同文件重新发布或撤下也会生成新的修订，用于防止旧预览覆盖新状态。每次操作有独立ID，相同请求重试返回原结果，不同内容复用操作ID会被拒绝。

发布数据采用不可变修订和原子索引。上传校验或写入失败保留上一版；临时/历史数据不进入消费市场。不应手工编辑内部索引、锁文件或修订文件，也不要单独恢复其中一部分。

操作前记录审计请求，提交后记录结果。数据库审计与文件系统并非一个事务；如果提交后响应或结果记录失败，界面会提示结果待确认并查询原操作回执。不要换一个操作ID盲目重复发布。

定期备份整个管理卷和相应数据库。将 `MULTICA_RESOURCE_PUBLISH_DIR` 置空会同时停用后台发布，并从市场隐藏托管模板；管理卷内数据与已保存的工作空间资源仍然保留。不要删除卷或索引来模拟撤下操作。

## 密码重置

账号详情里的“重置密码”使用临时密码，并复验管理员自己的密码。用户下次登录必须改密。重置会撤销目标用户的 Web/桌面会话与相关令牌，取消其运行时关联任务；成员关系、安装记录及历史保留。禁用账号不会因重置密码自动恢复。临时密码由管理员通过企业批准的方式交付，系统不自动发送邮件或短信。

# 分拣台使用与部署说明

分拣台用于审核主动投递的任务。新输入先进入待分拣队列，由工作空间成员决定是否纳入正式工作。普通任务创建、项目内创建和已有任务保持原有流程，不会因为开启分拣台而全部转入审核。

本文对应 T1 人工分拣实现。2026-10-06 已完成 CI 修复与发布收尾：`main` 上 `5f4fe5f3b` 的 CI、Mobile Verify 通过，v0.5.6 后端/Web 双架构镜像及 changelog 已发布，分拣端到端 17/17 通过；目标内网升级及新桌面安装包发布未执行，详见[验收与部署记录](../.trellis/tasks/10-04-triage-t1/verification.md)。Web 和桌面端共用分拣页面；T1 不提供移动端分拣界面，但服务端同样限制旧客户端和移动端对未准入任务的执行操作。

## 启用与权限

分拣台默认关闭。人工 `owner` 或 `admin` 在工作空间**设置 → 分拣台**中启用并保存后，侧边栏显示入口，地址为 `/{工作空间 slug}/triage`。已有正式任务不会回填到队列。

设置包括接受后的状态、接受时是否必须指定优先级，以及分拣责任。接受后的状态只能选择当前有效的 `backlog` 或 `todo` 类别状态，默认是 `todo`。

| 分拣责任 | 新任务进入时的行为 |
| --- | --- |
| 不指定 | 不自动指定责任人或发送责任通知 |
| 通知指定成员 | 通知该成员，任务仍未指定分拣责任人 |
| 指定分拣责任人 | 指定该成员负责分拣，并通知该成员 |

责任设置只影响后续投递和重新审核，不批量改写已有任务。分拣责任人与执行负责人是两回事；被指定负责分拣也不会独占审核权限，其他有权限的人工成员仍可处理。责任人离开工作空间后，记录会显示其已失效，可由当前成员重新指定。

责任人自己手动投递时，不再给自己发送进入通知。通知投递前会检查成员是否仍在工作空间中。

| 操作 | 权限 |
| --- | --- |
| 查看队列、详情和审核历史 | 当前工作空间成员 |
| 手动投递 | 具有现有任务创建权限的调用者；智能体仍须达到 `Contributor` 自治级别 |
| 审核、批量处理、重新审核、CSV 导入 | 当前工作空间的人工成员 |
| 修改分拣台设置 | 人工 `owner` 或 `admin` |
| 接受并执行 | 人工成员，且对最终智能体或 AI小队负责人具有调用权限 |
| 重试执行 | 原“接受并执行”的人工操作者，且当前权限和执行上下文仍然有效 |

智能体可以通过明确的投递 API 提交候选任务，但不能接受、拒绝、标记重复、安排稍后处理或修改设置。机器凭据携带的用户身份不构成人工审核授权，提高智能体自治级别也不会授予审核权。

## 投递与查看

点击**创建待分拣任务**，填写标题，可补充描述、标签、日期、附件、原始链接、候选项目和候选执行负责人。提交后立即获得任务编号，状态为待分拣。候选项目和负责人此时尚未成为正式关联，也不会启动智能体。标题最多 500 个字符，描述最多 1 MiB。

队列分为**可处理**、**全部未决**、**稍后处理**和**审核历史**。可按来源、优先级、候选项目、标签、分拣责任人、提交者和进入时间筛选，按进入时间或优先级排序。顶部未决计数包含安排了稍后处理的任务，不随当前筛选条件变化。

待分拣任务保留独立的详情链接，可以补充内容、评论和附件。评论中的提及不会发起执行；这段时期保存的提及也不会在接受后被延迟派发。任务只有在接受后才进入普通任务列表、搜索和项目统计。

## 四种审核结果

| 操作 | 结果 |
| --- | --- |
| 接受 | 任务纳入正式工作；本次填写的项目、负责人、优先级、标签和日期与审核结果一起保存。普通接受不会启动执行，包括选中了智能体、AI小队或 `todo` 状态的情况。 |
| 拒绝 | 填写 1–2,000 个非空原因字符，保留原任务与记录，移出未决队列。 |
| 标记重复 | 选择本工作空间中的正式任务，可选已结束任务；不能选择自身或其他工作空间的任务。原输入保留，评论和附件不合并到目标，目标任务不被修改。 |
| 稍后处理 | 选择未来 90 天内的时间，暂时移出可处理队列；仍属于未决任务。到期后自动回到可处理队列，也可提前恢复。 |

如果启用了优先级要求，必须指定有效优先级才能接受。目标项目或负责人失效、调用权限变化、其他成员已修改任务时，审核会失败，不会只保存一半字段。界面保留输入；遇到版本冲突应先刷新当前任务，再决定如何处理。

**接受并执行**是单独的明确操作，需要选择智能体或 AI小队，并通过调用权限与运行时检查。接受成功后若执行准备或入队失败，任务仍为已接受，页面显示执行尚未启动，原操作者可重试执行。重试沿用原审核动作和执行身份，不会再次接受或重复创建执行；已经获得 `task_id` 的动作会返回原执行。

重试并不允许悄悄换人执行。负责人、AI小队负责人、运行时、项目资源或相关执行内容发生变化时，旧动作会被拒绝；请查看当前正式任务，并重新作出明确的执行决定。

已拒绝或标记重复的任务可以填写原因后**重新审核**，开启新一轮分拣；旧轮次历史保留。已接受的任务不能用该操作退回待分拣。

## 批量处理

勾选明确要处理的任务后，可批量接受、拒绝、安排稍后处理或指定分拣责任人。先预检，再确认选中的有效任务；不会自动处理整个筛选结果，也不支持批量“接受并执行”或批量标记重复。

每条任务独立提交。结果区区分成功、版本冲突、校验失败、权限变化和其他失败，重试只针对未成功项。成功项不会因另一条失败而回滚，也不应重复提交新的请求来重做。

## 导入 CSV

CSV 必须为 UTF-8 编码，可带 BOM，最多 5 MiB、1,000 行数据，不含表头。超出文件限制或编码无效时整个文件被拒绝，不会截断导入。表头不能为空或重复；包含逗号、引号或换行的单元格请按标准 CSV 格式保存。

1. 点击**导入 CSV**并选择文件，查看预览。预览保存导入批次和行结果，但不创建任务，也不发送任务通知。
2. 检查每列映射，可以使用常见中英文表头，也可手动修改或忽略。修改映射后点击**应用映射**生成新预览；同一业务字段不能同时映射两列。
3. 查看逐行错误、警告和重复提示。勾选有警告的有效行表示确认按预览结果导入；有错误的行不能导入。
4. 确认导入已选行，查看每行的创建、跳过或失败结果。需要重试时保留原批次，重试失败行；也可稍后选择本次未选的行。

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填，最多 500 个 Unicode 字符 |
| 描述 | 最多 1 MiB，保留单元格内换行 |
| 优先级 | `urgent`、`high`、`medium`、`low` 或 `none`；留空按 `none` |
| 项目、标签 | 按当前工作空间中的名称解析；不会自动创建 |
| 负责人 | 成员邮箱或可见智能体名称，导入后仅为候选负责人 |
| 开始日期、截止日期 | `YYYY-MM-DD`；截止日期不能早于开始日期 |
| 原始链接 | 完整 HTTP 或 HTTPS 地址 |
| 外部编号 | 最多 1,000 个 UTF-8 字节；用于识别同文件或既往导入中的重复输入 |
| 状态、迭代、附件及其他忽略列 | 不采用；有值时给出警告 |

项目、标签或负责人找不到、存在同名歧义或不可访问时，预览会清空对应候选值并提示警告。正式提交时还会重新检查引用和权限。相似标题仅提供重复候选，不会自动合并或吞掉任务。

外部编号重复的行默认跳过。确实需要保留另一条输入时，对该行明确选择**仍要导入此重复行**再勾选导入。网络中断后重试同一批次和行，不会重复创建；即使对应任务后来被删除，该行仍保留已消费身份，不会借重试重新创建任务。

失败行可下载为 CSV，保留原始列、原始行内容、数据行号和错误原因；可能被表格软件当成公式的值会作文本保护。修正原始数据或映射需要重新预览；临时错误修复后可以重试原批次。批次明细、提交和失败下载仅供原导入者在仍具有工作空间成员权限时访问。

导入通知按批次汇总，不逐行刷屏。同一批次后续重试更新累计结果，不重复发送一批相同通知。

## 审核历史与通知

审核历史记录操作者、时间、轮次、原因和变更前后的字段。历史筛选支持处理结果、处理人、处理时间和来源；重新审核不会覆盖旧决定。CSV 批次也有汇总记录。

标记重复时会保留目标编号，目标删除后仍能看懂当时指向哪条任务。任务删除后，消费过的投递请求、审核动作和已成功导入行仍保留必要身份；重放投递或审核请求会返回已删除结果冲突，导入行返回原结果身份，不会复活任务。

收件箱只是通知入口。已读、归档或删除通知不会接受、拒绝或移除待分拣任务。通知投递失败可以独立重试，不会回滚已提交的审核决定。稍后处理到期依靠时间判断恢复队列，服务端重启不会丢失恢复时间；仅当通知仍适用于当前责任人和当前稍后时间时才发送到期提醒。

## 关闭、升级与回退

关闭前必须处理完全部未决任务，**包括稍后处理**。关闭后侧边栏入口隐藏，但 `/{工作空间 slug}/triage?view=history` 仍可查看历史；已接受任务继续按正式任务使用。关闭不会删除审核记录、导入记录或请求身份，也不会把拒绝、重复任务变成正式任务。再次投递或重新审核需先启用。

部署时先备份数据库，并在明确的目标环境应用仓库迁移。T1 使用 **513–535**：513 增加准入字段和分拣表，514–534 分别建立并发索引，535 增加执行与评论派发防线。通过现有 `make migrate-up` 按完整迁移序列执行，不能只摘取表结构或跳过中间索引；并发索引不能包在事务中执行。

服务端和客户端部署后，先在默认关闭状态验证原有任务流程，再由人工管理员为选定工作空间开启。`GET /api/triage/settings` 返回 `supported: true` 表示服务端支持；旧服务端返回 404 时新客户端显示不支持。网络和权限错误应单独排查，不能当成“功能已关闭”。

旧客户端可能仍展示状态或负责人操作。服务端会对未准入任务的受保护写入返回 HTTP 409，包含 `code: "triage_review_required"`、说明、`issue_id` 和 `issue_path`；请使用支持分拣台的客户端完成审核。`admission_status` 由服务端管理，改普通状态、metadata、`--no-start` 或直接调用执行接口都不能替代审核。当前没有 `multica triage` CLI 子命令；集成应使用 `/api/triage/*` API 和现有工作空间认证。

**关闭功能不等于可以降级数据库。** 只要存在分拣设置行、历史、预览批次、导入行、通知、已消费请求身份、非默认准入状态或禁止派发的评论记录，相关 down 迁移会拒绝删除。清空队列、删除任务或关掉入口都不能消除这些保留要求。已有数据的环境应保留结构并向前修复，不得删记录或索引来强行绕过拒绝；不具备准入防线的旧服务端也不能接管已使用分拣台的环境。

空数据回退演练只应在隔离测试 schema 进行。实际回退需要停止全部 API 和后台写入并保持维护状态；down 文件的 `ACCESS EXCLUSIVE NOWAIT` 锁只保护单文件，遇到并发写入会拒绝，不能代替整个回退过程的停写。

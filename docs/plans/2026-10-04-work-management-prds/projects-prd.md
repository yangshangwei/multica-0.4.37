## 1. 产品定位与阅读约定

项目承载多条任务共同推进的目标，帮助成员判断目标是否明确、当前风险是什么、谁需要协调、结果是否经过验收。任务继续承载具体工作、评论、执行和任务级验收。

本需求沿用"项目"界面名称、现有 Project 数据身份和工作空间边界，不增加"专项"并列导航、第二套项目实体或跨工作空间项目。

文中"已有"表示现有产品基线，"增强／新增"表示本轮产品建议；P1、P2、P3 是交付阶段，不是项目优先级。项目优先级继续使用既有值。阶段、权限、准入与统计若有跨模块疑问，先以共同契约为准；源代码证据集中在[现状与参考依据](research.md)。

## 3. 问题、目标与非目标

### 3.1 要解决的问题

- 任务很多时，成员必须逐个查状态、负责人和日期，才能判断项目是否需要介入。
- 描述能存放目标，但缺少可复用的写作结构；项目关闭和目标验收容易被混为一谈。
- 范围闭合进度包含取消任务，单看百分比可能高估实际交付。
- 进展散落在任务评论和执行中，后加入者难以理解最近变化、风险和下一步。
- 单项目任务甘特图不能回答多个项目是否挤在同一交付窗口。

### 3.2 目标与成功行为

1. 成员打开项目概览后，能找到目标、范围、验收标准和最新进展。
2. 负责人能从明确的风险计数进入对应任务，不必手动拼接筛选条件。
3. 进度、交付完成、取消、项目状态和目标验收分别可见，含义不混淆。
4. 项目状态与任务执行继续独立；新增管理操作不带来隐式执行。
5. 后续由 AI 减少整理进展的劳动，但成员仍能检查证据并决定是否发布。

### 3.3 非目标

- 不新增跨工作空间专项、组织级权限、访客协作或匿名项目入口。
- 不替换现有任务视图、资源、默认小队、智能体执行或自动化系统。
- 不把项目变成必须经过审批的阶段流程，不要求所有现有项目补填目标模板。
- 不在 P1 建设工时、预算、估算点数、容量、收益评分或预测完成日期。
- 不以任务状态、范围闭合 100% 或智能体判断自动宣告业务目标通过验收。

## 6. 页面与主要流程

### 6.1 项目列表和详情

- 项目列表沿用现有入口。P1 可显示状态、负责人、日期、范围闭合进度、完成／取消数、健康摘要和最近进展时间；隐藏列不改变统计。
- 项目详情提供"概览"和既有任务视图入口。概览按目标、健康、最新进展组织内容，属性、资源、默认小队和自动化仍使用原有编辑入口。
- "目标与范围"读取项目描述；选择模板只帮助编辑描述，不增加另一个内容相同的目标详情页。
- 健康卡片显示计算时间，点击"阻塞""逾期""未分配""待验收"进入该项目任务视图并应用对应条件。
- 从健康卡片进入任务视图时，提示当前筛选条件，支持清除；回到概览仍显示项目总体统计。
- "发布进展"打开编辑器；"记录验收"预选验收类型，展示当前验收标准与描述版本。

### 6.2 目标确认与推进流程

1. 成员创建或打开项目，按需选择目标模板，填写目标、范围、验收标准和参考资料。
2. 成员关联正式任务，按现有规则设置负责人、日期和迭代；选择项目本身不启动执行。
3. 负责人查看健康概览，打开风险任务处理或发布进展，记录需要谁决定什么。
4. 验收成员检查标准和证据，发布验收结论；任务完成数量只作为事实之一。
5. 有权限成员显式调整项目状态；存在未结束任务或未确认标准时显示提示并允许继续。

### 6.3 P2 页面补充

项目列表新增"组合时间线"视图，一行代表一个项目；项目内已有甘特图继续一行代表任务。AI 草稿放在"发布进展"流程内，里程碑仅在启用可选增强包的项目展示。

## 8. P1 目标模板与目标验收

### 8.1 一份描述保存长期约定

模板建议包含"背景""目标""范围内""范围外""验收标准""关键约束""参考资料"。成员可删减或改名，不因缺少标题阻止创建、编辑或执行。

模板内容仍保存在现有项目描述中；概览和智能体上下文读取同一份内容。不新增可分别编辑的目标、范围、验收标准镜像字段，不进行双写。空描述可直接插入模板；非空描述默认追加用户选中的章节，先展示差异。重复应用模板必须由成员选择缺失章节，不能再次插入整套标题。

验收标准建议描述可观察结果，例如"授权新成员能完成首次任务创建，并看见正确项目归属"；"完成所有任务"不足以代替结果标准，但不作为阻止保存的校验。

模板是编辑辅助，不承诺从任意历史描述自动解析结构。非模板描述原样展示，允许直接进入现有编辑器维护。

### 8.2 验收记录与状态独立

"记录验收"创建一种项目进展记录，包含结论"通过／部分通过／未通过"、适用描述版本、验收范围、证据和说明。通过与部分通过均要求填写证据引用或可复核说明。

记录引用当时的描述版本或不可变快照，供审计重现；这不是第二份可独立编辑的目标事实。后续修改目标、范围或标准不会重写历史记录。

P1 不要求逐条结构化勾选标准，也不计算"标准通过率"。验收成员在记录中明确哪些标准通过、哪些未通过；未填写验收记录时显示"尚无验收记录"。

描述变更后，旧验收记录显示"针对旧版本，请复核"，不能继续给当前描述展示无条件的"已通过"。单纯修改图标等非描述属性不会使记录失效。

验收通过不自动调整项目状态、任务状态或触发外部发布。项目变为 `completed` 也不补造验收通过记录。

### 8.3 带剩余任务完成项目

进入 `completed` 前显示未结束任务数、取消数和最新验收结论，提供"查看任务"和"继续完成"。建议记录完成原因，并支持关联后续承接项目或任务。

保留现有状态修改能力：未结束任务、缺少验收记录或未填写原因都不新增服务端硬性阻止条件。未填原因时，状态变更记录明确"未填写原因"，不能自动生成业务理由。

提示和原因在增强客户端完整呈现；旧客户端/API 仍可合法改变状态，但必须记录操作者、时间及未填写说明，不将它描述为已通过验收。

## 9. P1 统计集合、公式与健康定义

### 9.1 统计集合

令 `S(p,t)` 为时刻 `t` 当前工作空间内、仍关联项目 `p`、未被删除的正式任务集合。无需审核的原有任务和已接受任务属于正式任务；待分拣、拒绝、重复均不属于集合。

以稳定任务 ID 去重，父任务与子任务符合条件时各计一次。分页、折叠、个人视图筛选、分组和项目固定偏好不改变集合；任务数量不称为工作量或产能。

使用任务已有状态类别解析能力识别自定义状态，不通过展示名称猜测状态。数据缺失且不能解析时，显示"统计暂不完整"，不能把未知状态算作完成。

任务被删除或移出项目后，从实时集合移除；已发布进展保存的当时统计与结束迭代的快照保持不变。历史链接可显示任务已删除或已改归属。

| 符号／指标 | 精确定义 | 展示规则 |
| --- | --- | --- |
| `N` 总数 | `count(S(p,t))` | 含所有正式任务，不含非正式任务 |
| `F` 完成数 | `count(i ∈ S 且 category(i)=done)` | 明确标注"完成" |
| `C` 取消数 | `count(i ∈ S 且 category(i)=cancelled)` | 单列"取消"，不能标作已交付 |
| `U` 未结束集合 | `{i ∈ S : category(i) 不属于 done、cancelled}` | 数量为 `N-F-C`；未知状态单独提示 |
| 范围闭合进度 | `N>0 时 (F+C)/N × 100%` | 延续已有进度含义；旁列完成和取消 |
| 实际完成占比 | `N>0 时 F/N × 100%` | 若展示，使用完整名称，不称为原有进度 |
| 无任务 | `N=0` | 显示"暂无任务"和零计数；比例为不适用，不显示 100% |

百分比建议显示到整数，但计算与排序使用未舍入值；接近 100% 时仍显示未结束数，不能用舍入结果触发任何业务行为。

### 9.2 日期与健康快照

健康快照包含计算时刻、基准日 `D` 和使用的 IANA 时区。`D` 按工作空间显式设置的默认时区取得；尚未设置时明确显示 UTC，由 `owner`／`admin` 配置。

项目和任务日期仍是纯日期，不随查看者时区移动。截止日等于 `D` 表示今天到期；只有截止日早于 `D` 才逾期。默认时区改变只影响后续计算，不重写历史进展快照。

同一次概览的总数、分项和下钻条件使用同一计算版本；如果任务在点击后变化，任务视图显示已刷新提示，而不是继续承诺旧计数。

### 9.3 风险集合与派生指标

| 指标 | 定义／公式 | 边界 |
| --- | --- | --- |
| 阻塞 `B` | `{i ∈ U : category(i)=blocked}` | 仅显式阻塞；不能只因执行失败推断 blocked |
| 逾期 `O` | `{i ∈ U : due_date(i) 存在且 due_date(i)<D}` | 完成、取消、无截止日期任务不计；今天到期不计 |
| 未分配 `A` | `{i ∈ U : 无有效任务负责人引用}` | 成员、智能体、AI小队按现有任务指派类型识别 |
| 待验收 `R` | `{i ∈ U : category(i)=in_review}` | 是任务流程信号，不等同于项目目标尚未验收 |
| 项目逾期 `L` | 项目截止日期早于 `D`，且项目状态不为 `completed`、`cancelled` | `paused` 不冻结日期；与逾期任务数分开 |
| 风险任务数 | `count(B ∪ O ∪ A ∪ R)` | 去重后的任务数；四卡片计数可以重叠，不能直接相加 |
| 最近进展时长 | 当前时刻减最近一次已发布进展时间 | 无进展显示"尚未发布"，不虚构零天 |

"有效任务负责人引用"指负责人类型和 ID 配对，且指向当前工作空间内仍存在的有效成员、智能体或 AI小队。项目 lead 和项目默认小队不等于任务负责人。

智能体存在但运行时离线，仍属于已分配；另显示"执行环境不可用"信号。成员已离开、负责人引用失效时计入未分配，并解释需要重新指定，不能静默替换负责人。

### 9.4 健康摘要与人工判断

- 统计未完整加载或权限校验未完成：显示"暂不可计算"，不显示绿色结论或缓存成功提示。
- `N=0`：显示"暂无任务"；若 `L=true`，同时提示项目日期已过，不用空集合掩盖延期。
- `N>0` 且 `|B|>0`、`|O|>0` 或 `L=true`：显示"有风险"，列出全部命中原因。
- 其余项目若 `|A|>0`、`|R|>0`、项目负责人失效，或进行中项目七个日历日未发布进展：显示"需关注"。
- 其余项目显示"暂无上述风险"；这只表示当前规则未命中，不表示交付成功或质量合格。
- 进行中但从未发布进展的项目，从最近一次进入 `in_progress` 起满七个日历日后提示；不足七日仅显示"尚未发布"。
- `paused`、`completed`、`cancelled` 状态标签始终独立呈现；已结束项目仍有未结束任务时，额外提示该事实，不隐去任务风险。

"七日未更新"是可评审的 P1 固定建议阈值，不作为阻止状态修改的条件。人工判断可写入进展，始终标明作者和时间，不覆盖系统风险事实。

## 10. P1 手动进展与通知

### 10.1 发布内容

进展类型分为"常规进展""风险说明""验收记录"。常规模板提示填写"本次变化""已完成""风险与阻塞""下一步""需要的决定"，允许直接写完整正文。

已发布记录至少包含项目身份、作者、发布时间、类型、正文和修订版本；可附当前统计快照、人工健康判断、任务链接、执行链接及资料链接。

统计快照由系统生成并标明采集时刻，成员不能直接把自动计数改成别的数字；补充解释写在正文。正文中的人为数字不被自动当作系统统计。

成员可保存编辑中的输入、取消或发布；取消不产生进展记录。网络失败保留当前输入并明确"尚未发布"，刷新后的恢复能力由客户端现有草稿机制承接。

### 10.2 更正与历史

有项目编辑权限的成员可更正已发布记录，必须填写更正说明，并保留旧版本、操作者和修改时间。P1 不提供无痕覆盖或硬删除单条进展的入口。

更正已过期验收记录不能让它自动适用于新目标；必须基于当前描述另建验收记录。旧记录和其证据保留原含义。

项目删除会删除项目描述、状态、资源和项目专属进展；删除确认需明确该影响。任务评论、执行记录以及迭代历史不因此删除。

### 10.3 通知边界

默认不向整个工作空间广播进展。P1 仅对正文中显式提及的当前工作空间成员产生站内通知；用户发布前可看到接收者，无权限者不得成为接收者。

进展编辑器中的提及只发送站内通知，不沿用任务评论中可能启动智能体的提及行为。提及智能体只能作为引用展示，不启动执行。

通知已读、归档、稍后处理不会改变项目、任务或验收状态。P1/P2 不自动发送邮件、聊天消息或外部回执；外发需独立配置与明确授权。

## 11. P2 组合时间线与 AI 进展草稿

### 11.1 P2-A 组合时间线

组合时间线位于当前工作空间项目列表，一行一个项目，显示名称、状态、负责人、开始／截止日期、健康摘要与范围闭合进度。任务明细仍在各项目既有甘特图中查看。

支持按项目状态、负责人、优先级筛选，按周／月缩放和跳转今天。默认显示 `planned`、`in_progress`、`paused`；可以显式包含已完成、已取消项目。

只有开始日期或截止日期的项目显示单端日期标记，并说明另一端未设置；两端都缺失的项目进入"未排期"列表。不能猜测日期，也不能用任务日期静默覆盖项目日期。

拖动或编辑只修改项目自身日期，保存前展示原值、新值和"任务日期保持各自设置"的影响说明。成员可取消；失败后回到服务端原值并保留待重试输入。

多个项目日期重叠只表示计划重叠，不自动解释为资源冲突。P2 不推算共享成员产能，不自动移动其他项目或任务，也不把任务依赖提升为项目依赖。

筛选和加载始终限定当前工作空间；分享的视图链接需要接收者有现有权限，不生成公开访问。若以后提供导出，只能包含当前有权访问的范围，不能借组合视图导出其他工作空间数据。

### 11.2 P2-B AI 草稿生成与发布

成员点击"生成进展草稿"，选择当前有权调用的智能体或 AI小队，并预览材料范围、时间窗口和执行提示。项目负责人为智能体不等于已经授权调用它。

材料默认包括当前项目描述、正式任务属性、授权可见的相关评论与执行结果、上次已发布进展；资源访问遵守已有执行与资源规则，不因项目汇总放宽文件或仓库权限。

首次生成时间窗口从项目创建开始到本次采集；后续默认从上次已发布进展采集时刻到本次采集，允许成员改成明确日期范围。材料截断、未读到全部任务或来源缺失必须展示。

草稿包含变化摘要、风险、下一步和待决定事项。事实句附任务／执行／进展引用和采集时间；无法取得证据的内容标注"待核实"，建议单列，禁止伪造链接或把推测写成确定结果。

生成动作复用现有明确启动的执行流程，允许取消与查看错误；不能通过"生成草稿"顺带修改任务、验收标准、项目状态或自动化配置。

草稿尚未发布时不进入进展流、不发通知、不作为最近进展计算依据。成员可改写、删除建议、重生成或放弃，发布记录标明 AI 辅助、生成时间和最终发布成员。

发布前重新检查工作空间权限和所引用来源。若描述、关键任务状态或来源权限发生变化，显示差异／失效提示并要求成员确认更新后的内容；不能把过期草稿静默标为最新。

已失去访问权限的来源内容必须移除或生成不含内容的失效提示。P2 只有当前有权限的成员可最终发布，智能体不自动外发、不自动发布项目进展。

## 12. P2-M 可选里程碑

里程碑用于描述项目内一个可独立验收的阶段结果，默认不启用。启用仅增加项目内部的组织能力，不要求所有任务必须有里程碑。

| 规则 | 产品要求 |
| --- | --- |
| 项目归属 | 每个里程碑只属于一个项目，工作空间继承该项目；不能跨项目共享 |
| 任务归属 | 一条正式任务最多属于当前项目的一个里程碑；无项目任务、非正式任务不能直接关联 |
| 必填信息 | 名称非空；目标说明和验收标准可选但提供提示；截止日期可空 |
| 状态 | 建议 `planned`、`in_progress`、`completed`、`cancelled`，与项目及任务状态分别维护 |
| 完成 | 成员显式确认并记录结论；有未结束任务时提示数量并要求填写处理说明，允许继续 |
| 零任务 | 可为纯业务检查点；不能显示任务完成 100%，仍需显式确认结果 |
| 重开 | 可从 completed/cancelled 重开，保留原完成／取消记录，不修改关联任务 |
| 任务换项目 | 保存前说明里程碑不匹配，将同步解除旧里程碑关联；不得保留跨项目引用 |
| 删除里程碑 | 有项目编辑权限的成员确认后删除，解除任务里程碑关联，保留任务、项目和迭代 |
| 删除项目 | 项目专属里程碑随项目删除并解除任务里程碑关联，不删除任务或迭代历史 |

里程碑不是任务子任务的执行 `stage`，不能从智能体阶段或小队角色自动推导。组合时间线可在展开项目时显示里程碑点，但该显示不改变 P2-A 的项目日期来源。

里程碑自身范围闭合与完成数量沿用项目的正式任务口径；项目总数按任务 ID 计算，不能把里程碑当任务再加一遍。历史进展引用被删里程碑时显示已删除标记。

## 13. 状态、权限与执行边界

### 13.1 项目状态语义

| 状态 | 表达的项目事实 | 禁止隐含的副作用 |
| --- | --- | --- |
| `planned` | 目标或计划准备中 | 不把任务全部改为 backlog/todo |
| `in_progress` | 项目正在推进 | 不因切换状态启动智能体或 AI小队 |
| `paused` | 项目层面暂缓推进 | 不自动停止正在执行的任务、不冻结逾期统计 |
| `completed` | 成员已将项目标为完成 | 不自动将剩余任务 done、不代表目标验收通过 |
| `cancelled` | 项目不再继续 | 不自动取消任务、不清空迭代归属 |

五状态之间沿用现有合法修改能力，不新增强制审批或单向状态机。重新打开项目保留进展和验收历史，当前验收适用性仍按描述版本判断。

暂停项目时说明已有执行仍会继续，提供查看执行入口；成员若需停止执行，应在现有执行界面使用其有权限的停止操作。

### 13.2 权限矩阵

| 操作 | member | owner／admin | 智能体 |
| --- | --- | --- | --- |
| 查看项目、健康与进展 | 按工作空间现有访问权限 | 同左 | 按已有服务端授权范围 |
| 创建／编辑项目与日期 | 允许 | 允许 | 仅已有工具已授予的能力；lead 不增加能力 |
| 发布／更正手动进展、记录验收 | 允许 | 允许 | P1/P2 不作为最终发布者 |
| 请求 AI 草稿 | 另需有权调用选定执行者 | 同左 | 不能仅因 lead 身份自行触发 |
| 创建／编辑／删除里程碑 | P2-M 按项目编辑权限 | 同左 | 后续工具权限需明确适配 |
| 删除项目 | 不允许 | 允许 | 不因 lead 或项目上下文获得删除权限 |
| 配置全空间时区、自动跟进策略 | 不允许 | 允许 | 不允许自行扩大策略 |

所有读写、计数、搜索、下载和未来导出都在服务端校验工作空间权限。不能因知道项目 ID、持有旧链接或查看过草稿读取其他工作空间的数据。

## 14. 字段与校验

以下长度是本次新增内容的建议验收边界；既有字段继续沿用服务端有效限制，实施前确认现有上限，不静默收紧旧内容。

| 字段 | 阶段与规则 | 校验反馈 |
| --- | --- | --- |
| 项目名称、图标、优先级、状态 | 既有字段；不新增必填项或枚举 | 无效状态沿用明确错误，不自动改成 planned |
| 项目描述 | P1 模板复用既有内容与编辑能力 | 超出现有限制时保留输入并说明限制 |
| 项目开始／截止日期 | P1 沿用；新增编辑路径校验开始日不晚于截止日 | 历史异常值显示待修正，不静默互换 |
| 项目负责人／默认小队／资源 | 沿用有效引用和现有访问规则 | 失效引用显示原因，不自动改配 |
| 进展类型、正文 | P1 类型必选；正文去空白后 1—10,000 字符 | 空正文不能发布；中文与英文按同一字符计数规则 |
| 进展人工判断 | P1 可选"按计划／需关注／有风险" | 仅作为作者判断，不覆盖系统计算 |
| 证据引用 | P1 单条建议最多 50 个；站内目标须存在且可访问 | 失效引用逐项提示；普通外链不宣称已验证 |
| 验收结论／依据 | P1 验收类型必填；通过／部分通过需证据或可复核说明 | 缺失时保留输入并定位字段 |
| 更正说明 | P1 更正时必填，去空白后 1—1,000 字符 | 不能用空白覆盖旧记录 |
| 里程碑名称／说明 | P2-M 名称去空白后 1—120 字符；说明建议上限 10,000 | 重名允许但在选择器同时显示日期和状态 |
| 里程碑日期 | P2-M 纯日期；项目日期外允许但提示 | 不自动扩展项目日期 |
| AI 材料时间窗口 | P2-B 起点不晚于终点、终点不晚于本次采集 | 无材料时返回说明，不能编造进展 |

正文与外部引用按现有富文本和链接安全规则展示；链接中的指令、任务正文和资源内容都不能改变生成草稿的权限与行为边界。

## 15. 跨模块契约

- 分拣：候选项目可保存为准入信息，但未接受前不进入项目普通任务视图、甘特图、健康、AI 材料或里程碑。可另示待分拣数量入口，标明不计入正式范围。
- 接受：成功接受并选择项目后，任务才进入实时项目集合；只接受不触发项目默认小队或负责人执行。接受与字段校验不能部分成功。
- 迭代：一个项目可以跨多次迭代，一个迭代可包含多个项目；新增、更换或结转迭代不改变项目归属或任务执行状态。
- 历史：迭代结束快照包含当时项目标识或摘要；项目改名、删除或任务换项目不重写该快照，打开实时对象时说明变化。
- 任务移动：任务从项目 A 转入 B 后，两个项目实时统计分别减少／增加；原进展快照仍保留当时事实。
- 默认小队：设置项目和设置任务负责人仍是两件事；已有任务不因项目默认小队变更而改配。
- 项目上下文：描述模板保存后进入原有项目上下文路径；项目进展不会被无上限地追加到每次任务执行中。
- 自动化：已有自动化入口继续使用；新跟进策略不能绕过待分拣执行门槛，也不能仅因健康变红就启动执行。
- 收件箱：只承载通知和跳转；通知处理结果不改变项目业务状态。

## 16. 异常、并发与删除一致性

| 情况 | 必须呈现的结果 |
| --- | --- |
| 两位成员同时改描述 | 后保存者看到版本冲突和最新内容，保留自己的输入，不能静默覆盖 |
| 发布请求超时后重试 | 同一发布意图只产生一条记录及一组通知；可查询已成功结果 |
| 正在编辑时项目被删除 | 停止提交，显示项目已删除；允许复制自己的正文但不能恢复删除对象 |
| 查看期间失去工作空间权限 | 清除受保护页面内容与候选项，后续请求拒绝，不能继续读缓存证据 |
| 统计部分查询失败 | 标明暂不可计算及失败部分，保留明确标时的旧值，不伪造最新健康 |
| 成员离开或智能体失效 | 保留历史署名，当前责任显示待重新指定；不自动交给其他成员 |
| AI 执行失败／中断 | 无已发布进展，不改项目数据；保留可检查的失败原因与重试入口 |
| 发布时证据变化 | 显示差异和采集时间，重新核对可见性；不引用已经无权读取的内容 |
| 跨端修改状态或日期 | 以服务端确认结果更新；冲突提示后允许基于最新版本重试 |
| 删除项目同时有任务加入 | 删除与关联校验保证只留下"加入失败"或"加入后解除"的一致结果，不能产生悬空项目引用 |
| 删除项目过程中失败 | 整体失败并保留可用项目，或完成全部清理；不能只删除资源而留下半个项目 |
| 有相关自动化的项目被删除 | 清理或禁用依赖该项目的规则并显示失效原因；不删除历史执行，不停止正在运行的执行 |

项目删除确认需列出关联任务数、迭代归属保留说明、将删除的项目专属内容，以及相关自动化的处理。现有执行使用其已取得的上下文继续遵守执行规则，项目删除不授予新增资源访问。

## 18. 指标、质量与观察窗口

产品成效建议按上线后四周观察；先采集基线，再确认阈值。不能用项目数量增长或取消数量增加来证明交付效率提高。

| 指标 | 定义 | 建议目标或用途 |
| --- | --- | --- |
| 目标信息可找到率 | 可用性测试中能定位目标与验收标准的成功次数／有效测试次数 | P1 建议达到 90%，测试包含历史描述 |
| 风险定位耗时 | 从进入概览到打开指定风险任务集合的耗时 | P1 建议中位数不超过 30 秒 |
| 进展覆盖率 | 过去七日有已发布进展的进行中项目数／进行中项目数 | 趋势指标；零分母显示不适用 |
| 验收留痕率 | 观察期内变 completed 且有适用验收记录的项目数／同期变 completed 项目数 | 趋势指标，不用来禁止既有状态转换 |
| AI 草稿采用率 | 人工发布且保留 AI 辅助标记的草稿数／成功生成草稿数 | P2 观察；同时记录重生成和放弃 |
| 证据错误率 | 抽检发现无依据或错误引用的事实数／抽检事实数 | P2 发布门槛：抽检不能有越权引用；其他阈值结合基线确认 |
| 统计一致性 | 同版本概览与下钻集合计数一致的检查次数／有效检查次数 | 正确性验收要求 100%，覆盖自定义状态与分拣 |

建议性能场景：单工作空间 500 个项目、单项目 10,000 条正式任务；常用概览和组合时间线首屏在约定测试环境 P95 不超过 2 秒，任务更新后跨端统计 5 秒内收敛。工程评审需确认基线与分页方案后锁定目标，不把建议数值当成已测结果。

性能降级时保留时间戳、明确分页和材料截断；不得用只取第一页的计数冒充全量。键盘可完成模板选择、风险下钻和进展发布，状态不能只依赖颜色表达。

## 19. 上线与回退要求

P1 先验证现有项目无损读取，再开放模板、概览与进展入口。未开启分拣台的既有项目统计结果应保持原口径；开启后的正式范围变化需有说明。

旧客户端仍可管理原有项目；不会因不知道新进展字段而丢失内容或绕过服务端准入。移动端未提供新编辑入口时可展示明确的能力限制，不能显示已发布成功但没有记录。

回退新界面后保留已发布进展与验收记录；是否支持只读查看、如何恢复入口由工程方案确认。不能以回退为由删除任务、改写项目状态或重算迭代历史。

上线前至少覆盖权限矩阵、统计样例、状态副作用、并发发布、删除关联、旧客户端兼容；P2 分别补充时间线、AI 证据和里程碑验收。

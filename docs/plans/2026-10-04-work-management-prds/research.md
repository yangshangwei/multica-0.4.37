## 3. 直接借鉴与适配决定

| 主题 | HiFox 文档中的做法 | Multica PRD 的适配建议 |
| --- | --- | --- |
| 待分拣 | 任务状态类别的一部分 | 独立准入维度，保留现有七类执行状态；所有执行入口统一校验 |
| 来源 | 包含组织成员、空间访客和特定外部集成 | T1 来源限成员手动创建和 CSV 导入，不接入聊天连接器，不假设存在组织／访客权限体系 |
| 接受 | 进入常规工作流并可修改属性 | 普通接受不启动执行；显式接受并执行复用既有执行流程 |
| 关闭分拣 | 将未决任务移到待规划 | 第一阶段有未决任务时阻止关闭，避免管理员不知情地批量放行 |
| 重复处置 | 将任务设为重复类终态 | 准入重复结果与任务执行类别分别表达；保留关系，不自动合并内容 |
| 手动迭代 | 可以多个迭代同时进行 | 第一阶段限制一个当前迭代，避免自动加入和结束目标出现多义性 |
| 历史迭代 | 尽量保存最终快照，也允许补入历史任务 | 第一阶段采用不可变结束快照；历史更正不静默重算，后续单独设计 |
| 自动结转 | 可自动将未完成工作移到下一期 | 手动模式明确选择去向；自动模式使用已配置策略，并保留来源和次数 |
| 专项命名 | 以专项目标组织任务 | 复用项目，不增加另一套专项入口、负责人和执行上下文 |
| 跨空间 | 专项可关联多个空间 | 不直接跨 Multica 工作空间，以免改变数据与权限隔离 |
| 项目进度 | 汇总任务进度 | 保留 Multica 范围闭合口径，单列完成与取消，并增加风险明细 |
| 智能体跟进 | 文档列出可协助的工作 | 本次建议增加可核对证据的进展草稿；自动发布属于后续可选范围 |

## 4. 明确属于本次扩展的建议

- T1 新增 CSV 导入，作为分拣台唯一的批量来源，导入结果一律待分拣；这是 2026-10-04 评审确定的范围，见[总览](README.md)第 10 节。
- 分拣建议显示理由、使用的数据范围及建议生成时间；初期人工采纳。
- 任务准入门槛覆盖智能体唤醒、默认小队和自动化，普通接受与执行明确分开。
- 迭代记录原始承诺、范围增减与结转次数；取消、删除、移出不能抹去原始承诺分母。
- 项目健康概览同时展示具体风险任务，避免只有一个无法解释的健康分数。
- 项目进展可留下可追溯记录；智能体先生成草稿，由有权限的成员发布。
- 多项目组合时间线和可选里程碑属于增强方案，不能据此声称参考页面已实现相同细节。

## 5. 验证范围与待续工作

本轮验证文档、代码定义和需求内部一致性，不运行产品测试或修改业务代码。实现前仍需完成：CSV 导入的列格式与去重键、旧客户端能力检测、准入与执行调度衔接、周期快照的持久化与恢复、现有统计查询的兼容方案、性能基线和迁移回退设计。

三份 PRD 的需求目标、默认阈值和分期均为评审稿，不构成既有线上行为或交付日期承诺。

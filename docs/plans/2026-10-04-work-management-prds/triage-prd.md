# 分拣台需求文档

版本：v0.2 需求评审稿（已纳入 2026-10-04 评审结论）
日期：2026-10-04
所属方案：[需求总览](README.md)
参考来源：[HiFox 分拣台](https://help.hifox.com/docs/space/triage)
交付阶段：T1 人工闭环；T2 规则与建议；T3 受约束的自动处理。

本文描述期望的产品行为。除明确标为已有的能力外，均为待实现需求；默认取舍仍可在产品评审中调整。

## 1. 问题与目标

### 1.1 需要解决的问题

外部反馈、集成创建的任务和成员主动投递的需求，可能尚未确认是否有效、是否重复、优先级如何、谁来处理。如果它们立即进入常规看板和执行链路，会混淆"收到请求"和"承诺执行"，也可能触发不必要的智能体运行。

现有收件箱解决通知触达，Bug triage 自动化模板解决缺陷评估，二者都不承担完整的准入审核责任。

### 1.2 产品目标

1. 让团队在一个入口看到尚未决定是否接下的工作。
2. 为每条输入留下接受、拒绝、重复或延期处理的明确结果。
3. 保证未经准入的任务不能通过其他入口进入迭代或开始执行。
4. 将审核责任与具体执行责任分开。
5. 批量处理和连续处理应减少重复打开页面、切换表单的成本。

### 1.3 不在本期范围

- 新的组织、访客或匿名公开提交体系。
- 客服工单、外部聊天和邮件双向同步。
- 自动合并重复任务的评论、附件、执行记录。
- 跨工作空间移动、跨工作空间重复匹配。
- 首期完全自动审核、轮班排班、SLA 升级系统或复杂规则脚本。
- 把已经开始执行的正式任务退回准入阶段。

## 5. 信息架构与页面

### 5.1 工作空间入口

- 启用后在工作空间导航展示分拣台及当前可处理数量。
- 数量不受个人筛选条件影响；默认不含仍在稍后处理期间的任务。
- 页面内分别展示全部未决、当前可处理、稍后处理数量，避免隐藏的任务被误认为已处理。
- 普通任务列表默认排除未准入和审核未通过的任务；显式搜索和分拣历史可以查询。

### 5.2 队列页面

- 宽屏采用左侧列表、右侧任务详情；窄屏在列表与详情间切换，返回后保留筛选、排序和滚动位置。
- 默认显示当前可处理任务，按首次进入本轮审核时间从早到晚排序。
- 列表展示标题、来源、进入时间、优先级、分拣责任人；任务编号、候选项目、截止日期可选显示。
- 顶部提供搜索、筛选、排序、显示稍后处理、创建待分拣任务、导入 CSV 及历史入口。
- 详情展示原任务内容、评论、附件、来源链接及审核历史；底部固定处理操作。
- 处理成功后定位下一条；失败时保留当前任务、选择和输入，不提前消失。

### 5.3 历史页面

可按处理结果、处理人、处理时间、来源搜索。打开历史项可查看当前任务、当次处理理由和字段变化；不把当前内容冒充审核当时的内容。

### 5.4 设置页面

路径表达为"工作空间设置 → 分拣台"。T1 包含开关、来源说明、准入目标状态、明确优先级要求、责任模式和责任人。T2 增加规则及试运行入口。

## 6. 准入与执行状态

### 6.1 准入状态表

准入状态独立于任务现有的七类执行状态。待分拣是面向用户的审核状态，不作为新的执行状态类别。

| 准入状态 | 含义 | 正式任务范围 | 允许执行 | 后续操作 |
| --- | --- | --- | --- | --- |
| 无需审核 | 原有任务或不匹配分拣规则的合法新任务 | 是 | 遵守现有执行规则 | 正常任务操作 |
| 待分拣 | 等待审核，可能有稍后处理时间 | 否 | 否 | 接受、拒绝、重复、稍后处理 |
| 已接受 | 审核通过 | 是 | 准入已解除；是否启动仍取决于明确执行动作 | 正常任务操作 |
| 已拒绝 | 未接下，保留理由 | 否 | 否 | 重新审核 |
| 重复 | 与已有正式任务重复 | 否 | 否 | 打开目标、重新审核 |

待分拣任务的执行状态保持 backlog 类别；优先在页面上展示待分拣标识。接受目标默认是 todo 类别，可由 admin 配置为 backlog 或 todo 类别中的有效状态。拒绝、重复使用 cancelled 类别结束该输入，但必须保留独立准入结果以区别正式任务取消。

### 6.2 状态转换规则

| 原状态 | 动作 | 新状态与副作用 |
| --- | --- | --- |
| 待分拣 | 接受 | 已接受；设置目标执行状态及明确提交的属性；清除稍后处理 |
| 待分拣 | 接受并执行 | 先完成接受，再按明确授权启动一次执行；具体失败处理见 TRI-FR-09 |
| 待分拣 | 拒绝 | 已拒绝；写入理由；清除稍后处理 |
| 待分拣 | 标记重复 | 重复；关联正式目标；清除稍后处理 |
| 待分拣 | 稍后处理／取消稍后处理 | 准入状态不变，只改变队列可见时刻 |
| 已拒绝／重复 | 重新审核 | 待分拣；清除当前重复指向和稍后处理，保留历史；重设本轮进入时间 |
| 已接受／无需审核 | 重新审核 | T1 不支持；使用现有任务暂停、取消或重新规划操作 |

稍后处理是全工作空间共同的任务安排，不是个人隐藏偏好，也不改变任务截止日期。

## 7. 详细功能需求

### TRI-FR-01 启用与停用（T1）

默认关闭。owner、admin 可以启用；开启后仅影响此后匹配规则的新任务，不把历史正式任务回填进分拣台。

关闭前统计全部待分拣任务，包括稍后处理任务。数量不为零时阻止关闭，并提供进入队列处理的入口；不能把关闭开关等同于批量接受。关闭后保留只读审核历史，禁止主动创建待分拣任务或将历史结果重新审核；需要先由 owner、admin 启用。导入入口随之隐藏，API 拒绝新的导入。开关校验适用于页面、API 及重试，不只隐藏按钮。

### TRI-FR-02 来源判定（T1）

| 创建来源 | 默认是否审核 | 规则 |
| --- | --- | --- |
| 成员从普通任务页、项目页创建 | 否 | 维持原有工作流 |
| 成员从分拣台主动创建 | 是 | 创建结果明确显示待分拣 |
| 成员在分拣台导入 CSV | 是 | T1 唯一的批量来源，导入结果一律待分拣，见 TRI-FR-26 |
| 聊天连接器（飞书、Slack、钉钉、企业微信、Telegram 的 `/issue` 命令） | 否，T1 不接入 | 保持既有行为，创建的仍是正式任务；后续接入须单独评审并逐一通过准入验收 |
| 已有内部自动化、智能体或 CLI 以成员权限创建 | 否，除非明确投递审核 | 不能仅按创建者是智能体就强制改变既有内部流程 |
| 未授权来源、其他工作空间、匿名请求 | 不允许创建 | 启用分拣不授予提交权限 |

2026-10-04 评审确定 T1 不接入聊天连接器，因为团队目前没有在用的聊天渠道。后续接入时，连接器名单单独评审，并逐一通过准入验收。服务端依据认证主体、连接器配置和入口判定来源；任务正文或 CSV 内容中自称"来自内部"不得影响判定。

### TRI-FR-03 外部字段处理（T1）

CSV 导入行和后续接入的连接器提交的项目、负责人、优先级，可以作为经过权限校验的候选值保存。指定执行状态不改变待分拣结论。外部提供的迭代最多记录为候选信息（CSV 导入在 T1 不采用），不能建立正式迭代归属。

无效或越权字段必须被拒绝或明确报告未采用，不能造成跨空间关联；不得在错误信息中泄漏目标标题。同一导入批次或同一外部事件重试应返回同一任务。不同来源事件仅因标题或内容相似不能被静默丢弃，应保留为输入并提供重复候选。

### TRI-FR-04 筛选、排序与连续处理（T1）

支持来源、优先级、候选项目、标签、分拣责任人、创建者和进入时间筛选，搜索标题与任务编号。默认最早进入优先，可切换最新进入或优先级排序；同值按进入时间和稳定任务身份排序。

筛选无结果、队列已清空和只有稍后处理任务应分别提供说明；不能统一显示"没有任务"。

### TRI-FR-05 创建待分拣任务（T1）

复用任务创建字段和已有长度、附件校验。标题必填，默认不要求项目、负责人或优先级。创建成功后显示可追踪任务链接，任务保持待分拣且不继承会启动执行的项目行为。

### TRI-FR-26 CSV 导入（T1）

本条在 2026-10-04 评审后增加，编号接在 TRI-FR-25 之后，避免改动已有引用。

有任务权限的成员可以在分拣台导入 CSV 文件，把外部系统或表格里积压的需求批量带进来。导入结果一律是待分拣任务，不提供直接导入为正式任务的选项；分拣台未启用时不提供导入。

| 环节 | 要求 |
| --- | --- |
| 文件 | UTF-8 编码，可带 BOM，首行为表头。其他编码在预览前报错并说明如何转换，不静默乱码；是否兼容 GBK 由技术设计确认 |
| 规模 | 建议单个文件最多 1,000 行、5 MB。超出时整体拒绝，不截断导入；上限为建议值，实施前按基线锁定 |
| 列映射 | 按表头自动匹配，成员可在预览中调整或忽略某列。可映射标题（必填）、描述、优先级、标签、候选项目、候选负责人、开始日期、截止日期、原始链接和外部编号 |
| 不采用的列 | 状态和迭代列只在预览中报告未采用，不写入任务。附件不随 CSV 导入，描述里的链接按文本保留 |
| 字段校验 | 沿用 TRI-FR-03。候选项目和标签按名称匹配，候选负责人按成员邮箱或智能体名称匹配，范围限本工作空间内导入者有权引用的对象；匹配不到或无法唯一确定时该字段留空并标明，不新建项目或标签。优先级接受 `urgent`、`high`、`medium`、`low`、`none`；日期按纯日期解析，格式不合法的行报错 |
| 预览 | 确认前逐行标出有效、警告（字段未采用或留空）和错误（缺标题、日期非法、超长等）。预览不写入任务，也不发通知 |
| 重复 | 同一文件内外部编号重复的行，以及外部编号已在本工作空间导入过的行，默认跳过并标明，可逐行改为仍然导入。标题相似只提示重复候选，不阻止导入，进入队列后按 TRI-FR-10 处理 |
| 提交 | 只创建有效行和成员确认保留的警告行。逐行原子提交，允许部分成功；结果列出成功、跳过和失败数量，失败行可下载为 CSV，修改后重新导入。同一批次重试只处理未成功的行 |
| 来源记录 | 导入者是任务创建者；每条任务记录导入批次、文件名和行号。批次结果摘要保留在分拣历史中 |
| 执行边界 | 候选负责人和项目不触发项目默认小队、指派唤醒或自动化；描述中的 @提及按 TRI-FR-14 处理 |
| 通知 | 按 TRI-FR-18 的批次规则汇总发送，不逐行通知 |

### TRI-FR-06 接受与属性补齐（T1）

接受面板可以调整目标状态、负责人、优先级、标签、项目、开始日期、截止日期；启用迭代后可选择有效迭代，并可附处理说明。

保存前统一校验权限、优先级门槛、日期、目标项目、负责人和迭代。准入结果与属性一起生效；任一失败时整次接受不生效，保留输入。接受成功后正式队列和相关计数更新一次。

### TRI-FR-07 明确优先级要求（T1）

默认关闭。开启后 priority 为 none 的任务不能被接受，也不能通过通用编辑、批量操作或 API 改为正式任务。弹窗指出需要设置优先级，不替用户默认选择 medium。

该要求仅约束准入，不改变已被接受任务的日常优先级编辑规则。管理员调整规则不回溯撤销历史接受。

### TRI-FR-08 普通接受的执行边界（T1）

普通接受只解除准入门槛，不启动智能体或 AI小队。选择负责人、项目或继承项目默认小队都不能产生执行副作用。候选负责人未填写时，接受可以保留未分配。

此后用户显式启动、重新分配并确认执行，或其他经授权的后续动作遵循原有产品行为。接受事件本身不能被现有自动化立即解释为一次隐式启动。

### TRI-FR-09 接受并执行（T1）

提供与普通接受清楚区分的动作。仅在执行对象明确、用户具备执行权限且现有执行前置条件通过时可用，展示执行者、项目和资源概要。

准入校验失败时不得执行。准入已成功但执行启动失败时，任务保持已接受，明确显示"已接受，执行未启动"及失败原因；重试只重试启动，不重复接受。重复提交不得创建多次执行。

### TRI-FR-10 标记重复（T1）

通过搜索选择同一工作空间内有权查看的正式任务，可输入该任务链接；不能选择自身、其他待分拣输入、已拒绝／重复输入、已删除或不可见任务。正式任务即使已结束，也可被选作重复目标。

确认后保留当前任务、来源、评论及附件，记录重复目标和可选说明；不自动迁移内容、不订阅目标、不改变目标属性或执行状态。目标之后删除时保留处理时的引用记录并显示目标已删除。

### TRI-FR-11 拒绝（T1）

拒绝时要求填写原因，建议范围为 1 至 2,000 字符，前后空白不构成有效理由。该范围为本 PRD 的建议交互约束，技术设计需对齐现有评论长度上限。

原因写入审核记录；对仍有访问权限的内部提交者可生成结果通知。拒绝不删除任务，不发送外部邮件或聊天回复。

### TRI-FR-12 稍后处理（T1）

提供一小时后、明天上午、下周及自定义时刻；预设必须展开显示实际日期、时间和时区。明天和下周按操作者当前显示时区解释，保存后表示固定时刻。

仅允许未来时间，建议最长 90 天；任务详情显示谁设置、何时恢复。到期自动回到可处理队列，不修改本轮进入时间，不增加新任务，不等同于接受。首次进入至最终处理的统计包含等待期。

### TRI-FR-13 取消或重设稍后处理（T1）

有分拣权限的成员可从任务详情或显示稍后处理的列表恢复任务，也可重设时间。恢复和重设留痕。稍后期间仍允许审核；一旦接受、拒绝或重复，原定唤回失效。

### TRI-FR-14 审核期间补充信息（T1）

复用评论和附件进行补充。评论、提及和内容编辑不能隐式解除准入或启动执行；提及智能体可作为文本保留，并说明审核通过后才能执行。

新评论不自动取消全局稍后处理，也不自动接受。按现有评论通知规则通知有访问权限的关注者，避免同一事件重复发送审核责任通知。

### TRI-FR-15 分拣责任（T1）

设置支持"不指定""通知指定成员""指定分拣责任人"。责任候选限当前工作空间有效成员；T1 不把智能体或 AI小队设为拥有自主批准权的分拣责任人。

责任人与任务执行负责人是独立字段。"通知"只发提醒；"指定责任人"记录跟进责任并通知该成员，不占用任务 assignee。责任配置只对新进入审核的任务生效；修改历史任务责任须显式批量操作。

责任人离开后不删除任务、不自动接受，列表显示责任人失效；owner、admin 可重新指定，也可由其他成员直接处理。

### TRI-FR-16 批量处理（T1）

支持批量接受、拒绝、稍后处理和重新指定分拣责任人。T1 不提供批量标记重复或批量接受并执行。仅对当前明确选中的待分拣项生效，不默认扩展至全部搜索结果。

先预检逐项条件，展示可处理数与问题项；成员可选择只处理有效项。每条任务操作自身原子提交，批次允许部分成功；结果给出成功、冲突、校验失败和权限变化清单。重试仅处理未成功项。

### TRI-FR-17 历史与重新审核（T1）

审核记录至少含操作者、时间、旧结果、新结果、说明、字段变化和来源；自动处理需另外标识规则或策略。历史不能通过编辑当前理由直接覆盖。

分拣台已启用时，已拒绝／重复可由有分拣权限的成员重新审核，必须填写重审原因；清除当前结果，保留前次记录。重新进入算新审核轮次，不作为新任务计数。分拣台已关闭时拒绝重审，不产生新轮次；成员看到需要先启用的说明。

### TRI-FR-18 通知（T1）

| 事件 | 内部接收者 | 说明 |
| --- | --- | --- |
| 新任务进入审核 | 按责任配置指定的成员 | 每个审核轮次一次，不随列表刷新重复 |
| 稍后到期 | 当前有效分拣责任人（如有） | 恢复队列并可发一次提醒，不通知全部成员 |
| 接受／拒绝／重复 | 仍可访问的内部提交者与主动关注者 | 包含结果和任务链接；操作者的自发事件按现有去重规则处理 |
| 责任变更 | 新责任人 | 不等同于任务执行指派 |
| 批量操作 | 各任务按上述事件规则 | 操作者收到本次操作汇总，不发送额外全员通知 |
| CSV 导入批次 | 导入者；按责任配置指定的成员 | 每个批次各发一条汇总，替代逐条的进入审核通知 |

通知失败不撤销已生效的审核结果，重试通知不能重复处理任务。成员无访问权限时不发送内容；分拣台不会自动向外部来源发送回执。

### TRI-FR-19 全入口准入校验（T1）

创建、导入、状态更新、指派、批量操作、项目默认小队、迭代加入、@提及、自动化、CLI、API、智能体工具和移动端都受同一业务门槛约束。待分拣／拒绝／重复任务不能启动执行。

既有桌面或移动客户端不能理解准入状态时，服务端仍须阻止修改或启动；返回明确的待审核原因及可用任务链接。旧客户端能力适配属于上线条件，不能仅靠新页面限制。

### TRI-FR-20 快捷键与无障碍（T1）

建议使用 J／K 切换、1 接受、2 重复、3 拒绝、H 稍后、C 创建。快捷键只在队列具有焦点且没有输入框、编辑器或其他模态层占用时生效；重复、拒绝等动作仍打开必要的选择或说明界面。

所有操作都有可见按钮和可读标签。处理后焦点移动到下一条可见任务；最后一条处理完后回到队列空状态。列表状态不只用颜色表达。

### TRI-FR-21 规则配置与条件（T2）

owner、admin 可创建有名称、启用状态、条件和动作的规则。条件支持来源、优先级、创建者、候选负责人、项目、标签、日期和标题／描述文本匹配；同组条件"全部满足／任一满足"需要显式展示。

第一版规则不接受脚本或任意网络调用。条件与动作只能引用本工作空间有效对象，失效引用使规则停用并提示，不扩大匹配范围。

### TRI-FR-22 顺序、冲突与停止（T2）

规则按界面顺序运行，后规则观察前规则已修改的候选字段；同一字段后写覆盖前写，配置界面提示可能覆盖，执行记录保存实际覆盖链。

T2 动作限设置候选项目、优先级、标签、责任人和候选执行者，并可显式停止后续规则；不能自动接受、拒绝或启动执行。一次外部输入只进入一轮规则，规则自身修改不递归触发新一轮。

### TRI-FR-23 规则试运行与失败（T2）

发布规则前可用选定样本预览匹配和变化，不保存任务字段、不通知、不执行。展示规则版本、输入快照和每步结果。

正式运行发生失效引用或其他错误时，保留待分拣状态，回退本轮未完整生效的规则修改并标记人工处理；不得应用一半变化后声称规则成功。手动复跑需明确选择，记录操作者和版本。

### TRI-FR-24 AI 分拣建议（T2）

成员显式请求后生成优先级、项目、候选执行者、重复候选和缺失信息建议，展示理由、引用任务以及生成时间。仅使用调用者有权读取的数据，不自动检索其他工作空间。

AI 建议不改变准入、字段或执行状态。可以逐项采纳；任务或候选目标变化后需重新校验，不盲用旧建议。分析失败时保留人工流程，不显示虚构建议或把未知写成确定结论。

分析能力是受限的建议动作，不得借此启动待分拣任务的正常执行、修改仓库或调用具有写入能力的任务工具。

### TRI-FR-25 自动接受（T3）

由 owner、admin 明确开启，限定来源、规则、优先级和可接受范围，并提供试运行、暂停、审计与失败回退。默认不启用，不由模型自行扩大范围。

自动接受仅准入，不附带自动执行；如后续需要执行策略，须单独定义和授权。自动处理出错或条件不确定时保留待分拣，不能把模型自报置信度当作唯一依据。

## 8. 产品字段与验证

| 字段／信息 | 要求 |
| --- | --- |
| 任务身份、标题、内容、附件 | 复用既有任务约束和数据，不产生第二份可编辑副本 |
| 来源类型、来源事件或导入批次与行号、原始链接 | 可追踪且身份判定可信；链接不可用时任务内容仍保留 |
| 当前准入结果 | 无需审核、待分拣、已接受、已拒绝、重复之一 |
| 本轮进入时间、首次进入时间 | 分别支持轮次处理与任务整体追踪，不因稍后操作重置 |
| 分拣责任人 | 可为空；必须是有效工作空间成员，与执行负责人独立 |
| 稍后至 | 可为空；有效未来时刻；显示明确时区 |
| 重复目标 | 仅重复结果需要；同空间可见正式任务，不得指向自身 |
| 处理理由、重审理由 | 保留操作者与时间；拒绝和重审必填 |
| 候选项目、执行者、迭代 | 只是审核意向，未经接受不产生正式调度效果 |
| 审核记录 | 按轮次可追溯，不允许用当前状态替代完整历史 |

具体存储、API 字段和迁移方式不由本 PRD 指定，需在技术设计中落实。

## 10. 主要流程与异常处理

### 10.1 输入到接受

1. 校验来源授权和是否需要审核，创建任务并记录候选信息。
2. 任务出现在队列，按责任配置通知；项目和迭代不增加正式工作量。
3. 成员阅读详情，补信息，设置必要字段。
4. 选择普通接受或接受并执行；服务端重新校验当前状态与权限。
5. 接受成功后进入普通任务范围；只有显式执行动作才尝试启动。

### 10.2 重复、拒绝和稍后

重复需要选择有效目标；拒绝需要原因；稍后需要未来时刻。操作失败留在当前任务并保留输入。到期恢复只改变队列可处理性，已有审核结果优先于之前的定时安排。

### 10.3 冲突与恢复

| 情况 | 用户可见结果 |
| --- | --- |
| 两人同时接受／拒绝 | 只有先成功结果生效；另一人看到最新结果，原输入可复制但不会覆盖 |
| 处理时任务被删除 | 停止提交，说明任务不可用；从队列移除失效项 |
| 候选项目、负责人或迭代失效 | 指出需重新选择的字段，不部分接受 |
| 权限在提交前撤销 | 拒绝操作，不泄漏新的目标信息 |
| 网络超时，不确定提交结果 | 恢复后查询当前结果；重试不产生第二条审核记录或第二次执行 |
| 服务重启，稍后时间已到 | 首次恢复读取时应回到可处理范围，不能永久隐藏 |
| 规则失败／AI 不可用 | 保留人工队列和人工操作，明确标识建议或规则不可用 |
| 关闭时出现新的未决任务 | 重新校验并阻止关闭，避免检查后漏掉新任务 |

## 12. 成功指标与非功能目标

| 指标 | 口径与用途 |
| --- | --- |
| 首次响应时长 | 每轮首次人工评论或审核动作时间减去本轮进入时间；分别观察中位数与 P90 |
| 审核处理时长 | 最终接受／拒绝／重复时间减去本轮进入时间；包含稍后等待，避免通过隐藏美化指标 |
| 队列积压 | 所有未决、当前可处理、稍后三类数量及进入时长分布 |
| 结果分布 | 按轮次分别统计接受、拒绝、重复；分母是该窗口完成的审核轮次 |
| 重审率 | 曾处理后重新审核的轮次数／已处理轮次数，按来源观察 |
| 重复执行事故 | 待分拣绕过执行、重试导致多次执行；上线验收目标为零 |
| AI 建议采纳 | 逐字段采纳率与人工修改情况；不以高采纳率单独判断质量 |

首期先建立基线，连续观察两周后再设效率改善目标。功能验收不能以接受率高作为成功标准。

建议性能验收数据集为一个工作空间 10,000 条正式任务、2,000 条未决任务，默认每页 50 条；同区域稳定网络下列表与筛选 P95 不超过 2 秒，普通单条审核确认 P95 不超过 2 秒。此为待基线验证的目标，不是现有测量结果。CSV 导入建议以单文件 1,000 行为验收规模：预览 P95 不超过 5 秒，确认提交 P95 不超过 30 秒，超过 3 秒显示进度，同样待基线验证。稍后到期后，在页面刷新或实时更新时应于 60 秒内显示恢复。

## 13. 默认取舍与风险

- 当前建议由所有有任务权限的成员分拣，责任人不独占。若需要专职审批权限，应另行扩展角色能力，不能偷偷限制现有 member。
- 拒绝原因必填、有未决任务不能关闭、普通接受不执行，都是本次适配建议，与参考产品部分细节不同。
- 执行门槛需要覆盖所有已有入口，是 T1 最重要的联动风险；只做页面无法满足需求。
- T1 不接入聊天连接器。工作空间以后若启用聊天渠道，`/issue` 创建的仍是正式任务，不经过分拣台；接入须单独评审并逐一验收。
- CSV 导入是 T1 唯一的批量来源。行数上限、逐行预览和批次汇总通知，用于避免一次导入挤占队列或刷屏通知。
- 审核记录是产品追溯记录，不在本期声称具备不可篡改合规审计能力。
- 移动端完整审核 UI 后续补齐，但数据过滤与执行门槛随服务端上线共同生效。

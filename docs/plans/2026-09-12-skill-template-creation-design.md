# 从模板中修改并创建 skill：交互与技术方案

状态：已于 2026-09-12 完成实现与验证。

## 目标与首版范围

在“新建 skill”弹窗中增加“从模板中修改”。用户选择模板、理解其用途、修改自己的副本，最后创建一个独立的工作区 skill。

首版建议采用刚完成中文化的七个内置角色模板：发布检查、文档更新、安全审查、架构决策记录、代码审查、需求澄清、测试报告。用户已授权按本方案推进，首版采用这七项。它们来自服务端默认模板，与工作区中可能已经修改过的同名 skill 分开。

首版覆盖 Web 和 Desktop 共享视图。模板保存为普通 skill，创建后沿用已有编辑、分配、启用与删除功能。后续可增加“复制工作区现有 skill”，首版不引入模板管理后台、模板发布市场、AI 改写、版本订阅或自动同步。

## 推荐交互

### 1. 在现有入口增加第五种方式

保留现有样式，顺序为：手动创建、从模板中修改、从本地导入、从 URL 导入、从运行时复制。

- 标题：**从模板中修改**。
- 说明：**选择现成模板，修改后创建自己的 skill。**
- 图标使用现有 lucide 图标，沿用原卡片的字号、圆角、间距和悬停状态。
- 五项仍采用纵向列表。弹窗保持视口高度上限，方式列表可滚动，标题和关闭按钮固定，避免新增一项后底部被裁切。

依据：当前方法联合类型和卡片表分别位于 `packages/views/skills/components/create-skill-dialog.tsx:53`、`:69`；根弹窗在 `:611`，高度限制在 `:719`。当前 chooser 本身没有滚动中段，新增选项时需要补齐。

### 2. 选择模板并预览

点击新入口后，当前弹窗进入宽版模板面板，不再叠加另一层弹窗。

- 左侧显示七项模板名称、用途摘要和搜索框，支持中文名及原始调用名称搜索。
- 右侧展示当前模板的完整中文正文；默认预览第一项，用户点击其他项即可切换。
- 主按钮为 **使用此模板**。点击前只有读取，不创建数据库记录；点击后才生成本地草稿。
- 简短说明：**创建后可独立修改，不影响原模板。**
- 小屏使用单列的列表、预览流程，保留返回入口；底部主操作始终可达。
- 加载中、加载失败、无匹配结果各自有明确状态。失败时提供重试和返回手动创建。

模板标题和用途复用 `packages/views/skills/lib/skill-presentation.ts:27` 的内置目录显示方法；正文来自服务器，不在前端再维护一套模板字符串。字体与颜色沿用 `packages/ui/styles/tokens.css:90` 的语义角色。

### 3. 修改副本

在同一宽版弹窗中进入编辑步骤：

| 区域 | 行为 |
|---|---|
| 来源 | 显示选择的模板名称，提供“重新选择模板” |
| 名称 | 预填独立调用名称，例如 `multica-code-review-copy`；允许修改 |
| 描述 | 按当前界面语言的模板用途初始化，作为新 skill 的实际可编辑字段 |
| 正文 | 可编辑 Markdown 正文，支持编辑/预览切换 |
| 底部 | 返回选择、创建 skill |

名称和描述仅在表单中编辑，正文编辑器不重复暴露 YAML 中的同名字段。提交时由同一 helper 同步文件头，从而保证数据库字段和 `SKILL.md` 一致。其他 frontmatter 字段保留原模板的类型和值。

默认名称必须不同于全部内置 canonical 名称；即便工作区没有原项，也不能直接占用 `multica-code-review`。候选名已存在时递增为 `multica-code-review-copy-2` 等。最终重名仍由服务端的 409 裁决；表单保留草稿并提示用户改名，不覆盖已有 skill。

仅在本模板创建流程中提示/阻止使用已加载目录中的 canonical 原名，不改变普通手动创建 API 的既有名称契约。此限制用于避免误用，并不被当作权限边界。

当前七项没有附属文件。接口保留 `files`；若模板附有文件，复制时保留相对路径和内容，可用已有文件预览查看，创建后通过现有详情页管理，不增加第二套文件管理器。

正文初始值、描述语言和名称只在用户明确使用模板时确定。后台刷新、切换显示语言和重新渲染不得覆盖已编辑草稿。允许直接采用模板，不强制用户做一次无意义修改才能创建。

### 4. 创建与返回

点击 **创建 skill** 后才发出一次创建请求。验证成功响应的 ID 和工作区后，写入详情缓存、刷新工作区列表、清空草稿、关闭弹窗并进入新 skill 详情页，沿用 `create-skill-dialog.tsx:55` 的缓存处理和 `skills-page.tsx:779` 的导航回调。201 响应若缺少有效身份，也不能当作可导航的成功结果。

创建不自动分配给智能体，不复制源对象的绑定、标签、创建者或权限。选择“发布检查”模板不会授予 `operator` 权限。

```mermaid
flowchart LR
  A[选择创建方式] --> B[浏览模板与预览]
  B -->|使用此模板| C[编辑本地副本]
  C -->|创建 skill| D[提交一次创建请求]
  D -->|成功| E[新 skill 详情]
  D -->|失败或重名| C
  C -->|返回并保留草稿| B
```

## 草稿与异常行为

| 情况 | 约定 |
|---|---|
| 返回模板列表 | 保留当前草稿；再次选择同一模板可继续编辑 |
| 顶部返回创建方式 | 保留模板会话；再次进入模板方式可恢复。若转去其他创建方式且有手工修改，先确认放弃 |
| 换用另一模板 | 有手工修改时确认是否放弃；未修改时直接切换 |
| 关闭、Esc、点击遮罩 | 有手工修改时显示同一个放弃确认；仅浏览模板时直接关闭 |
| 模板重新加载或应用语言变化 | 不重新初始化草稿，不把显示变化算作用户修改 |
| 请求进行中 | 禁止重复提交、返回和关闭；仅此流程采用建议 30 秒的等待上限，超时恢复操作，不能无限锁住弹窗 |
| 409 重名 | 名称字段显示错误，其余草稿保持；不自动换名重试 |
| 网络错误、超时或畸形成功响应 | 保留草稿并进入“结果待核实”；允许退出等待，先核对原工作区列表和必要的详情，不盲目自动重试 |
| 空名称、空正文、无法解析模板文件头 | 不允许创建，说明需要修正的内容 |
| 模板端点加载失败，包括旧后端的 400/404 | 提供重试和返回手动创建；其他四种方式继续工作。保留正常错误语义，不把所有 400 都判为旧版 |
| 工作区变化 | 旧流程不向新工作区提交；已发请求的响应只更新原工作区缓存，不在新工作区导航 |

草稿仅在本次弹窗会话保留，关闭并放弃后不跨会话保存。未点击创建时，不产生 skill、绑定或草稿数据库记录。预览选择与草稿来源是两个不同状态：浏览另一模板不能替换草稿，只有点击“使用此模板”才进入替换判断。

终止等待不等于撤销服务端创建。结果待核实时保留本次提交快照，不能仅凭同名就声称找到本次创建；核对名称、描述、正文、附件、创建者等信息，存在歧义时展示候选供用户打开核对，不自动认领、不自动改名重发。关闭仍走同一草稿放弃流程，并说明关闭不会撤销已经发出的创建请求。当前 `fetchRaw` 没有请求超时（`packages/core/api/client.ts:820`），实现时必须补上此流程的有界等待。

## 技术设计

### API：一个读取入口，复用既有创建入口

新增 `GET /api/skills/templates`，注册到现有 skill 路由分组，与 `/{id}` 路由明确区分，沿用认证及工作区成员检查。普通工作区成员可以读取。

```json
{
  "templates": [
    {
      "name": "multica-code-review",
      "version": 1,
      "description": "Use when reviewing a diff: ...",
      "content": "完整的中文 SKILL.md，含原始 frontmatter",
      "files": []
    }
  ]
}
```

`name` 即稳定模板标识，不额外引入与它相同的 `key`。模板不是数据库 Skill，不返回虚构 UUID、工作区 ID 或创建者。当前七份正文总计 20,356 bytes，一个请求返回全部正文即可；无需首版增加单独详情接口或懒加载层。

实现直接调用 `server/internal/service/builtin_role_skills.go:107` 的 `RoleSkillTemplates()`。现有 `GET /api/agents/templates` 只有 `skill_names` 和角色 `instructions`，后者不是 skill 正文，不能拿来替代。参考 `server/internal/handler/agent_template.go:33`、`:54`。

兼容性注意：旧后端可能由 `/{id}` 路由接住 `/templates`，再因 UUID 无效返回 400，并非一定返回 404。新增静态路由可与 UUID 详情路由共存。客户端统一呈现目录加载失败状态，不依赖英文错误字符串猜测服务版本；用旧动态路由的实际 400 响应做回归样例。依据：`server/cmd/server/router.go:2220` 的 skill 详情路由。

保存沿用 `POST /api/skills`，提交 `name`、`description`、完整 `content`、`files`，以及可选的 `config.template_source = {name, version}`。本方案建议记录该来源，便于排查；它是可编辑的说明信息，不提供官方身份、权限或自动升级能力。

绝不复制 `config.origin.type = builtin_role_skill`。自定义副本按普通 skill 展示和编辑，当前 origin 渲染可以保持手动创建的既有行为，不增加“从来源更新”入口。

依据：`packages/core/types/agent.ts:886` 已包含完整创建字段；`server/internal/handler/skill.go:272`、`:478` 与 `skill_create.go:24`、`:74` 已处理主记录和附件事务。工作区内名称唯一约束见 `server/migrations/008_structured_skills.up.sql:14`。无需新表、迁移或 `/from-template` 写接口。

### Core：类型、查询、草稿序列化

- 新增独立 `SkillTemplate` 类型和 Zod schema。使用现有 `parseWithFallback` 模式处理接口漂移；缺少有效名称或正文的条目不能变成可提交的空模板。参考 `packages/core/api/client.ts:1569`、`schemas.ts:3514`。
- `api.createSkill` 的响应也必须经过现有 `SkillSchema` 解析，不能继续直接信任 JSON；拿到有效非空 ID 且响应工作区与提交时捕获的工作区一致后才能导航。参考 `packages/core/api/client.ts:3238`、`packages/core/api/schemas.ts:3334`。正常既有调用保持兼容，畸形成功响应标记为结果待核实。
- 为该调用提供可选的显式工作区上下文和 `AbortSignal`，只对模板创建设置有界等待，不给所有 API 请求追加全局超时。到期恢复 UI，但将服务端是否已提交视为未知。
- 在 `packages/core/workspace/queries.ts` 添加 `skillTemplates(wsId)` key 和查询配置，显式带工作区上下文，首次进入模板流程才加载。原查询 key 结构见 `:7`、`:21`。
- 在 `packages/core/skills/` 添加小型纯 helper：生成副本候选名、从模板初始化独立草稿、将名称/描述/正文序列化为 `SKILL.md`。
- 复用已声明的 `yaml` 依赖（`packages/core/package.json:175`），用 YAML document/AST 更新 `name` 和 `description`。不能直接重新序列化 `parseFrontmatter()` 返回值，因为现有读取器将布尔值及嵌套对象转换成了字符串（`frontmatter.ts:15`）。
- 只重写必要的 YAML 字段，保留未知字段类型、`user-invocable` 等开关；用户正文不被重新排版或 trim。对无效 YAML 明确报错。
- 生成副本时复制文件数组，不修改 React Query 缓存中的原模板对象。

### Views：扩展现有对话框

- `create-skill-dialog.tsx` 增加 `template` 方法、卡片、宽版布局与退出保护的接入，修复 chooser 的滚动区域。
- 新增 `template-skill-create-panel.tsx` 承载模板选择、预览和编辑步骤，避免继续扩大现有大文件，也不把保存后的详情页改造成创建页。
- 服务端数据由 React Query 管理；模板会话、草稿及 dirty 基线放在根 `CreateSkillDialog` 的本地状态，模板子面板使用受控状态。这样顶部返回方式选择、子面板卸载后仍能恢复，不新增跨页面 Zustand store。
- 预览复用 `FileViewer` 或 `RichContent`，正文输入使用已有 `Textarea`；复用现有放弃修改对话框样式。参考 `packages/views/skills/components/file-viewer.tsx:28`。
- 所有关闭路径和转去其他创建方式的路径通过同一个 dirty 检查；“返回模板列表”和“顶部返回创建方式”分别处理。请求结束或超时后保留草稿，恢复按钮。提交时捕获工作区 ID，成功回调核对当前上下文后再导航。
- 新增 en、zh-Hans、ja、ko 的入口、步骤、冲突、退出及失败文案。切换语言只更新界面标签，不改已存在的草稿字段。
- 路由继续通过 `NavigationAdapter`；Web/Desktop 自动复用，不新增平台路由或引入 `next/*`。

## 方案比较

| 方案 | 优点 | 代价与结论 |
|---|---|---|
| 内置七模板，先改后创建 | 基线稳定、新工作区也可用，取消无垃圾数据；复用现有创建链路 | 新增只读目录与编辑步骤；推荐首版 |
| 同时支持工作区任意 skill 复制 | 可复用团队定制和附属文件 | 需要区分两类来源、可见性、加载与完整文件复制；作为后续独立功能 |
| 先创建再跳转详情修改 | 初始代码量最少 | 用户尚未确认就产生记录，取消无法自然恢复；不采用 |

## 实施拆分

1. **目录与响应契约**：新增 `server/internal/handler/skill_template.go` 和对应测试；更新 `server/cmd/server/router.go`。只读取 registry，验证目录无数据库写入、认证及工作区隔离。
2. **客户端数据与纯函数**：更新 core 的 `types/`、`api/client.ts`、`api/schemas.ts`、`workspace/queries.ts`；验证创建响应、传递可选工作区及取消信号；在 `skills/` 增加草稿 helper 及测试，先覆盖 YAML 保真和名字冲突。
3. **交互流程**：新增模板面板，扩展现有创建弹窗与四套语言文案；复用预览、创建接口及导航回调。
4. **集成验证与文档**：覆盖创建/取消/重名/切换/错误/权限，检查 Web 与 Desktop、小屏和键盘操作，更新现有 skill 用户文档及前端规范。

后端目录可与纯函数开发并行；接口契约和序列化测试通过后再接入 UI。只在全部行为检查通过后交付，不为本功能顺带改造其他四种创建方式。

## 验收与测试

### 产品验收

1. 新入口名称准确，五种方式可见且可通过键盘到达，矮窗口不裁切底部选项。
2. 七模板在空工作区同样可用；仅预览或取消时 skill 数量不变。
3. 新 skill 使用新 UUID 和独立名称；模板及现有同名工作区 skill 完全不变。
4. 编辑后的名称/描述与文件头一致，正文、命令、其他 YAML 字段及附件内容按用户修改保存。
5. 创建成功后进入正确工作区的新详情页；初始无自动绑定，无权限变化。
6. 返回保留草稿；换模板及关闭只在有手工修改时询问是否放弃。
7. 重名和网络错误保留草稿；重复点击只有一个进行中的创建请求。超时不会无限锁住弹窗，结果不明时不自动重发。
8. 语言变化、查询刷新不覆盖草稿；旧后端及无权限场景有明确结果。

### 测试归属

- **Go handler/router**：目录的七项及原文相等、无物化写入、非成员拒绝；创建编辑后的独立记录、409 不覆盖原记录、附件事务与零自动绑定。
- **Core 单元**：schema 的缺字段/错误类型/未来字段、畸形 201 响应及返回工作区错误；名称候选及 canonical 原名避让；中文、引号、冒号、多行 description、CRLF、正文中的 `---`、布尔及嵌套 YAML 字段保真；源对象不被修改。
- **Views 组件**：入口顺序（更新当前 `create-skill-dialog.test.tsx:133` 的四入口断言）、模板选择/预览、表单编辑、dirty 退出、顶部返回方式选择后恢复、浏览其他模板后继续原草稿、重名重试、请求中关闭保护、切换语言及工作区、失败提示与键盘操作。
- **创建恢复场景**：用 fake timers 验证等待上限，覆盖服务端已提交但响应丢失、仅同名但内容/创建者不同、畸形成功响应、取消等待后原请求仍完成；不为此新增幂等写接口。
- **E2E/人工验证**：隔离测试工作区真实创建一份副本，读取确认正文和身份；取消不产生记录。真实 Web 和 Desktop 的成功导航、1280×720 与 375×667 布局。数据由 `TestApiClient` 准备并清理，不调用用户真实智能体。

实施时运行相关 Go tests/go vet、core/views Vitest、`pnpm typecheck`、`pnpm lint`、定向 Playwright 和 `git diff --check`。视觉验收按仓库要求记录 visual-verdict；本轮执行该方案；验证只使用隔离测试数据。

## 发布与回退

先发布包含模板目录的后端，再交付客户端入口。旧客户端不受新增读取接口影响；新客户端连接旧后端时保持其他四种方式可用。

回退客户端入口或只读路由即可；已创建的副本仍是普通 skill，不需要数据回滚。模板更新不会覆盖已有副本。中文正文来自当前源码默认模板，读取它们的后端必须包含上一轮的中文化改动。

## 独立审阅后补充

已吸收四项修订：旧后端实际可能返回 400；创建响应必须校验；顶部返回路径须保留模板会话；请求等待须有上限且不能把超时视为未创建。审阅仅核对源码与方案，没有实施功能或调用工作区 API。

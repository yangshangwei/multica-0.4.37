# 体验验证

## 何时使用

发布前后涉及关键用户路径、桌面/浏览器差异、可访问性或产品结果的变更时使用。它补充 QA 的回归门禁，不替代功能测试或产品验收。

## 工作方法

1. 固定 artifact、浏览器/客户端版本、视口、语言、测试数据、时间窗口和路径入口。
2. 按关键路径运行功能、键盘、焦点、语义、响应式、错误恢复和跨端差异检查，保存脱敏截图、日志和可重放步骤。
3. 把结果分成通过、失败和 `unknown`；没有可访问性结果、基线、覆盖缺口或真实环境时不得猜测。
4. 失败样例：关键路径截图通过但键盘焦点被遮挡，结论必须是 `hold`，并创建带路径和回归信号的修复任务。

## 交付

- 路径/环境/版本/数据/时间和证据链接。
- 功能、可访问性、跨端和产品结果矩阵，含失败、影响、owner、验收信号和停止条件。
- `unknown` 的缺失材料、补证任务和是否需要产品/发布人工审批。

## 边界

不读取生产凭据或客户原始数据，不执行生产操作，不修改代码或发布状态。不可复核的成功截图不是通过证据。

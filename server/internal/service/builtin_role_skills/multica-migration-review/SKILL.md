# 迁移审查

## 何时使用

涉及数据库 schema、API 响应/请求或已安装客户端兼容性的变更时使用。离线安装包检查本身不构成迁移审查。

## 工作方法

1. 固定旧/新契约、客户端范围、兼容窗口、artifact、数据形态和目标环境。
2. 核对迁移顺序、读写兼容、分批/幂等、校验查询、重试、孤儿数据、超时和恢复路径。
3. 检查无外键/级联、并发索引单语句等仓库规则，记录每个结论的文件、查询或测试证据。
4. 失败样例：旧客户端仍发送旧字段而新版只接受新字段，且没有 fallback 或兼容窗口，结论必须是 `hold`。
5. 没有校验查询、旧客户端证据或可执行回滚/重试条件时只能输出 `unknown`，不能把回退提交当成数据恢复。

## 交付

- 旧/新契约和兼容矩阵。
- 校验、幂等、重试、恢复/回滚限制、审批点和失败证据。
- 通过、hold 或 `unknown` 结论，以及补证任务的 owner 和验收信号。

## 边界

不执行生产迁移、回滚、凭据读取或破坏性查询，不修改 schema/API/客户端代码。发布工程师负责获批操作，架构与安全角色负责独立决策。

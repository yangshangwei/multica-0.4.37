# 可靠性工程

## 工作边界

只使用任务指定的服务、时间窗口、基线和脱敏信号。记录指标来源、采样完整性和时区；没有证据就写 `unknown`，不要用“没有告警”推导“没有影响”。

## 检查清单

1. 明确 SLI、SLO、错误预算和观察窗口。
2. 核对错误率、延迟、吞吐、队列、容量、依赖健康和降级信号。
3. 对发布或事故分别记录基线、候选产物、触发条件、恢复信号和未观测项。
4. 检查 RPO/RTO、备份恢复、重试/限流/故障转移证据；没有演练结果则标记未验证。
5. 输出 owner、验收信号、停止条件和需要人工审批的动作。

灾备结论必须区分“备份存在”“恢复演练通过”和“恢复后业务信号通过”。任一项缺失都标记 `unknown`，并记录恢复点、恢复时长、数据缺口和下一次演练负责人；不能用提交回滚或服务重新启动冒充 RPO/RTO 证据。

## 交付约束

报告区分事实、推断和未知。不要读取生产凭据或客户原始数据，不执行发布、回滚、切流、扩容、恢复备份或线上配置修改。需要操作时把计划交给发布工程师，并为每个动作请求单独人工审批。

有明显优化空间。搜索与筛选区域偏重，建议改成紧凑工具栏，让任务列表更早出现。

截图中，搜索输入框本身约 40 像素高，但 Tab 下沿到第一条任务之间约有 500 像素。统计、两段说明、重复标题、搜索区、筛选外框和匹配数逐层堆叠，是主要原因。仅缩短搜索框还不足以解决垂直空间问题。

这是 Operate（完成任务）界面。现有暗色视觉、三个 Tab、主次操作关系适合这个产品；计划、初始承诺、历史冻结和结转都有真实业务含义，应保留。无需增加装饰或大卡片。

1. **[P2] 搜索与筛选应成为一条工具栏。** 搜索使用了 1fr 列且没有最大宽度，导致随窗口扩展。桌面建议宽 240–320 CSS px，与“筛选”“分组”并排；窄面板再换行。保留可见搜索入口，不因当前只有两条任务而隐藏。把整行大边框折叠区改成轻量筛选入口，分组单独显示当前值。继续保留可访问名称及触摸目标。对应命令：impeccable layout / distill。依据：packages/views/iterations/iteration-issue-list.tsx:140、147。
2. **[P2] 计划阶段的信息应压成一条简短说明。** 移除 Tab 内重复的“任务”标题；把“计划任务 2”和“开始时确定初始承诺”合并成一行，统计口径说明放到就近帮助入口。默认不单独显示匹配数，筛选后显示结果提示。计划尚未开始时不必提供“原始承诺”切换，开始后按生命周期开放。必须保留全迭代统计、所选范围、筛选结果的语义区别；切换原始承诺时不能拿当前任务数当错误分母。对应命令：impeccable distill / clarify。依据：packages/views/iterations/iteration-page.tsx:125、127、128；iteration-issue-list.tsx:108、138、139、161。
3. **[P2] 折叠后仍须看见生效条件。** 当前筛选标题固定，没有条件数量或摘要；有匹配结果时没有统一清除入口。建议按钮显示“筛选 2”，启用时显示可移除条件及“清除筛选”；分组是独立视图设置，不随清除筛选意外重置。对应命令：impeccable clarify / harden。依据：packages/views/iterations/iteration-issue-list.tsx:147、172。
4. **[P2] 任务行要更容易扫读。** 截图中“已阻塞”和“待办”都是空心圆，状态混在第二行弱化文字里。建议标题为主、编号弱化，状态和负责人有稳定位置；阻塞用文字加适度语义强调。空项目省略，确实未分配的负责人可写“未分配”，历史未知不可混同未分配；去掉孤立分隔符。“结转 0”默认不突出，有结转或达到复盘阈值才强调。保留历史类别语义和长标题换行。对应命令：impeccable layout / clarify。依据：packages/views/iterations/iteration-issue-list.tsx:164–170。

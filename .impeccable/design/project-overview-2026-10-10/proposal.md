# 项目概览改版方案

目标：保留当前轻量、克制的 Multica 产品风格，把“概览”从一列文字摘要变成一页可以快速判断项目状态的工作台。

## 改版后的阅读顺序

```text
项目概览
├─ 任务统计 + 范围闭合轨
├─ 系统健康（主决策区）  |  目标验收（状态区）
└─ 项目进展时间线（记录类型、结果、时间、详情）
```

## 具体调整

### 1. 页签和标题

- “概览”使用 `LayoutDashboard`，“任务”使用 `ListTodo`。
- 保留文字标签和当前 active 背景，图标只做扫描锚点，不做 icon-only 导航。
- “概览”标题右侧收拢统计时间、信息提示和刷新动作。

### 2. 统计区

- 四个任务计数保留现有 `dl` 语义，并在“实际完成 / 取消 / 未结束”前加对应线性图标。
- 将“范围闭合”从第五个孤立数字变成一条分段轨：完成、取消、未结束三段分别对应真实统计，旁边同时显示 `40%` 和 `完成 1 + 取消 1 / 共 5 个任务`。
- 使用现有语义 token（`success`、`muted`、`border`），不使用页面级硬编码颜色。

### 3. 系统健康

- 状态标题行：`Activity` 图标 + “系统健康” + `TriangleAlert 有风险` 状态徽标。
- 四个风险下钻入口变成带图标的动作块：`Ban 阻塞`、`ClockAlert 逾期`、`UserRoundX 未分配`、`ClipboardCheck 待验收`；保留按钮行为和数字。
- 把当前分散在风险列表及额外 warning 段落中的依据合并成“需要关注”摘要，默认只显示一句最高优先级说明；完整依据放入可展开的 `details`。
- 每个状态同时由图标、文字和数字表达，不依赖颜色单独传达风险。

### 4. 目标验收

- 使用 `Target` 图标作为分区锚点。
- 当前描述验收和最近验收各占一行，结果使用带图标的状态徽标：尚未验收、部分通过、通过、未通过。
- “针对旧版本，请复核”继续保持常驻，放在最近验收下方，避免用户误把旧记录当成当前描述的有效结论。

### 5. 项目进展

- 将现有按 border 分隔的文章改成时间线：轨道 + 记录类型图标。
- 记录类型建议：`TrendingUp` 进展、`ShieldAlert` 风险、`ClipboardCheck` 验收。
- 每条记录的固定可见层：类型、结果、是否需复核、作者、时间、版本、首段摘要。
- 验收范围、可复核说明、发布时统计和完整证据作为折叠详情；完整内容仍然保留，避免数据丢失。
- “记录进展”作为主按钮，“记录验收”作为次按钮；沿用现有编辑、预览、发布、冲突比较和修订历史流程。
- 第二阶段可加筛选：`全部 / 进展 / 风险 / 验收`，只改变视图过滤，不改变服务端数据。

## 实施顺序

1. 先抽出 `ProjectHealthSummary`、`ProjectAcceptanceSummary`、`ProjectUpdateTimeline` 三个共享视图组件，先保持数据查询和路由不变。
2. 接入 `lucide-react` 图标和现有 semantic tokens，补齐图标的 accessible name、按钮 aria-label 和键盘 focus 状态。
3. 把风险原因与额外 warning 统一成一个展示模型，避免重复渲染。
4. 将 `project-detail.tsx` 的 `bg-emerald-500` 替换为 token，并让进度条旁显示 `done/total` 和百分比。
5. 增加组件测试：风险入口仍按 signal/version 下钻，旧验收仍显示复核警告，详情折叠不丢正文/证据，窄屏无横向溢出。

## 不建议

- 不把每个模块做成“图标 + 标题 + 正文”的同尺寸卡片墙；这会把当前的文字密集换成卡片密集。
- 不用彩色渐变、环形进度或装饰性插画；项目概览是 Operate 场景，状态可读性优先。
- 不删除风险原因、验收证据或统计快照；只做分层展示。
